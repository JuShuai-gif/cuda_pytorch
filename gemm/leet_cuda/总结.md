### hgemm.cu

1. hgemm_naive_f16_kernel:
最朴素的实现方式，直接进行相乘

2. hgemm_sliced_k_f16_kernel:
A 为 M * K
B 为 K * N
C 为 M * N

然后 按照 K 的方向进行按块进行划分

3. hgemm_t_8x8_sliced_k_f16x4_kernel
一个 16*16 的block处理 C 上大小为 128 * 128 
那说明每个线程处理 TM * TN (8*8)个元素
结果存到每个线程的 r_c 寄存器中

4. hgemm_t_8x8_sliced_k_f16x4_pack_kernel
一个 16*16 的block处理 C 上大小为 128 * 128 
那说明每个线程处理 TM * TN (8*8)个元素
读取内存的时候采用向量化加载，一次加载 64BITS

5. hgemm_t_8x8_sliced_k_f16x4_bcf_kernel:
在 4 的基础上避免 bank conflict

具体思路：
A 初始化是 行主序
B 初始化是 行主序

然后 s_a[BK][BM] 是BK在前面，s_b[BK][BN]也是BK在前面

另外它是通过外积实现的，也就是读取A的一列与B的一列，相乘相加，避免了bcf

6. hgemm_t_8x8_sliced_k_f16x4_pack_bcf_kernel
在上面的基础上读取采用向量化

7. hgemm_t_8x8_sliced_k_f16x8_pack_bcf_kernel
在6的基础上，并列两个f16*4


8. hgemm_t_8x8_sliced_k_f16x8_pack_bcf_dbuf_kernel
在 7 的基础上，采用double buffer

流程：
1. 加载buffer 0
2. for 循环中处理第2个块到倒数第二个块
    2.1 加载
    2.2 计算
3. 处理最后一个块

### hgemm_async.cu
1. hgemm_t_8x8_sliced_k16_f16x8_pack_dbuf_kernel
使用ldst128bits向量化加载，然后使用double buffer

2. hgemm_t_8x8_sliced_k16_f16x8_pack_dbuf_async_kernel
加载使用 async.cp,使用之前需要将 普通全局内存转换为shared,使用 __cvta_generic_to_shared 函数，然后使用 CP_ASYNC_CG，然后进行提交

为什么 A 不使用 cp.async ,因为他想控制 k 的遍历，不能使用
    LDST128BITS(r_load_a[0]) = LDST128BITS(a[load_gmem_a_addr]);

    // 循环将寄存器数据写入共享内存
    #pragma unroll 
    for (int i = 0; i < 8; ++i) { // reg -> shared, fast
      s_a[0][load_smem_a_k + i][load_smem_a_m] = r_load_a[i];
    }

CP_ASYNC_WAIT_GROUP(0)
等待所有已经提交的 cp.async group 都完成

for循环内部处理其他块，计算使用的是 __hfma()

最后计算最后一个块

3. hgemm_t_8x8_sliced_k32_f16x8_pack_dbuf_kernel
比着 2 相当于增加一个块，因为k的方向是32

4. hgemm_t_8x8_sliced_k32_f16x8_pack_dbuf_async_kernel
两个块进行 cp.async

5. hgemm_t_16x8_sliced_k32_f16x8_pack_dbuf_kernel
一个线程处理小块为 16 * 8

6. hgemm_t_16x8_sliced_k32_f16x8_pack_dbuf_async_kernel
5版本的double buffer模式

### hgemm_mma.cu

1. hgemm_mma_m16n8k16_naive_kernel
A 的小块 m16k16
B 的小块 k16n8
向量化加载
每个线程 uint32_t RA[4]; uint32_t RB[2];
A 总共 16 * 16 = 256 = 4 * 2 * 32

使用 __cvta_generic_to_shared 将全局内存指针转换到shared内存指针，然后利用 LDMATRIX_X4 加载到寄存器中
b也是如此

然后利用 HMMA16816 进行计算，将计算的结果存入到寄存器 RC 中，然后使用 LDST32BITS 加载到共享内存 s_a 中，然后从 s_a 中加载到全局内存中

2. hgemm_mma_m16n8k16_mma2x4_warp4x4_kernel
每个 block 包含 8 个warp(256个线程)，每个 block 计算一个 128 * 128的输出块，每个warp 计算一个 64 * 32 的输出块，每个warp 使用 2*4 个MMA 指令(每个 MMA 计算 16 * 8)


### hgemm_mma_stage.cu
1. hgemm_mma_m16n8k16_mma2x4_warp4x4_stages_kernel
其实就是将上面 2 的内容进行 流水线排布

load_gmem_a_addr 到 load_smem_a_ptr的时候，使用cp.async
b也类似

然后 CP_ASYNC_COMMIT_GROUP()

CP_ASYNC_WAIT_GROUP 等待计算所需

加载共享内存的时候使用 LDMATRIX_X4 指令
b 使用的是 LDMATRIX_X2_T
