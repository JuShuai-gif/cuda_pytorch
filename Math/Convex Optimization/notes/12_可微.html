第十二章 可微性

可微性是连接凸优化理论与现代深度学习的桥梁。本章从微积分中的导数定义出发，纵贯自动微分（反向传播）的实现原理、可微编程范式、物理仿真中的可微性，最终落脚于凸优化内部如何利用可微性来求解问题。

💡 关键概念速查

可微性 = "局部线性近似存在"

$f: \mathbb{R}^n \to \mathbb{R}^m$ 在 $x$ 处可微，当且仅当存在线性映射 $J$ 满足 $f(x+\Delta) = f(x) + J\Delta + o(\|\Delta\|)$。
那个 $J$ 就是 Jacobi 矩阵。对 $m=1$，梯度 $\nabla f(x) = J^\top$ 指向函数增长最快的方向。

梯度 = "方向导数最大的方向"

方向导数 $\nabla_v f = \nabla f \cdot v$。由 Cauchy-Schwarz 不等式，$v = \nabla f / \|\nabla f\|$ 时取得最大值。
→ 梯度下降：$x_{k+1} = x_k - \alpha \nabla f(x_k)$，沿着负梯度方向移动。

链式法则 = "反向传播的数学根基"

$h = g \circ f \implies Dh(x) = Dg(f(x)) \cdot Df(x)$。
计算图上的自动微分正是链式法则的系统化执行：前向模式（Jacobian-Vector Product）和反向模式（Vector-Jacobian Product = backprop）。

二次可微 = "局部曲率信息"

Hessian 矩阵 $H_f(x) = \nabla^2 f(x)$ 是一个 $n\times n$ 对称矩阵，刻画函数在某点的弯曲程度。
→ Newton 法：$x_{k+1} = x_k - H^{-1}\nabla f$；→ 凸性判定：$H \succeq 0 \iff f$ 凸。

12.1 什么是可微性

12.1.1 从导数到 Jacobi：标量 → 向量 → 矩阵

定义：导数（标量函数 $f: \mathbb{R} \to \mathbb{R}$）
$$f'(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}$$

几何意义：曲线在 $x$ 处的切线斜率。如果 $f'(x) = 0$，$x$ 可能是极值点（对凸函数一定是全局最小点）。

定义：梯度（多变量标量函数 $f: \mathbb{R}^n \to \mathbb{R}$）
$$\nabla f(x) = \left[ \frac{\partial f}{\partial x_1}, \frac{\partial f}{\partial x_2}, \dots, \frac{\partial f}{\partial x_n} \right]^\top$$

梯度的每一维是函数对该变量的偏导数。$\nabla f(x) = 0$ 是驻点的必要条件。

定义：Jacobi 矩阵（向量值函数 $f: \mathbb{R}^n \to \mathbb{R}^m$）
$$J_f(x) = \begin{bmatrix} \frac{\partial f_1}{\partial x_1} & \cdots & \frac{\partial f_1}{\partial x_n} \\ \vdots & \ddots & \vdots \\ \frac{\partial f_m}{\partial x_1} & \cdots & \frac{\partial f_m}{\partial x_n} \end{bmatrix} \in \mathbb{R}^{m \times n}$$
定义：二阶导数 / Hessian
$$H_f(x) = \nabla^2 f(x) = \begin{bmatrix} \frac{\partial^2 f}{\partial x_1^2} & \cdots & \frac{\partial^2 f}{\partial x_1 \partial x_n} \\ \vdots & \ddots & \vdots \\ \frac{\partial^2 f}{\partial x_n \partial x_1} & \cdots & \frac{\partial^2 f}{\partial x_n^2} \end{bmatrix}$$

若 $f$ 二次连续可微，则 Hessian 对称（Schwarz 定理）。正定 Hessian → $f$ 在该点局部严格凸。

12.1.2 可微 ↔ 不可微：凸函数的关键分界线

💡 直觉

凸函数不一定处处可微，但一定处处次可微。次梯度（subgradient）是可微性的推广：

$$g \in \partial f(x_0) \iff f(x) \ge f(x_0) + g^\top(x - x_0), \quad \forall x$$

对可微点，次梯度就是梯度（唯一）；对不可微点（如 ReLU 在 $x=0$），次梯度是集合 $[0, 1]$。

函数可微性梯度/次梯度在 DL/机器人中的角色
$f(x) = x^2$处处可微$2x$MSE 损失，LQR 代价
$f(x) = |x|$$x=0$ 不可微$\partial f(0) = [-1, 1]$L1 正则化，鲁棒损失
$f(x) = \max(0, x)$$x=0$ 不可微$\partial f(0) = [0, 1]$ReLU 激活函数
$f(x) = -\log x$$x>0$ 可微$-1/x$交叉熵损失，障碍函数
$f(x) = \|x\|_2$$x=0$ 不可微$x/\|x\|_2$（$x \neq 0$）LK 光流，位姿图残差
🔧 工程案例：ReLU 在 0 点的次梯度选择

PyTorch 中 ReLU'(0) = 0（而非理论上的 $[0, 1]$），这是一个工程权衡——单值输出实现简单，且 $x=0$ 在浮点运算中出现概率极低。但如果你写自定义 CUDA Kernel 做量化训练，需要注意某些框架（JAX）在 0 点返回不同值。

12.2 自动微分（Automatic Differentiation, AD）

12.2.1 三种求导方式对比

数值微分符号微分自动微分（AD）
方法$f'(x) \approx \frac{f(x+h)-f(x)}{h}$手动推导公式 + 代入链式法则在计算图上的系统执行
精度受截断误差 + 舍入误差影响精确机器精度（与解析解一致）
速度$O(n)$ 次函数求值（每个参数）表达式膨胀（exponential swell）反向模式：$O(1)$ 次向前 + 1 次向后
适用验证梯度正确性（gradcheck）小规模公式推导所有 DL 框架（PyTorch, JAX, TF）

12.2.2 前向模式 AD vs 反向模式 AD

前向模式（Forward-mode AD）：Jacobian-Vector Product (JVP)

从输入到输出，逐节点计算 $\dot{v} = J \cdot \dot{x}$（一个方向上的导数）。

  • 计算量：$O(n)$ 次正向传播（$n$ = 输入维数）
  • 适用场景：输入少输出多（如参数敏感性分析、ODE 的 forward sensitivity）
  • DL 中的应用：JVP 用于计算 Hessian-Vector Product（HVP），常用于二阶优化
反向模式（Reverse-mode AD）：Vector-Jacobian Product (VJP)

从输出到输入，逐节点计算 $\bar{x} = \bar{v} \cdot J$（梯度的完整向量）。

  • 计算量：$O(1)$ 次正向 + 1 次反向传播
  • 适用场景：输入多输出少（典型 DL：百万参数 → 标量 loss）
  • 代价：需要存储中间激活值（PyTorch 的 .grad 和 JAX 的 checkpointing 都在解决这个）
💡 为什么反向传播统治了深度学习

一个典型的 Transformer（GPT-2 级别）有约 1.5 亿参数（输入维 $n$）但输出是标量交叉熵损失（输出维 $m=1$）。
→ 反向模式：$O(1)$ 次反向即可得到所有梯度
→ 前向模式：需要 $1.5\times 10^8$ 次正向传播
差距是 8 个数量级。这就是为什么所有 DL 框架都用反向模式 AD。

12.2.3 计算图与梯度累积

自动微分将任意计算表达为有向无环图（DAG）：

x ──┐ ├──[mul]── a ──┐ w ──┘ ├──[add]── loss │ b ─────────────────┘ Forward: a = w * x; loss = a + b Backward: ∂loss/∂a = 1; ∂loss/∂w = x * 1; ∂loss/∂x = w * 1; ∂loss/∂b = 1
🔧 工程案例：混合精度训练中的梯度缩放

FP16 训练时，梯度 $\partial L/\partial w$ 可能下溢（< $2^{-14}$）。PyTorch AMP 的做法：
1. Forward: 在 FP16 下计算 loss
2. Loss Scaling：$L_{scaled} = L \times S$（$S=2^{16}$）
3. Backward: 在 FP16 下反向传播，梯度自动放大 $S$ 倍
4. Unscale + 梯度裁剪 + Optimizer step（FP32）
关键：链式法则的线性性保证了 scaling 的正确性——$\partial (S\cdot L)/\partial w = S \cdot \partial L/\partial w$。

12.3 可微编程

12.3.1 什么是可微编程

定义

可微编程（Differentiable Programming）是将整个程序（包括控制流、数据结构、IO）写为可微的形式，使得程序输出的梯度可以通过自动微分反向传播到输入参数。深度学习只是可微编程的一个特例——程序是神经网络。

12.3.2 典型范式

范式描述代表框架DL/机器人场景
Define-by-Run 每次 forward 动态构建计算图，图即代码执行轨迹 PyTorch, TensorFlow Eager 可变长度序列、动态控制流（if/while）
Define-and-Run 先构建静态计算图，再执行 TensorFlow 1.x, Theano 图优化、算子融合、部署（TensorRT）
Functional / JIT 纯函数式，JIT 编译 + 自动批处理（vmap） JAX 大规模并行训练、可微物理仿真

12.3.3 关键机制

vmap（自动向量化）

将单样本函数 $f(x)$ 自动提升为批量函数 $f_{batch}(X)$，无需手动写 batch 维度循环。在 JAX 中：batch_f = jax.vmap(f)。

DL 意义：写代码时只用考虑单个样本，vmap 自动处理 batch 维——这对实现 Attention、LayerNorm 等算子极其方便。

Checkpointing / Rematerialization

反向传播需要前向的中间激活。GPU 显存放不下时，在前向时丢弃部分中间结果，反向时重新计算。

$$ \text{显存节省} \propto \frac{1}{\sqrt{\#\text{layers}}} \quad \text{计算量增加} \propto \sqrt{\#\text{layers}} $$

LLM 训练中的应用：Megatron-LM 的 activation checkpointing 使训练 175B GPT-3 成为可能——否则中间激活会吃掉 TB 级显存。

12.4 可微仿真

12.4.1 为什么仿真需要可微性

💡 核心问题

机器人控制、物理仿真、渲染引擎的传统实现是不可微的黑箱：给定输入参数 → 运行仿真器 → 得到状态轨迹。你无法计算「轨迹对参数的梯度」。

可微仿真 = 仿真器的每个时间步都是可微的 → 梯度可以从最终状态反向传播到初始参数 → 你可以用梯度下降优化控制策略、设计参数、初始条件。

12.4.2 三种实现路径

路径方法优点缺点
1. 从头用 AD 框架写 用 JAX/PyTorch 重写整个物理引擎 梯度精确，端到端可微 工作量大，性能可能不如手写 CUDA
2. 伴随方法 手动推导仿真器 ODE 的伴随方程，和原系统一起求解 内存高效（不需存中间状态） 需要深厚的控制理论功底
3. 差分穿透 在仿真器外部用有限差分 / REINFORCE 估计梯度 对仿真器零侵入 高方差 / 高计算量

12.4.3 具体场景

🔧 机器人：可微动力学（Differentiable Dynamics）

刚体动力学：$M(q)\ddot{q} + C(q,\dot{q})\dot{q} + g(q) = \tau + J_c^\top f_c$

传统做法：给定 $\tau$，用 RK4 积分得到 $q(t)$，然后用有限差分调 $\tau$。
可微做法：用 JAX 重写整个积分器 → $\partial q(T)/\partial \tau(0:T)$ 可以自动算出 → 用梯度下降直接优化控制序列。
代表工作：MuJoCo MJX（Google DeepMind）、Brax、DiffTaichi。

🔧 深度学习：可微渲染（Differentiable Rendering）

渲染管线：3D mesh → 投影 → 光栅化 → 着色 → 图像。
光栅化不可微：像素归属判定是离散操作。
解决方案：用 soft rasterizer（如 SoftRas、PyTorch3D）将离散边界替换为 sigmoid 平滑过渡。
应用：单张图片 3D 重建（NeRF 之前的 SOTA）、可微 SLAM。

🔧 LLM：可微推理 / 可微搜索

Transformer 推理管线的每一步（token 采样、KV cache 更新）被封装为可微操作：

  • Gumbel-Softmax 可微采样：将离散的 argmax token 选择替换为连续近似，使梯度可以流过采样操作
  • 可微 Top-K：在 MoE routing 中，Top-K expert 选择的梯度通过 straight-through estimator 近似
  • 推测解码梯度：draft model 的接受率作为可微指标 → 用梯度优化 draft 策略

12.5 可微性与凸优化的关系

12.5.1 凸优化内部对可微性的依赖

算法需要的导数阶数可微性要求
次梯度下降0 阶（次梯度）不需要可微，只需要凸 + 次梯度存在
梯度下降1 阶目标函数可微
Newton 法2 阶目标函数二次可微 + Hessian 可逆
内点法（障碍法）2 阶障碍函数二次可微
💡 核心洞察

凸优化求解器的每一步迭代，本质上是计算梯度/Hessian + 求解线性系统（KKT）。
自动微分使得你可以只写 forward 函数，框架自动给出梯度/Hessian——这正是 cvxpy 和 Differentiable Convex Optimization (DCO) 的思想。

12.5.2 DCO：可微凸优化层

定义：Differentiable Convex Optimization (DCO)

在神经网络中嵌入一个凸优化问题作为可微层。Forward: 求解凸优化得到最优解 $x^*(\theta)$。Backward: 通过隐函数定理计算 $\partial x^* / \partial \theta$（微分 KKT 条件）。

🔧 代表工作：cvxpylayers（Agrawal et al., 2019）

将 CVXPY 定义的凸优化问题包装为 PyTorch 可微层：

import cvxpy as cp import cvxpylayers.torch # 定义凸优化问题 x = cp.Variable(n) objective = cp.Minimize(cp.sum_squares(A @ x - b) + lam * cp.norm1(x)) prob = cp.Problem(objective) # 包装为 PyTorch 可微层 layer = cvxpylayers.torch.CvxpyLayer(prob, [A, b], [x]) x_star, = layer(A_tensor, b_tensor) # forward: 求解 loss = ...; loss.backward() # backward: 梯度流向 A_tensor!

12.6 三层实现剖析：可微性 → 可微编程 → 可微物理引擎

💡 三层架构总览

三者不是并列关系，而是逐层构建的栈：

┌──────────────────────────────────────────┐ │ 可微物理引擎 (MuJoCo MJX / Brax / Taichi) │ ← 应用层：用梯度优化物理参数 ├──────────────────────────────────────────┤ │ 可微编程框架 (PyTorch / JAX / TF) │ ← 框架层：自动构建计算图 + AD ├──────────────────────────────────────────┤ │ 可微性数学 (导数 / 链式法则 / 次梯度) │ ← 数学层：理论基础 └──────────────────────────────────────────┘

第一层：可微性 — 如何实现「计算导数」

数值微分 — 最朴素，工程上用
$$f'(x) \approx \frac{f(x+h) - f(x-h)}{2h} \quad \text{（中心差分，} O(h^2) \text{ 精度）}$$
# PyTorch 的 gradcheck 用数值微分验证 AD 正确性 def numerical_grad(f, x, eps=1e-6): return (f(x + eps) - f(x - eps)) / (2 * eps) # torch.autograd.gradcheck 内部原理： # 1. 用 AD 算出 analytical_grad # 2. 用数值微分算出 numerical_grad # 3. 断言 ||analytical - numerical|| / max(||analytical||, ||numerical||) < atol

问题：$n$ 个参数需要 $2n$ 次函数求值。GPT-3 有 1750 亿参数 → 完全不可行。

符号微分 — 精确但会膨胀

对表达式树做代数规则替换，如 $\frac{d}{dx}(x^2 + \sin x) = 2x + \cos x$。

# 符号微分的问题：表达式膨胀 (expression swell) f(x) = x * x * x * x * x * x # 即 x^6，写法简洁 f'(x) = 1*x*x*x*x*x + x*1*x*x*x*x + x*x*1*x*x*x + ... # 6项，每项6个因子 # 未经简化的符号导数是原表达式的 O(n) 倍大小

DL 不用的原因：一层 Transformer 的表达式树巨大，符号求导后 TFLOP 量级从可行变成不可行。

自动微分 — DL 的标准答案

核心思想：任何计算都可以分解为基本运算（+, ×, sin, exp, matmul…）的组合。每个基本运算的导数已知且极简。AD 就是链式法则在这些基本块上的系统化执行。

实现 = 三件事：

步骤做什么PyTorch 对应
1. 构建计算图 执行 forward 时记录每一步操作及其输入输出，形成 DAG 每个 Tensor 有 .grad_fn 指向创建它的操作（如 MulBackward0）
2. 定义每个 Op 的 backward 对每个 Op 实现 VJP（Vector-Jacobian Product）：给定上游梯度 $\bar{y}$，输出下游梯度 $\bar{x} = \bar{y} \cdot \partial y/\partial x$ C++ 层 ConvolutionBackward、AddmmBackward 等手写 CUDA kernel
3. 拓扑反向遍历 从 loss 节点出发，按计算图的拓扑逆序依次调用每个 Op 的 backward，用链式法则累积梯度 loss.backward() 触发 Engine::execute()（C++ autograd engine）
🔧 具体例子：$L = \|Wx + b - y\|_2^2$ 的 AD 过程
Forward 构建图（同时存中间值）： t1 = W @ x # MulBackward: 存 W 和 x t2 = t1 + b # AddBackward: 存 t1 和 b t3 = t2 - y # SubBackward: 存 t2 和 y loss = t3.norm()² # NormBackward: 存 t3 Backward 遍历（拓扑逆序）： loss.grad = 1 # 起点 t3.grad = NormBackward(t3, 1) # ∂loss/∂t3 = 2*t3 t2.grad = SubBackward(y, t3.grad) # 梯度不变传下去 b.grad = AddBackward(t1, t2.grad) # ∂loss/∂b = t2.grad t1.grad = AddBackward(b, t2.grad) # 实际是 identity (add 对两个输入都传梯度) W.grad = MulBackward(x, t1.grad) # ∂loss/∂W = t1.grad @ xᵀ x.grad = MulBackward(W, t1.grad) # ∂loss/∂x = Wᵀ @ t1.grad
🔧 PyTorch autograd engine 的关键数据结构
// C++ 层 torch/csrc/autograd/engine.cpp 核心逻辑（简化版） struct Edge { // 图中的一条边 Node* function; // 指向产生该 Tensor 的 Op uint32_t input_nr; // 是该 Op 的第几个输出 }; struct Node { std::vector<Edge> next_edges; // 下游节点 → 构建拓扑图 virtual variable_list apply(variable_list&& grads) = 0; // backward 逻辑 }; void Engine::execute(...) { // 1. 从 loss.grad 开始，拓扑逆序遍历所有 Node // 2. 每个 Node 准备好所有输入梯度后，调用 apply() // 3. apply() 内部调用手写的 backward kernel（CUDA/native） // 4. 梯度累积到参数的 .grad 属性中 }

第二层：可微编程框架 — 如何将「任意程序」变得可微

💡 核心挑战

数学函数（+, ×, sin）天然可微。但程序有分支（if/else）、循环（for/while）、IO、可变状态——这些不是简单的数学函数。可微编程框架必须回答：梯度如何流过这些程序结构？

机制 1：条件分支 — trace 当前路径

PyTorch 的做法：Define-by-Run

每条 if/else 分支在执行时被记录为计算图的一部分。下次输入不同，可能走入不同分支，构建不同的计算图。

# 动态控制流 — PyTorch 天然支持 def f(x): if x > 0: return x ** 2 # backward: 2x else: return x ** 3 # backward: 3x² # backward 时，按照 forward 实际走的路径计算梯度 # 不会去求"未走过的分支"的梯度

代价：每次 forward 都重新构建图 → Python overhead。解决：torch.compile（Dynamo）在第一次运行后缓存编译好的图。

JAX 的做法：Functional + JIT

JAX 的 jit 要求程序在 JIT 边界内是纯函数的。条件分支必须通过 jax.lax.cond 或 jax.lax.switch 表达——它们同时执行所有分支然后选择结果，保证可微的连续性。

# JAX 的条件分支 — 必须是 functional 的 import jax.numpy as jnp from jax import lax def f(x): return lax.cond(x > 0, lambda x: x**2, lambda x: x**3, x) # 内部会同时计算两个分支，然后用 select 选择 ← 保证可微

代价：两条分支都计算 → 浪费计算量。但换来的是 JIT 编译 + vmap + 梯度全链路优化。

机制 2：可变状态 — 梯度如何流过 in-place 修改

PyTorch 的做法

In-place 操作（如 x += 1、x[0] = 3）会覆盖历史值，破坏反向传播所需的前向信息。PyTorch 通过版本号追踪和报错来处理：

x = torch.randn(3, requires_grad=True) y = x * 2 x.add_(1) # RuntimeError: in-place 操作修改了被计算图需要的 Tensor # PyTorch 检测到 x 的版本号变了 → 拒绝执行，要求你 clone() # 正确的写法： y = x.clone() * 2 # clone 创建新节点 x.add_(1) # 现在 x 的修改不影响 y 的图

对可微编程的影响：这是为什么 PyTorch 代码中要频繁 clone()、detach()——你在用操作维护计算图的完整性。

机制 3：不可微操作 — 人为注入近似梯度

Straight-Through Estimator (STE)

对不可微操作（量化取整、argmax、阈值比较），在前向时正常执行离散操作，在反向时假装它是一个恒等映射（梯度 = 1）。

# STE 的实现：自定义 autograd Function class STEQuantize(torch.autograd.Function): @staticmethod def forward(ctx, x): return torch.round(x) # 前向：真的取整 @staticmethod def backward(ctx, grad_output): return grad_output # 反向：假装没取整，梯度直通！ # 这是 LLM 量化训练（QAT）和 VQ-VAE 的核心技巧

LLM 中的应用：GPTQ 量化时对 round 操作的梯度处理、MoE routing 中 Top-K 选择的梯度近似，全部依赖 STE。

机制 4：控制流 + 循环的梯度 — 反向时重放

💡 while 循环的梯度计算

while 循环的迭代次数可能依赖于输入。反向时你不知道循环执行了几次 → 必须存下每次迭代的中间值（PyTorch）或在反向时重新执行整个循环（JAX 的 scan）。

# PyTorch: 内存换时间，存下所有中间状态 states = [] while not converged: x = f(x, theta) states.append(x) # ← 每轮都存，反向时直接取用 # 缺点：无限 while → 可能 OOM # JAX: 时间换内存，用 scan 折叠循环 # scan 将 while 转为固定次数的 for，反向时重新执行 def body_fn(carry, _): return f(carry, theta), None final, _ = lax.scan(body_fn, x0, None, length=max_iters) # 反向时重新计算 body_fn，不存中间状态

第三层：可微物理引擎 — 如何让刚体动力学变得可微

💡 核心难题

物理仿真的核心是碰撞检测 + 约束求解，这两个操作本质上是离散且不可微的：

  • 碰撞检测：两个物体的距离 d。d > 0 → 不碰撞；d < 0 → 碰撞。发生碰撞的瞬间，接触力从 0 跳变为非零——梯度不连续
  • 摩擦：库仑摩擦模型是分段函数（静摩擦 vs 动摩擦），转角处不可微
  • LCP（线性互补问题）：接触力求解最终化为 $\lambda \ge 0,\ \phi \ge 0,\ \lambda \cdot \phi = 0$——这是非光滑的

路径 1：解析伴随方法（Analytical Adjoint）— 推导连续系统的伴随 ODE

原理

不试图对仿真器的每一步求导，而是把整个仿真看作连续 ODE $dx/dt = f(x, \theta)$，手动推导伴随方程（adjoint ODE）并在反向时求解。

前向 ODE（仿真）： $dx/dt = f(x(t), \theta), \quad x(0) = x_0$ 伴随 ODE（反向梯度）： $d\lambda/dt = -\lambda \cdot \partial f/\partial x, \quad \lambda(T) = \partial L/\partial x(T)$ 参数梯度： $\partial L/\partial \theta = \int_0^T \lambda(t) \cdot \partial f/\partial \theta \ dt$ 关键优势：内存 $O(1)$（不需存中间状态！只需在反向时重新积分一次） 关键代价：需要自己推导 $\partial f/\partial x$ 和 $\partial f/\partial \theta$（对于多体动力学非常复杂）
🔧 实际框架：DiffTaichi

DiffTaichi 让用户用 Taichi 语言写仿真 kernel，编译器自动生成 forward 和 backward（通过源码变换 + AD）。对刚体碰撞，它使用软化接触模型（将硬接触替换为连续力场）使系统可微：

# 硬接触（不可微）→ 软化接触（可微） # 硬接触: f = 0 if d>0 else k*d （分段，拐点不可微） # 软化: f = k * softplus(d) （处处可微！） # Taichi kernel 中的写法（简化） @ti.kernel def collide(): for i in particles: d = dist_to_ground(particles[i]) particles[i].force.y += k * ti.log(1 + ti.exp(-d)) # softplus → 可微

路径 2：隐函数微分（Implicit Differentiation）— 不对仿真步求导，对不动点求导

原理

物理仿真的每一步本质上在求解一个隐式方程 $g(x^*, \theta) = 0$（如力平衡）。我们不需要微分整个求解过程，只需要微分解本身：

$$\frac{\partial x^*}{\partial \theta} = -\left[ \frac{\partial g}{\partial x} \right]^{-1} \frac{\partial g}{\partial \theta}$$

这就是隐函数定理的直接应用。它比微分整个积分过程更稳定、计算量更小。

🔧 实际框架：Brax / MuJoCo MJX（Google DeepMind）

这两者都基于 JAX 实现，利用 JAX 的 AD 能力加上隐函数微分：

# Brax 中的可微仿真（简化） def step(state, action): # 1. 计算外力（motor torques → generalized forces） qf = actuator(action) # 2. 前向动力学（solve M * qdd = qf - C - g + Jᵀ*f_contact） qdd = solve_forward_dynamics(state, qf) # 隐式求解 # 3. 半隐式 Euler 积分 next_state = integrate(state, qdd) return next_state # 用 jax.grad 求 loss 对 action 的梯度 loss = final_state_error(rollout(init_state, actions)) grad = jax.grad(loss)(actions) # ← 整个 rollout 可微！

关键技术：碰撞检测的「平滑化」——将 discrete contact 替换为 soft contact（力是 penetration depth 的光滑函数），使全局可微。

路径 3：强化学习的梯度估计（REINFORCE）— 对仿真器零侵入

原理

不要求仿真器可微。将控制策略视为概率分布 $\pi(a|s)$，用 score function 估计梯度：

$$\nabla_\theta J = \mathbb{E}\left[ R \cdot \nabla_\theta \log \pi_\theta(a|s) \right]$$
🔧 实际框架：Isaac Gym

NVIDIA Isaac Gym 提供非可微的高速 GPU 物理仿真（万级并行环境）。梯度不是从仿真器来，而是从 PPO/REINFORCE 的 TD 误差来。

# Isaac Gym 不可微 → 用 PPO 的 actor-critic 梯度 # 优势：不需要推导物理梯度，仿真器可跑任意快 # 劣势：需要百万级环境交互（vs 可微仿真的千次级） # 混合趋势：先用可微仿真快速预训练，再用 Isaac Gym RL fine-tune

📌 关键认知

「可微物理引擎」不是把传统引擎改一行代码就变可微了。它的核心工作在于：

  1. 软化非光滑操作（碰撞 → soft contact，摩擦 → sigmoid 过渡，LCP → 凸 QP 替代）
  2. 选择梯度路径（微分整个 rollout vs 隐函数定理 vs REINFORCE 估计）
  3. 用 AD 框架重写（C++ 引擎 → JAX/PyTorch，放弃部分手写优化的性能换取可微性）
