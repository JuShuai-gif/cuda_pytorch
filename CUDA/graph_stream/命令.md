# CUDA Graph / Kernel Fusion 编译与检测命令

## CUDA Graph Demo

```bash
# 编译
nvcc -O3 -std=c++17 cuda_graph_demo.cu -o cuda_graph_demo

# 直接运行
./cuda_graph_demo

# nsys 检测
nsys profile --stats=true -o /tmp/graph_report ./cuda_graph_demo

# 查看 CPU 端 API 开销（重点关注 cudaLaunchKernel vs cudaGraphLaunch 次数和耗时）
# 查看 GPU Kernel 时间线（20,001 次 shortKernel，区分普通启动和 Graph 启动区间）
nsys-ui /tmp/graph_report.nsys-rep
```

### 检测关键指标

| 指标                      | 数值       | 说明                                       |
| ------------------------- | ---------- | ------------------------------------------ |
| `cudaLaunchKernel`        | 20,021 次  | 普通模式每次 kernel 独立走 CPU→GPU 调度    |
| `cudaLaunchKernel` 耗时    | ~1.3 us/次 | 单次 kernel 启动的 CPU 开销                |
| `cudaGraphLaunch`         | 1,001 次   | Graph 模式每步 1 次替代 20 次 kernel 启动  |
| GPU Kernel 总执行         | 20,001 次  | 20,000 正式 + 1 预热                       |

## Kernel Fusion Demo

```bash
# 编译
nvcc -O3 -std=c++17 cuda_fusion_demo.cu -o cuda_fusion_demo

# 直接运行
./cuda_fusion_demo

# nsys 检测
nsys profile --stats=true -o /tmp/fusion_report ./cuda_fusion_demo

# 查看编译资源（寄存器数等）
nvcc -O3 -std=c++17 -Xptxas=-v cuda_fusion_demo.cu -o cuda_fusion_demo

# 查看报告
nsys-ui /tmp/fusion_report.nsys-rep
```

### 检测关键指标

| Kernel             | 单次耗时     | 显存流量             | 说明             |
| ------------------ | ------------ | -------------------- | ---------------- |
| `abs_kernel`       | ~1.21 ms     | 读 x + 写 tmp        | 未融合 Kernel 1  |
| `sum_kernel`       | ~0.61 ms     | 读 tmp + 归约        | 未融合 Kernel 2  |
| `sum_abs_kernel`   | ~0.56 ms     | 读 x + 归约（无 tmp） | 融合版           |
| 未融合合计         | ~1.82 ms     | ~768 MB              | 3 倍显存流量     |
| 融合版             | ~0.56 ms     | ~256 MB              | 加速 **3.2x**    |

---

## 两者对比总结

|                | CUDA Graph                  | Kernel Fusion                 |
| -------------- | --------------------------- | ----------------------------- |
| 优化层级       | CPU 侧启动开销              | GPU 侧显存流量 + Kernel 数量  |
| Kerenl 是否改变 | 不变，仍为独立 Kernel       | 合并为一个或更少的 Kernel     |
| 中间数组       | 仍然存在                    | 被消除                        |
| 显存流量       | 不变                        | 显著降低                      |
| 可同时使用     | 是                          | 是                            |

## CUDA Stream Demo

```bash
# 编译
nvcc -O3 -std=c++17 cuda_stream_demo.cu -o cuda_stream_demo

# 直接运行（看终端输出：各场景耗时和加速比）
./cuda_stream_demo

# nsys profile — 最关键：在 nsys-ui 时间线中看 stream 重叠
nsys profile --stats=true -o /tmp/stream_report ./cuda_stream_demo

# 只看 GPU trace（不含 CPU API trace），更关注 GPU 端并行度
nsys profile --trace=cuda -o /tmp/stream_gpu ./cuda_stream_demo

# 查看时间线 GUI
nsys-ui /tmp/stream_report.nsys-rep

# 导出 NVTX/stream 统计（看每个 stream 的 kernel 时间分布）
nsys stats --report cuda_gpu_kern_sum /tmp/stream_report.nsys-rep
```

### nsys 时间线中要关注什么

| 场景                | 默认流时间线                     | 多流时间线                           |
| ------------------- | -------------------------------- | ------------------------------------ |
| Light kernel(小)    | 4个 kernel 串行, 无重叠          | 4个 kernel 在 4 个 stream 上**重叠** |
| Heavy kernel(大)    | 4个 kernel 串行, 各占满 SM       | 4个 kernel **仍串行**（GPU 饱和）    |
| Copy+Compute        | H2D → kernel → D2H 严格串行     | H2D/kernel/D2H 跨 stream **流水线**  |
| Event dependency    | -                                | stream 0 kernel 完成 → event → stream 1 kernel 开始 |

### 检测关键指标

| 指标                          | 默认流        | 多流           | 说明                                          |
| ----------------------------- | ------------- | -------------- | --------------------------------------------- |
| Light kernel 耗时             | ~1.7 ms       | ~0.78 ms       | 2.17x 加速, 小 kernel 不饱和 GPU              |
| Heavy kernel 耗时             | ~487 ms       | ~502 ms        | 无加速, 大 kernel 已占满所有 SM                |
| Copy+Compute 时间线重叠       | 串行          | H2D||Kernel||D2H | copy engine 和 SM 并行, 通过不同 stream 实现   |
| `cudaStreamCreateWithFlags`   | 0 次          | 4 次           | NonBlocking 避免隐式同步                      |
| GPU 时间线 stream 列           | 仅 Default    | Stream13/14/15/16 | 不同 stream ID, 操作重叠                    |

### 核心结论

1. **多流加速的前提**: kernel 不够大, GPU 有空闲 SM — 否则多流无加速（无更多硬件资源可用）
2. **最大收益场景**: 拷贝+计算重叠 — H2D/D2H 走 copy engine, kernel 走 SM, 天然并行
3. **PyTorch 中**: `DataLoader(pin_memory=True)` + `.to('cuda', non_blocking=True)` 自动实现拷贝-计算流水线
4. **cudaStreamNonBlocking**: 必须使用, 否则默认流会隐式串行化所有操作
5. **精细同步用 event**: `cudaEventRecord` + `cudaStreamWaitEvent` 比 `cudaDeviceSynchronize` 开销小

## 三者对比总结

|                | CUDA Graph                  | Kernel Fusion                 | CUDA Stream                    |
| -------------- | --------------------------- | ----------------------------- | ------------------------------ |
| 优化层级       | CPU 侧启动开销              | GPU 侧显存流量 + Kernel 数量  | GPU 硬件单元并行利用           |
| Kerenl 是否改变 | 不变，仍为独立 Kernel       | 合并为一个或更少的 Kernel     | 不变，仍为独立 Kernel          |
| 中间数组       | 仍然存在                    | 被消除                        | 仍然存在                       |
| 显存流量       | 不变                        | 显著降低                      | 不变                            |
| 适用场景       | 重复的小 kernel 序列        | 连续的逐元素操作              | 独立数据块并行 / 拷贝计算重叠  |
| 可同时使用     | 是                          | 是                            | 是                              |
