## 章节概述

在实验室中表现良好的模型最终会在生产环境中出现问题——不是因为模型"变坏了"，而是环境发生了变化。新的用户行为、产品更新、流量模式变化和数据源的演变会逐渐改变模型训练时的统计假设。

这些变化表现为**分布漂移**（distribution drift）：输入分布 `p(x)` 可能变化（协变量漂移），类别频率 `p(y)` 可能变化（先验漂移），或者输入与输出之间的关系 `p(y|x)` 可能变化（概念漂移）。同时，生产系统自身引入了队列、批处理、缓存行为和硬件条件等动态因素。

### 三大核心主题

| 主题 | 说明 |
|------|------|
| 漂移检测与处理 | 使用轻量级监控（滚动直方图、PSI、KS检验、卡方检验）检测并分类漂移 |
| 基于证据的调试 | 通过结构化日志、指标和追踪（trace）诊断故障，可复现地隔离根因 |
| 有目的的重新训练 | 基于证据触发重训练，通过可复现流水线和受控发布（影子测试、金丝雀发布）推进模型 |

### 四种漂移类型

| 漂移类型 | 概率变化 | 典型响应 |
|---------|---------|---------|
| 协变量（特征）漂移 | `p(x)` 变化 | 检查特征流水线、更新归一化常量 |
| 预测漂移 | 模型输出分布变化 | 监控校准度、分数分布 |
| 先验（标签）漂移 | `p(y)` 变化 | 调整决策阈值或重新校准 |
| 概念漂移 | `p(y\|x)` 变化 | 重训练、可能需要特征重设计 |

### 三大可观测性支柱

| 工具 | 用途 | 实现方式 |
|------|------|---------|
| 结构化日志 | 每个请求自描述、可查询 | JSON 行格式，含请求ID、模型版本、形状 |
| 指标 | 速率、延迟、错误摘要 | 原子计数器 + 定期刷新 |
| 追踪 | 端到端延迟分解为命名阶段 | 作用域计时器，发射 span 持续时间 |

## 技术速查

### 漂移检测统计方法

| 方法 | 适用场景 | 注意事项 |
|------|----------|----------|
| PSI（Population Stability Index） | 分区间数值特征比较 | PSI < 0.1: 无漂移; 0.1–0.25: 中度; > 0.25: 显著 |
| KS 检验 | 连续分布的最大距离 | 对分布尾部敏感；非参数检验 |
| 卡方（χ²）检验 | 类别分布比较 | 对小样本使用 Yates 校正或合并区间 |
| KL 散度 | 概率分布差异度量 | 非对称；对零概率敏感 |
| JS 散度 | 对称且始终有限 | KL 的对称变体，更适合监控 |

### 漂移响应策略

| 漂移类型 | 最小干预 | 最大干预 |
|---------|---------|---------|
| 先验/标签漂移 | 调整决策阈值、校准 | 按队列重训练 |
| 特征漂移（流水线问题） | 修复归一化/编码 | 升级 schema 版本 |
| 特征漂移（无流水线问题） | 按最近数据重训练 | 特征重设计 |
| 概念漂移 | 重训练 + 特征重设计 | 蒸馏学生模型、按队列路由 |

### 三种 bug 类别

| 类别 | 典型症状 | 第一步诊断 |
|------|---------|-----------|
| 数值 bug | NaN/Inf 传播、FP16/FP32 不一致、softmax 饱和 | 使用数值稳定形式（log-sum-exp）、比较精度 |
| 数据合约 bug | 未知类别激增、PSI 尖峰、形状不匹配 | 强制 schema 版本、监控未知 token 比率 |
| 并发/同步 bug | 非确定性故障、偶发超时、死锁 | ASan/TSan、添加显式同步、使用消息传递 |

### 安全发布阶梯

| 阶段 | 流量比例 | 监控指标 | 回滚条件 |
|------|---------|---------|---------|
| 影子测试 | 0%（镜像） | 分歧率、延迟奇偶性 | — |
| 金丝雀 5% | 5% | p95/p99 延迟、错误率、领域 KPI | 延迟超限 10 分钟或业务指标恶化 |
| 金丝雀 25% | 25% | 同上 + 按队列切片 | 同上 |
| 金丝雀 50% | 50% | 同上 | 同上 |
| 全量上线 | 100% | 所有指标 | 保留前冠军模型热备 |

### 延迟标签前导指标

| 指标 | 说明 |
|------|------|
| 冠军-挑战者分歧 | 影子流量上模型间的分歧增加 |
| 弃权/覆盖率 | 人工审核队列或规则回退的比率 |
| 预测分布 | 类别混合、置信度分布、分数百分位数 |
| 下游代理信号 | 退款率、申诉、安全标记、点击率变化 |

## 注意事项

### 外部库依赖

本章所有实现均为**纯 STL（C++17）**，无外部库依赖。这确保所有示例在任意标准 C++ 环境中均可编译运行。

| 文件 | 需要的外部库 | 说明 |
|------|-------------|------|
| 所有文件 | 无（纯 STL） | 使用 C++17 标准库即可编译运行 |
| `06_numerical_stability.cpp` | 无（纯 STL） | CUDA_CHECK 宏仅作演示，编译时默认不链接 CUDA |

### PDF 中提及但未独立实现的库用法

以下知识点在 PDF 中有详细示例，但在本章代码中以引用说明的形式出现，因为需要额外安装对应库或特定硬件：

| 知识点 | PDF 页 | 说明 |
|--------|--------|------|
| CUDA 错误检查与 compute-sanitizer | 439–440 | `06_numerical_stability.cpp` 提供了 CUDA_CHECK 宏，但未编译实际 CUDA 代码 |
| OpenTelemetry / Prometheus 集成 | 参考阅读 | `03_inprocess_metrics.cpp` 和 `04_distributed_tracing.cpp` 提供了轻量级实现，生产环境建议接入 OpenTelemetry |
| INT8 量化、模型蒸馏 | 参考阅读 | `08_retraining_workflow.cpp` 的接受门禁中引用了相关概念 |

### 其他注意事项

- `07_micro_batcher.cpp` 中的 `Tensor` 类型使用了 `std::vector<float>` 作为占位符，实际生产环境应替换为 `torch::Tensor` 或其他张量类型。
- `06_numerical_stability.cpp` 中的 `CUDA_CHECK` 宏仅在定义了 `USE_CUDA=1` 时编译 CUDA 相关代码，默认不使用。
- 所有示例使用 C++17 标准。`01_drift_detection.cpp` 使用了 `<numeric>` 中的 `std::accumulate` 和 `<algorithm>` 中的 `std::transform`。
- 漂移检测中的 PSI/KS/卡方检验实现为演示参考；生产环境建议使用专业库（如 Alibi Detect、Evidently AI）。
