# Spatio-Temporal Joint Trajectory Optimization - 横纵时空联合轨迹优化

## 背景

这是**自动驾驶运动规划 (Motion Planning)** 的核心课题。车辆在行驶中需要同时决策：

- **横向 (Lateral)**: 什么时候变道？偏离参考线多远？
- **纵向 (Longitudinal)**: 什么时候加速/减速？目标速度多少？
- **时间 (Temporal)**: 动作在什么时间尺度内完成？

"横纵时空联合"意味着在 **Frenet 坐标系** 下，将横向 (d) 和纵向 (s) 的轨迹统一表示为时间 (t) 的多项式函数，并通过多目标代价函数联合优化。

核心参考文献：*"Optimal Trajectory Generation for Dynamic Street Scenarios in a Frenet Frame"* (Werling et al., ICRA 2010) — 这是百度 Apollo 等自动驾驶系统的理论基础。

## 算法原理

### 1. Frenet 坐标系

将车辆运动分解为沿参考线的纵向运动 s(t) 和垂直于参考线的横向偏移 d(t)：

```
                 d (lateral offset)
                 ^
                 |
    vehicle ●────|──→ s (along reference path)
                 |
                 |
```

### 2. 多项式轨迹表示

- **横向**: 五次多项式 (quintic) `d(t) = a5·t⁵ + a4·t⁴ + ... + a0`
  - 6 个边界条件：起点 (d₀, ḋ₀, d̈₀) + 终点 (d₁, ḋ₁, d̈₁)
- **纵向**: 四次多项式 (quartic) `s(t) = b4·t⁴ + b3·t³ + ... + b0`
  - 5 个边界条件：起点 (s₀, ṡ₀, s̈₀) + 终点 (ṡ₁, s̈₁)，位置 s₁ 自由

### 3. 候选轨迹生成

通过采样生成大量候选轨迹：

| 参数 | 含义 | 典型采样范围 |
|------|------|-------------|
| d₁ | 终点横向偏移 | -4.0 ~ 4.0m (25 个采样) |
| T | 时间跨度 | 1.0 ~ 8.0s (20 个采样) |
| v_target | 终点目标速度 | 5 ~ 25 m/s (20 个采样) |

总候选数 = 25 × 20 × 20 = **10,000 条轨迹**

### 4. 多目标代价函数 (Cost Functions)

对每条候选轨迹，计算以下代价项的加权和：

| 代价项 | 公式 | 物理含义 | 典型权重 |
|--------|------|----------|----------|
| **Jerk** | ∫(d⃛² + s⃛²)dt | 舒适性：加加速度（冲击度） | 1.0 |
| **Lateral Acceleration** | ∫(d̈²)dt | 舒适性：横向加速度 | 10.0 |
| **Longitudinal Acceleration** | ∫(s̈²)dt | 舒适性：纵向加速度 | 10.0 |
| **Reference Deviation** | ∫(d - d_ref)²dt | 跟踪性：偏离参考线 | 5.0 |
| **Obstacle Avoidance** | Σ exp(-dist / radius) | 安全性：障碍物距离 | 50.0 |
| **Velocity Deviation** | (v_final - v_target)² | 效率性：速度偏差 | 5.0 |
| **Time Cost** | T | 效率性：鼓励快速到达 | 1.0 |
| **Curvature Limit** | max(κ) 超过 0.3 时惩罚 | 安全性：曲率限制 | 50.0 |
| **Centripetal Accel** | max(v²·κ) 超过 3.0 时惩罚 | 安全性：向心加速度 | 30.0 |

**总代价 = Σ(weight_i × cost_i)**，选择总代价最小的轨迹作为输出。

## CUDA 并行化策略

- **每条轨迹一个 CUDA 线程**: 10,000 条轨迹 → 10,000 个线程并行计算
- **每线程内循环**: 沿时间采样点 (如 50 个) 计算各时刻的状态和代价
- **并行归约**: 先块内归约 → 再全局归约，找出代价最小的轨迹索引
- **障碍物代价**: 每个时间点检查所有障碍物（原子操作无需，每个线程独立）

## 性能对比

| 候选数 | CUDA | CPU | 加速比 |
|--------|------|-----|--------|
| 175 | 0.065s | 0.044s | 0.67x (GPU 启动开销 > 计算) |
| **10,000** | **0.005s** | **2.533s** | **562x** |

小规模时 GPU 启动开销占主导，但候选轨迹数增加后 GPU 优势急剧放大。实际自动驾驶系统中通常有 10K~100K 条候选轨迹，GPU 加速至关重要。

## 适用场景

| 适用 | 不适用 |
|------|--------|
| 自动驾驶运动规划 (L3/L4) | 简单定速巡航 |
| 结构化道路变道决策 | 非结构化环境 (越野、停车场) |
| 大量候选轨迹需要实时评估 | 候选数 < 100（CPU 反而更快） |
| 多障碍物复杂场景 | 单障碍物简单场景 |
| 在线重规划 (replanning) | 离线全局路径规划 |
| ADAS 功能 (AEB, LKA, ACC 联合) | 纯几何路径规划（无速度剖面） |

## 实际落地案例

| 场景 | 具体案例 |
|------|----------|
| 百度 Apollo EM Planner | **就是这套方案**：Frenet 采样 + S-T 图 + 代价函数选优 |
| Waymo 行为规划 | 数十万条候选轨迹并行评估，CUDA 加速 |
| 特斯拉 FSD 规划 | 类似框架，但代价函数由端到端神经网络学习 |
| 自动泊车 (APA/HPA) | 低速场景简化为 2D 时空联合搜索最优泊车轨迹 |
| 高速 NOA 变道 | 横纵解耦：横向五次多项式 + 纵向四次多项式 |
| 机器人动态避障 | 移动机器人在人群中的实时轨迹重规划 |

## 扩展方向

这个框架可以进一步扩展：

1. **更多采样维度**: 采样终点横向速度、加速度，候选数可达 100K+
2. **碰撞检测升级**: 使用占用栅格 (occupancy grid) 替代点障碍物
3. **动态障碍物**: 预测障碍物未来轨迹，代价与时间相关
4. **多阶段规划**: 联合优化粗规划 + 精规划两个阶段
5. **学习代价权重**: 使用逆强化学习从人类驾驶数据学习权重

## 改进方向

| 方向 | 来源 | 说明 |
|------|------|------|
| Lattice Planner | 工业: Apollo 4.0+ | 用预计算的运动基元 (motion primitive) 替代在线多项式求解 |
| iLQR / DDP | 学术: Tassa et al. (2014) | 微分动态规划，局部迭代优化轨迹，比采样更精确 |
| MPC 滚动时域 | 工业: 学术通用 | 每步重规划 + 只执行第一步，闭环鲁棒性远高于开环 |
| 凸优化 (OSQP) | 学术: Stellato et al. (2020) | 把轨迹优化转为 QP 问题，OSQP 算子分裂法求解 |
| 逆强化学习 (IRL) | 学术: Ziebart et al. (2008) | 从人类驾驶数据学习代价权重，替代人工标定 |
| 占用栅格碰撞 | 工业: 特斯拉/Waymo | 用栅格替代点障碍物，支持任意形状 + 概率占用 |
| 博弈论交互 | 学术: 前沿方向 | 同时优化自车 + 他车轨迹，纳什均衡找最优交互策略 |
