# 系统调用、磁盘IO与网络

## strace与Syscall Overhead

Demo：`29_syscall_bad_good`。Bad每字节open/write/close，Good一次open并批量write。

```bash
strace -c ./src/build/29_syscall_bad_good
strace -f -tt -T ./program
strace -e trace=openat,read,write ./program
ltrace -c ./program
```

- read/write多：小IO未批量。
- openat多：重复查配置、模型或文件。
- futex长：锁/条件变量等待候选。
- poll/epoll_wait：可能是正常事件循环，也可能上游无数据。

strace有明显扰动，只用于次数/类型/相对耗时，不替代原生Benchmark。ltrace看动态库调用，strace看内核syscall。

## Disk IO

安全Demo只写小文件，不自动创建GB数据。

```bash
iostat -xz 1
iotop
strace -c ./src/build/11_io_bottleneck /tmp/profiling-io.tmp
fio --name=seq --filename=/tmp/profiling-fio --size=64M --rw=write --bs=1M
fio --name=small --filename=/tmp/profiling-fio --size=64M --rw=randread --bs=4k --iodepth=16
```

关注IOPS、throughput、await/latency、queue depth、iowait。page cache与direct IO是不同实验。当前缺fio。

## 网络与ROS云边链路

```bash
ping -c 20 HOST
iperf3 -c HOST -P 4
iperf3 -c HOST -u -b 100M
ss -ti
tcpdump -i IFACE -w /tmp/trace.pcap
```

分布式VLA/ROS关注RTT、bandwidth、jitter、packet loss和TCP retransmission。带宽足够但P99高，可能是排队、重传或DDS QoS。抓包可能含敏感数据，只对授权接口使用。

## syscall不等于瓶颈

调用次数多不必然慢。epoll_wait可能表示线程高效睡眠；read可能命中page cache；futex可能是无竞争快速路径后的少量等待。需要同时看calls、time/call、总占比和业务阶段。

## 小IO为何昂贵

每次syscall涉及用户态/内核态边界、参数检查、文件描述符状态和可能的调度。open/close还涉及路径解析与元数据。buffering、writev/readv、批量提交可摊销固定成本。

## IO实验公平性

- 明确是否包含fsync；
- 明确buffered还是direct IO；
- 冷cache与热cache分测；
- 固定文件大小和block size；
- 不在系统盘无节制压测；
- latency与throughput分别报告；
- 监控磁盘空间并清理测试文件。

## Queue Depth

QD提高可增加设备并行和throughput，也可能增加排队latency。机器人日志写入应避免高QD影响模型加载或camera录制。fio结果应结合应用实际块大小与读写比例。

## 网络尾延迟

平均RTT低但P99高可能来自Wi-Fi重传、拥塞排队、TCP retransmission、DDS discovery或大消息分片。UDP没有传输层重传但会丢包；TCP保证字节流却可能产生head-of-line blocking。

## ROS网络诊断示例

```text
camera发布30Hz，订阅端只有22Hz
→ topic hz/bw确认频率与带宽
→ DDS统计看drop/retransmit
→ tcpdump看分片与重传
→ callback timeline看executor排队
→ 区分网络、序列化和消费端处理
```

## 安全说明

tcpdump/pcap可能包含敏感数据；fio可能破坏目标文件。只在授权接口和明确临时文件上运行，不使用通配路径。
