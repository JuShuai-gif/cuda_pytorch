## Leak与Fragmentation

Leak是对象生命周期结束后资源仍不可达；Fragmentation是对象可能已释放，但heap空洞或allocator保留arena导致RSS不降。

Valgrind分类：

- definitely lost：没有任何指针可达。
- indirectly lost：由已丢失对象拥有。
- possibly lost：只剩内部指针等不确定引用。
- still reachable：退出时仍可达，不一定是泄漏。

```bash
valgrind --leak-check=full --show-leak-kinds=all ./src/build/08_memory_leak
heaptrack ./src/build/31_memory_fragmentation
MALLOC_CONF=prof:true,prof_active:true ./jemalloc_program
HEAPPROFILE=/tmp/hprof ./tcmalloc_program
```

## ASan、LSan、UBSan、TSan与Valgrind

```bash
cmake -S src -B asan -DCMAKE_CXX_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer -g'
cmake --build asan --target 09_use_after_free 32_heap_buffer_overflow
ASAN_OPTIONS=detect_leaks=1 ./asan/09_use_after_free
./asan/32_heap_buffer_overflow
```

ASan查越界/UAF，LSan查leak，UBSan查未定义行为，TSan查data race，MSan查未初始化读取。它们首先是正确性工具，不是严格性能Profiler。Valgrind无需重编但更慢；Sanitizer适合开发和CI。

危险Demo `08_memory_leak`、`09_use_after_free`、`32_heap_buffer_overflow`不进入自动脚本。

## 分配器视角

应用请求的对象大小、allocator实际保留的span/arena和操作系统RSS是三种不同量。glibc malloc、jemalloc和tcmalloc都有线程cache或arena。对象释放只代表返回分配器，不保证立即munmap给内核。

## 高频分配的诊断流程

```text
RSS/P99异常
→ 应用allocation counter
→ heaptrack找调用栈
→ Massif看峰值时间线
→ allocator profile区分active与retained
→ reserve/reuse/pool
→ 复验allocation count、peak、P99
```

累计allocated bytes很大不等于峰值很大；同一buffer反复分配释放会有巨大累计量但较小live heap。

## VLA Buffer生命周期

建议明确所有权：

| Buffer | 推荐生命周期 |
|---|---|
| Camera capture | 驱动buffer pool/ring |
| Decode output | decoder surface pool |
| Resize/normalize | 预分配workspace |
| H2D staging | pinned double buffer |
| TensorRT binding | engine生命周期 |
| KV cache | session生命周期 |
| Action/state | 固定容量ring |

每帧new Tensor、clone或vector扩容会增加allocator锁、cache扰动和尾延迟。

## Leak长期实验

短时Valgrind通过不能证明服务运行24小时不增长。长期稳定性应周期采集RSS、active heap、GPU allocated/reserved、queue depth和frame drop，并对时间做趋势分析。

线性增长常提示每请求泄漏；阶梯增长可能是cache扩容；增长后平台期可能是allocator warm-up；RSS不降但active稳定可能是fragmentation或retained arena。

## Sanitizer工程实践

- RelWithDebInfo保留可读栈；
- 首先修复第一个报告，后续可能是级联错误；
- TSan与ASan通常分开构建；
- 第三方库未插桩可能限制MSan；
- 高性能手写SIMD/CUDA边界优化后必须回归ASan和correctness。

## RAII Good Case

优先vector、array、unique_ptr和作用域对象。共享所有权只在真实需要时使用shared_ptr；滥用shared_ptr增加原子引用计数和生命周期复杂性。

## 练习

1. 运行allocation实验并解释为何次数下降远大于runtime下降。
2. 用ASan手动运行UAF和overflow，定位首个非法访问。
3. 对fragmentation实验同时记录RSS和live object，证明两者不能互相替代。
