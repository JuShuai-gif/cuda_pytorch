# 环境与验证结果

## 当前环境

Ubuntu 24.04，GCC 13.3，CMake 3.28，Python 3.13。可用：perf、strace、gprof、bpftrace、trace-cmd、nvcc、nsys、ncu、numactl。不可用：Valgrind、heaptrack、VTune、LIKWID、fio、cyclictest、tegrastats、jtop。PyTorch 为 CPU build。主机只有一个 NUMA node。

CUDA程序可以运行，但 `nvidia-smi` 存在 NVML driver/library mismatch；ncu 因 `ERR_NVGPUCTRPERM` 无法读取硬件计数器。未使用sudo或修改系统权限。

## 已完成验证

| 实验 | Bad | Good | 结论 |
|---|---:|---:|---|
| CPU Hotspot | 18.5 ms | 7.9 ms | 相对误差约9.8e-13 |
| Random/Sequential | 约100 ms | 约4.6 ms | checksum一致 |
| Column/Row-major | 83–89 ms | 4.7–5.0 ms | 空间局部性差异清晰 |
| AoS/SoA | 25.8 ms | 9.4 ms | 仅访问x/y时SoA更优 |
| Allocation | 1,040,001次 | 1次 | reserve/reuse有效 |
| Lock | 199 ms | 1.0 ms | 局部归约消除大临界区 |
| shared_mutex | 127.3 ms | mutex 124.7 ms | shared_mutex并非必快 |
| Imbalance | 91.7 ms | 19.1 ms | 动态分配改善拖尾 |
| Syscall | 55.6 ms | 0.002 ms | batch大幅减少syscall |
| CUDA Pipeline | 13.73 ms | 4.93 ms | 双流双buffer有效 |
| Realtime 50Hz | wake-up P99约0.13 ms | 0 miss | 当前压力较轻 |

## 实际运行过的Profiler

```bash
perf stat -e cycles,instructions,branches,branch-misses,cache-references,cache-misses,page-faults,context-switches,cpu-migrations ./src/build/21_cache_locality_bad_good
strace -c ./src/build/29_syscall_bad_good
nsys profile -t cuda,nvtx,osrt -o /tmp/stage2 ./src/build/cuda_13_kernel_hotspot_bad_good
nsys stats --report cuda_gpu_kern_sum,cuda_api_sum /tmp/stage2.nsys-rep
ncu --set basic --kernel-name regex:slow_kernel --launch-count 1 ./src/build/cuda_13_kernel_hotspot_bad_good
```

perf、strace、nsys成功；nsys确认slow_kernel占GPU kernel时间80.7%。ncu连接成功但计数器权限受限。所有数值都必须在目标硬件、频率、温度和输入上重新采集。
