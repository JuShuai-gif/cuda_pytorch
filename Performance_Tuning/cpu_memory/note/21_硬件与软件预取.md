## 3. 核心概念

- **Prefetching（预取）**：提前把数据装入缓存以隐藏延迟。
- **Hardware Prefetching（硬件预取）**：CPU 自动识别访问模式并预取。
- **Software Prefetching（软件预取）**：程序插入预取指令（如 `_mm_prefetch`）。
- **Prefetch Distance（预取距离）**：当前访问点与预取点之间间隔多少元素。
- **Stream（流）**：一组连续/规律的内存访问；CPU 追踪 8~16 条流。
- **NTA（Non-Temporal Aligned）**：hint 告知"数据不会被重用，别污染缓存"。
- **Speculative Load（投机加载）**：提前发起、结果暂不可用的加载（IA-64 ld8.a/ld8.c.clr）。
- **Helper Thread（辅助线程）**：专门的预取线程，跑在主线程前面若干元素。
- **prefetchw**：AMD 特有的"预取即置 M 态"指令（写优化）。

## 4. 硬件工作流程

### 4.1 预取如何隐藏延迟

```text
无预取：CPU 需要数据 → 发起读 → 等 200+ 周期 → 继续
有预取：提前 200 周期发起读 → 等 CPU 需要时数据已在缓存 → 立即继续

流水线/OOO 最多只能隐藏"命中缓存"的访问延迟；
主存延迟必须靠预取或超长指令队列
```

### 4.2 硬件预取触发与限制（PDFp60~61）

```text
触发：同一模式 ≥2 次缓存 miss
  可识别：相邻缓存行、固定步长（strides）
  不识别：非线性/随机模式
追踪：8~16 条独立流（L1i/L1d 各一个预取单元；L2+ 共享给所有核心）

限制：
  ✗ 不能跨页（demand paging 会触发 OS 事件、可能请求无意义页面）
  ✗ 页边界处必 miss，除非程序显式预取/读取新页
  ✗ 预取窗口 ~512 字节（4KB 页下）
```

- 若随机访问触发误预取：只能改布局；Intel 可用 MSR（IA32_MISC_ENABLE bit9 禁用、bit19 禁相邻行预取）在 kernel 里关闭。

### 4.3 软件预取：`_mm_prefetch`（PDFp61）

```cpp
#include <xmmintrin.h>
enum _mm_hint {
    _MM_HINT_T0 = 3,   // 预取到所有级（包含缓存）/最低级（独占缓存），最可能马上用
    _MM_HINT_T1 = 2,   // 预取到 L2，不进 L1d
    _MM_HINT_T2 = 1,   // 预取到 L3（若有）
    _MM_HINT_NTA = 0   // 非临时：尽量不污染缓存
};
void _mm_prefetch(void *p, enum _mm_hint h);
```

- 无效指针一般被忽略（x86 上安全），但仍应避免无谓预取（占带宽、可能逐出脏行）。
- hint 是"弱规范"，各 CPU 实现略有差异，需实测。
- NTA 危险点：工作集太大把 NTA 行逐出 → 再读需从内存重新加载。

### 4.4 预取距离与收益（图 6.7，PDFp61~62）

- 测试：随机排列链表 + 每节点处理 ~160 周期，NPAD=31（每条 2 条缓存行）。
- 距离 5 个元素：5×160 周期 ≈ 足够覆盖两条缓存行的加载。
- 结果：工作集 ≤ L2（512kB）时无差别；超 L2 后每元素省 50~60 周期（约 8%）。

### 4.5 辅助线程（图 6.8，PDFp63~64）

- 主线程做算术、辅助线程跑在主线程前 ~100 个元素、**读**（非预取指令）所有缓存行。
- 两线程绑定到同一核心的两个超线程（用 libNUMA `NUMA_cpu_level_mask(...,1)` 找线程兄弟，或读 sysfs thread_siblings）。
- 工作集在 L2 内：辅助线程纯浪费（慢 10%~60%，多数低端）。
- 工作集超 L2：省约 25%——主线程算术与辅助线程加载互补。
- 注意同步（futex/POSIX 同步），防止辅助线程跑太远污染缓存。

### 4.6 投机预取（IA-64 示例，PDFp62~63）

```text
普通 ld8：有数据依赖，不能提前执行（可能与 st8 冲突）
投机版：
   ld8.a   r6 = [r8]     // 提前发起
   ...其它指令...
   st8     [r4] = 12
   ld8.c.clr r6 = [r8]   // 若 st8 未覆盖 → 直接用投机结果；覆盖了 → 重新加载
```

- 优点：把值直接载入寄存器（不占缓存行，避免被逐出）。
- 缺点：需较多寄存器；未广泛使用。

## 5. PDF 核心观点

> 来源：PDF 第 60~64 页；对应章节 6.3~6.3.4、图 6.7、图 6.8。以下为概括。

1. **预取目的**（PDFp60）：掩盖主存延迟；OOO 只能隐藏缓存命中，无法覆盖主存延迟。
2. **硬件预取触发**（PDFp60）：同一模式 ≥2 次 miss；旧硬件只认相邻行，现代认步长。
3. **误预取浪费带宽**（PDFp60）：随机访问常见，故需 ≥2 次 miss 才启动；避免为随机访问预取。
4. **不能跨页**（PDFp60~61）：demand paging 下跨页预取可能触发 OS 事件、请求无意义页面；页边界必 miss。
5. **预取逻辑不复杂**（PDFp61）：4KB 页下约 512 字节窗口；不识别非线性模式。
6. **可关硬件预取**（PDFp61）：Intel MSR（IA32_MISC_ENABLE bit9/bit19），需 kernel 权限；带宽耗尽/过早驱逐时用。
7. **软件预取四 hint**（PDFp61）：T0 全级/最低级、T1 进 L2、T2 进 L3、NTA 非临时；实现相关需实测。
8. **无效指针安全但勿滥用**（PDFp61）：x86 忽略错误；无谓预取占带宽、可能逐出脏行。
9. **预取距离要算**（PDFp61~62）：160 周期/节点 × 2 行 → 距离 5 足够；图 6.7 省 50~60 周期（~8%）。
10. **辅助线程**（PDFp63~64）：超线程跑预取线程，L2 内纯浪费（慢 10%~60%），超 L2 省约 25%；要同步防跑太远。
11. **投机预取**（PDFp62~63）：IA-64 ld8.a/ld8.c.clr 把值载入寄存器、避免缓存行占用；需足够指令间隔与寄存器。
12. **gcc `-fprefetch-loop-arrays`**（PDFp62）：编译器自动为数组循环插入预取；效果依赖代码形态，可能变慢，慎用。
13. **用性能计数器验证**（PDFp62）：先找 miss 大户，逐处加预取，看"有用预取"计数器是否上升。

## 6. 通俗解释

预取就像**餐厅提前备菜**：

> 客人点菜（需要数据）才现做（从内存取）会很慢。聪明的厨师（CPU 硬件预取）发现"这桌连点三道菜"的规律
> 就提前把第四道备好。但厨师不敢去"菜单上没有的店"（不能跨页）拿食材。

软件预取是你**自己给厨师下单**：

> `_mm_prefetch(ptr, hint)` 说"等下要用 ptr，先备着"。
> hint 像"备到灶台（L1）/备到冰柜（L2）/备到仓库（L3）/别占我桌面（NTA）"。
> 距离太近来不及、太远被逐出——得算好"从下单选菜到上桌需要几道菜的功夫"。

辅助线程像**另请一个专门跑腿的伙计**：

> 主厨专心炒菜（算术），伙计提前把后面 100 道菜的食材搬上桌。
> 菜都在桌面时（L2 内）多请伙计纯费工钱；桌面不够（超 L2）时伙计的价值才体现（省 25%）。

## 7. 示例分析

### 7.1 预取距离计算（图 6.7）

- 每节点处理 160 周期；每元素 2 条缓存行（NPAD=31）。
- 需要提前 ~320 周期（两条行加载）。
- 距离 5 个元素 = 5×160 = 800 周期，足够。
- 若距离太短 → 预取未完成；太长 → 数据被逐出。

### 7.2 hint 选择

- 数据马上用 → T0（进 L1）。
- 工作集大、L1 装不下全部 → T1（进 L2）/ T2（进 L3）。
- 数据只用一次（流式）→ NTA（不污染缓存）。

### 7.3 硬件预取 vs 软件预取

| | 硬件预取 | 软件预取 |
|---|---|---|
| 代码改动 | 无 | 需插指令/宏 |
| 模式要求 | 简单（顺序/步长） | 任意（程序员保证地址有效） |
| 跨页 | 不能 | 可以（但要程序员处理页有效性） |
| 误预取风险 | 随机访问可能误触发 | 程序员控制 |
| 可移植性 | 自动 | hint 语义弱规范，需实测 |

## 8. 未优化代码

对应"随机链表 + 无预取"的程序（pointer chasing，缓存 miss 大）。

```cpp
// bad.cpp: 随机链表 pointer chasing，无预取
#include <vector>
#include <algorithm>
#include <random>

struct Node { Node* n; long pad[7]; };  // 64B/节点

int main() {
    constexpr int N = 1 << 18;
    std::vector<Node> pool(N);
    std::vector<int> order(N);
    std::mt19937 rng(42);
    for (int i = 0; i < N; ++i) order[i] = i;
    std::shuffle(order.begin(), order.end(), rng);
    for (int i = 0; i < N; ++i) pool[i].n = &pool[order[(i + 1) % N]];

    Node* cur = &pool[0];
    long long sum = 0;
    for (int i = 0; i < N; ++i) { sum += (long long)cur->n; cur = cur->n; }
    return sum == 0;
}
```

## 9. 优化后代码

对应"软件预取"版本（提前取 5 个元素后的节点）。

```cpp
// good.cpp: 软件预取，距离 5
#include <vector>
#include <algorithm>
#include <random>
#include <xmmintrin.h>

struct Node { Node* n; long pad[7]; };

int main() {
    constexpr int N = 1 << 18;
    constexpr int DIST = 5;
    std::vector<Node> pool(N);
    std::vector<int> order(N);
    std::mt19937 rng(42);
    for (int i = 0; i < N; ++i) order[i] = i;
    std::shuffle(order.begin(), order.end(), rng);
    for (int i = 0; i < N; ++i) pool[i].n = &pool[order[(i + 1) % N]];

    Node* cur = &pool[0];
    long long sum = 0;
    // 先走到 DIST 前
    for (int i = 0; i < DIST && i < N; ++i) cur = cur->n;
    // 预取 + 前进
    Node* pre = cur;
    for (int i = 0; i < N; ++i) {
        _mm_prefetch(pre->n, _MM_HINT_T0);   // 预取下一个要用的节点
        sum += (long long)cur->n;
        cur = cur->n;
        pre = pre->n;
    }
    return sum == 0;
}
```

> 预取收益需实测（src/16_prefetch）；不同机器/距离/数据布局差异大，论文也只报 ~8%。

## 10. 为什么会更快

| 角度 | 无预取 | 软件预取 |
|---|---|---|
| 主存延迟隐藏 | 每次等 200+ 周期 | 提前加载，命中缓存 |
| L2/LLC miss | 高 | 降低 |
| 内存带宽 | 突发占用 | 平滑占用 |
| 指针追逐等待 | 每节点全等 | 已就位 |

论文数据：图 6.7 省 50~60 周期/元素（~8%）；图 6.8 辅助线程超 L2 时省 ~25%。量级参考，本机实测为准。

## 12. 实验结果应该怎么看

- 对比"无预取/软件预取/不同距离"：看 miss 事件与耗时是否随预取改善。
- 距离扫描：太近（未完成）/太远（被逐出）都会变差，中间有最优。
- 若软件预取没有效果，可能原因（论文原意）：预取写错、距离太近来不及、或预取逐出了仍需要的数据。
- 事件名与 CPU 相关，脚本自动容错。

## 13. 常见误区

- **误区 1：软件预取一定更快**。论文只有 ~8%；预取距离/布局错误可能变慢或污染缓存。
- **误区 2：硬件预取能跨页**。不能；页边界必 miss，除非显式预取新页。
- **误区 3：NTA 是最佳 hint**。NTA 只在"数据不重用"时对；工作集大把 NTA 行逐出会更糟。
- **误区 4：辅助线程总是有用**。L2 内纯浪费（慢 10%~60%），超 L2 才省 ~25%。
- **误区 5：`-fprefetch-loop-arrays` 无脑开**。gcc 自己都警告可能变慢。
- **误区 6：预取=提前读**。辅助线程用"读"而非预取指令，是另一种形态（图 6.8）。

## 15. 本章总结

- 预取的目的：隐藏主存延迟，OOO 做不到。
- 硬件预取：≥2 次 miss 触发、识别相邻/步长、8~16 条流、**不跨页**、~512B 窗口。
- 软件预取：`_mm_prefetch` 四 hint（T0/T1/T2/NTA），距离要算，逐处验证。
- 投机预取（IA-64 ld8.a/ld8.c.clr）与辅助线程是另两种形态。
- 辅助线程：超 L2 省 ~25%，L2 内拖慢。
- 预取是"有条件"的优化：必须用计数器/实测确认收益，否则可能帮倒忙。
