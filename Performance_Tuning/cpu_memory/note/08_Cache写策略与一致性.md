# 08 Cache 写策略与一致性

> 对应 PDF：第 3.3.3 节 Write Behavior（PDFp25）、第 3.3.4 节 Multi-Processor Support 的 MESI 开头部分（PDFp25~26）；图 3.18 MESI 状态转移（PDFp26）
> 本篇回答：缓存写操作有哪两种策略？为什么写回（write-back）是主流？写合并与不可缓存是什么？脏行如何引出一致性需求？

## 1. 本章要解决的问题

- 写透（write-through）与写回（write-back）各是什么、各有什么代价？
- 为什么"脏缓存行"（dirty line）是多核一致性的关键？
- 写合并（write-combining）与不可缓存（uncacheable）内存用在哪？
- MESI 协议四个状态如何描述缓存行的所有权？（详细分析留到 note/09）

## 2. 前置知识

- note/05：缓存行、Tag/Set/Offset、驱逐。
- note/03：FSB/内存总线带宽有限。
- MTRR（Memory Type Range Registers）：x86 上由内核配置的地址区间内存类型寄存器。

## 3. 核心概念

- **Write-Through（写透 / 写通）**：写缓存的同时立即写主存。
- **Write-Back（写回）**：先只写缓存并标记脏，被驱逐时才写回主存。
- **Dirty Cache Line（脏缓存行）**：已被修改、尚未写回主存的缓存行。
- **Write-Combining（写合并）**：把多次局部写合并后再一次性写出（常用于显存等设备内存）。
- **Uncacheable Memory（不可缓存内存）**：不映射到真实 RAM 的地址区间（如 PCIe 设备、LED 寄存器），必须禁用缓存。
- **MTRR（Memory Type Range Registers）**：x86 上设置地址区间内存策略的寄存器。
- **Cache Coherency（缓存一致性）**：多处理器看到相同内存内容的保证。
- **RFO（Request For Ownership，所有权请求）**：处理器请求独占某缓存行以进行写操作。

## 4. 硬件工作流程

### 4.1 两种写策略

**写透（Write-Through）**

```text
CPU 写 → 更新缓存行 ──立即──► 写主存
                   （每条写操作都产生 FSB 流量）
```

- 简单：缓存内容可随时丢弃，主存永远最新。
- 慢：反复修改局部变量也每次写主存，制造大量 FSB 流量。

**写回（Write-Back）**

```text
CPU 写 → 更新缓存行，置 Dirty 位 ──(不立即写主存)──► 未来被驱逐时写回
```

- 快：多数写只停在缓存；可在 FSB 空闲时提前写回、清除脏位。
- 复杂：脏行在别处时，别处读到/写到它不能直接走主存（主存过期）。

### 4.2 脏行与多处理器

```text
CPU0: 行 X 脏（Modified）
CPU1: 读 X ──► 不能读主存（旧数据）──► 从 CPU0 的缓存拿，主存同步更新
CPU1: 写 X ──► 从 CPU0 拿内容 + 把 CPU0 副本作废（RFO）
```

- 读他人脏行：CPU0 把行发给 CPU1，状态变 Shared，内存控制器把内容同步回主存。
- 写他人脏行：CPU0 发内容并标记本地 Invalid（RFO），代价昂贵。

### 4.3 MESI 状态（图 3.18，PDFp26）

| 状态 | 含义 | 关键性质 |
|---|---|---|
| M (Modified) | 本处理器已修改，是唯一副本 | 主存过期；需提供给请求者 |
| E (Exclusive) | 未修改，且已知无其他副本 | 本地写无需广播，E→M 快 |
| S (Shared) | 未修改，可能有多份副本 | 本地写需广播作废他人副本 |
| I (Invalid) | 无效/未使用 | — |

初始全 I；读加载→若他人也有则 S，否则 E；本地写加载→M。

## 5. PDF 核心观点

> 来源：PDF 第 25~26 页；对应章节 3.3.3、3.3.4（开头）。以下为概括。

1. **写透 vs 写回**（PDFp25）：写透实现一致性最简单，但反复写一个局部变量会产生大量 FSB 流量；写回只在驱逐时写回，性能显著更好，是"像样处理器"的默认选择。
2. **写回可利用 FSB 空闲提前写回**（PDFp25）：处理器可在总线空闲时主动把脏行写回主存并清除脏位，这样驱逐时就能直接丢弃。
3. **写回引入一致性问题**（PDFp25）：脏行在某处理器缓存中时，其他处理器读同一地址不能走主存，必须从持有者缓存取，内存控制器同步主存。
4. **写合并与不可缓存**（PDFp25）：这两种策略用于非真实 RAM 的地址区间；MTRR 由内核设置；写合并常见于显存（连续像素地址往往是邻居），不可缓存用于 PCIe 设备/LED 等不能缓存或会外部改变的地址。
5. **直接访问他人缓存不现实**（PDFp25~26）：连接不够快；替代方案是"按需转移缓存内容"。
6. **广播每次写不现实**（PDFp26）：多数访问是读且不脏；广播每次写变更成本太高。因此发展出 MESI 协议。
7. **MESI 命名来自四状态**（PDFp26）：Modified / Exclusive / Shared / Invalid。
8. **RFO 昂贵**（PDFp26）：在最后一级缓存执行 I→M 或获取所有权较昂贵；写透还叠加写主存成本。
9. **E 状态是性能优化**（PDFp26）：E→M 比 S→M 快得多（本地写无需广播），处理器尽量让行保持 E；E 可以省略而不破坏功能，只是性能下降。

## 6. 通俗解释

**写透 vs 写回**，就像记账的两种习惯：

> 写透：每次花钱，你立刻打电话给银行更新账本（每次写都写主存）。账本永远准确，但话费惊人。
> 写回：先在自己小本子上记着（只写缓存，标个"待同步"），到月底统一对账（驱逐时才写回主存）。
> 中间还能趁话费便宜（FSB 空闲）顺手同步几笔。

**脏行**就是"小本子上记了、但银行还没收到"的那几笔账。别人要查你欠多少（读你的脏行），不能问银行（主存过期），只能问你本人。

**MESI** 就是四个"账本状态标签"：

> - M：我改了，只此一份，主存是旧账。
> - E：我有一份干净副本，别人没有——我改不用通知别人。
> - S：我有一份干净副本，别人可能也有——我改得先宣布"我要独占"（RFO）。
> - I：这一行对我无效。

## 7. 示例分析

### 7.1 反复写一个局部变量

- 写透：每次 `x++` 都写主存 → 大量 FSB 流量，纯浪费（数据短命且无人共享）。
- 写回：`x` 所在行标脏，只在驱逐时写一次 → 省下成百上千次总线写。

### 7.2 为什么写合并适合显存

- 屏幕上一行像素地址连续，写入相邻像素地址相邻。
- 若写一个像素就传整行，浪费；写合并把整行凑齐后一次传出。
- 这正对应 `movnt` 系列/写合并缓冲区，见 note/22。

### 7.3 为什么不可缓存地址必须禁缓存

- PCIe 设备内存可能被设备自己改变，缓存副本会过期。
- LED 寄存器要"立即生效"，缓存延迟不可接受。
- MTRR 把这些地址区间标记为 UC（uncacheable），硬件自动绕过缓存。

## 8. 未优化代码

对应"write-allocate 行为"的低效写法：不完整地、零散地写入一个大数据块，触发反复加载-修改-写回。

```cpp
// bad.cpp: 零散写，每行都要 load-for-ownership
#include <vector>

int main() {
    constexpr int N = 1 << 20;
    std::vector<int> data(N, 0);
    for (int i = 0; i < N; i += 2)   // 隔一个写一个，行内只改一半
        data[i] = 1;
    return data[0] == 0;
}
```

## 9. 优化后代码

对应"整行写完"的写法：连续写满缓存行，减少写分配/读改写开销。

```cpp
// good.cpp: 连续完整写入，写合并/写回友好
#include <vector>

int main() {
    constexpr int N = 1 << 20;
    std::vector<int> data(N, 0);
    for (int i = 0; i < N; ++i)     // 整行写完，一次 load 全行随后覆盖
        data[i] = 1;
    return data[0] == 0;
}
```

> 更极端情况（不读旧值、纯流式写）可考虑 non-temporal store（note/22、src/17）。
> 验证写入行为见 src/08_write_back_behavior。

## 10. 为什么会更快

| 角度 | 零散写 | 连续写 |
|---|---|---|
| Write-allocate 开销 | 每行只改一半仍要 load 整行 | 整行写满，load 成本摊销 |
| 写回次数 | 每行一次（相同） | 相同 |
| Dirty 行覆盖 | 半行脏 | 整行脏（驱逐更高效） |
| 写合并 | 难凑整行 | 天然整行 |
| FSB/内存写流量 | 每行一次（相同量级） | 相同量级但更紧凑 |

> 说明：写策略在单核下对"总流量"影响有限，真正的差异在多核一致性（note/09）与流式写（note/22）中放大。

## 13. 常见误区

- **误区 1：写缓存必然立刻写主存**。写回策略下，缓存行被驱逐前主存都可能没更新。
- **误区 2：写透就是错的**。某些场景（简单实现、需要立即持久）仍适用；只是性能一般不占优。
- **误区 3：所有内存都可缓存**。PCIe/设备/IO 映射区域必须不可缓存，由 MTRR 等机制控制。
- **误区 4：E 状态可有可无**。省略 E 不影响功能，但 S→M 需要广播，性能明显下降。
- **误区 5：一致性只是"缓存要不要刷新"**。它涉及所有权转移（RFO）、脏行供应、总线同步，是系统级协议。

## 15. 本章总结

- 写透：简单但慢（每次写都上总线）。
- 写回：主流，靠脏位延迟写回，可利用总线空闲提前写回。
- 脏行要求其他处理器绕过主存、从持有者取数据——引出一致性协议。
- 写合并与不可缓存用于设备/IO 地址区间（MTRR 控制）。
- MESI 四状态（M/E/S/I）为多核一致性奠定基础，详细机制见 note/09。
