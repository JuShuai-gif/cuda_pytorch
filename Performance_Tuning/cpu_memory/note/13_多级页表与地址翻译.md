# 13 多级页表与地址翻译

> 对应 PDF：第 4.1 节 Simplest Address Translation（PDFp37）、第 4.2 节 Multi-Level Page Tables（PDFp37~38）、图 4.1、图 4.2、图 4.3
> 本篇回答：虚拟地址如何一步一步变成物理地址？多级页表为什么省内存？一次页表遍历（page walk）到底发生什么？ELF 的对齐要求怎么读？

## 1. 本章要解决的问题

- 单级页表的结构与不可行性（2^20 项 = 4MB）。
- 多级页表的稀疏表示如何节省内存。
- 4 级页表遍历的完整步骤（图 4.2）。
- 一个具体地址的翻译计算示例。
- 页大小与页表层级数的关系；ELF 程序头的对齐字段。

## 2. 前置知识

- note/12：虚拟内存、MMU、页表、TLB 概览。
- 2 的幂与位运算：地址切分（如 note/05 的 Tag/Set/Offset）。
- 位向量索引数组：用地址的一部分作为数组下标。

## 3. 核心概念

- **Page Directory（页目录）**：存放目录项的数组。
- **Page Directory Entry（目录项）**：指向下一级目录或物理页的指针 + 权限位。
- **Page Table Walk（页表遍历）**：从顶级目录逐级索引到最终物理页的过程。
- **Sparse Tree（稀疏树）**：只有被使用的分支才分配目录。
- **Contiguous Mapping（连续映射）**：虚拟地址空间集中放置 → 目录数最少。
- **ASLR**：地址空间布局随机化，摊开各段导致目录数增加。
- **ELF Program Header Align**：可执行文件的段对齐要求（图 4.3 显示 2MB）。

## 4. 硬件工作流程

### 4.1 单级翻译（图 4.1，PDFp37）

```text
虚拟地址 (32 位, 4MB 页):
| Page Directory Index (10 位) | Offset (22 位) |

页目录（1024 项，存主存）：
  用 Index 选一项 → 目录项 = 物理页基址(10 位) + 权限
  物理地址 = 页基址 + Offset（合成 32 位）
```

### 4.2 4 级翻译（图 4.2，PDFp37~38）

```text
虚拟地址 (x86-64, 4KB 页):
| L4(9) | L3(9) | L2(9) | L1(9) | Offset(12) |

L4 目录基址存于 CPU 寄存器 (如 CR3)
  L4[L4索引] ──► L3 目录基址
    L3[L3索引] ──► L2 目录基址
      L2[L2索引] ──► L1 目录基址
        L1[L1索引] ──► 物理页基址
          物理地址 = 物理页基址 + Offset
```

- 若某目录项标记为空，则该子树不分配 → 稀疏紧凑。
- x86/x86-64 硬件自动遍历；其他架构可能需 OS 协助。

## 5. PDF 核心观点

> 来源：PDF 第 37~38 页；对应章节 4.1、4.2、图 4.1、4.2、4.3。以下为概括。

1. **翻译按页进行**（PDFp37）：虚拟地址切分后，各部分索引各级目录；目录项可多个指向同一物理页。
2. **目录基址放专用寄存器**（PDFp37）：OS 分配连续物理内存存放目录，基址存寄存器。
3. **4MB 页单级方案**（PDFp37）：x86 上 Offset 22 位 + 目录 10 位（1024 项），每项 10 位页基址。
4. **4KB 页单级不现实**（PDFp37）：Offset 12 位 → 目录 20 位 → 2^20 项 → 4MB 表/进程 → 物理内存被页目录吃光。
5. **多级页表稀疏**（PDFp37）：未用区域不分配目录；表示紧凑，许多进程页表可共存。
6. **现代最多 4 级**（PDFp37）：L4 由专用寄存器引用；L4~L2 指向下级目录；L1 项 = 物理页基址 + 权限。
7. **页表树越小越好**（PDFp38）：内存放得越集中，所需目录越少；物理地址位置无所谓。
8. **数字示例**（PDFp38）：x86-64 4KB 页、512 项/目录 → 2MB 只需每级各 1 个目录（共 4 个）；1GB 连续内存需 L2~L4 各 1 + 512 个 L1。
9. **栈与堆在地址空间两端**（PDFp38）：为保证两者都能增长，通常需两个 L2 目录及更多下级目录。
10. **ASLR 增加目录数**（PDFp38）：代码/数据/堆/栈/DSO 随机分布，很少能用一两个 L2/L3 目录；性能优先时可关闭随机化并连续装载 DSO。
11. **页大小与层级**（PDFp40）：页越大，Offset 位越多、目录位越少 → 层级减少 → TLB miss 遍历工作更少。
12. **ELF 对齐**（PDFp40，图 4.3）：`eu-readelf -l /bin/ls` 显示 LOAD 段 Align=0x200000=2MB，对应处理器最大页大小；增大最小页大小可能使旧 ELF 无法装载。

## 6. 通俗解释

多级页表就像**图书馆的目录索引**：

> 单级目录 = 一本把整馆每本书都列出来的大册子，几百万条（2^20），又大又难维护。
> 多级目录 = "楼层→书库→书架→书"四层查法：只有用了的楼层才建目录页，
> 图书馆不用为每本没写的书预留位置（稀疏）。

地址翻译就是查索引：

> 虚拟地址被拆成 4 段楼层号 + 1 段页码。先翻顶层找对应书库，再找对应书架……
> 每翻一层，目录项告诉你下一层目录在哪（或直接给出书的位置 = 物理页）。

为什么树越小越好？

> 越紧凑，页表占的内存越少，TLB 命中（翻译缓存）也越可能保留。栈和堆各占一端、
> ASLR 又东一摊西一摊，就像把同一层的书拆到不同楼——得多建好几个目录节点。

## 7. 示例分析

### 7.1 翻译一个具体虚拟地址（x86-64，4KB 页，4 级）

设虚拟地址 `0x0000_7f00_1234_5678`：

```text
L4 索引 = (addr >> 39) & 0x1FF
L3 索引 = (addr >> 30) & 0x1FF
L2 索引 = (addr >> 21) & 0x1FF
L1 索引 = (addr >> 12) & 0x1FF
Offset  = addr & 0xFFF
```

- 从 CR3 取 L4 目录基址 → 读 `L4[L4索引]` 得到 L3 基址 → ... → `L1[L1索引]` 得物理页基址 → 加上 Offset。
- 每一步都是"上一级结果 → 下一级基址"的串行依赖，这就是 TLB 存在的理由。

### 7.2 2MB 与 1GB 的目录开销

- 2MB 连续虚拟区（4KB 页）：L2/L3/L4 各 1 个目录 + 1 个 L1 目录 = 4 个。
- 1GB 连续虚拟区：L2/L3/L4 各 1 个 + 512 个 L1 目录。
- 栈、堆分两端 → 至少两个 L2。

### 7.3 大页减少层级

- 4KB 页：4 级（48 位虚拟地址切 4 段 + 12 位偏移）。
- 2MB 页（x86-64）：Offset 21 位，只剩 3 段索引 → 少一级遍历。
- 1GB 页：Offset 30 位 → 更少层级。
- 层级少 → TLB miss 时遍历更快（PDFp40 原意）。

### 7.4 读 ELF 对齐

```bash
eu-readelf -l /bin/ls
# LOAD ... Flg R E Align 0x200000   → 2MB
```

- Align 表示该段要求的加载对齐，等于（或小于）处理器支持的最大页大小。
- 若系统把最小页大小提高到 2MB 以上，按旧对齐构建的 ELF 可能无法装载（PDFp40 原意）。

## 8. 未优化代码

对应"虚拟内存布局不友好"的程序：大量小分配分散在地址空间各处（碎片化）。

```cpp
// bad.cpp: 大量分散的小分配，页表树膨胀 + TLB 压力
#include <vector>
#include <memory>

int main() {
    std::vector<std::unique_ptr<char[]>> chunks;
    for (int i = 0; i < 1 << 16; ++i)
        chunks.emplace_back(new char[64]);   // 每个 64B 一个映射
    long long sum = 0;
    for (auto &c : chunks) sum += (long long)c.get();
    return sum == 0;
}
```

## 9. 优化后代码

对应"虚拟内存布局友好"的程序：大块连续分配，页表树紧凑。

```cpp
// good.cpp: 单块大分配，页表稀疏性最优
#include <vector>

int main() {
    constexpr int N = 1 << 20;
    std::vector<char> pool(N);               // 一个连续大映射
    long long sum = 0;
    for (int i = 0; i < N; ++i) sum += pool[i];
    return sum == 0;
}
```

> 分配策略对页表树/内存布局的影响，可配合 perf 与 /proc/self/maps 观察。

## 10. 为什么会更快

| 角度 | 碎片化小分配 | 大块连续分配 |
|---|---|---|
| 页表目录数 | 多（稀疏性差） | 少（紧凑） |
| TLB 覆盖 | 每块独立页，覆盖效率低 | 一页覆盖大量数据 |
| 页表遍历/占内存 | 多 | 少 |
| 分配/释放开销 | 高 | 低 |
| 局部性 | 差 | 好 |

> 注意：真正的 TLB 优势靠"大页 + 集中放置"共同获得；碎片化实验主要展示布局对页表树的影响。

## 13. 常见误区

- **误区 1：页表是"一张大表"**。现代是多级稀疏树，未用区域不占内存。
- **误区 2：地址连续 = 物理连续**。虚拟连续只需映射到若干物理页即可，物理可不连续。
- **误区 3：翻译一次只要一次内存访问**。4 级页表最多 4 次串行访问，这正是 TLB 的意义。
- **误区 4：ASLR 只影响安全不影响性能**。它摊开地址段，增加页表目录数（论文明确提到）。
- **误区 5：任何机器都能用任意大页**。最大可用页受处理器与 ELF 对齐限制（图 4.3）。

## 15. 本章总结

- 地址翻译按页进行，单级页表因 4MB/进程的表而不可行。
- 多级（4 级）页表稀疏紧凑，只有使用的分支才分配目录。
- 页表遍历是逐级串行的多次主存访问，靠 TLB 缓存翻译结果。
- 页越大 → 层级越少 → TLB miss 遍历更便宜；但受物理连续与 ELF 对齐限制。
- 布局优化（集中放置、大块分配、大页）能显著减少页表与 TLB 压力。
