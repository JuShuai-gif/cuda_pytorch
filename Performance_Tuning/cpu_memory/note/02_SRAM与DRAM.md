# 02 SRAM 与 DRAM

> 对应 PDF：第 2.1 节 RAM Types（PDFp5~7）、第 2.1.1 节 Static RAM、第 2.1.2 节 Dynamic RAM、第 2.1.4 节 Conclusions；附录 C Memory Types（PDFp105~107）
> 本篇回答：为什么一台机器里既有 SRAM 又有 DRAM？它们如何存储一个"位"？为什么 DRAM 慢且麻烦，却仍是主流？

## 1. 本章要解决的问题

- 内存为什么不是"一种"东西，而是 SRAM 和 DRAM 并存？
- SRAM 单元和 DRAM 单元的内部结构有何不同，成本差异根源在哪？
- DRAM 有哪些固有的麻烦（刷新、漏电、读破坏、电容充放电）？
- DRAM 如何用"行列矩阵 + 地址复用"节省引脚？
- 附加主题：什么是 ECC 内存、寄存器（Registered）内存？

## 2. 前置知识

- 晶体管与电容的基础概念（把 0/1 存成"电压高低 / 电荷有无"即可）。
- 与非门/反相器构成的存储单元思想（SRAM 的交叉耦合反相器）。
- 芯片引脚（pin）：芯片对外连接的金属触点，数量有限且昂贵。
- 多路复用/多路分解（demultiplexer）：用 N 根线选出 2^N 条输出中的一条。
- 信号完整性与时序（信号的建立/保持、充放电不是瞬时的）。

## 3. 核心概念

- **SRAM（Static RAM，静态随机存储器）**：用触发器锁存状态的存储单元，通电即保持，无需刷新。
- **DRAM（Dynamic RAM，动态随机存储器）**：用电容存储电荷，因漏电必须周期性刷新。
- **6T SRAM Cell**：由 6 个晶体管（4 个组成交叉耦合反相器 + 2 个访问管）构成的一个位。
- **1T1C DRAM Cell**：由 1 个晶体管 + 1 个电容构成的位。
- **Refresh（刷新）**：周期性地重新读出再写回 DRAM 内容，防止电荷漏光；约每 64ms 一次。
- **Leakage（漏电）**：电容电荷随时间流失的现象。
- **Sense Amplifier（读出放大器）**：放大电容上极其微弱的电荷信号，以区分 0 和 1。
- **Row/Column Array（行列阵列）**：DRAM 芯片把单元排成行×列矩阵，用两个小解码器替代一个巨型解码器。
- **RAS / CAS**：行地址选通 / 列地址选通，DRAM 地址分两次送入。
- **Address Multiplexing（地址复用）**：先送行地址、后送列地址，把地址引脚数量减半。
- **ECC（Error Correction Code）**：纠错码内存，内存控制器为数据附加校验位，可纠正单位错误。
- **SEC / SEC-DED**：单位纠错 / 单位纠错双位检错（基于汉明码）。
- **Registered（Buffered）Memory（寄存器内存）**：模块上带缓冲芯片，减轻内存控制器电气负担，但增加延迟。

## 4. 硬件工作流程

### 4.1 SRAM 单元（论文图 2.4，PDFp5）

```text
          WL（字线，横贯所有行单元）
      Vdd
      +--+
      |  |
   M2 o--o M4
      |  |
   M1 o--o M3       交叉耦合反相器 → 两个稳定状态 0/1
      |  |
      +--+---+------  BL 与 BL（互补位线）
      |      |
   存取管 M5/M6（由 WL 控制）
```

读：抬高 WL → 交叉耦合反相器的状态经 M5/M6 立刻反映到 BL/BL。

要点（论文 PDFp5）：
- 一个单元 6 个晶体管；
- 需要持续供电维持状态；
- **状态几乎立即可用**，信号像晶体管信号一样"矩形"；
- **稳定，不需要刷新**。

### 4.2 DRAM 单元（论文图 2.5，PDFp6）

```text
       AL（访问线，即行选择）
        |
   DL ---- M(晶体管) ---- C(电容)      ← 仅 1 管 1 容
```

- 读：抬高 AL → 若电容有电，DL 上有电流；否则无。
- 写：先把 DL 设为期望值，再抬高 AL 足够长时间给电容充电/放电。

四个固有麻烦（论文 PDFp5~6）：
1. **读是破坏性的**：读操作本身放掉电容电荷，必须随后回充。
2. **漏电**：电荷几十毫秒就漏光，必须周期刷新（现代约 64ms）。
3. **信号太弱**：需要读出放大器；而且电荷只剩"几十个常数电子"，0/1 区分很勉强。
4. **充放电不瞬时**：`Q_charge(t) = Q0(1 - e^(-t/RC))`、`Q_discharge(t) = Q0·e^(-t/RC)`，信号不是矩形，只能按保守时序等待。

### 4.3 DRAM 行列寻址（论文图 2.7，PDFp7）

```text
   a0,a1 ──► Row Address Selection (RAS) ──► 选中整行（全部列同时读出）
                                                 │
                                              Cells
                                                 │
   a2,a3 ──► Column Address Selection (CAS) ──► 选出 1 列 → Data
```

- 若逐个单元独立寻址，1Gbit 芯片需要 30 根地址线 + 2^30 根选择线，解码器和引脚都无法承受。
- 排成行列矩阵后，只需要一个行解码器 + 一个列多路选择器，各处理一半地址。
- 地址还要**复用**：先送行地址（RAS），保持有效；再送列地址（CAS），只需 2 根外部地址线（示例中）。
- 代价：引入新问题——RAS/CAS 切换与预充电的时序延迟（见 note/03）。

## 5. PDF 核心观点

> 来源：PDF 第 5~7 页、第 105~107 页；对应章节 2.1、2.1.1、2.1.2、2.1.3、2.1.4、附录 C。以下为概括。

1. **为什么不全部用 SRAM：成本**（PDFp5）：SRAM 无论生产还是使用都昂贵得多，而 DRAM 单元极小且结构规则、便于密集排布。
2. **结论**（PDFp6）：成本差异太悬殊，除路由器等专用硬件外，主存必须是 DRAM；程序员必须接受 DRAM 的特性。
3. **SRAM 的用途**（PDFp7, 2.1.4）：SRAM 用于 CPU 缓存和片上，连接短、完全由 CPU 设计者控制；SRAM 速度取决于投入的成本。
4. **DRAM 寻址的现实约束**（PDFp7）：引脚珍贵，数据必须尽量并行（如 64 位一批）；地址必须复用以省引脚。
5. **2.1.4 小结**（PDFp7）：不是所有内存都是 SRAM 是有原因的；内存单元必须被单独选中；地址线数量直接决定内存控制器、主板、内存模块和芯片的成本；读写结果需要时间才能可用。
6. **ECC 的目的**（PDFp105）：宇宙射线、α 衰变等会造成内存单元 0/1 翻转；内存越大、错误概率越高，某些服务器环境不能容忍。
7. **ECC 是内存控制器的功能，不是内存的功能**（PDFp105~106）：DRAM 模块只是多存校验位；控制器写入时实时计算 ECC，读出时校验并在可能时纠错。
8. **为什么是 64+8**（PDFp106）：对 W=64 数据位，SEC-DED 需要 E=8 个校验位，开销 12.5% 足够低，且 64/8 都是 8 的倍数，与芯片 8 位输出吻合。
9. **ECC 与 Register 内存都不普及的原因**（PDFp107）：多一个芯片增加成本，校验计算增加延迟；非 ECC 普通内存可以快得多。
10. **错误频率参考**（PDFp107）：厂商声称 256MB 内存平均每 750 小时可能出错一次；内存翻倍后该间隔缩短 75%。

## 6. 通俗解释

**SRAM vs DRAM** 可以这样理解：

> SRAM 像一块"用插销锁住状态"的白板：只要插销插着（供电），字就一直留着，随取随用，但每个插销都贵。
> DRAM 像一个"往杯子里倒水"的水池：水（电荷）会慢慢蒸发（漏电），所以每过一会儿就得重新加水（刷新）；
> 看水位（读）还会把水倒掉一些（破坏性读），看完得马上加回去。

为什么 DRAM 赢了？

> 因为一个 DRAM 位只需要"1 个阀门 + 1 个水杯"，能塞得又密又便宜；SRAM 一位要 6 个插销，又大又贵。
> 所以"又便宜又能装"的主存用 DRAM，而"又快但贵"的缓存用 SRAM。

**ECC 内存** 就像是给每个 64 位数据配了一位"保镖"（8 位校验码），保镖能发现并纠正单个被宇宙射线击中的错误位——但保镖工作的是内存控制器，不是内存芯片自己。

## 7. 示例分析

### 7.1 为什么读 DRAM 会"破坏"数据

- 读取时，位线 DL 要与电容分享电荷：电容上的电荷一部分流到位线电容上，原始电荷被稀释。
- 若不回充，多次读后电荷耗尽，0/1 无法区分。
- 所以"读"必须紧跟"回充"，这额外占用时间（成为 DRAM 时序的一部分）。

### 7.2 为什么 1Gbit DRAM 必须复用地址

- 直接寻址：30 根地址线、2^30 根选择线，解码器面积与复杂度爆炸，30 根同步信号也极难布成等长。
- 行列矩阵：行解码器（比如 15 位→32768 行）+ 列多路选择器（15 位），各解码器减半。
- 地址复用：地址分两段发送，外部地址引脚再减半（示例从 4 根变 2 根）。
- 代价：行/列切换、预充电产生额外延迟——这正是 note/03 要讲的 DRAM 访问协议。

### 7.3 为什么 ECC 用 (64, 8)

- 汉明码要求 `E = ⌈log2(W + E + 1)⌉`。
- 对 W=64：`E=7` 只够 SEC；加一位奇偶到 `E=8` 变成 SEC-DED。
- 64 位数据 + 8 位校验 = 72 位，恰好是 9 个 8 位芯片，与内存模块通常按 8 位/芯片组织的结构天然吻合。

## 8. 未优化代码

本节是硬件原理，直接对应可优化代码的"前置认识"。对应错误认知的代码行为：**假设读内存像读寄存器一样快、随意随机访问**。

```cpp
// bad.cpp: 无局部性，频繁跨大数组跳跃访问
#include <vector>
#include <random>

int main() {
    constexpr int N = 1 << 24;
    std::vector<int> data(N, 1);
    std::mt19937 rng(42);
    long long sum = 0;
    for (int i = 0; i < N; ++i) {
        int idx = static_cast<int>(rng() & (N - 1));  // 乱序
        sum += data[idx];
    }
    return sum == 0;
}
```

（为什么不行的完整分析，结合 DRAM 行切换延迟看 note/03 实验。）

## 9. 优化后代码

对应"尊重 DRAM 行列结构"的认识：**按顺序、按行访问，让行保持打开状态（row buffer hit）**。

```cpp
// good.cpp: 顺序访问，命中打开的 DRAM 行
#include <vector>

int main() {
    constexpr int N = 1 << 24;
    std::vector<int> data(N, 1);
    long long sum = 0;
    for (int i = 0; i < N; ++i)   // 线性扫描
        sum += data[i];
    return sum == 0;
}
```

真正的量化对比（顺序 vs 随机、步长）在 src/02 与 src/04 实验里做，这里只是原理导向。

## 10. 为什么会更快

DRAM 层面（并非 Cache 层面）：

| 角度 | 随机访问 | 顺序访问 |
|---|---|---|
| DRAM 行命中（Row Buffer Hit） | 每访问一个新页都要预充电+开新行 | 同一行内连续命中，无需频繁切行 |
| 预充电/激活开销 | 每个元素可能触发一次 | 摊销到整行 |
| 刷新冲突 | 刷新可能恰好撞上访问 | 相同，但顺序访问更易被调度器避开 |
| 数据总线利用率 | 突发传输被切碎 | 整行突发，总线 100% 占用 |

> 注意：在普通程序中，DRAM 层优化（顺序访问）与 Cache 层优化（空间局部性、预取）目标一致，
> 所以"顺序更快"的理由同时来自 Cache 与 DRAM 两层。这也是为什么论文要先讲 DRAM 再讲 Cache。

## 12. 实验结果应该怎么看

- 在 src/04 stride 实验中，观察步长增大时 ns/element 的变化：步长超过某阈值后，顺序预取失效、行切换频繁，延迟跳升。
- 在 src/02 顺序 vs 随机中：随机访问的 GB/s 显著低于顺序访问，且 cache-misses、dTLB 事件升高。
- 这些现象是 Cache（note/05~11）与 DRAM（本篇+note/03）两层机制共同作用的结果，解读时不要归因于单一因素。

## 13. 常见误区

- **误区 1：SRAM 一定比 DRAM 快**。正确说法是"可以做得更快"，但速度取决于投入的成本；低速低功耗 SRAM 也存在（PDFp5 原意）。
- **误区 2：ECC 是内存条自己在纠错**。纠错逻辑在内存控制器里，内存条只是多存了校验位。
- **误区 3：寄存器内存 = 更快**。它降低控制器电气负担、支持更多内存条，但增加了延迟和功耗（PDFp105~106）。
- **误区 4：DRAM 随机访问只慢在"寻址"**。实际上还有预充电、激活、刷新、读破坏回充等一连串时序。
- **误区 5：64ms 刷新是"每 64ms 全部刷一次"**。实际是按行轮转刷新，每行 64ms 内刷一次，不是整片同时停摆；论文指出部分工作负载可能因刷新损失高达 50% 的访存（PDFp6）。

## 15. 本章总结

- SRAM 快但贵：用于缓存/片上，6T 单元、免刷新。
- DRAM 便宜但麻烦：1T1C 单元，需要刷新、破坏性读、弱信号放大、保守时序。
- DRAM 用"行列矩阵 + RAS/CAS 地址复用"解决引脚与解码器成本，代价是访问时序复杂。
- ECC 内存由内存控制器提供纠错（SEC/SEC-DED，常用 64+8 位），适合不能容忍随机位翻转的服务器。
- 程序员的核心认知：DRAM 不是均匀快速的随机存储，访问模式（顺序 vs 随机）决定 DRAM 行命中与总线利用率。
