## 3. 核心概念

- **Non-Temporal Store（非临时写/流式写）**：绕过缓存、直接把数据写到内存的写指令。
- **Write-Allocate（写分配）**：普通写先读整行进缓存再改，即使整行会被覆盖。
- **Write-Combining（写合并）**：把多个部分写合并成整行后一次写出。
- **`_mm_stream_si128 / _mm_stream_pd / _mm_stream_si32` 等**：流式写 intrinsics。
- **sfence**：确保流式写顺序/可见性的内存屏障。
- **Cache Pollution（缓存污染）**：不常用的数据占用缓存，挤掉有用数据。
- **dcbz（PowerPC）**：清空整条缓存行，从内存读零而分配缓存行。

## 4. 硬件工作流程

### 4.1 普通写 vs 非临时写

```text
普通写（write-allocate）：
  写某字 → 整行读入缓存（哪怕整行都要被覆盖）→ 改缓存行 → 逐出时写回

非临时写（stream）：
  写某字 → 直接写入写合并缓冲 → 凑齐整行后一次写内存 → 不进缓存
```

- 非临时写"不读缓存行再改"，直接写内存。
- 若写合并成功凑齐整行 → 无需任何内存读。
- 优点：避免读入无用的旧数据、避免污染缓存。

### 4.2 写合并要求（PDFp47~48）

```cpp
#include <emmintrin.h>
void setbytes(char *p, int c) {
    __m128i i = _mm_set_epi8(c, c, c, c, c, c, c, c,
                             c, c, c, c, c, c, c, c);
    _mm_stream_si128((__m128i *)&p[0],  i);   // 16B
    _mm_stream_si128((__m128i *)&p[16], i);
    _mm_stream_si128((__m128i *)&p[32], i);
    _mm_stream_si128((__m128i *)&p[48], i);   // 64B 整行
}
```

- 地址须按 8/16 字节对齐。
- 写合并缓冲只保留部分写有限时间：**修改同一缓存行的指令必须紧挨着发出**，才能被合并。
- memset 大块就是这种模式（标准 C 库做法）。

### 4.3 表 6.1：矩阵初始化时序

| 写方式 | 内层按行 | 内层按列 |
|---|---|---|
| 普通（用缓存） | 0.048s (~750MB/s) | 0.127s (~280MB/s) |
| 非临时（绕过） | 0.048s（写合并生效） | 0.160s (~225MB/s，25% 更差) |

- 顺序写：非临时与普通一样快——写合并 + 更松的内存序（显式 sfence）让带宽利用充分。
- 列写：非临时更差（0.16 vs 0.127）——**无写合并**，每单元独立寻址、频繁换 DRAM 行。

## 5. PDF 核心观点

> 来源：PDF 第 47~48 页；对应章节 6.1、表 6.1、图 6.1。以下为概括。

1. **数据产生后不立即消费时，普通写有害**（PDFp47）：先读整行再改 → 把"可能还要用的行"挤出缓存，换进"马上不用的行"；大矩阵填满时，第一元素在填充完成前就被逐出，缓存写失效。
2. **非临时写**（PDFp47）：不读缓存行、直接写内存；配合写合并可完全不读内存。
3. **x86 intrinsics**（PDFp47）：`_mm_stream_si32/_mm_stream_si128/_mm_stream_pd/_mm_stream_ps` 等；地址须对齐 8/16B。
4. **写合并缓冲容量有限**（PDFp47~48）：修改同一缓存行的指令需紧挨着执行，否则无法合并。
5. **绕过缓存避免污染**（PDFp48）：如 memset 大块，既免读行又免污染缓存。
6. **非临时写时序放宽**（PDFp48）：内存序更自由，但程序需显式 `sfence` 保证顺序/可见性。
7. **表 6.1**（PDFp48）：顺序写非临时与普通一样快（写合并 + 带宽利用）；列写非临时反而差 25%（无写合并、每单元独立寻址、频繁换 DRAM 行）。
8. **何时不用**（PDFp47）：矩阵乘法 A.1 不用于非临时——因为写的值短时间内会重用。
9. **PowerPC dcbz**（PDFp48）：清整行、不读内存但分配缓存行、只限全零，无需写合并逻辑。

## 6. 通俗解释

Non-temporal store 就是**"不要搬进桌面，直接发快递"**：

> 普通写：写一个数字前，先得把整页资料从仓库搬上桌（读整行），改完再放回仓库。
> 如果你接下来要把整页全部重写（大矩阵填充），那"先搬旧资料上桌"纯属浪费——旧资料反正不要了。
> 非临时写：直接在桌上凑齐一页（写合并）就发走，旧资料根本不用搬上桌。

为什么能一样快？

> 快递小哥（写合并）把你要发的 4 个 16 字节块拼成一整包 64 字节一次发出去，
> 和"搬上桌再改再寄"用时一样，还省了搬旧货的力气。

什么时候会反而更慢？

> 如果你写的地址是"跳着写"（列优先），凑不成整包，每个字节都要单独跑一趟仓库
> （每单元独立寻址 + 换 DRAM 行），比普通写还慢 25%。

## 7. 示例分析

### 7.1 为什么矩阵填充适合流式写

- 3000×3000 矩阵远超缓存。
- 普通写：写第 1 个元素先读整行（旧数据），写完逐出时又写回——缓存写了又清。
- 非临时写：整行写合并一次发走，不污染缓存、不读旧行。
- 前提：按行顺序写满整行（写合并成功）。

### 7.2 列优先为什么失效

- 列访问 `m[i][j]`（内层 i 变）：每次写到不同行，无法凑齐整行写合并。
- 每单元独立寻址 + 频繁换 DRAM 行 → 非临时写 0.16s 比普通写 0.127s 还慢 25%。

### 7.3 何时用/不用

| 场景 | 推荐 |
|---|---|
| 大块数据只写一次、之后很久才读 | 用流式写（如 memset、矩阵填充） |
| 写后立刻/短时间内重用 | 用普通写（如矩阵乘法 A.1） |
| 写模式随机/列优先 | 普通写可能更好 |

## 8. 未优化代码

对应"大矩阵填充用普通写"的程序（write-allocate 浪费）。

```cpp
// bad.cpp: 大数组普通写，先读后改 + 缓存污染
#include <vector>

int main() {
    constexpr int N = 1 << 26;
    std::vector<int> data(N);
    for (int i = 0; i < N; ++i)
        data[i] = 1;              // 普通写：write-allocate
    return data[0] == 0;
}
```

## 9. 优化后代码

对应"大数组流式写"的程序（非临时写）。

```cpp
// good.cpp: 流式写（需 SSE2 与运行时检测；不支持则回退）
#include <vector>
#include <emmintrin.h>
#include <cstring>

int main() {
    constexpr int N = 1 << 26;
    std::vector<int> data(N);

    char* p = reinterpret_cast<char*>(data.data());
    std::size_t bytes = N * sizeof(int);
    __m128i v = _mm_set1_epi32(1);

    std::size_t i = 0;
    for (; i + 16 <= bytes; i += 16)
        _mm_stream_si128(reinterpret_cast<__m128i*>(p + i), v);
    for (; i < bytes; ++i) p[i] = 1;   // 尾部普通写

    _mm_sfence();                      // 确保流式写可见
    return data[0] == 0;
}
```

> 完整实验（含 CPU 指令集检测、对齐、屏障、不支持回退）见 src/17_non_temporal_store。

## 10. 为什么会更快

| 角度 | 普通写 | 流式写 |
|---|---|---|
| 读旧行 | 每次写先读整行（浪费） | 不需要 |
| 缓存污染 | 污染（挤掉有用数据） | 不污染 |
| 写合并 | 也可能合并 | 明确配合 |
| 带宽利用 | 读+写双占用 | 纯写 |
| DRAM 行切换 | 顺序时 OK | 顺序时 OK |

论文数据（表 6.1）：顺序写两者同为 0.048s；列写流式 0.16s 反而比普通 0.127s 慢 25%。收益只在"顺序写满整行"时出现。

## 12. 实验结果应该怎么看

- 大数组顺序写：流式写与普通写可能接近（写合并 + 顺序预取），甚至略快（省读旧行/污染）。
- 写后立即读的场景：流式写可能更慢（要回内存读），说明"何时不用"很重要。
- 若 CPU 不支持 SSE2/流式指令：程序应回退到普通写并提示，不报错。
- 不要期望"流式写总是快"——论文数据本身就显示列写时它更慢。

## 13. 常见误区

- **误区 1：流式写总是更快**。列优先/随机写时它更慢（表 6.1：25% 更差）。
- **误区 2：流式写不需要屏障**。内存序放宽，需 `sfence` 保证可见性/顺序。
- **误区 3：所有 CPU 都支持**。需运行时检测指令集，不支持回退。
- **误区 4：任何写入都该绕过缓存**。写后重用数据（矩阵乘法）不该用，否则下次读要从内存来。
- **误区 5：写合并自动发生**。修改同一缓存行的指令必须紧挨着发出，合并窗口有限。

## 15. 本章总结

- 非临时写绕过缓存、配合写合并，适合"大块数据只写一次、短期不重用"。
- 关键 intrinsics：`_mm_stream_si128/_mm_stream_pd/_mm_stream_si32`；需对齐与运行时检测。
- 写合并要求：修改同一行的指令紧挨着发；顺序写满整行才生效。
- 需显式 `sfence` 保证流式写顺序与可见性。
- 列优先/随机写时流式写反而更差（表 6.1：25%）。
- 写后重用数据时不该用（如矩阵乘法 A.1）。
