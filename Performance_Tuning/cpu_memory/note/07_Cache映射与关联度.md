## 3. 核心概念

- **Associativity（关联度）**：同一集合（set）内可存放的缓存行数（ways）。
- **Fully Associative（全相联）**：任何缓存行可映射到缓存任意位置（S=0）。
- **Direct-Mapped（直接映射）**：每个地址恰好映射到唯一缓存条目（1-way）。
- **Set-Associative（组相联 / N-way）**：地址先选集合，集合内有 N 条可竞争。
- **Cache Set（缓存集合）**：由地址的 S 位选择的缓存槽组。
- **Cache Tag（标签）**：用于区分同一集合中不同别名的地址高位。
- **Conflict Miss（冲突未命中）**：容量未满，但因多个地址映射到同一集合而互相逐出导致的 miss。
- **Capacity Miss（容量未命中）**：工作集超过缓存容量导致的 miss。
- **Compulsory Miss（强制未命中）**：首次访问某缓存行不可避免的 miss。
- **`缓存大小 = 行大小 × 关联度 × 集合数`**：三者互相制约。

## 4. 硬件工作流程

### 4.1 三种映射（论文图 3.5~3.7，PDFp17~18）

**全相联（图 3.5）**：每个缓存行存任意地址，Tag = 除 Offset 外全部地址位。

```text
Tag(T) ──► [比较器]×N ──► 选中命中行
每个缓存条目一个比较器，N=65536 条就要 65536 个 T 位比较器 → 面积/延迟爆炸
```

**直接映射（图 3.6）**：用 S 位直接寻址唯一条目。

```text
Tag | Set | Offset
Set 位直接选 1 条 → 1 个比较器 + 多路选择器
缺点：映射到同一 Set 的地址互相驱逐（即使缓存未满）
```

**组相联（图 3.7）**：Set 选集合，集合内 N 条并行比较 Tag。

```text
Tag | Set | Offset
Set 选集合 → 集合内 N 条 Tag 并行比较 → MUX 选中数据
N=8 时只需要 8 个比较器
```

### 4.2 地址字段切分（PDFp15、p19）

```text
|           Tag (T 位)         |  Set (S 位)  |  Offset (O 位) |
                                    │                │
                              选择缓存集合        行内字节偏移
O = log2(行大小)
S = log2(集合数)
T = 地址位数 - S - O
缓存大小 = 2^O × 2^S × 关联度
```

示例（4MB/64B/8-way）：4MB/(64×8)=8192 集合；S=13、O=6、T=32-19=13。

## 5. PDF 核心观点

> 来源：PDF 第 17~19 页；对应章节 3.3、3.3.1、表 3.1、图 3.8。以下为概括。

1. **全相联不现实**（PDFp17）：4MB/64B 缓存有 65536 个条目，若全相联需要 65536 个 T 位比较器，且必须在几周期内完成；只有"几十个条目"的小缓存（如某些 TLB）才用全相联。
2. **直接映射很诱人但脆弱**（PDFp18）：一个比较器 + MUX，晶体管随缓存增大只缓慢增长；缺点是对地址分布敏感，命中集中时某些条目反复被逐出、其余闲置。
3. **组相联折中**（PDFp18）：集合内并行比较（类似全相联的局部版本），既不容易被"刻意挑地址"打败，大小也不受比较器数量限制。关联度增加 → 行数（列）增加，比较器数只随关联度增加。
4. **表 3.1 / 图 3.8 数据**（PDFp19）：gcc 编译负载下，8MB 缓存从直接映射到 2-way 省约 44% 缺失；关联度收益递减，8 路以上收益甚微。
5. **"关联度=缓存翻倍"的说法仅限极端情况**（PDFp19）：4MB→8MB 的跳变体现这种极端，继续翻倍关联度并不等价于翻倍容量。
6. **多核摊薄有效关联度**（PDFp19）：超线程共享 L1、多核共享 L2 时，相当于多个程序"打同一个缓存"，有效关联度减半/四分之一；因此共享缓存需要更高关联度，16-way 已很困难，需转向共享 L3。
7. **工作集与缓存选择**（PDFp20）：峰值工作集 5.6M 下 16MB 缓存仍可能有冲突（2-way 优于直接映射）；但 32MB 缓存收益可忽略。买机器该按实测工作集决定缓存大小。

## 6. 通俗解释

把缓存想象成**停车场**：

- **全相联**：任何车（数据）可以停任何车位——但要找车时得挨个看所有车位（65536 个都要比对），停车场一建大就完蛋。
- **直接映射**：车牌号（地址）直接决定停几号位——找车快，但"尾号相同"的车会抢同一个车位，哪怕停车场还空着很多位（冲突未命中）。
- **组相联**：先把车按"尾号"分到几排（set），每排有 8 个位——尾号相同的车最多 8 辆能同停一排，超出才有人被赶走。

冲突未命中就像：

> 停车场明明空着大半，但你的"尾号"那排停满了，你得等别人挪车（驱逐）才能停。
> 解决方法是"多画几个位"（提高关联度），但停车场面积（成本/面积）有限。

## 7. 示例分析

### 7.1 为什么直接映射容易被"撞"

- 设缓存 1MB/64B/直接映射，S=14（16384 集合）。
- 地址 `A` 与 `A + 1MB`、`A + 2MB`…（集合位相同）会映射到同一集合。
- 若程序交替访问相距恰为缓存大小的两个数组区域，两者互相驱逐，命中率暴跌，即使缓存容量够放两者。

这就是 src/06、src/07 实验的构造方法：**挑步长 = 集合大小整数倍**的地址制造冲突。

### 7.2 冲突 vs 容量

- 容量未命中：工作集 2MB > 缓存 1MB，必然 miss。
- 冲突未命中：工作集 128KB < 缓存 1MB，但两个区域撞同一集合，仍大量 miss。
- 实验 src/06 用"容量未满但地址精心选择"来演示后者。

### 7.3 关联度与集合数换算

- 4MB/64B/8-way：8192 集合，13 个集合位。
- 4MB/64B/直接映射：65536 集合，16 个集合位，比较器只有 1 个。
- 4MB/64B/全相联：1 个集合，65536 个比较器。

## 8. 未优化代码

对应"踩中集合冲突"的程序：两个数组相隔恰为集合周期，交替访问。

```cpp
// bad.cpp: 冲突未命中演示（步长≈集合映射周期）
#include <vector>

int main() {
    constexpr int N = 1 << 20;      // 4MB 数组
    constexpr int STRIDE = 1 << 12; // 4096 = 集合位对齐的步长
    std::vector<int> data(N, 1);
    long long sum = 0;
    for (int rep = 0; rep < 64; ++rep)
        for (int i = 0; i < N; i += STRIDE)
            sum += data[i];
    return sum == 0;
}
```

## 9. 优化后代码

对应"避开集合冲突"的程序：顺序遍历，天然摊开到所有集合。

```cpp
// good.cpp: 顺序访问，避免集合冲突
#include <vector>

int main() {
    constexpr int N = 1 << 20;
    std::vector<int> data(N, 1);
    long long sum = 0;
    for (int rep = 0; rep < 64; ++rep)
        for (int i = 0; i < N; ++i)
            sum += data[i];
    return sum == 0;
}
```

## 10. 为什么会更快

| 角度 | 冲突步长 | 顺序 |
|---|---|---|
| 集合利用率 | 只踩少数集合，反复驱逐 | 均匀摊到所有集合 |
| Conflict Miss | 大量（容量未满也 miss） | 极少 |
| L1/L2/LLC 命中 | 低 | 高 |
| 预取 | 无效（跨集合跳跃） | 有效 |
| DRAM 访问 | 每步长一次 | 每行一次 |

> 注意：冲突效应依赖"物理地址映射到集合的方式"。虚拟地址→物理地址的映射（页着色等）可能打乱

## 13. 常见误区

- **误区 1：缓存 miss 只剩"容量 miss"一种**。还有强制 miss（首次）、冲突 miss（集合打架）、容量 miss（超容）三类。
- **误区 2：关联度越高越好**。超过 8 路收益甚微（论文数据），且面积/功耗/延迟成本上升。
- **误区 3：冲突可以随便演示**。虚拟→物理地址映射 + 页大小会使你的"步长"不一定落在同一集合；需要实验验证并说明限制。
- **误区 4：全相联最理想**。只在条目极少（几十个）的缓存（如 TLB）可行，数据缓存做不到。
- **误区 5：缓存大小决定一切**。同样大小下，关联度与行大小显著影响命中率（表 3.1）。

## 15. 本章总结

- 全相联太贵、直接映射太脆，组相联是实际选择（L1 常用 8-way，L2/L3 更高）。
- 地址切分为 Tag/Set/Offset；缓存大小 = 行大小 × 关联度 × 集合数。
- 冲突未命中是"容量未满却 miss"的元凶，可通过提高关联度缓解。
- 多核共享缓存会摊薄有效关联度，因此共享缓存需更高关联度或改用共享 L3。
- 对程序员：顺序访问、避免按集合周期大步长，是减少冲突 miss 的实操手段。
