## 1. 本章要解决的问题

- 如何用全书知识把一段朴素代码优化到接近硬件极限？
- 完整优化流程：测量 → 数据布局 → 分块 → 向量化 → 多线程。
- 如何正确记录与汇报优化结果（不编造提升比例）。

## 3. 核心概念

- **FLOPS（每秒浮点运算次数）**：衡量浮点计算性能。
- **MFLOPS/GFLOPS**：10^6/10^9 FLOPS。
- **优化链（Optimization Chain）**：依次叠加的优化步骤，每步记录独立收益。
- **Baseline（基线）**：未优化版本，作为对比基准。
- **Checksum**：验证优化前后结果一致。

## 4. 硬件工作流程（项目流程）

```text
第 0 步：基线测量（perf + 计时）
第 1 步：数据布局（行主序、对齐）
第 2 步：访问模式优化（转置/重排）
第 3 步：分块（blocking，扫 block size）
第 4 步：向量化（SIMD，运行时检测）
第 5 步：多线程（绑核、局部化）
第 6 步：验证（checksum + 多轮 + 记录环境）
```

## 6. 通俗解释

综合实践项目就像**把散落的优化课用在一个真实工程上**：

> 朴素版本是"原始土路"，每一步优化是"铺一段路"：先对齐地基（数据布局），
> 再修直主干道（转置/重排），再建立交桥（分块），最后上高速（SIMD + 多线程）。
> 每一步都量一下"这段路省了多少时间"，全部加起来才是最终收益。

## 7. 示例分析

### 7.1 为什么分块能免拷贝

- 转置需要 tmp 矩阵（额外内存 + 拷贝）。
- 分块直接在小块内顺序访问，不需要转置 → 免拷贝（表 6.2：23.4%→17.3% 再省 6.1%）。

### 7.2 分块大小扫描

- SM 太小：块利用率低、循环开销大。
- SM 太大：超出 L1d/L2，miss。
- 扫描 8/16/32/64/128 找出本机最优（src/10）。

### 7.3 向量化的前提

- 数据布局连续（行主序、SoA 式）。
- 指令集检测（SSE2 几乎全有；AVX2/AVX-512 需检查并回退）。
- 对齐（aligned 分配/加载）。

## 8. 未优化代码

朴素矩阵乘法（src/28 的 baseline）。

```cpp
// baseline.cpp
#include <vector>

int main() {
    constexpr int N = 512;
    std::vector<std::vector<double>> A(N, std::vector<double>(N, 1.0));
    std::vector<std::vector<double>> B(N, std::vector<double>(N, 1.0));
    std::vector<std::vector<double>> C(N, std::vector<double>(N, 0.0));
    for (int i = 0; i < N; ++i)
        for (int j = 0; j < N; ++j)
            for (int k = 0; k < N; ++k)
                C[i][j] += A[i][k] * B[k][j];
    return C[0][0] == 0.0;
}
```

## 9. 优化后代码

分块 + 转置 B + 可选 SIMD 的版本（完整版见 src/28）。

```cpp
// optimized.cpp
#include <vector>

int main() {
    constexpr int N = 512;
    constexpr int SM = 8;
    std::vector<double> A(N * N, 1.0), B(N * N, 1.0), T(N * N, 0.0), C(N * N, 0.0);
    for (int i = 0; i < N; ++i)
        for (int j = 0; j < N; ++j)
            T[j * N + i] = B[i * N + j];
    for (int i = 0; i < N; i += SM)
        for (int j = 0; j < N; j += SM)
            for (int k = 0; k < N; k += SM)
                for (int i2 = 0; i2 < SM; ++i2)
                    for (int k2 = 0; k2 < SM; ++k2) {
                        double a = A[(i + i2) * N + (k + k2)];
                        for (int j2 = 0; j2 < SM; ++j2)
                            C[(i + i2) * N + (j + j2)] += a * T[(k + k2) * N + (j + j2)];
                    }
    return C[0] == 0.0;
}
```

## 10. 为什么会更快

| 角度 | baseline | 分块+转置(+SIMD) |
|---|---|---|
| 缓存行利用 | mul2 列访问 ~12.5% | ~100% |
| L1d/L2 miss | 高 | 低 |
| 预取 | mul2 失效 | 全部有效 |
| 指令级并行 | 标量串行 | SIMD 并行 |
| 时间局部性 | 无 | 块内复用 |

最终 FLOPS 以本机实测为准，记录环境（CPU/内核/编译器/优化级别）。

## 12. 实验结果应该怎么看

- 每阶段输出：运行时间、MFLOPS/GFLOPS、相对基线的倍数。
- 验证 checksum：所有阶段结果必须一致（数值误差在容差内）。
- 多轮统计：不要用单次结果。
- 记录环境字段，保证可复现。

## 13. 常见误区

- **误区 1：直接抄论文 9.47%**。那是 2007 Core 2 数据；本机要实测。
- **误区 2：只报加速不报环境**。CPU/内核/编译器/优化级别必须记录。
- **误区 3：不验证结果正确性**。checksum 必须一致（含浮点容差）。
- **误区 4：一次改全部无法归因**。每阶段独立提交，看每步增量。
- **误区 5：没有基线就谈优化**。必须和基线对比。
