## 3. 核心概念

- **Locality（局部性）**：空间（相邻地址）+ 时间（刚用的还用）。
- **Alignment（对齐）**：数据按缓存行边界对齐，一次访问不跨行。
- **Transposition（转置）**：把矩阵转置使访问变为顺序。
- **Sub-Matrix / Blocking（子矩阵/分块）**：把大矩阵拆成能放进制约缓存的小块分别计算。
- **Unrolling（循环展开）**：一次迭代处理多个元素，充分利用缓存行。
- **SIMD / Vectorization（单指令多数据/向量化）**：一条指令并行处理多个数据。
- **pahole**：显示结构体相对缓存行的布局的工具。
- **restrict**：C99 关键字，告知编译器指针无别名，帮助优化。

## 4. 硬件工作流程

### 4.1 朴素矩阵乘法的访问模式（图 6.1 思想，PDFp49）

```text
for i: for j: for k:
   res[i][j] += mul1[i][k] * mul2[k][j];

mul1[i][k]：按行顺序访问 → 空间局部性好（顺序）
mul2[k][j]：内层 k 循环使行号变化 → 每步都跳到不同行 → 空间局部性差（随机/列访问）
res[i][j]：按行顺序 → 好
```

- 内层循环每轮：三个矩阵各需要 1000 条缓存行（64B），远超 32kB L1d → 全部 miss。
- `mul2` 的 `(0,0)` 与 `(0,1)` 本在同一缓存行，但等内层跑完一行，该行早已被逐出。

### 4.2 优化链条（表 6.2，PDFp50~51）

```text
Original   → 16,765,297,870 周期 (100%)
Transposed →  3,922,373,010 周期 (23.4%)   转置后两矩阵都顺序
Sub-Matrix →  2,895,041,480 周期 (17.3%)   分块，免拷贝
Vectorized →  1,588,711,750 周期 (9.47%)   SSE2 一次算 2 个 double
```

- 转置省 76.6%：拷贝开销被 1000 次非顺序访问省下的钱覆盖。
- 子矩阵版本：不拷贝，靠分块让块落在缓存内；比转置再省 6.1%。
- 向量化再省 7.3% 相对原始；最终 318 MFLOPS → 3.35 GFLOPS（单线程 2.66GHz Core 2）。

### 4.3 分块代码结构（PDFp50）

```text
#define SM (CLS / sizeof(double))   // 缓存行能装的 double 数
for (i = 0; i < N; i += SM)
for (j = 0; j < N; j += SM)
for (k = 0; k < N; k += SM)
  ... 内层三个循环处理 SM×SM 块 ...
```

- 外层步长 = SM（缓存行可容纳的元素数），把大乘法拆成小块，块内局部性好。
- 内层顺序：`k2` 外、`j2` 内，因为只有一个表达式依赖 k2、两个依赖 j2。
- `rres/rmul1/rmul2` 指针变量用于把公共表达式提出内层循环（gcc 对数组索引优化不聪明）。
- `restrict` 告知无别名（论文注：C 编译器仍未充分支持 restrict；Fortran 默认无别名是数值计算首选的原因）。

## 5. PDF 核心观点

> 来源：PDF 第 49~51 页；对应章节 6.2、6.2.1、表 6.2、图 6.2。以下为概括。

1. **聚焦 L1d 收益最大**（PDFp49）：L1 优化收益最好，且会惠及更高级缓存；主题 = 改善局部性 + 对齐。
2. **顺序访问被硬件自动预取**（PDFp49）：现代 CPU 对顺序未缓存访问优化良好；随机访问尽量避免。
3. **随机访问慢 70%**（PDFp49）：本例中随机访问因 RAM 实现慢 70%。
4. **转置收益**（PDFp49）：1000×1000 double，转置后 76.6% 加速；拷贝成本被覆盖。
5. **不拷贝的替代**（PDFp50）：矩阵太大或内存不足时不能拷贝；利用"加法顺序无关"重新排列内层循环。
6. **内层循环的缓存行利用**（PDFp50）：一次处理中循环的 2 次迭代用同一缓存行，L1d miss 减半；要整行利用，中循环展开 8 次（64B/8B）、外循环也展开 8 次以整行写 res。
7. **缓存行大小获取**（PDFp50）：`sysconf(_SC_LEVEL1_DCACHE_LINESIZE)` 或 `getconf`；通用二进制用最大缓存行大小编译 `gcc -DCLS=$(getconf LEVEL1_DCACHE_LINESIZE)`。
8. **六重循环的动机**（PDFp50）：外层按 SM 分块保证局部性；内层三个循环处理块内；交换 k2/j2 顺序因依赖差异。
9. **跨缓存行数据结构的惩罚**（PDFp51，图 6.2）：两个元素一个在行首一个在行尾 → 顺序访问在 L2 内约慢 17%、主存级约 27%；随机访问在 L2 内慢 25%~35%，主存级因基准本身变慢反而降回 ~10%。
10. **用 pahole 检查布局**（PDFp51）：`struct foo { int a; long fill[7]; int b; }` 可用 pahole 看相对缓存行的位置。

## 6. 通俗解释

缓存访问优化的核心就一句话：**让你一次搬进来的缓存行，在被赶走之前被用够**。

> 像自助餐厅的取餐盘：厨房（内存）一次给你端一大盘菜（64B 缓存行）。
> 你若一次只挑一道菜（读一个 int）就换盘，厨房得不停端盘子——慢。
> 优化 = 把相邻的菜一起点（顺序访问）、一次把整盘吃完（整行利用）、别跨着两盘夹菜（对齐）。

矩阵乘法的故事：

> 朴素写法里，乘号左边的矩阵顺序好读，右边的矩阵要"竖着读"——每读一个数就跳一行，缓存行全浪费。
> 第一次救法：把右边矩阵抄成横着放的（转置），竖读变横读，快 4 倍多。
> 第二次救法：干脆不抄，把整个乘法切成能放进桌面的小块（分块），小块内都是横着读，再快一点。
> 第三次救法：用"一次夹两道菜"的筷子（SIMD），再快 1.7 倍。最后总共只要原来的 10% 时间。

## 7. 示例分析

### 7.1 为什么 mul2 的列访问慢

- `mul2[k][j]`：内层 k 循环，行号 k 在变。
- 每取一个元素就跳到下一行 → 每条缓存行只用 1 个 double → 空间局部性为零。
- 1000 行 → 每轮内循环要 1000 条缓存行 → 远超 L1d → 全部从 L2/主存取。

### 7.2 为什么展开 8 次

- 64B 缓存行 / 8B double = 8 个元素。
- 中循环展开 8 次：mul1 的一行 8 个元素正好一条缓存行，全部用上 → L1d miss 减半。
- 外循环也展开 8 次：res 一次写 8 个结果（整行写），减少写分配开销。

### 7.3 图 6.2 的读法

- 顺序访问、跨 2/4 条缓存行：L2 内慢约 17%，主存级约 27%。
- 随机访问、跨 4 条缓存行：L2 内慢 25%~35%，主存级掉回 ~10%——不是惩罚变小，而是主存访问本身太贵，分母变大。

## 8. 未优化代码

朴素矩阵乘法（对 mul2 列访问）。

```cpp
// bad.cpp: 朴素矩阵乘法，mul2 列访问
#include <vector>
#include <cstdio>

int main() {
    constexpr int N = 256;
    std::vector<std::vector<double>> mul1(N, std::vector<double>(N, 1.0));
    std::vector<std::vector<double>> mul2(N, std::vector<double>(N, 1.0));
    std::vector<std::vector<double>> res(N, std::vector<double>(N, 0.0));

    for (int i = 0; i < N; ++i)
        for (int j = 0; j < N; ++j)
            for (int k = 0; k < N; ++k)
                res[i][j] += mul1[i][k] * mul2[k][j];  // mul2 列访问

    return res[0][0] == 0.0;
}
```

## 9. 优化后代码

转置 + 分块（缓存行感知）的版本。

```cpp
// good.cpp: 转置 + 分块（简化版）
#include <vector>

int main() {
    constexpr int N = 256;
    constexpr int SM = 8;  // 64B / sizeof(double)
    std::vector<double> mul1(N * N, 1.0);
    std::vector<double> mul2(N * N, 1.0);
    std::vector<double> tmp(N * N, 0.0);
    std::vector<double> res(N * N, 0.0);

    for (int i = 0; i < N; ++i)          // 转置
        for (int j = 0; j < N; ++j)
            tmp[j * N + i] = mul2[i * N + j];

    for (int i = 0; i < N; i += SM)
        for (int j = 0; j < N; j += SM)
            for (int k = 0; k < N; k += SM)
                for (int i2 = 0; i2 < SM; ++i2)
                    for (int k2 = 0; k2 < SM; ++k2) {
                        double a = mul1[(i + i2) * N + (k + k2)];
                        for (int j2 = 0; j2 < SM; ++j2)
                            res[(i + i2) * N + (j + j2)]
                                += a * tmp[(k + k2) * N + (j + j2)];
                    }
    return res[0] == 0.0;
}
```

## 10. 为什么会更快

| 角度 | 朴素 | 转置+分块 |
|---|---|---|
| Cache Line 利用率 | mul2 每行只 1 个 double | 全部用满 |
| L1d miss | 每元素一次 | 每缓存行一次 |
| 时间局部性 | 行被逐出才再用 | 块内短时间内复用 |
| 预取 | mul2 无法预取 | 全部顺序可预取 |
| DRAM 访问 | 大量 | 大幅减少 |

论文数据：转置 23.4%、子矩阵 17.3%、向量化 9.47%（相对原始 100%）。这是 2007 年 Core 2 数据，量级参考。

## 12. 实验结果应该怎么看

- 对比行遍历 vs 列遍历：列遍历的 cache-misses 与耗时显著更高。
- 分块大小扫描：不同 block size 在 L1/L2 命中上出现差异；最优块通常略小于缓存大小（留余量给代码与栈）。
- 转置：虽然多一次拷贝，但主计算收益更大——验证"拷贝成本被覆盖"。

## 13. 常见误区

- **误区 1：循环重排是万能的**。前提是数学允许交换顺序（加法顺序无关）；有浮点精度顾虑时需评估。
- **误区 2：转置一定划算**。矩阵太小或拷贝成本高时可能不划算；论文用 1000×1000 验证。
- **误区 3：分块越大越好**。块要能放进缓存；过大反而 miss。
- **误区 4：编译器会自动做一切**。gcc 对数组索引/别名不聪明（论文原意）；`restrict` 支持也不彻底。
- **误区 5：随机访问只是"稍微慢"**。论文明确：随机访问慢 70%，应尽量避免。

## 15. 本章总结

- L1d 优化主题：改善空间/时间局部性 + 对齐。
- 朴素矩阵乘法因 mul2 列访问而灾难性慢；转置 → 23.4%、分块 → 17.3%、SIMD → 9.47%。
- 缓存行大小应动态获取（sysconf/getconf），按行大小展开循环。
- 跨多条缓存行的数据结构有明确惩罚（图 6.2）。
- 随机访问应尽量避免（论文：慢 70%）。
