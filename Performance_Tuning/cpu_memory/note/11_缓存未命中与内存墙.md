## 3. 核心概念

- **Cache Miss Factors**：决定缓存 miss 代价的因素集合。
- **Bytes/Cycle（每周期字节数）**：带宽计量，读/写/复制测试的指标。
- **Critical Word First & Early Restart（关键字优先与提前重启）**：优先传程序正等的那一个字，其余随后补。
- **Compulsory / Capacity / Conflict Miss**：强制/容量/冲突未命中（note/07 已定义）。
- **DTLB Exhaustion**：工作集过大导致 TLB 条目不够（图 3.24 的 2^18 台阶）。
- **Cache Placement（缓存布局）**：缓存相对超线程/核心/处理器的位置关系。
- **FSB Influence**：前端总线/内存频率对性能的影响。

## 4. 硬件工作流程

### 4.1 读操作带宽随工作集的变化（图 3.24，P4）

```text
工作集 ≤ L1d ：~16B/周期（movaps 每周期一条）
工作集 > L1d ：暴跌到 <6B/周期
工作集 > 2^18 ：再跌（DTLB 用尽，每页额外工作）
工作集 > L2 ：顺序预取可流式，~5.3B/周期
```

### 4.2 写操作带宽（图 3.24 vs 3.26）

- P4（Netburst）L1d 用 **Write-Through**：写带宽卡在 ~4B/周期（受 L2 速度限制）；L2 不足后跌到 **0.5B/周期**，比读慢 10 倍。
- Core 2 用 **Write-Back**：小工作集可接近 16B/周期；L1d/L2 不足后性能显著下降，L2 不足时读写差达 **20 倍**。

### 4.3 Critical Word First（3.5.2，PDFp34~35）

```text
缓存 miss → 内存按 64 位块突发传输（8 或 16 块/行）
每个 64 位块比前一块晚 ≥4 周期到达
程序要的第 8 块 → 要等额外 ≥30 周期
优化：告知控制器"关键字" → 先传它 → 程序继续执行，其余边传边补（Early Restart）
```

- 优点：显著减少 miss 等待。
- 限制：**预取时不知道关键字**，无法优化顺序；若预取在途时命中请求，只能等。

### 4.4 Cache Placement（3.5.3，PDFp35~36）

```text
早期多核：无共享缓存（每核独立 L1+L2）
Intel 双核：共享 L2（Smart Cache）
Intel 四核：每对核心共享 L2，无更高级缓存
AMD 10h：独立 L2 + 统一共享 L3
```

共享缓存的权衡：

- 工作集重叠大 → 共享缓存有效容量增大，受益；
- 工作集不重叠 → 智能缓存管理尝试防止单核独占，但再平衡的驱逐可能选得差；
- 实测（图 3.31）：两进程不共享内存、无 RFO，但写进程在 2^20 字节前性能就开始下降——纯缓存驱逐问题，每核有效缓存接近 1MB 而非 2MB。

### 4.5 FSB 影响（3.5.4，PDFp36）

- 同款 Core 2，667MHz vs 800MHz DDR2（内存快 20%）。
- 大工作集（FSB 吃紧）下最大提升 18.2%，接近理论上限。
- 小工作集（缓存容纳）下几乎无影响。

## 5. PDF 核心观点

> 来源：PDF 第 32~36 页；对应章节 3.5~3.5.4、图 3.24~3.32。以下为概括。

1. **读带宽 L1d 内是 16B/周期**（PDFp32）：P4 上 movaps 每周期一条；L1d 不足后掉到 <6B/周期；2^18 台阶来自 DTLB 用尽。
2. **顺序预取可把主存流式化到 ~5.3B/周期**（PDFp33）：预取不进入 L1d；这些是实践上限，真实程序达不到。
3. **P4 写是 Write-Through**（PDFp33）：小工作集写也只有 ~4B/周期，受 L2 限；L2 不足后 0.5B/周期，比读慢 10 倍——写优化更重要。
4. **超线程共享一切除寄存器**（PDFp33）：两线程各占一半缓存与带宽；双方都在等内存，互相让不出周期——这是超线程最差用法。
5. **Core 2 是写回**（PDFp33）：写可接近 16B/周期；L2 不足时读写差达 20 倍；但整体仍优于 Netburst。
6. **Core 2 双核写冲突**（PDFp33~34，图 3.27）：双核共享 L2，但小工作集写仍要 RFO 且处理不按 L2 速度；工作集超 L1d 后性能反而升（写被冲进共享 L2，L1d miss 由 L2 满足，RFO 减少）——观察到 50% 速度差异。
7. **AMD 10h Opteron**（PDFp34，图 3.28）：L1d 可每周期处理 2 条指令（读 >32B/周期）；但**不预取或预取低效**，读曲线快速平坦到 2.3B/周期；写按 L1d/L2/L3/主存四级下跌（18.7/6/2.8/0.5B/周期）。
8. **复制性能受读写中较慢者限制**（PDFp34）：先受读、后受写主导。
9. **关键字优先**（PDFp34~35）：64 位块每块晚 ≥4 周期到达，第 8 块要多等 ≥30 周期；Critical Word First & Early Restart 可先传关键字；预取时关键字未知则无法优化。
10. **关键字在行尾有小幅损失**（PDFp35，图 3.30）：L2 不足后，指针在行尾比在行首慢约 0.7%。
11. **共享缓存双进程实验**（PDFp35~36，图 3.31）：无 RFO 的纯驱逐问题，写进程在 1MB 前就开始劣化，每核有效缓存接近 1MB 而非 2MB。
12. **四核双 L2 只是权宜之计**（PDFp36）：无更高级缓存，跨核通信用 FSB，无快速通道；未来是更多层级。
13. **FSB/内存频率**（PDFp36，图 3.32）：800 vs 667MHz 大工作集最大提升 18.2%；缓存内无影响；未来 1333MHz 再加 60%。
14. **对程序员**（PDFp36）：不同设计让调度决策变复杂，需知道机器架构再定 affinity。

## 6. 通俗解释

**内存墙**就是"你 CPU 再快，取数太慢也白搭"：

> 读缓存里的数：每次 1 拍（1 周期/条 16B）。读主存：要等几百拍。
> 于是"缓存 miss"像快递堵在路上，CPU 只能干等（图 3.24 掉下来的那段就是墙）。

**Write-Through vs Write-Back 的差别**，在带宽图上看得清清楚楚：

> P4 每写一笔都要同步到 L2（写透），所以写带宽天生矮一截；
> Core 2 先记在 L1 里（写回），小数据能跑满，大了才摔下来。

**Critical Word First** 就像外卖：

> 你点了 8 道菜，其他 7 道还没炒好，但第 3 道先出锅。聪明的外卖先送第 3 道让你先吃，
> 其余做好了再送（Early Restart）。缺点是：如果餐厅提前把整单做好了打包好（预取），就没法先挑第 3 道了。

**共享缓存** 像是"合租厨房"：

> 两人做饭用的菜重叠多，合租反而省地方；重叠少，就得靠"智能分配"抢灶台，抢来抢去可能谁都做不好（驱逐选得差）。

**FSB 快 20%** 只有在"锅都端不动"（大工作集超出缓存、全靠搬）时才明显——搬得快当然省时；小菜都在手边，搬得快没用。

## 7. 示例分析

### 7.1 为什么读 L1d 外性能暴跌

- L1d 内：movaps 每周期取 16B（1 次 load/周期）。
- L1d 外：每次 load 要等 L2/主存，每周期能完成的 load 数骤降。
- 加上 DTLB 用尽（2^18 台阶）：每页都要额外的翻译工作。

### 7.2 Critical Word 例子

- 64B 缓存行 = 8 个 64 位块。
- 程序要第 8 块（行尾），突发从第 1 块开始：每块晚 ≥4 周期，第 8 块比第 1 块晚 ≥28~30 周期。
- Critical Word First：先传第 8 块 → 程序立即继续，其余 7 块随后到，缓存最终一致。
- 图 3.30：行尾 vs 行首指针，L2 不足后慢约 0.7%（随机访问更明显时差异方向一致）。

### 7.3 FSB 快 20% 的真实收益

- 实测最大 18.2% 提升，接近理论上限（20%）。
- 前提：工作集 > 缓存（4MB L2），系统整体工作集含所有进程、内核，小程序也能轻易超 4MB。

## 8. 未优化代码

对应"大量缓存 miss + 依赖慢速写路径"的程序（随机写大数组）。

```cpp
// bad.cpp: 随机写，写 miss + RFO + 带宽双输
#include <vector>
#include <random>

int main() {
    constexpr int N = 1 << 26;   // 256MB，远超 LLC
    std::vector<int> data(N, 0);
    std::mt19937 rng(42);
    for (int i = 0; i < N; ++i) {
        int idx = static_cast<int>(rng() & (N - 1));
        data[idx] = i;           // 随机写
    }
    return data[0] == 0;
}
```

## 9. 优化后代码

对应"顺序写满整行 + 可预取"的程序。

```cpp
// good.cpp: 顺序写，写回友好
#include <vector>

int main() {
    constexpr int N = 1 << 26;
    std::vector<int> data(N, 0);
    for (int i = 0; i < N; ++i)
        data[i] = i;             // 顺序写
    return data[0] == 0;
}
```

## 10. 为什么会更快

| 角度 | 随机写 | 顺序写 |
|---|---|---|
| 写 miss / 写分配 | 每元素一次 | 每行一次 |
| 写回流量 | 相同但分散 | 连续整行 |
| 缓存行利用率 | 部分行反复驱逐 | 全用 |
| 预取 | 无效 | 有效 |
| 与 Read 的 20 倍差 | 常踩最差档（0.5B/周期级） | 停留在高带宽档 |

> 论文图 3.26：Core 2 写在大工作集下与读相差 20 倍。顺序写是避开最差档的第一步；
> 纯流式不读旧值可进一步用 non-temporal store（note/22）。

## 13. 常见误区

- **误区 1：写和读一样快**。很多 CPU 写带宽明显低于读（Netburst 写透 10 倍差、Core 2 大工作集 20 倍差）。
- **误区 2：缓存共享一定更好**。共享缓存对重叠工作集有利；不重叠时智能管理可能造成驱逐摩擦（图 3.31）。
- **误区 3：内存频率提升一定提速**。只在工作集超出缓存（FSB 吃紧）时才有意义（图 3.32）。
- **误区 4：预取能让任何访问都快**。预取不进 L1d、跨页受限、随机访问无效（图 3.28 AMD 读曲线）。
- **误区 5：带宽数字可以直接照搬**。论文数据来自 2007 年的特定处理器，仅作量级参考；本机以实测为准。

## 15. 本章总结

- 缓存 miss 的代价是数量级的：L1d 内 16B/周期 vs 主存级 ~0.5~5B/周期。
- 写带宽常远低于读（写透/写回策略差异，Core 2 大工作集差 20 倍）。
- DTLB 用尽会额外制造台阶。
- Critical Word First & Early Restart 减少 miss 等待，但预取时无法应用。
- 缓存共享是双刃剑：重叠工作集受益，不重叠时驱逐摩擦。
- FSB/内存频率提升只在大工作集（FSB 吃紧）时显著。
- 对程序员：知道机器架构、顺序访问、减少写 miss 是避开内存墙的关键。
