# 03 DRAM 访问原理

> 对应 PDF：第 2.1.3 节 DRAM Access（PDFp6~7）、第 2.2 节 DRAM Access Technical Details（PDFp8~12）、第 2.2.1~2.2.3 节、第 2.2.5 节 Conclusions
> 本篇回答：一次内存读到底经历了哪些时序？为什么"随机访问 DRAM"这么慢，而"顺序访问"能跑满带宽？

## 1. 本章要解决的问题

- SDRAM 读访问的完整时序：RAS → CAS → 数据。
- 为什么不能只传一个数据字，而要一次传 2/4/8 个字（突发传输）？
- 预充电（Precharge）与激活（Activation）为什么拖慢随机访问？
- DRAM 刷新（Recharging）对性能的影响，以及为什么解释测量结果时要想到它。
- DDR/DDR2/DDR3 各代如何在不提高单元频率的前提下翻倍带宽。
- 时序参数记号 `w-x-y-z-T`（如 2-3-2-8-T1）怎么读。

## 2. 前置知识

- note/02：DRAM 单元（1T1C）、行列阵列、RAS/CAS 地址复用。
- 同步电路概念：所有信号在时钟（CLK）上升沿采样，信号只要在采样时刻稳定即可。
- 引脚（pin）与总线宽度：数据并行传输（64 位 = 8 字节）。
- 突发传输（burst）：一次访问请求后连续传输多个数据字。

## 3. 核心概念

- **SDRAM（Synchronous DRAM，同步动态随机存储器）**：与时钟同步工作，是 DDR 的基础。
- **DDR（Double Data Rate DRAM，双倍速率 DRAM）**：每个时钟周期传输两次数据（上升沿 + 下降沿）。
- **RAS（Row Address Select，行地址选通）**：把行地址送入 DRAM 的信号。
- **CAS（Column Address Select，列地址选通）**：把列地址送入 DRAM 的信号。
- **tRCD（RAS-to-CAS Delay）**：RAS 到 CAS 的延迟，行激活后必须等待这么多周期才能送列地址。
- **CL（CAS Latency，CAS 延迟）**：CAS 发出后，数据真正出现在总线上的延迟（可为整数或半值，如 2.5）。
- **tRP（Row Precharge Time，行预充电时间）**：预充电命令发出后，到新行可被选择所需的周期数。
- **tRAS（Active to Precharge Delay）**：从行激活到可以预充电的最小周期数，通常约为 tRP 的 2~3 倍。
- **Command Rate（T1/T2）**：DRAM 模块接受新命令的间隔周期；T1 表示每个周期都能接受。
- **Precharge（预充电）**：在打开新行之前，把当前行的位线恢复到待命电压的过程。
- **Burst Length（突发长度）**：一次 CAS 后连续传输的数据字数（常为 2/4/8）。
- **Refresh（刷新）**：每行 64ms 内必须刷新一次；8192 行时约每 7.8125µs 一条刷新命令。
- **DDR 记号 `w-x-y-z-T`**：分别表示 CL、tRCD、tRP、tRAS、Command Rate。例：2-3-2-8-T1。

## 4. 硬件工作流程

### 4.1 SDRAM 读访问时序（论文图 2.8，PDFp8）

```text
CLK    __|‾|__|‾|__|‾|__|‾|__|‾|__|‾|__|‾|__
       |   |     |        |        |   |   |
RAS    ‾‾|   |_____        |        |   |   |
       |   |      |        |        |   |   |
CAS    ‾‾‾‾‾|         |________     |   |   |
       |   |          |       |     |   |   |
Addr   |Row|  X   Col |  X    |     |   |   |
       |   |          |       |     |   |   |
DQ     ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|______|   D0 D1 D2 D3
       |   |  tRCD     |  CL   |     |   |   |
       |   |<--------->|<----->|
```

步骤：

1. 内存控制器把行地址放到地址总线，拉低 RAS（在读信号边沿采样）。
2. 等待 tRCD 个周期后，把列地址放到地址总线，拉低 CAS。
3. 等待 CL 个周期，第一个数据字出现在数据总线 DQ 上。
4. 突发传输：按突发长度连续输出多个数据字（SDR 每周期 1 个，DDR 每周期 2 个）。

要点：

- 地址分两半在**同一条地址总线**上先后传输（复用）。
- 行保持"打开"（open）时，可以只发新 CAS 而不重发 RAS，连续读取更快。
- 是否保持行打开由内存控制器决定；无条件保持打开对真实程序并不总是最优（PDFp8 提及 [3]）。
- 连续 CAS 的间隔受 Command Rate 约束（T1 最理想）。

### 4.2 预充电与激活（论文图 2.9，PDFp9）

```text
上一行数据传完 → 发预充电 → 等 tRP → 新 RAS 激活新行 → tRCD → CAS → CL → 数据
                  |<--tRP-->| |<-tRCD->| |<-CL->|
```

- 打开新行前必须关闭旧行：先预充电，等 tRP，再发 RAS。
- 预充电命令可借 WE+RAS 同时拉低来编码（没有专用引脚）。
- tRAS 约束：RAS 之后必须等够 tRAS 才能预充电，若 tRAS > (tRCD+CL+传输时间) 会进一步延迟。
- **关键数字（论文示例）**：一次"换行随机访问"，数据总线可能 7 个周期只忙 2 个周期。以 800MHz 四倍泵总线算，理论 6.4GB/s 实际只剩约 1.8GB/s。

> 这就是"随机访问慢"的硬件根源：大量时间花在预充电 + 激活 + 等待，而不是传输。

### 4.3 DDR 系列演化（论文图 2.10~2.13，PDFp10~11）

```text
SDR:   cell array f MHz ──► bus f MHz      每周期 1 字
DDR1:  cell array f MHz ──► I/O buffer ──► 2f 传输  每周期 2 字（上下沿）
DDR2:  cell array f MHz ──► 4bit buffer ──► 4f 传输 每周期 4 字
DDR3:  cell array f MHz ──► 8bit buffer ──► 8f 传输 每周期 8 字
```

- 核心思想：**只提高 I/O buffer 的速率，不提高庞大的 cell array 频率**（省电、稳定）。
- 功耗公式 `Power = C·V²·f`：DDR3 从 1.8V 降到 1.5V，仅电压一项就带来约 30% 省电（PDFp10）。

### 4.4 刷新（论文 2.2.3，PDFp9~10）

```text
每 64ms：所有行各刷新一次
8192 行 → 平均每 7.8125µs 一条刷新命令（可排队，实际间隔可更长）
```

- 刷新 = 一次丢弃结果的读操作；刷新期间该行不可访问。
- 若恰好要读正被刷新的行，处理器可能停很长时间（论文引 [3]：刷新组织对性能影响"惊人"）。
- 程序员无法控制刷新时机，但解读测量结果时必须把它纳入考虑。

## 5. PDF 核心观点

> 来源：PDF 第 6~12 页；对应章节 2.1.3、2.2、2.2.1~2.2.5。以下为概括。

1. **总线频率≠传输速率**（PDFp8）：SDRAM 时代总线双泵/四泵，"有效频率"被营销放大；200MHz 四泵=800MHz 有效。
2. **传输速率 = 8 字节 × 有效总线频率**（PDFp8）：如 800MHz 有效 → 6.4GB/s，但这只是**突发峰值**，协议存在大量无法传数据的空闲期。
3. **读协议三段式**（PDFp8）：行地址+RAS → 等 tRCD → 列地址+CAS → 等 CL → 数据；一次可传 2/4/8 字以填满缓存行。
4. **换行必须预充电**（PDFp9）：旧行要先预充电（tRP）才能开新行；tRAS 通常为 tRP 的 2~3 倍，可能进一步限制。
5. **随机访问使总线利用率暴跌**（PDFp9）：示例中数据总线 7 周期只传 2 周期，6.4GB/s 掉到 1.8GB/s。
6. **DDR 五参数记号**（PDFp9）：`w-x-y-z-T` = CL, tRCD, tRP, tRAS, Command Rate；买机器和解释测量都靠它。
7. **DDR1/DDR2/DDR3 是带宽工程而非延迟工程**（PDFp10~11）：每一代都把 I/O buffer 做快一倍（1/2/4 bit→每周期 1/2/4/8 字），cell array 频率不变；延迟（CL）并没有同比例下降。
8. **DDR3 初期 CL 甚至更高**（PDFp11）：DDR2 技术更成熟；DDR3 主要赢在带宽而非延迟。
9. **DDR 并行总线受限**（PDFp11）：DDR2 每条通道最多 2 条模块、DDR3 高频时 1 条；240 引脚/通道使北桥最多驱动 2 通道 → 消费级主板最多 4 条内存。
10. **结论**（PDFp12）：DRAM 能跑满 100% 总线（整行突发、双通道 DDR2-800 = 12.8GB/s），但非连续访问要靠预充电 + 新 RAS，此时需要帮助——预取（见 note/21）能掩盖延迟并错开读写争用。

## 6. 通俗解释

把 DRAM 读访问想象成"去图书馆借书"：

1. **RAS（行激活）**：管理员走进一排书架，把一整排书（一行）搬到借阅台上——需要时间（tRCD）。
2. **CAS（列选择）**：从借阅台上选出你要的那一本——又要等（CL）。
3. **数据**：拿到书。
4. **预充电**：借完书，管理员要把书架推回原位、整理好，才能接待下一个读者——花时间（tRP）。

为什么顺序访问快？

> 因为"一排书架"（一行 DRAM）一次性搬上来了，你连续取第 1、2、3…本都是秒取（行命中 + 突发传输）。
> 但如果你每次随机跳到不同书架（不同行），管理员就得不停"整理归位（预充电）→ 再搬新一排（激活）"，
> 大部分时间都在搬书架，而不是在给你书。

为什么 DDR 不能更快？因为"书"（数据）在 DRAM 单元里很慢才能稳定出来，加速只能靠"书架出口的传送带"（I/O buffer）加宽加快，传送带变快了一倍、四倍，但取第一本书的等待时间基本没变。

## 7. 示例分析

### 7.1 一次换行随机访问的时序账

假设 SDR 参数：tRCD=2、CL=2、tRP=2、命令率 T1、突发 2 字、传输 2 周期。

- RAS → (tRCD=2) → CAS → (CL=2) → 传 2 字 (2 周期)
- 传完 → 预充电 (tRP=2，可与传输重叠一部分) → 新 RAS
- 若 tRAS=8 但 (tRCD+CL+传=6)<8，预充电还要再等 2 周期（论文图 2.9 的推演）

净效果：数据总线真正忙的时间只占一小部分（示例 7 周期中 2 周期 = 28.6%），有效带宽远低于峰值。

### 7.2 为什么突发长度要能对齐缓存行

缓存行 64B = 8 个 8B 字。允许一次 CAS 传 8 字（对 DDR2 就是 8 个字），正好填满一整条缓存行，无需再发 RAS/CAS，省掉整套换行开销。这就是"让软件访问模式尽量顺序"的硬件原因之一。

### 7.3 参数记号 `2-3-2-8-T1` 怎么读

| 位置 | 含义 | 示例值 |
|---|---|---|
| w | CAS Latency (CL) | 2 |
| x | RAS-to-CAS (tRCD) | 3 |
| y | RAS Precharge (tRP) | 2 |
| z | Active to Precharge (tRAS) | 8 |
| T | Command Rate | T1 |

## 8. 未优化代码

对应"把内存当均匀随机存储"的程序行为：随机访问大数组，最大化预充电/激活开销。

```cpp
// bad.cpp: 随机访问，撞 DRAM 换行墙
#include <vector>
#include <random>

int main() {
    constexpr int N = 1 << 24;
    std::vector<int> data(N, 1);
    std::mt19937 rng(42);
    long long sum = 0;
    for (int i = 0; i < N; ++i) {
        int idx = static_cast<int>(rng() & (N - 1));
        sum += data[idx];
    }
    return sum == 0;
}
```

## 9. 优化后代码

对应"尊重 DRAM 行结构"的程序行为：顺序访问，行打开 + 突发传输 + 硬件预取全部生效。

```cpp
// good.cpp: 顺序访问
#include <vector>

int main() {
    constexpr int N = 1 << 24;
    std::vector<int> data(N, 1);
    long long sum = 0;
    for (int i = 0; i < N; ++i)
        sum += data[i];
    return sum == 0;
}
```

## 10. 为什么会更快

| 角度 | 随机访问 | 顺序访问 |
|---|---|---|
| DRAM 行命中 | 每次换行都要预充电+激活 | 整行打开后持续命中 |
| tRCD + CL | 每次访问都全额付出 | 首字付出一次，后续突发分摊 |
| 数据总线利用率 | 大量空闲（例：28.6%） | 接近 100%（整行突发） |
| 硬件预取 | 无法预测 | 完美匹配 |
| 刷新冲突概率 | 每次访问都可能撞刷新 | 访问本身短促，调度更从容 |
| Cache 命中（间接） | miss 多，回到 DRAM | hit 多，很少真正访 DRAM |

需要澄清：普通程序的"顺序快"是 **Cache 层**（note/05~11）与 **DRAM 层**（本篇）共同贡献的。本实验只测端到端，不做归因拆分；归因分析见各笔记"为什么会更快"表。

## 12. 实验结果应该怎么看

- src/04 stride：步长从 1、2、4…翻倍时，只要访问仍在同一 DRAM 行/缓存行内，延迟平缓；一旦跨越行/页，延迟出现台阶。
- src/02：随机访问的 ns/element 远高于顺序访问，且 GB/s 远低于峰值——这就是"换行墙"的宏观表现。
- 对照"11:1 时钟比"（note/01）：内存侧每多停 1 周期，CPU 侧就损失约 11 周期，所以延迟的微小差异会被放大成明显的运行时间差异。

## 13. 常见误区

- **误区 1：DDR 频率翻倍 = 更快的内存**。DDR 翻的是带宽（传输速率），延迟基本没变；大工作集下才有收益。
- **误区 2：理论峰值带宽就是实际带宽**。论文示例 6.4GB/s 在随机访问下只有 1.8GB/s。
- **误区 3：行一直开着最好**。内存控制器要权衡；乱序访问时保持行打开反而妨碍其他行（PDFp8 原文提示）。
- **误区 4：刷新是均匀无感的**。刷新会占用访存窗口，测量大工作集时要考虑；论文引 [3] 称刷新组织可"惊人地"影响性能。
- **误区 5：超频改时序参数很安全**。论文明确警告 BIOS 调 tRCD/CL 等属于"自担风险"（PDFp9 原文）。
- **误区 6：所有内存条能插满主板**。DDR2/DDR3 每通道模块数受限（2/1），消费级主板最多 4 条（PDFp11）。

## 15. 本章总结

- 一次 DRAM 读 = 行激活(RAS) → tRCD → 列选(CAS) → CL → 突发数据，换行还需预充电(tRP)。
- 随机访问把数据总线利用率打到谷底（示例约 28%），这是"随机慢"的硬件原因。
- DDR 各代只加宽/加快 I/O buffer（1→2→4→8 字/周期），cell array 频率与访问延迟基本不变。
- 刷新（64ms/行，8192 行约 7.8µs 一条命令）是测量时不可忽视的背景噪声。
- 结论：顺序访问 + 预取是对抗 DRAM 时序的唯一有效手段（细节在 note/21）。
