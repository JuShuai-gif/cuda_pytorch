## 3. 核心概念

- **Atomic Operation（原子操作）**：不可分割的读-改-写，并发下结果确定。
- **CAS（Compare-and-Swap）**：仅当当前值等于期望值时写入新值，返回成败。
- **LL/SC（Load Lock / Store Conditional）**：LL 标记位置，SC 仅当期间未修改才写入。
- **Atomic Arithmetic（原子算术）**：x86/x86-64 支持的原子加减等（如 `lock add`）。
- **lock 前缀**：x86 上使指令原子化的前缀。
- **RFO（Request For Ownership）**：原子操作也需要所有权转移。
- **DCAS（Double-word CAS）**：双字 CAS，x86/x86-64 特有。

## 4. 硬件工作流程

### 4.1 为什么并发自增会丢

```text
线程1: 读 var (S 态) → 算 +1 → 等 E 态 → 写回
线程2: 读 var (S 态) → 算 +1 → 等 E 态 → 写回
若两线程同时读旧值，其中一个 +1 丢失
```

- 处理器故意不保证非原子结果（避免 99.999% 情况下的不必要开销）。
- 需要原子操作：必须等到"能原子执行"才读旧值；有些还向主板设备广播原子操作信号。

### 4.2 原子递增的三种实现（图 6.12，PDFp68~69）

```cpp
// 1. Add and Read Result
__sync_add_and_fetch(&var, 1);      // 0.23s（1M 次 × 4 线程）

// 2. Add and Return Old Value
__sync_fetch_and_add(&var, 1);      // 0.21s

// 3. Atomic Replace (CAS 循环)
do { v = var; n = v + 1; }
while (!__sync_bool_compare_and_swap(&var, v, n));   // 0.73s
```

- 前两个相似（返回旧值略快）；CAS 显著更贵（0.73s）。

### 4.3 CAS 为什么慢（PDFp69）

```text
① 两次内存操作（读 + CAS）
② CAS 本身更复杂，还需条件操作
③ 并发下可能失败 → 循环重试
线程1: v=var(n=E) → n=v+1 → CAS(→E on P1)
线程2: v=var → n=v+1 → CAS(→E on P2，失败) → 重试
       （期间缓存行状态变化 ≥3 次，其中 2 次 RFO）
```

- 原子算术（lock add）：处理器把 load+store 绑在一起，并发的缓存行请求被阻塞直到原子操作完成 → 每次迭代至多 1 次 RFO。

### 4.4 lock 前缀与跳过（PDFp69）

```asm
    cmpl $0, multiple_threads
    je   1f
lock add  $1, some_var
1:
```

- 单线程时跳转跳过 lock（无原子开销）；多线程执行 lock 版本。
- 代价：分支误预测 + 每指令多一个条件跳；但原子操作 ~200 周期，交叉点很低。
- 注意：此技巧无法用 gcc `__sync_*` 表达。

## 5. PDF 核心观点

> 来源：PDF 第 68~70、89~91 页；对应章节 6.4.2、8.1、8.2.1、图 6.12。以下为概括。

1. **非原子结果是有意的**（PDFp68）：避免不必要成本；需要时才用原子操作。
2. **四类原子操作**（PDFp68）：位测试、LL/SC、CAS、原子算术；架构要么支持 LL/SC 要么支持 CAS，二者等价。
3. **CAS 是统一基础但昂贵**（PDFp68~69）：用 CAS 可实现一切原子操作，但性能差（内存处理开销巨大）。
4. **x86 有专属原子算术**（PDFp69）：`lock` 前缀指令，并发缓存行请求被阻塞，每次迭代至多 1 次 RFO。
5. **lock 前缀可运行时跳过**（PDFp69）：单线程跳 lock；原子操作 ~200 周期，交叉点低；但 __sync_* 用不了。
6. **8.1 原子操作问题**（PDFp89）：锁免费结构需要原子原语；多数架构只原子读写一个字；CAS 或 LL/SC 是实现基础；x86/x86-64 还有 DCAS 与更多原子操作。

## 6. 通俗解释

原子操作像**银行的"同一笔账并发转账"**：

> 两个柜员同时给同一账户 +1。若不原子，两个人都读到旧余额再写回，一笔就丢了。
> 处理器默认允许这种丢失（因为极少发生，保证它太贵）。
> 需要原子时，就用"锁住账户再操作"（lock/原子指令）或"先核对余额再改，不行重试"（CAS）。

CAS vs 原子算术，像两种柜员流程：

> CAS：读余额 → 想加多少 → 检查"还是不是刚才那个数？是就写，不是就重来"。并发高时反复重来（0.73s）。
> 原子算术：直接"锁住 + 加 + 解锁"一步到位（0.21s）。因为处理器把整个加法焊死成一条指令。

为什么 CAS 要重试？

> 两个人同时操作，一个成功另一个发现"余额变了"，就得重新读、重新算、重新试。
> 而原子算术内部把对方挡在门外（阻塞请求），做完才放行，所以不重试。

## 7. 示例分析

### 7.1 图 6.12 的性能对比

- `__sync_add_and_fetch`：0.23s（lock 前缀 add，含结果返回）。
- `__sync_fetch_and_add`：0.21s（返回旧值，略快）。
- CAS 循环：0.73s（两次访存 + 条件 + 失败重试）。
- 结论：能用原子算术就别用 CAS 兜底。

### 7.2 CAS 缓存行状态演变（两线程）

```text
线程1: v=var        → 行在 P1 为 E
线程1: n=v+1
线程1: CAS(var)     → 行变 S (P1+P2)
线程2: v=var        → 行在 P2 为 E
线程2: n=v+1
线程2: CAS(var)     → 行回到 E on P1？→ 失败 → 重试
```

- 短周期内状态变 ≥3 次、其中 2 次 RFO → 内存开销巨大。

### 7.3 LL/SC（8.2.1）

- LL 把值载入寄存器，同时把位置"锁定"。
- SC 仅在 LL 后位置未被修改时才成功写入；失败则重试。
- CAS 可由 LL/SC 实现（反之亦然）。

## 8. 未优化代码

对应"共享计数器用 CAS 循环"的程序。

```cpp
// bad.cpp: CAS 循环自增（可读性好但慢）
#include <thread>

int main() {
    constexpr long N = 10'000'000;
    long counter = 0;
    std::thread t1([&] {
        for (long i = 0; i < N; ++i) {
            long v, n;
            do { v = counter; n = v + 1; }
            while (!__sync_bool_compare_and_swap(&counter, v, n));
        }
    });
    t1.join();
    return counter == 0;
}
```

## 9. 优化后代码

对应"原子算术自增"或"局部计数"的程序。

```cpp
// good.cpp: 原子算术自增（单线程时；多线程仍会竞争）
#include <thread>

int main() {
    constexpr long N = 10'000'000;
    long counter = 0;
    std::thread t1([&] {
        for (long i = 0; i < N; ++i)
            __sync_fetch_and_add(&counter, 1);
    });
    t1.join();
    return counter == 0;
}
```

> 若多线程且可分离：用每线程局部计数 + 最后合并（note/23 建议）比原子更优。
> 完整对比（局部/atomic/mutex/reduction）见 src/14_atomic_contention。

## 10. 为什么会更快

| 角度 | CAS 循环 | 原子算术 | 局部归约 |
|---|---|---|---|
| 内存操作次数 | 2/迭代 | 1/迭代 | 0（栈变量） |
| RFO 次数 | 1+/迭代（可能重试） | 至多 1/迭代 | 0 |
| 失败重试 | 有 | 无 | 无 |
| 缓存行状态变化 | 频繁 | 受控 | 无 |

论文数据：CAS 0.73s vs 原子算术 ~0.21s（1M×4 线程）。多线程共享计数器场景，局部归约最优。

## 12. 实验结果应该怎么看

- 单线程：几种方式差异小；CAS 略慢。
- 多线程共享计数：CAS 与 mutex 明显慢于原子算术；局部归约最快且几乎不随线程数变化。
- 用 perf 看 cache-misses/总线事件，解释 RFO 与重试的影响。
- 不要只用单线程数据下结论。

## 13. 常见误区

- **误区 1：原子操作都差不多**。CAS 循环比原子算术慢 3 倍（图 6.12）。
- **误区 2：CAS 是万能最优方案**。它通用可移植，但 x86 上有更好的原子算术。
- **误区 3：原子操作不需要考虑缓存竞争**。原子写也要 RFO；高竞争下依旧慢。
- **误区 4：多线程共享计数器一定用原子**。能局部归约就先局部归约，原子只是兜底。
- **误区 5：lock 前缀永远需要**。单线程可跳过（运行时判断），但 __sync_* 无法表达。

## 15. 本章总结

- 并发写需要原子操作；处理器默认不保证非原子结果。
- 原子操作四类：位测试、LL/SC、CAS、原子算术；架构选其一为基础。
- CAS 通用但贵（两次访存 + 重试 + RFO）；x86 原子算术每次至多 1 次 RFO。
- lock 前缀可运行时跳过以省单线程开销。
- 多线程共享计数：优先局部归约，其次原子算术，CAS/mutex 兜底。
