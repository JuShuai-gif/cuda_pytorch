# 人形机器人全身控制与平衡

## 1. 人形机器人 vs 机械臂：性能难度差异

机械臂（6-7 DOF）固定在桌面或基座上，运动学链闭合于固定基座，不存在整体平衡问题。
人形机器人（30+ DOF）的根本挑战在于：

| 维度 | 机械臂 | 人形机器人 |
|------|--------|------------|
| 基座 | 固定 | 浮动（双脚交替支撑） |
| 平衡约束 | 无 | ZMP/CoM 必须在支撑多边形内 |
| 接触状态 | 恒定 | 动态切换（双脚→单脚→双脚） |
| DOF 数量 | 6-7 | 30-40 |
| 控制频率 | 100-500 Hz | 500-2000 Hz |
| 雅可比矩阵 | 6×7 | 6×34（每任务） |
| 质心矩阵 | 7×7 | 34×34 |
| 实时计算预算 | 2-10 ms | 0.5-1 ms |

**关键认知**：人形机器人的性能瓶颈不是单个任务的精度，而是**在极短时间内完成高维矩阵分解**的能力。

## 2. 全身控制（WBC）

### 2.1 问题定义

给定 n 个关节（典型 30-40 DOF），需要同时满足 m 个任务（平衡、抓取、姿态等），
但 m 个任务维度之和常远超 n。WBC 通过**严格优先级排序**解决任务冲突：

```
P0: 关节限位（硬约束，不可违反）
P1: 平衡（ZMP/CoM，防止摔倒）
P2: 足底接触力（摩擦锥，防止打滑）
P3: 末端执行器跟踪（手/头姿态）
P4: 姿态（直立，膝关节微屈）
```

### 2.2 零空间投影（Null-Space Projection）

核心思想：低优先级任务只能在高优先级任务的零空间中执行，不得干扰高优先级任务。

**递推公式**：

- 任务 k 的增广雅可比：**Ĵₖ = Jₖ · Nₖ₋₁**
- 速度增量：**q̇ₖ = q̇ₖ₋₁ + Ĵₖ⁺ (vₖ − Jₖ q̇ₖ₋₁)**
- 零空间更新：**Nₖ = Nₖ₋₁ − Ĵₖ⁺ Ĵₖ**

其中 **Ĵₖ⁺** 是增广雅可比的伪逆，**N₀ = I**（全零空间），任务按优先级 **k = 0, 1, 2, ...** 依次求解。

### 2.3 阻尼最小二乘（Damped Least Squares）

纯伪逆在奇异构型附近数值不稳定。工程中普遍使用阻尼伪逆：

**J⁺ = Jᵀ (J Jᵀ + λ² I)⁻¹**

阻尼因子 λ 引入后，零空间投影不再是严格投影（N² ≠ N），但在 λ ≪ 1 时近似成立。
λ 的典型取值为 0.01 ~ 0.1，可通过条件数自适应调节。

### 2.4 计算成本分析

对 m×n 的雅可比（m=6, n=34）：

- **J Jᵀ**：O(m²n) ≈ O(36·34) = 1224 次乘法
- **矩阵求逆**（m×m）：O(m³) ≈ 216 次（通过 Cholesky 分解）
- **Jᵀ · inv**：O(nm²) ≈ 1224 次
- **零空间更新**（n×n）：O(n²m) ≈ 6936 次

单任务投影总成本约 10,000 FLOPs。4 个任务约 40,000 FLOPs。
在现代 CPU 上（~50 GFLOPS/core），**理论耗时 < 1μs**。
实际瓶颈是**内存带宽**：读取 30+ 个关节状态、写入 30+ 个力矩指令。

## 3. ZMP 平衡判据与 LIPM 简化模型

### 3.1 ZMP（零力矩点）

ZMP 是地面上一点，地面反力对该点的合力矩在水平分量为零。
保持平衡的充要条件：**ZMP 始终位于支撑多边形（脚掌凸包）内部**。

多体动力学 ZMP 计算公式：

**p_zmp = (Σ mᵢ(rᵢ − p_z)äᵢ − Σ mᵢ(rᵢ − p_z)g) / (Σ mᵢ(äᵢ_z − g_z))**

### 3.2 LIPM（线性倒立摆模型）

假设质心在恒定高度 zc 上运动，忽略角动量变化，得到线性化模型：

**ẍ = ω² (x − p_zmp)**，其中 **ω = √(g / zc)**

该模型将 34-DOF 多体动力学化简为一个**单质点线性系统**，可在微秒级完成更新。
是实时步态规划的核心工具。

### 3.3 步态模式生成

给定足部落点序列，通过**预览控制（preview control）**生成质心轨迹：

1. 确定每个步态阶段的支撑多边形
2. 将 ZMP 参考轨迹设为支撑多边形中心
3. 用 LIPM 动力学前向推演质心轨迹
4. 验证每个时刻 ZMP 是否在支撑多边形内

质量守恒约束：质心轨迹必须满足动力学一致性（速度连续、加速度平滑）。

## 4. 30+ DOF 系统的实时计算挑战

### 4.1 为什么 1ms 如此困难

| 组件 | 运算 | 时间预算 |
|------|------|----------|
| 传感器读取（编码器、IMU） | 总线通信 | ~50μs |
| 状态估计（KF） | 小规模矩阵运算 | ~100μs |
| **WBC 求解** | **伪逆 + 零空间投影** | **~200μs** |
| 运动学正解（FK） | 正余弦 + 矩阵乘 | ~100μs |
| 逆动力学（ID） | RNEA 递推 | ~100μs |
| 力矩输出（CAN/EtherCAT） | 总线通信 | ~50μs |
| **总计** | | **~600μs** |

在 1kHz（1ms 周期）控制环中，上述计算占用 ~60%。剩余 40% 用于通信抖动、中断处理、
操作系统调度开销。如果 WBC 求解超过 500μs，系统将大概率丢帧。

### 4.2 内存带宽瓶颈

34-DOF 系统每次控制迭代的数据吞吐：

- **输入**：34 个关节位置 + 34 个关节速度 + IMU 12 维 + 足底力 12 维 ≈ 400 bytes
- **中间**：雅可比矩阵 6×34×4 任务 ≈ 3,264 bytes（double 精度）
- **输出**：34 个力矩指令 ≈ 272 bytes

看似数据量不大，但注意：**零空间投影矩阵 N 是 34×34 ≈ 9KB**，需要频繁更新。
如果 L1 数据缓存为 32KB，N 矩阵本身占用近 30%，加上雅可比矩阵和中间变量，
很容易超出 L1 缓存造成 cache miss。每次 cache miss 代价 ~50ns（L2）~200ns（L3）。

**优化方向**：使用 32-bit float（减半内存占用）、缓存分块、预取。

## 5. 步态切换时的约束矩阵动态管理

### 5.1 接触状态切换

行走周期是双脚支撑→单脚支撑→双脚支撑的循环：

- **双脚支撑（DS）**：2 脚 × 6 维约束 = 12 个等式约束
- **单脚支撑（SS）**：1 脚 × 6 维约束 = 6 个等式约束 + 摆动脚轨迹跟踪任务

约束矩阵在切换瞬间发生维度变化。工业实践要点：

1. **禁止在切换时动态分配内存**：全部矩阵在初始化时按最大尺寸预分配
2. **Smooth 过渡**：约束力从旧接触面按 `t/T` 线性过渡到新接触面，避免冲击
3. **切换检测**：通过足底力传感器阈值判断接触状态（>10N 视为接触）

### 5.2 接触力优化

摩擦锥非线性约束 **|f_t| ≤ μ f_n** 线性化为 4 条平面：

```
[ 1,  0, -μ] · [f_x, f_y, f_z]ᵀ ≤ 0
[-1,  0, -μ] · [f_x, f_y, f_z]ᵀ ≤ 0
[ 0,  1, -μ] · [f_x, f_y, f_z]ᵀ ≤ 0
[ 0, -1, -μ] · [f_x, f_y, f_z]ᵀ ≤ 0
```

同时约束 **f_z ≥ f_min**（防止离地）和 **f_z ≤ f_max**（防止过载）。

## 6. 性能经验总结

1. **WBC 求解应在 200-300μs 内完成**：使用阻尼最小二乘替代 SVD 分解，避免完整的对角化
2. **零空间投影是 O(n²m) 操作**：34-DOF × 6 维任务 ≈ 7,000 次乘法，不是瓶颈；34×34 姿态任务投影才是主要的 N² 开销
3. **预分配一切**：雅可比、零空间、中间矩阵全部在构造时分配，运行时禁止 new/malloc
4. **float 精度足够**：WBC 的数值精度要求不高（力矩指令经底层 PID 再次修正），32-bit float 较 64-bit double 节省 50% 内存带宽
5. **1kHz 控制环是分水岭**：低于 500Hz 无法稳定控制动态行走；高于 2kHz 的收益递减而功耗线性增长
6. **ZMP 检查仅需 1μs**：点-多边形判定用射线法，8 个顶点的凸包可在几十个周期内完成
7. **LIPM 预测 1ms 计算 500ms 轨迹**：前向推演每秒可计算数千步，适合在线重规划
8. **接触切换是脆弱期**：30% 的摔倒在支撑相切换时发生，切换期间力矩输出需保守限幅
9. **RT-PREEMPT 内核**：标准 Linux 非实时内核的调度抖动可达 1ms+，人形机器人必须使用实时内核将抖动压至 10-50μs
10. **CAN/EtherCAT 总线是隐藏瓶颈**：34 个关节的 1kHz 同步通信需要总线周期 <100μs，EtherCAT 分布式时钟（DC）是当前主流方案
