# 第1章：你好，C++的并发世界

## 章节概述

本章是并发编程的入门章，回答"什么是并发"、"为什么要学并发"以及"C++ 如何支持并发"这三个核心问题。不会涉及太多代码细节，重点建立对并发世界的整体认知。

---

## 1. 本章核心问题

### 什么是并发？

**并发**（Concurrency）是指一个系统能同时处理多个任务。注意"同时处理"不等于"同时执行"（那是并行）。C++ 标准委员会的定义更精确：**并发意味着多个线程同时活跃且可能同时取得进展**。

### 为什么需要并发编程？

1. **关注点分离**（Separation of Concerns）：比如 GUI 程序，主线程负责渲染界面，后台线程负责下载文件。两者互不阻塞。
2. **性能**：单核时代靠任务切换不让 CPU 闲着；多核时代靠真正并行提升吞吐量。
3. **自然的业务建模**：很多业务本身就是并发的，比如游戏里多个 NPC 在同时行动。

### C++ 如何支持并发？

在 C++11 之前，C++ 标准对并发只字未提。多线程全靠平台 API（pthread、Win32 Thread）。C++11 引入了完整的并发标准库：`std::thread`、`std::mutex`、`std::future` 等，让跨平台并发编程成为可能。

## 2. 知识点总览

```
并发概念
├── 任务切换（Concurrency）vs 真正并行（Parallelism）
├── 多进程（Multi-process）vs 多线程（Multi-thread）
├── C++ 并发标准历史（C++11 → C++14 → C++17 → C++20）
└── 第一个多线程 Hello World
```

| 概念 | 解释 |
|------|------|
| 任务切换 | 单核 CPU 快速来回切换多个任务，让人感觉"同时执行" |
| 真正并行 | 多核 CPU 各自独立执行不同任务，物理上同时进行 |
| 多进程 | 每个进程有独立内存空间，通信靠 IPC，隔离性好但重量级 |
| 多线程 | 同一进程内共享地址空间，共享数据方便但容易出问题 |
| C++11 | 首次引入 `std::thread`、`std::mutex`、`std::condition_variable` |
| C++14 | 新增 `std::shared_lock` 等辅助类型 |
| C++17 | 引入并行 STL 算法（`std::execution::par`） |
| C++20 | 引入 `std::jthread`（自动 join）、协程 |

## 3. 通俗解释

### 并发 vs 并行——厨房类比

**单核并发（任务切换）**：
你一个人在家做饭，一会儿切菜、一会儿看锅、一会儿接电话。你不是同时做这些事，而是快速来回切换。邻居从窗外看，觉得你"同时"在做三件事。这就是**假的并行，真的并发**。

**多核并行**：
餐厅厨房里有三个厨师。甲切菜、乙炒菜、丙摆盘，三人完全同时工作。这就是**真正的并行**。

**多线程**就是在一个程序（进程）里分出多条执行流，它们共享同一片内存（就像三位厨师共享同一个厨房的操作台和食材）。好处是交流方便（共享内存），坏处是容易打架（数据竞争）。

## 4. 关键 API

### 创建并启动一个线程

```cpp
#include <iostream>
#include <thread>

void hello() {
    std::cout << "Hello from thread: "
              << std::this_thread::get_id() << "\n";
}

int main() {
    std::thread t(hello);   // 创建线程，立即开始执行 hello()
    t.join();               // 主线程等待 t 执行完毕
    std::cout << "Hello from main\n";
    return 0;
}
```

### 用 Lambda 创建线程

```cpp
std::thread t([]() {
    std::cout << "Hello from lambda thread\n";
});
t.join();
```

### 线程 ID

```cpp
std::thread::id tid = t.get_id();              // 获取线程对象的 id
std::thread::id self = std::this_thread::get_id(); // 获取当前线程的 id
```

### 判断线程是否可 join

```cpp
if (t.joinable()) {
    t.join();   // 或 t.detach()
}
```

## 5. 常见坑点

### 坑1：忘记 join 或 detach，程序崩溃

```cpp
// ❌ 错误！线程对象析构时如果还 joinable，std::terminate() 会被调用
void bad() {
    std::thread t([]{ /* ... */ });
    // t.joinable() 为 true，析构时崩溃！
}

// ✅ 正确做法
void good() {
    std::thread t([]{ /* ... */ });
    t.join();  // 或 t.detach()
}
```

**记牢**：`std::thread` 对象在析构前必须 `join()` 或 `detach()`，这是 C++ 标准规定的，不是"建议"。

### 坑2：忘记处理异常

```cpp
void risky() {
    std::thread t(do_work);
    // 如果 do_more() 抛出异常，t.join() 永远不会被调用
    do_more();
    t.join();  // 可能跳过了！
}
```

解决方案：用 RAII 包装（第2章详细讲）。


## 8. 本章小结

- **并发** ≠ **并行**：并发是逻辑上同时进行（单核也能并发），并行是物理上同时执行（必须多核）。
- **多线程** 是 C++ 并发的核心手段，线程间共享地址空间，通信方便但风险高。
- C++11 是分水岭，之前用平台 API，之后用标准库。C++17/C++20 进一步增强了并发支持。
- 线程创建后必须 `join()` 或 `detach()`，忘记就是灾难。
- 多线程编程的难点在于**共享数据的保护**和**线程间同步**，这些将在后续章节深入。

## 9. 面试常问

**Q1: 并发和并行有什么区别？**

并发是逻辑概念，指多个任务可以独立推进（单核通过时间片切换实现）；并行是物理概念，指多个任务真正在同一时刻执行（需要多核）。并发是"看起来同时"，并行是"物理上同时"。

**Q2: 多进程和多线程的优缺点？**

| | 多进程 | 多线程 |
|---|---|---|
| 内存隔离 | 独立地址空间，安全 | 共享地址空间，容易数据竞争 |
| 通信方式 | IPC（管道、共享内存、socket） | 直接读写共享变量 |
| 创建开销 | 大（fork/exec） | 小 |
| 崩溃影响 | 一个进程崩溃不影响其他 | 一个线程崩溃可能拖垮整个进程 |

**Q3: C++11 之前怎么做多线程？**

POSIX 平台用 pthread，Windows 用 Win32 Thread API，都需要手动管理线程句柄，且不跨平台。Boost.Thread 在那时是事实标准。
