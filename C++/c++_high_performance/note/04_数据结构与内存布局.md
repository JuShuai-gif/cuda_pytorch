## 1. 本章解决什么问题

- 计算机内存有哪些性质（缓存层次、局部性），为什么影响数据结构选择？
- 顺序容器（array/vector/deque/list/forward_list/basic_string）各自适用场景？
- 关联容器（树 vs 哈希表）的复杂度与实际表现有何差异？
- 哈希质量与 load_factor 如何影响性能？
- `priority_queue` 如何用 O(n log m) 实现"只取前 m 个"？
- 并行数组（SoA）比 AoS 快多少？代价是什么？

一句话：**数据结构的内存布局决定了遍历与访问的缓存行为，其影响常超过渐近复杂度。**

## 4. 核心概念

| 术语 | 含义 |
|---|---|
| **缓存层次** | L1/L2/L3/主存，相邻层级延迟差约一个数量级 |
| **缓存行（cache line）** | 一次读取的最小单位（通常 64 字节） |
| **时间局部性** | 刚访问过的数据很可能再次访问 |
| **空间局部性** | 相邻地址的数据很可能一起访问 |
| **Cache thrashing** | 内层循环反复刷掉缓存行，性能骤降 |
| **顺序容器** | 按添加顺序排列：array/vector/deque/list/forward_list/string |
| **关联容器** | 按元素本身组织：树（O(log n)）/ 哈希表（O(1)） |
| **分离链接** | 哈希冲突用桶内链表解决 |
| **load_factor** | 元素数/桶数，超 max_load_factor 触发 rehash |
| **并行数组（SoA）** | 把对象字段拆成同索引的多个数组 |
| **AoS** | Array of Structures：完整对象连续排列 |

## 5. 工作原理

### 5.1 缓存层次与局部性

> 来源：PDF 第 104～107 页
> 原始小节：Properties of computer memory

内存按字节寻址 O(1)，但实际读取按 **缓存行**（64 字节）进行。相邻层级延迟：
L1 ~0.5ns、L2 ~7ns、主存 ~100ns（书中引用 Jeff Dean 的 Latency Numbers）。

两种局部性决定缓存命中率：
- 时间局部性：复用刚读过的数据；
- 空间局部性：访问相邻数据（一次取回整行）。

**cache thrashing 实验**（本实验实测）：8192² 矩阵行主序 ~33ms，列主序 ~180ms
（5.4 倍）。列主序每次跨行访问，内层循环反复清空缓存行。

### 5.2 顺序容器

> 来源：PDF 第 108～112 页
> 原始小节：Sequence containers

| 容器 | 布局 | 关键复杂度 | 备注 |
|---|---|---|---|
| `std::array` | 栈连续 | 固定大小 | 类型含大小 |
| `std::vector` | 堆连续 | 尾 O(1) 均摊 | 默认首选 |
| `std::deque` | 分块 | 头尾 O(1) | 非全连续 |
| `std::list` | 双链 | 有迭代器时 O(1) 插入 | 遍历缓存差 |
| `std::forward_list` | 单链 | 同上 | 省内存 |
| `std::basic_string` | 连续(C++17+) | SSO | 可传 C API |

本实验实测（200 万元素遍历）：vector ~182µs、deque ~486µs、
forward_list ~3.6ms、list ~3.7ms——链表慢约 20 倍（节点分散）。

### 5.3 关联容器与哈希

> 来源：PDF 第 112～117 页
> 原始小节：Associative containers / Hash and equals / Hash policy

- 树：自平衡二叉搜索树，O(log n)；要求 `<`；
- 哈希表：桶数组 + 分离链接，平均 O(1)；要求 `==` + 哈希函数。

本实验实测（100 万键查找）：`map` ~15ms、`unordered_map` ~1.7ms（约 9 倍）。

**哈希质量**：坏哈希把所有键塞进一个桶，查找退化为 O(n)。本实验实测
坏/好哈希查找差 **~47500 倍**。自定义哈希应包含所有判等字段且分布均匀。

**load_factor**：超过 `max_load_factor`（默认 1.0）触发 rehash（桶翻倍）。
`reserve()`/`rehash()` 可预分配桶数。

### 5.4 priority_queue 与部分排序

> 来源：PDF 第 117～120 页
> 原始小节：Container adaptors / Priority queues

"文档搜索返回前 10 个最高分命中"的三种方案：
- `std::sort`：O(n log n)；
- `std::partial_sort`：O(n log m)，需随机访问迭代器；
- `std::priority_queue` 最小堆：O(n log m)，只需前向迭代器，内存 O(m)。

### 5.5 并行数组（SoA）

> 来源：PDF 第 120～127 页
> 原始小节：Parallel arrays

遍历只访问部分字段时，对象越小越快。书中 User 从 128→40 字节（快 2 倍），
再用并行数组（只存所需字段）进一步到 0.7ms（11 倍于原版）。

本实验实测（1M 用户数 level）：BigUser 5.5ms → SmallUser 4.2ms →
`vector<short>` 0.25ms（**22 倍**）；playing 用 `vector<bool>` 0.77ms。

**书中警告（PDF 127 页）**：并行数组破坏封装、索引同步易错、多字段算法反而
更慢；**不要在没有真实性能问题前使用，先采用良好设计**。

## 7. 简单示例

```cpp
// 并行数组：遍历只需要 level 字段（书中 p.126）
auto num_users_at_level(int level, const std::vector<int>& levels) {
    return std::count(levels.begin(), levels.end(), level);
}
```

## 8. 未优化版本

- `BigUser` 全字段内联 + 遍历全部（`aos_vs_soa` baseline）；
- 列主序矩阵访问（`cache_thrashing`）；
- 坏哈希的 `unordered_map`（`hash_policy`）。

## 9. 优化版本

- 缩小对象 / 拆字段（`SmallUser`）；
- 并行数组 SoA（`vector<short>` + `vector<bool>`）；
- 行主序访问、好哈希、`reserve`。

## 10. 为什么可能更快（逐维度分析）

| 维度 | 分析 |
|---|---|
| 时间复杂度 | 树 O(log n) vs 哈希 O(1)（100 万键实测 9 倍）；priority_queue O(n log m) |
| 空间复杂度 | vector<bool> 位数组 1/8 内存；forward_list 单指针 |
| 动态内存分配 | list 每节点分配；vector 连续一次分配 |
| Cache Locality | **本章核心**：连续 vs 分散（实测 20 倍） |
| 对象复制和移动 | vector 扩容搬移（Chapter 3） |
| 分支 | 哈希均匀分布减少桶内线性扫描 |

## 11. 该优化什么时候可能无效

- **数据量小**：小集合上树 vs 哈希差异可忽略；
- **对象小**：对象本身小于缓存行时 AoS vs SoA 差异缩小；
- **多字段访问**：SoA 需同时取多字段时反而更慢（书中明确警告）；
- **增加复杂度**：SoA 破坏封装、索引同步易错；
- **依赖平台**：缓存大小/预取器不同，数字因机器而异；
- **编译器已优化**：`-O3` 可能自动向量化某些连续访问；
- **额外内存开销**：reserve 预分配浪费内存换性能。

## 13. 汇编观察点

- 连续遍历 → 自动向量化（`movdqu` 等）；
- 链表遍历 → 每元素 `mov` 加指针解引用，无法向量化；
- `vector<bool>` count → 位运算（`popcnt`/位块处理）；
- 哈希查找 → 哈希计算 + 取模 + 内存访问（非内联函数较多）。

## 14. 常见错误

- **认为 vector 永远比 list 快**：只在遍历/随机访问场景成立，插入频繁时
  链表可能更优（取决于迭代器位置）；
- **用坏哈希**：分布不均使 unordered_map 退化为 O(n)；
- **哈希字段与判等字段不一致**：等值对象哈希不同 → 找不到；
- **忘记 reserve**：大量插入反复 rehash（Chapter 3）；
- **盲目用 SoA**：破坏封装、索引错位、多字段场景更慢；
- **把 vector<bool> 当普通 vector**：代理引用陷阱；
- **忽略缓存访问顺序**：列主序矩阵慢 5 倍以上。

2. **简单**：给 `unordered_map` 用 `reserve(100000)` 后再插入 10 万键，
   对比 rehash 次数（可打印 bucket_count 变化）；
3. **中等**：为自定义类型（如 `std::pair<std::string,int>`）写哈希函数，

## 17. 本章总结

- **缓存局部性是现代 CPU 上最大的性能杠杆**：连续内存遍历比分散快一个量级；
- 顺序容器默认选 `vector`，需要头尾插入选 `deque`，需要稳定引用且频繁
  插入才考虑 `list`；
- 关联容器：有序遍历用树，纯键查找用哈希表；哈希质量决定哈希表上限；
- `priority_queue` 是"部分排序"的高效工具（O(n log m)）；
- 并行数组（SoA）加速明显但有封装与同步代价，遇到真实问题再考虑；
- 一切以实测为准：本环境数据见 `benchmark_results/chapter04/`。
