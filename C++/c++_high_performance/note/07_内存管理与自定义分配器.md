## 4. 核心概念

| 术语 | 含义 |
|---|---|
| **虚拟地址空间** | 进程独立的内存视图，由 MMU 映射到物理内存 |
| **内存页 / 页错误** | 固定大小内存块；未映射访问触发 page fault（从磁盘加载） |
| **Thrashing** | 内存不足导致频繁换页，系统几乎停滞 |
| **栈** | 连续、固定上限、每线程独立、永不碎片、分配只移栈指针 |
| **堆（free store）** | 全局共享、任意分配/释放、易碎片化 |
| **placement new** | 在已分配内存上构造对象（分离分配与构造） |
| **对齐（alignment）** | 对象地址必须是 alignof(T) 的倍数 |
| **padding** | 编译器为满足对齐插入的不可见字节 |
| **所有权** | 资源（内存/连接/句柄）由谁负责释放 |
| **SSO（SBO）** | 短字符串/小对象内联在对象里，免堆分配 |
| **Arena** | 固定缓冲 + 分配策略（bump allocator） |
| **自定义 STL 分配器** | 供容器使用的内存源（如栈上 arena） |

## 5. 工作原理

### 5.1 虚拟内存与栈堆

> 来源：PDF 第 175～182 页
> 原始小节：Computer memory / Process memory

- 虚拟内存让进程以为独占全部内存；MMU 映射虚拟→物理；
- 内存分页：未映射页访问 → page fault → 从磁盘加载（慢）；
- 内存不足 → 换出脏页（paging）→ 持续换页即 **thrashing**；
- **栈**：连续、固定上限（Linux 默认 ~8MB，`ulimit -s`）、每线程独立；
  分配/释放只移动栈指针 → 极快、不碎片化；
- **堆**：全局共享、任意顺序分配/释放 → 需并发处理、易碎片化。

### 5.2 new/delete 与生命周期

> 来源：PDF 第 182～185 页
> 原始小节：Creating and deleting objects

`new` 做两件事：分配内存 + 构造；`delete` 做：析构 + 释放。
**placement new** 把两者分开：在已分配内存上构造。没有 placement delete，
须显式 `p->~T()`（仅此情况合法）+ 释放。

C++17 `<memory>` 提供 `std::uninitialized_fill_n`/`std::destroy_at` 替代
placement new 与显式析构。

### 5.3 对齐与 padding

> 来源：PDF 第 186～189 页
> 原始小节：Memory alignment / Padding

- 每个类型有对齐要求（`alignof`）；未对齐访问低效甚至崩溃；
- `new`/`malloc` 保证返回 `max_align_t` 对齐内存（`alignof(max_align_t)=16`）；
- 编译器在成员间插入 padding 满足对齐；
- **成员重排（大的在前）可缩小结构体**：24B → 16B（本实验实测）。

### 5.4 智能指针与所有权

> 来源：PDF 第 190～196 页
> 原始小节：Memory ownership / Smart pointers

- `unique_ptr`：独占、move-only、零开销；
- `shared_ptr`：引用计数、计数原子更新（线程安全）、控制块开销；
- `weak_ptr`：不保持存活，`lock()` 提升；
- **`make_shared` 一次分配 vs `shared_ptr(new T)` 两次分配**（本实验实测
  1 vs 2 次），且前者异常安全。

### 5.5 SSO

> 来源：PDF 第 196～198 页
> 原始小节：Small size optimization

`std::string` 用 union 提供两种布局（短：内联缓冲；长：堆指针），用 flag 位
区分。本实验实测 libstdc++ SSO 边界 15 字符（≤15 零分配，16+ 一次分配）。
libc++ 是 22（书中的 24 字节 string）。

### 5.6 Arena 与自定义分配器

> 来源：PDF 第 199～208 页
> 原始小节：Custom memory management / A custom memory allocator

- **Arena**：`alignas(max_align_t) char buffer[N]` + bump 指针 `ptr_`；
  - `allocate`：对齐取整后检查剩余空间，够则 bump，不够回退 `::operator new`；
  - `deallocate`：仅回收栈顶块（栈语义），非栈顶忽略；非缓冲指针走
    `::operator delete`；
  - `reset()`：一次性回收全部；
  - 不可复制/移动。
- **ShortAlloc<T,N>**：有状态分配器，持 Arena 引用；容器用它取栈内存。
- 为什么容器默认不用类专属 operator new：`std::vector`/`make_shared` 用
  placement new 构造，需显式分配器参数。

## 7. 简单示例

```cpp
// Arena 最小用法（PDF p.200-203）
Arena<1024> arena;
auto* p = new (arena.allocate(sizeof(int))) int{42};  // 从 arena 分配+构造
p->~int();                                            // 仅 placement new 后可显式析构
arena.reset();                                        // 一次性回收
```

## 8. 未优化版本

- 大量小对象反复 `new`/`delete`（全局堆，锁开销+缓存miss）；
- `shared_ptr(new T)` 两次分配；
- 长字符串频繁构造（无 SSO 时）。

## 9. 优化版本

- 栈上 Arena + ShortAlloc 容器（`std::set`/`std::vector` 用栈内存）；
- `make_shared` 单次分配；
- 短字符串靠 SSO（零分配）。

## 10. 为什么可能更快（逐维度分析）

| 维度 | 分析 |
|---|---|
| 时间复杂度 | arena bump O(1)；malloc 需要元数据/空闲链表搜索 |
| 空间复杂度 | 成员重排省 padding；SSO 省 16 字符堆块 |
| 动态内存分配 | arena 消除每次对象分配；make_shared 合并两次为一次 |
| Cache Locality | arena 连续分配 → 空间局部性好；make_shared 对象+控制块相邻 |
| 锁竞争 | 单线程 arena 无锁；全局堆多线程需锁 |
| 生命周期 | arena reset 一次性回收（批量析构） |

## 11. 该优化什么时候可能无效

- **数据量大**：arena 放不下回退堆，收益消失；
- **分配模式杂乱**：arena 只回收栈顶，乱序 free 会浪费内存；
- **多线程**：无同步的 arena 有数据竞争（需每线程 arena 或加锁）；
- **编译器已优化**：SSO/小对象可能已被内联处理；
- **增加复杂度**：自定义分配器难写对（对齐/容量/生命周期），书中警告
  "先找现成库"（`boost::container::small_vector` 等）；
- **异常安全**：arena 构造对象失败需正确析构已构造部分；
- **依赖平台**：栈大小、SSO 边界因平台/库而异。

## 13. 汇编观察点

- `new`/`delete` → `call malloc/free`（或 `operator new`）；
- arena `allocate` → 内联的地址计算+比较（无外部调用，除非回退）；
- 短字符串 → 无 `call` 分配；长字符串 → `call operator new`；
- `std::string` SSO 判断 → `test`+分支（flag 位）。

## 14. 常见错误

- 手写 `delete` 而非 RAII/智能指针；
- 对 placement new 对象 `delete p`（应显式析构+释放）；
- 大对象/大数组放栈上 → 栈溢出崩溃（本实验 8MB arena 曾踩坑）；
- 忽略对齐：自定义分配器返回未对齐内存 → UB/崩溃；
- `make_shared` vs `shared_ptr(new T)`：后者两次分配且异常不安全；
- arena 生命周期短于使用它的容器 → 悬垂；
- arena 非栈顶释放被静默忽略 → 内存增长不可见。

## 15. 实践练习

1. **简单**：把 `alignment_padding` 的 `DocumentV1` 改成更多成员组合
   （char/bool/int/double），观察 sizeof 变化并验证"大的在前"原则；
2. **简单**：测 `small_string` 在 libstdc++ 的精确 SSO 边界（15），并比较
   空串/单字符是否也零分配；
3. **中等**：用 Arena 实现一个固定大小对象池（如 `new/delete` 1 万个
   8 字节对象的循环），对比全局堆的分配次数与耗时；
4. **中等**：给 `ShortAlloc` 接上 `std::pmr::memory_resource`（C++17
   `<memory_resource>`），观察与手写 arena 的等价性；
5. **困难**：实现一个支持**任意顺序释放**的空闲链表分配器（free list），
   对比 bump-only arena 在乱序 free 下的内存利用率，说明何时需要后者。

## 17. 本章总结

- 栈快但不持久，堆灵活但有分配/碎片/并发成本；
- 用 RAII/智能指针表达所有权，避免手写 `new`/`delete`；
- 理解对齐与 padding：重排成员免费省内存，自定义分配器必须保证对齐；
- SSO 让短字符串零堆分配；
- `make_shared` 单次分配且异常安全；
- 自定义分配器（Arena）在小对象/短生命周期/单线程场景可显著提速，
  但复杂度高，先分析模式再决定（书中明确建议先找现成库）；
- 一切以实测为准：本环境数据见 `benchmark_results/chapter07/`。
