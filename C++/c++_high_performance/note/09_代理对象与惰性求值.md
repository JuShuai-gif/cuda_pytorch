## 1. 本章解决什么问题

- 惰性求值（lazy）与急切求值（eager）有何区别？何时该延迟操作？
- 代理对象（proxy object）如何把优化藏进库内部、同时保持用户语法不变？
- 字符串拼接 `(a + b) == c` 为何构造临时对象？代理对象如何省掉它？
- 比较两点距离时，`std::sqrt()` 可不可以不执行？`DistProxy` 如何做到？
- `&&`（r-value 限定）如何防止代理对象被误用（悬垂引用、重复求值）？
- 管道运算符 `numbers | contains(x)` 与中缀运算符 `x <in> range` 如何用代理实现？

一句话：**用隐藏在库内部的代理对象延迟求值，让"干净的语法"与"底层的优化"兼得。**

## 4. 核心概念

| 术语 | 含义 |
|---|---|
| **惰性求值（lazy evaluation）** | 推迟操作，直到其结果真正被需要 |
| **急切求值（eager evaluation）** | 立即执行操作（C++ 默认行为） |
| **代理对象（proxy object）** | 库内部的隐藏临时对象，收集表达式数据、延迟并优化运算 |
| **`ConcatProxy`** | 持有两个 `const std::string&`，比较时直接比对而非拼接 |
| **r-value 限定 `&&`** | 成员函数只在临时对象上可调用，防误用 |
| **`operator T() const &&`** | 只允许临时代理隐式转换为结果类型 |
| **`DistProxy`** | 持有平方距离，比较用 `dist*dist`，仅在需要时 `sqrt` |
| **`ContainsProxy`** | 管道运算符右操作数代理：`numbers \| contains(x)` |
| **`InProxy` / `InTag` / `in`** | 中缀运算符 `x <in> range` 的实现机制 |

## 5. 工作原理

### 5.1 惰性 vs 急切

> 来源：PDF 第 259 页
> 原始小节：Lazy versus eager evaluation

急切求值在参数传入时立即执行，即使结果未被使用也会付出代价：

```cpp
// get_eager：无论 map 是否命中，"otherwise" 已先构造
audio = library.get_eager("red_fox", load_audio("default_fox.wav"));
// get_lazy：传入一个函数，仅当未命中时才调用它
audio = library.get_lazy("red_fox", [] { return load_audio("default_fox.wav"); });
```

### 5.2 代理对象的一般模式

> 来源：PDF 第 260 页
> 原始小节：Proxy objects

代理对象在用户视野之外工作：

1. `operator+` 等运算符**不直接计算结果**，而是返回一个持有操作数的代理；
2. 代理在**最终运算符**（如 `==`、`<`、隐式转换）被触发时才真正计算；
3. 计算前代理有机会合并/简化运算（去掉临时对象、去掉昂贵的 `sqrt`）。

### 5.3 ConcatProxy：字符串比较

> 来源：PDF 第 261～264 页
> 原始小节：Comparing concatenated strings using a proxy

朴素写法 `(a + b) == c` 会分配一个临时拼接字符串。代理写法：

- `operator+(const String&, const String&)` 返回 `ConcatProxy{a, b}`（只存引用）；
- `operator==(ConcatProxy&&, const String&)` 里用 `is_concat_equal`
  直接两段比对：`a.size()+b.size()==c.size()` + 两次 `std::equal`；
- 语法不变：`(a + b) == c`；性能提升 10.7x（去掉临时分配）。

### 5.4 r-value 限定与赋值

> 来源：PDF 第 264～265 页
> 原始小节：The r-value modifier / Assigning a concatenated proxy

- `operator==` 只接收 `ConcatProxy&&`：把代理存成变量再比较会编译失败，
  避免临时字符串析构后引用悬垂；
- 需要把拼接结果存成字符串时，提供 `operator String() const &&`
  隐式转换；注意 `auto c = a + b` 得到的是 `ConcatProxy`，必须显式写 `String c = ...`。

### 5.5 DistProxy：推迟 sqrt

> 来源：PDF 第 265～273 页
> 原始小节：Postponing an sqrt computation when comparing distances

- `distance()` 不再返回 `float`，而是返回持有**平方距离**的 `DistProxy`；
- `operator<(float dist)` 用 `dist_sqrd_ < dist * dist`，不调用 `sqrt`；
- `operator<(const DistProxy&)` 直接比平方距离；
- 隐式 `operator float() const &&` 才真正 `sqrt`，且限定临时对象，
  防止同一代理多次触发 sqrt（低效）或被误用（平方距离混入普通距离）；
- 用户语法不变：`a.distance(bingo) < b.distance(bingo)`，最近点搜索实测 2x。

### 5.6 创造性运算符重载

> 来源：PDF 第 274～277 页
> 原始小节：The pipe operator as an extension method / The infix operator

**管道运算符**模拟扩展方法：`numbers | contains(seven)`

```cpp
template <typename T> struct ContainsProxy { const T& value_; };
template <typename Range, typename T>
auto operator|(const Range& r, const ContainsProxy<T>& p) {
    return std::find(r.begin(), r.end(), p.value_) != r.end();
}
template <typename T> auto contains(const T& v) { return ContainsProxy<T>{v}; }
```

**中缀运算符**模拟 Python 的 `in`：`"Botswana" <in> africa`

```cpp
template <typename T> struct InProxy { const T& val_; };
struct InTag {};
constexpr static auto in = InTag{};
template <typename T> auto operator<(const T& v, const InTag&) { return InProxy<T>{v}; }
template <typename T, typename Range>
auto operator>(const InProxy<T>& p, const Range& r) {
    return std::find(r.begin(), r.end(), p.val_) != r.end();
}
```

## 7. 简单示例

```cpp
// DistProxy 核心：比较时只比平方距离（PDF p.267-268）
class DistProxy {
public:
    DistProxy(float x0, float y0, float x1, float y1)
        : dist_sqrd_{std::pow(x0 - x1, 2) + std::pow(y0 - y1, 2)} {}
    auto operator<(float dist) const { return dist_sqrd_ < dist * dist; }
    operator float() const && { return std::sqrt(dist_sqrd_); }
private:
    float dist_sqrd_{};
};
```

## 8. 未优化版本

- `(a + b) == c`：每次比较构造临时字符串（堆分配 + 拷贝）；
- `distance()` 立即 `sqrt`：即使只比较大小，仍付平方根成本；
- 急切 `get_eager(id, value)`：未命中路径之外也预先构造参数；
- 手写 `is_near0`/`is_near1` 两套函数：要么语法好、要么性能好。

## 9. 优化版本

- `ConcatProxy`：比较免临时字符串（书中 10.7x；本机实测 5.2x）；
- `DistProxy`：比较免 sqrt（书中 2x；本机实测 1.14x——现代 x86 的
  `sqrtss` 是单条指令，收益远小于 2017 年硬件），需要真距离时才 `sqrt`；
- `get_lazy(id, fn)`：仅未命中时调用函数；
- 代理对象让 `is_near0` 的语法拿到 `is_near1` 的性能。

## 10. 为什么可能更快（逐维度分析）

| 维度 | 分析 |
|---|---|
| 时间复杂度 | 比较距离 O(1) 内省掉 sqrt；字符串比较免一次拼接+分配 |
| 空间复杂度 | ConcatProxy 只存引用，无临时字符串 |
| 动态内存分配 | 拼接临时对象被消除（主要收益来源） |
| 对象复制和移动 | `operator String() const &&` 在临时对象上移动/拼接 |
| Cache Locality | — |
| 函数调用和内联 | 模板代理全内联；sqrt 仅按需调用 |
| 编译期计算 | — |
| SIMD / 并行 | 无直接关系 |

## 11. 该优化什么时候可能无效

- **代理被存成变量**：`auto concat = a + b;` 后引用悬垂（`&&` 限编译失败）；
- **重复转换**：`float f0 = dist; float f1 = dist;` 触发两次 sqrt（`&&` 禁掉）；
- **拼接结果确实要存**：最终仍需分配一次临时字符串（但只需一次）；
- **字符串很短**：分配器开销占比小，收益随规模增长；
- **CPU 已有硬件 sqrt**：现代 x86 的 `sqrtss` 单指令实现使 DistProxy 收益
  大幅缩水（本机仅 1.14x，书中 2017 硬件为 2x）；
- **滥用运算符重载**：管道/中缀是可读性双刃剑，生产代码慎用（书中明确警告）。

## 13. 汇编观察点

- 是否内联：代理的 `operator==`/`operator<` 在 `-O2` 全部内联；
- 是否消除调用：`DistProxy` 比较路径不应出现 `sqrt` 的 `call`；
- 是否分配：`ConcatProxy` 比较路径不应出现 `operator new`。

## 14. 常见错误

- 代理存 `const&` 而临时字符串先析构 → 悬垂引用（用 `&&` 限定防编译）；
- `auto dist = a.distance(b);` 得到代理而非数值 → 需要时显式 `float`；
- 忘写 `const &&` 上的 `const` → 无法在临时对象上调用；
- 平方距离与真实距离混用 → `operator<(float)` 自动处理，但暴露 `dist_sqrd_`
  会制造 bug（书中强调不暴露）；
- 管道/中缀运算符全局重载污染命名空间 → 只在必要场景使用。

## 17. 本章总结

- 惰性求值推迟操作到结果真正被需要；急切求值可能白付代价；
- 代理对象在库内部隐藏优化：收集表达式、延迟计算、保持用户语法；
- `ConcatProxy` 免临时字符串（书中 10.7x，本机实测 5.2x）；
- `DistProxy` 免 sqrt（书中 2x，本机实测 1.14x，收益依赖硬件）；
- r-value 限定 `&&` 是代理安全护栏：防悬垂、防重复求值、防类型混用；
- 管道/中缀运算符展示代理 + 运算符重载的创造力，但滥用伤可读性；
- 代理的代价：`auto` 拿不到真实结果类型、需要隐式转换或显式转换。
