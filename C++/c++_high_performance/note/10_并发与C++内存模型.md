- 并发性能指南：争用、线程数、优先级、亲和性、伪共享（false sharing）如何影响性能？

一句话：**用线程 + 同步原语写出无数据竞争、无死锁的并发程序，并理解其性能代价。**

## 4. 核心概念

| 术语 | 含义 |
|---|---|
| **并发（concurrency）** | 多个控制流在重叠时间段内运行（不一定同时） |
| **并行（parallelism）** | 多个控制流真正同时执行（需要多核） |
| **时间片 / 上下文切换** | 单核上 OS 轮流调度线程；切换代价高（缓存缺失） |
| **数据竞争（data race）** | 两线程同时访问同一内存且至少一个在写 → **未定义行为** |
| **临界区（critical section）** | 必须串行执行的、访问共享可变数据的代码段 |
| **互斥锁（mutex）** | 保证同时只有一线程进入临界区的同步原语 |
| **争用（contention）** | 线程被锁阻塞等待；降低可扩展性 |
| **死锁（deadlock）** | 两线程互相等待对方持有的锁，均无法推进 |
| **条件变量（condition_variable）** | 让线程等待某条件成立 / 通知条件变化 |
| **promise / future** | 值的写端 / 读端，可跨线程传结果与异常 |
| **packaged_task** | 自动包装 promise 的可调用对象 |
| **std::async** | 最小并发的任务式 API（推荐） |
| **原子类型（atomic）** | 无数据竞争的共享变量；可能内部用锁（is_lock_free） |
| **顺序一致性（SC）** | 默认内存序：执行结果如同按程序顺序交错 |
| **acquire / release 围栏** | 互斥锁在临界区边界建立的一向内存围栏 |
| **无锁队列** | 单读单写、固定容量，仅 size_ 是原子 |
| **伪共享（false sharing）** | 两线程各自更新同缓存行的不同数据，互相失效缓存 |

## 5. 工作原理

### 5.1 数据竞争与两种解决方案

> 来源：PDF 第 284～285 页
> 原始小节：Data races

`++counter` 是读-改-写多指令序列；两线程交错时可能丢失更新（42+1+1 却得 43）。
数据竞争 = 未定义行为。两种避免手段：

1. **原子类型**：`std::atomic<int> counter; ++counter;`（当大小 ≤ 机器字长时通常无锁）；
2. **互斥锁**：临界区包 `lock_guard`，同时保证只一线程进入。

不可变对象天然无线程安全问题；常用"创建新对象再原子 swap"缩小临界区。

### 5.2 死锁与 std::lock

> 来源：PDF 第 287、294～295 页
> 原始小节：Deadlock / Avoiding deadlocks

一个线程持有一把锁还去取另一把锁时可能死锁。转账例子中
`from`/`to` 两个账户各有一把锁，两线程以相反顺序加锁 → 互相等待。
用 `std::unique_lock + defer_lock` 构造两个未加锁的 RAII 对象，再
`std::lock(lock1, lock2)` **同时**获取，避免顺序竞争。

### 5.3 条件变量：生产者-消费者

> 来源：PDF 第 296～298 页
> 原始小节：Condition variables

- 消费者：`unique_lock` 锁住互斥量后 `cv.wait(lock)`——**睡眠时释放锁**，
  唤醒返回前重新获锁；用 `while` 而非 `if` 包裹等待（应对 spurious wakeup）；
- 生产者：锁内 push 队列，锁外 `cv.notify_one()`（不必持有锁通知）；
- `done` 哨兵值通知消费者结束。

### 5.4 promise/future 与任务抽象

> 来源：PDF 第 298～300 页
> 原始小节：Returning data / Tasks

- **promise/future**：`promise.set_value(v)` / `promise.set_exception(e)`，
  另一线程 `future.get()`（未就绪则阻塞）可拿到值或异常——无需共享全局与显式锁；
- **packaged_task**：自动设置 promise，函数写回普通签名即可；
- **std::async**：一行完成，由库决定是否开线程（任务式 > 线程式，推荐）。

### 5.5 原子类型与 shared_ptr

> 来源：PDF 第 300～304 页
> 原始小节：Atomic support / Using shared_ptr

- `std::atomic<T>`：所有成员函数多线程安全；`is_lock_free()` 可查询是否无锁；
- `atomic<T>` 要求 T 平凡可复制（`atomic<string>` 编译错误）；
- `shared_ptr`：**控制块（引用计数）线程安全**（内部原子计数器）；
  **被指向的对象不线程安全**，需自行加锁；同一 `shared_ptr` 对象被多线程
  读写要用 `std::atomic_load/atomic_store`。

### 5.6 内存模型

> 来源：PDF 第 305～308 页
> 原始小节：C++ memory model / Atomics and memory orders

- 编译器和硬件会重排指令，只要单线程下不可观察；
- 多线程共享变量时，我们必须用原子/锁告知编译器哪些重排不允许；
- 互斥锁在临界区边界建立 acquire/release 围栏：任何读写不得越过围栏
  （acquire 上方不许越过，release 下方不许越过）——从而保证临界区数据不逃逸；
- 无数据竞争 + 默认内存序 = **顺序一致性**：结果如同各线程指令按程序序交错；
- 弱内存序（relaxed）只防撕裂写、不保证顺序，书建议除非精通否则别用。

### 5.7 无锁队列

> 来源：PDF 第 309～311 页
> 原始小节：Lock-free queue example

固定容量环形缓冲 + 单读单写：
- `read_pos_` 仅读线程用、`write_pos_` 仅写线程用，都无需原子；
- 只有 `size_` 是 `std::atomic<size_t>`（`fetch_add`/`fetch_sub`）；
- 算法保证读写线程永不并发访问同一数组元素 → 无数据竞争；
- 适用场景：实时音频线程不能阻塞、不能加锁、不能分配内存。

### 5.8 性能指南

> 来源：PDF 第 311～315 页
> 原始小节：Performance guidelines

- **避免争用**：锁/原子会禁用编译器与硬件优化；缩短、少进临界区；
- **避免阻塞**：UI 主线程超过 16ms 即掉帧，长 I/O 必须异步化；
- **线程数**：CPU 密集任务线程数 ≈ 核数即可，过多线程上下文切换反噬；
  I/O 密集可更多线程；用线程池控制总线程数；
- **优先级**：C++ 无标准 API，用 `native_handle()` 走系统调用；
  警惕**优先级反转**（高优先级等低优先级持有的锁），实时线程不能加锁/分配；
- **亲和性**：让共享数据的线程跑同核以暖缓存（`pthread_setaffinity`，不可移植）；
- **伪共享**：相邻元素同缓存行、各自更新导致互相失效。
  C++17 用 `alignas(std::hardware_destructive_interference_size)` 对齐到独立缓存行。

## 7. 简单示例

```cpp
// 生产者-消费者核心（PDF p.296-297）
std::condition_variable cv;
std::queue<int> q;
std::mutex mtx;

void consumer() {
    auto lock = std::unique_lock<std::mutex>{mtx};
    while (q.empty()) {
        cv.wait(lock);  // 睡眠时释放锁，唤醒前重新获锁
    }
    const auto v = q.front();
    q.pop();
    // 处理 v ...
}
```

## 8. 未优化版本

- 无保护共享 counter：数据竞争，结果不确定（未定义行为）；
- 两线程按相反顺序手动加锁：死锁；
- 用共享全局 + 显式锁返回结果：难维护、无错误传递；
- 多个线程各写数组相邻元素：伪共享，缓存互相失效；
- 线程数 = 任务数：线程创建/切换开销大。

## 9. 优化版本

- `mutex`/`atomic` 保护共享数据：正确且可预期；
- `std::lock` 同时取多把锁：消除死锁风险；
- 条件变量：消费者睡眠不占 CPU，唤醒才消费；
- promise/future + async：无全局、无显式锁、可传异常；
- 无锁队列：单读单写零锁，适合实时线程；
- `alignas(hardware_destructive_interference_size)`：消除伪共享；
- 线程池 + 线程数 ≈ 核数：控制总线程数。

## 10. 为什么可能更快（逐维度分析）

| 维度 | 分析 |
|---|---|
| 时间复杂度 | 并行任务理论加速比 ≈ 核数；但锁/原子引入串行化 |
| 空间复杂度 | 伪共享浪费缓存带宽；padding 用空间换速度 |
| 动态内存分配 | 实时线程禁止分配；无锁队列固定容量避免分配 |
| 对象复制和移动 | — |
| Cache Locality | 亲和性让共享数据线程同核暖缓存；padding 隔离缓存行 |
| 函数调用和内联 | — |
| 编译期计算 | — |
| SIMD / 并行 | 多核并行是本章核心收益；锁与原子会禁用部分优化 |

## 11. 该优化什么时候可能无效

- **争用过高**：临界区长/频繁，并行化可能比单线程更慢（书中明确警告）；
- **线程数超过核数（CPU 密集）**：上下文切换开销反超收益；
- **任务本身串行依赖**：无法并行，加线程徒增开销；
- **小任务**：线程创建/同步开销 > 计算量时无收益；
- **伪共享/亲和性依赖平台**：效果因 CPU 架构而异；
- **数据竞争快但错**：未定义行为，快而无用（书中强调"先正确再优化"）。

## 13. 汇编观察点

- 无锁循环：`fetch_add`/`fetch_sub` 编译为 `lock xadd` 等原子指令；
- mutex 临界区：lock/unlock 附近有 acquire/release 围栏（禁止重排）；
- 伪共享：无 padding 版本热点缓存行在两核间抖动，perf 可见高 cache-miss。

## 14. 常见错误

- 忘 `join`/`detach` 析构 `std::thread` → 程序 abort（`std::terminate`）；
- 共享可变数据不加锁 → 数据竞争（未定义行为）；
- 手动 lock/unlock 忘记解锁 → 用 `lock_guard`/`unique_lock`（RAII）；
- 多把锁按顺序加 → 死锁；用 `std::lock` 一次获取；
- `wait` 用 `if` 而不用 `while` → 无法应对 spurious wakeup；
- 认为 `shared_ptr` 让对象线程安全 → 只有引用计数安全，对象需自行同步；
- 多线程读写同一 `shared_ptr` 对象 → 需 `atomic_load/atomic_store`；
- 线程数开太多 → 上下文切换开销；CPU 密集 ≈ 核数即可；
- 共享相邻数组元素 → 伪共享；用缓存行对齐。

## 17. 本章总结

- 并发 ≠ 并行：并发是结构，并行需要多核；并发编程难在共享状态；
- 数据竞争是未定义行为；用 `mutex` 或 `atomic` 保护临界区；
- 死锁可被 `std::lock` 同时取锁避免；RAII（lock_guard）防忘解锁；
- 条件变量让等待线程休眠、事件驱动唤醒；
- 高层抽象（promise/future → packaged_task → async）减少锁与全局、可传异常；
- `shared_ptr` 控制块线程安全、对象不安全；`atomic` 需平凡可复制；
- 内存模型：默认顺序一致性 + acquire/release 围栏；弱序慎用；
- 无锁队列 = 单读单写 + 固定容量 + 唯一原子 size_；
- 性能：避免争用与阻塞、线程数 ≈ 核数、警惕优先级反转与伪共享；
- **先写对，再优化**——"快速但错误的并发程序"毫无价值。
