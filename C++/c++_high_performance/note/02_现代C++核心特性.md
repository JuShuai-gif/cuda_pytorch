## 4. 核心概念

| 术语 | 含义 |
|---|---|
| **`auto` 类型推导** | 编译器从初始化式推导变量/返回类型 |
| **转发引用 `auto&&`/`T&&`** | 模板上下文中能绑定任意左值/右值的引用，用于转发 |
| **lambda** | 内联匿名函数对象；捕获块 = 类成员变量 + 构造函数 |
| **捕获** | `[x]` 值捕获、`[&x]` 引用捕获、`[=]`/`[&]` 全部、`[c=expr]` 初始化 |
| **`mutable` lambda** | 允许修改值捕获的副本（默认 `operator() const`） |
| **`std::function`** | 类型擦除的可调用容器，任何同签名 callable 都可存 |
| **类型擦除（type erasure）** | 隐藏具体类型，仅保留调用接口 |
| **SBO（Small Buffer Optimization）** | `std::function`/`std::any` 内部小缓冲，小对象免堆分配 |
| **移动语义** | 把资源从源对象"偷"到目标，O(1)；源保持有效但未指定 |
| **r-value** | 不绑定名字的临时对象，或 `std::move()` 包裹的具名对象 |
| **Rule of Three/Five/Zero** | 资源管理类的特殊成员数量与必要性 |
| **`noexcept`** | 声明函数不抛异常；影响 STL 容器是否使用移动 |
| **空析构函数陷阱** | `~T(){}` 破坏 trivial copyability，抑制移动，阻止 `memmove` |
| **`std::optional<T>`** | 栈分配的"最多一个元素"容器 |
| **`std::any`** | 运行时任意类型的值（类型擦除） |

## 5. 工作原理

### 5.1 `auto` 与引用

> 来源：PDF 第 44～47 页
> 原始小节：Automatic type deduction with the auto keyword

- `auto`（值）：拷贝，剥掉引用与顶层 const；
- `const auto&`：const 引用，可绑定临时对象（生命周期延长）；**作者推荐默认用它**；
- `auto&`：可变引用，不可绑定临时；
- `auto&&`：转发引用，可绑定一切；仅用于转发给其他代码。

C++17 的复制消除保证 `auto x = Foo{};` 与 `Foo x{};` 等价（无临时对象）。

### 5.2 lambda 与类的等价性

> 来源：PDF 第 51～54 页
> 原始小节：Similarities between a Lambda and a class

```
auto is_above = [th](int v) { return v > th; };
// 等价于
class IsAbove {
 public:
  IsAbove(int th) : th_(th) {}
  auto operator()(int v) const { return v > th_; }
 private:
  int th_{};
};
```

每个 lambda 有唯一类型。`mutable` 去掉隐式 `const`。引用捕获的成员是引用成员。
`[=]` 只复制实际用到的变量。

### 5.3 `std::function` 的类型擦除

> 来源：PDF 第 56～59 页
> 原始小节：Lambdas and std::function / Performance consideration of std::function

`std::function<R(Args...)>` 是一个可赋值的对象，可持有任意签名匹配的 callable
（lambda、仿函数、函数指针）。运行时通过虚表/函数指针间接调用——这就是
**类型擦除**。作者列出的三个性能问题（PDF 59 页）：
1. **不能内联**；
2. **堆分配捕获变量**（除非捕获小于 SBO 阈值）；
3. **调用需更多操作**。

### 5.4 移动语义

> 来源：PDF 第 65～75 页
> 原始小节：Move semantics explained

三个关键操作：
- 复制构造：分配新资源 + 拷贝 → 慢；
- 交换：`std::swap` 互搬资源 → 中；
- 移动构造：`b = std::move(a)` 把 a 的资源指针给 b，a 置空 → O(1)。

编译器在源是 **r-value** 时使用移动（PDF 73 页）：函数返回值，或 `std::move()` 包裹。
具名非常量变量是 l-value → 复制；`const` 变量不可移动。

### 5.5 空析构函数陷阱

> 来源：PDF 第 77～78 页
> 原始小节：A note on empty destructors

```cpp
struct Point { int x, y; ~Point(){} };          // 手写空析构
struct Point2 { int x, y; ~Point2() = default; }; // 显式 default 析构
struct Point3 { int x, y; };                      // 无析构
```

- `Point`：用户提供析构函数 → 类型**非 trivially copyable**，且**抑制隐式移动**；
- `Point2`：仍非平凡可移动（用户声明了析构），但**是** trivially copyable；
- `Point3`：完全平凡。

`std::copy` 对 `Point3` 可优化为 `memmove`（一次内存移动），对 `Point` 只能
逐元素复制循环。**结论：用 `= default` 或干脆不声明析构，避免空 `{}` 析构。**

> 原理补充：trivially copyable 决定编译器能否把对象复制当作"字节搬移"。
> `std::is_trivially_copyable<T>` 为真时标准库可用 `memmove`/`memcpy` 实现
> `std::copy`。用户声明析构（哪怕 `= default`）会抑制隐式移动构造/赋值的生成，
> 但 `= default` 保持 trivial 性。因此规则是"能不放就放，要放就 `= default`"。

### 5.6 `std::optional` 与 `std::any`

> 来源：PDF 第 80～84 页
> 原始小节：Representing optional values / dynamic values with std::any

- `optional<T>`：栈上"最多一个 T"，开销 = 1 bool + padding；
  比较规则：空 < 非空，两空相等 → 排序时空值排最前；
- `any`：运行时任意类型，堆分配持有值（有 SBO），`any_cast<T>` 读取，
  类型不符抛 `bad_any_cast`。

## 7. 简单示例

```cpp
// 按值接收：l-value 复制，r-value 移动，一个函数覆盖两场景（PDF 75 页）
auto str_to_lower(std::string s) -> std::string {
    for (auto& c : s) c = static_cast<char>(std::tolower(c));
    return s;  // NRVO/移动
}
// 调用
auto a = str_to_lower(std::string{"ABC"});   // 移动
auto named = std::string{"ABC"};
auto b = str_to_lower(named);                 // 复制
```

## 8. 未优化版本

- `std::function` 保存回调（`callable_overhead`）：间接调用阻止内联；
- 捕获大对象进 `std::function`（`std_function_cost`）：堆分配；
- 非 `noexcept` 移动（`noexcept_move`）：容器扩容退化为复制；
- 复制大对象而非移动（`copy_vs_move`）：分配+拷贝。

## 9. 优化版本

- 模板参数/直接 lambda 替代 `std::function`（热路径）；
- 小捕获利用 SBO，避免堆分配；
- 移动构造/赋值标记 `noexcept`；
- 移动替代复制（偷指针）；
- Rule of Zero：RAII 成员，避免手写特殊成员。

## 10. 为什么可能更快（逐维度分析）

| 维度 | 分析 |
|---|---|
| 时间复杂度 | 移动 O(1) vs 复制 O(n)（`copy_vs_move` 实测 343x） |
| 空间复杂度 | `optional` +1 bool；`any` 16 字节 + 可能堆分配 |
| 动态内存分配 | `std::function` 大捕获堆分配；SBO 可避免 |
| 对象复制和移动 | 移动语义是本实验核心 |
| Cache Locality | 堆分配捕获导致缓存 miss（PDF 59 页提到） |
| 分支 | — |
| 函数调用和内联 | `std::function` 间接调用阻止内联（约 3 倍开销） |
| 类型擦除 | 类型擦除是 `std::function`/`any` 慢的本源 |
| 虚函数 | 同理：虚调用无法内联（本章未直接测） |
| 编译期计算 | lambda 模板化可在编译期实例化、内联 |
| SIMD / 并行 | — |

## 11. 该优化什么时候可能无效

- **调用不频繁**：低频回调里 `std::function` 的 3 倍开销无感；
- **编译器已优化**：`-O3` 下简单 lambda 循环可能被常量折叠（本实验已修正）；
- **捕获很小且 SBO 覆盖**：无堆分配，`std::function` 差距缩小；
- **移动只是拷贝**：无资源对象移动=复制，没有收益；
- **可维护性**：手写特殊成员（Rule of Three）易错，Rule of Zero 更省心；
- **依赖实现**：SBO 阈值随标准库不同（libstdc++ 16 字节）；
- **异常安全**：非 `noexcept` 移动被容器规避是安全机制，不是 bug；
- **大对象频繁移动**：移动本身便宜，但移动后的源对象生命周期管理要留意。

## 13. 汇编观察点

- `std::function` 调用 → 出现 `call *%rax`（间接调用），无法内联；
- trivial 类型的 `std::copy` → `jmp memmove`；空析构类型 → 逐元素 `mov` 循环；
- lambda/仿函数 → 内联为直接计算（`-O3` 甚至常量折叠）；
- `sizeof` 输出反映 SBO 边界。

## 14. 常见错误

- `std::move` 一个 const 对象：仍是复制（const 不可移动）；
- 对无资源对象用 `std::move`：无收益甚至阻碍优化（PDF 78 页）；
- 忘写 `noexcept` 移动：容器偷偷退化复制（本实验实测）；
- 手写空析构 `~T(){}`：破坏 trivial 性、抑制移动；
- lambda 引用捕获外部变量后 lambda 离开作用域：悬垂引用；
- 对 `std::function` 热路径高频调用：浪费 3 倍时间；
- `operator*` 访问空 `optional`：UB（应检查或 `value()`）；
- 把 `std::any` 当作高效动态类型：它堆分配且 `any_cast` 慢。

## 17. 本章总结

- `auto` 用于推导类型，但引用/值语义必须显式表达（默认 `const auto&`）；
- lambda 是"可内联的匿名函数对象"，捕获 = 成员；在热路径优先用 lambda/模板，
  而非 `std::function`；
- 移动语义是值语义高性能的关键：O(1) 偷资源，但必须 `noexcept`，源对象保持有效；
- 资源管理优先 Rule of Zero；必须手写时用 Rule of Five + `noexcept`；
- 空析构函数是隐蔽的性能陷阱：能不放就不放，要放就 `= default`；
- `optional` 表达"可能为空"（廉价、类型安全），`any` 表达"任意类型"（昂贵）；
- 一切性能结论以实测为准（本环境数据见 `benchmark_results/chapter02/`）。
