## 1. 本章解决什么问题

- 模板如何"生成代码"？非类型模板参数与 `static_assert` 如何利用编译期信息？
- type traits 如何回答类型问题、变换类型、条件启用函数（enable_if/SFINAE）？
- `is_detected` 如何检查类成员？
- `constexpr` 与 `if constexpr` 如何把计算移到编译期？如何验证真发生了编译期计算？
- `std::tuple`/`variant`/`any` 如何构建异构容器？如何编译期遍历 tuple？
- 反射（`reflect()`）、`safe_cast`、编译期字符串哈希如何实际应用？

一句话：**用模板 + 类型萃取 + constexpr 在编译期生成代码与计算，把运行期成本降到零。**

## 4. 核心概念

| 术语 | 含义 |
|---|---|
| **模板元编程** | 代码生成代码：编译器把模板实例化为常规 C++ 代码 |
| **非类型模板参数** | `template<int N>`：每个值生成独立函数 |
| **`static_assert`** | 编译期断言，失败即编译错误 |

## 5. 工作原理

### 5.1 模板生成代码与非类型参数

> 来源：PDF 第 210～214 页
> 原始小节：Introduction to template metaprogramming

模板为每种实例化生成一份常规函数/类。`pow_n<float>` 与 `pow_n<int>` 是
两个独立函数。**非类型模板参数** `template<int N>` 让每个 N 生成独立函数，
且 N 在编译期已知——可被 `static_assert` 检查，也可参与编译期计算。

### 5.2 type traits / decltype / enable_if

> 来源：PDF 第 214～219 页
> 原始小节：Type traits / decltype / enable_if_t

- 布尔 traits 以 `_v` 结尾（`is_same_v`）；类型变换以 `_t` 结尾
  （`remove_pointer_t`）；
- `decltype` 取类型，配合 `remove_reference_t` 处理引用参数；
- `enable_if_t<Cond, T>` 作为返回类型条件启用函数：条件不满足则函数
  不存在（SFINAE）。

### 5.3 is_detected

> 来源：PDF 第 219～221 页
> 原始小节：Introspecting class members with std::is_detected

`std::experimental::is_detected<has_member, T>::value` 检查 T 是否有该成员
（成员函数/变量/typedef）。与 enable_if 组合可为"拥有某能力的类型"自动
生成泛型函数（如 `print()` 按 `to_string()`/`name_` 分派）。

### 5.4 constexpr 与 if constexpr

> 来源：PDF 第 222～227 页
> 原始小节：The constexpr keyword / if constexpr

- `constexpr` 函数在输入为常量时编译期求值，否则运行期执行；
- `std::integral_constant<T, expr>` 要求 expr 是常量表达式 → 可证明编译期计算；
- **`if constexpr`**：与普通 `if` 不同，假分支的代码**根本不生成**。普通
  `if` 即使条件为 false 也会编译所有分支（若某分支不合法则编译失败）。

### 5.5 异构容器

> 来源：PDF 第 227～242 页
> 原始小节：Heterogeneous containers

- `tuple`：静态异构，`std::get` 访问，用 `if constexpr` 编译期遍历
  （`tuple_for_each`/`tuple_any_of`）；
- `vector<any>`：任意类型但运行期检查、可能堆分配；
- `vector<variant<...>>`：固定类型集、栈存储、`std::visit` + 多态 lambda。

### 5.6 实际应用三例

> 来源：PDF 第 242～257 页
> 原始小节：Real world examples of metaprogramming

1. **反射**：`reflect()` 返回 `std::tie` 成员元组，自动生成 `==`/`<`/`<<`；
   书中验证汇编与手写版一致（零开销）；
2. **safe_cast**：`if constexpr` 按转换种类分派，`make_false<T>()` 延迟断言；
3. **编译期哈希**：PrehashedString 编译期算哈希，汇编为 `mov $294`。

## 7. 简单示例

```cpp
// tuple_for_each：编译期展开（PDF p.230-231）
template <typename Tuple, typename F, std::size_t I = 0>
void tuple_for_each(const Tuple& t, F f) {
    if constexpr (I < std::tuple_size_v<Tuple>) {
        f(std::get<I>(t));
        tuple_for_each<Tuple, F, I + 1>(t, f);
    }
}
```

## 8. 未优化版本

- 手写 `operator==`/`<`/`<<`（反射消除的样板代码）；
- 运行期字符串哈希（PrehashedString 移到编译期）；
- 手写多份 `make_string` 重载（变参包替代）；
- 运行期 if 处理异构类型（`if constexpr` 替代）。

## 9. 优化版本

- 反射：`reflect()` + 泛型运算符自动生成；
- `safe_cast`：if constexpr 分派，Release 零运行期检查；
- PrehashedString：编译期哈希，查找零成本；
- tuple 算法：编译期展开（无运行期循环开销）。

## 10. 为什么可能更快（逐维度分析）

| 维度 | 分析 |
|---|---|
| 时间复杂度 | 编译期哈希省去每次查找的哈希计算；tuple_for_each 无运行期循环 |
| 空间复杂度 | `vector<variant>` 栈存储（无 any 的每元素堆分配） |
| 动态内存分配 | any 可能堆分配；variant 无 |
| 对象复制和移动 | — |
| Cache Locality | variant 紧凑连续；any 间接 |
| 函数调用和内联 | 模板实例化全部内联；if constexpr 消除死分支 |
| 编译期计算 | **本章核心**：哈希/常量在编译期算好 |
| SIMD / 并行 | 无直接关系 |

## 11. 该优化什么时候可能无效

- **编译时间**：大量模板实例化增加编译时间（编译期计算同理）；
- **数据量小**：小字符串哈希无感（书中明确承认是微优化）；
- **运行期输入**：constexpr 在运行期调用时退回运行期，无收益；
- **复杂度**：模板元编程可读性差，应隐藏在库接口后（PDF 210 页）；
- **依赖实现**：`is_detected` 是实验性 API；
- **可维护性**：复杂元代码难调试（编译错误冗长）。

## 13. 汇编观察点

- **是否常量折叠**：`hash_function("abc")` → `mov $294`（本实验实测）；
- 是否内联：模板函数在 `-O2` 全部内联；
- 是否消除分支：`if constexpr` 假分支无汇编残留；
- 是否出现 `call`：编译期求值后无运行期函数调用。

## 14. 常见错误

- `static_assert(false)` 直接写在函数体内（无论实例化与否都失败）
  → 用 `make_false<T>()` 延迟；
- 用普通 `if` 处理异构类型（编译所有分支失败）→ 用 `if constexpr`；
- 用 `Iterator::iterator_category` 而非 `iterator_traits`（Chapter 5 教训）；
- `PrehashedString` 存非字面量字符串（悬垂指针）；
- 期望 constexpr 总是编译期求值（运行期输入时并不）；
- `std::to_string` 用于 string（应直接输出或 c_str）。

## 15. 实践练习

1. **简单**：给 `const_pow_n` 加 `-fconstexpr-ops-limit` 观察编译期递归/循环
   的编译时间变化；
2. **简单**：用 `is_detected` 检测一个类是否有 `begin()`，并写出
   `has_begin_v<T>`；
3. **中等**：实现 `tuple_find`（返回第一个满足谓词的索引），仿照
   `tuple_any_of`；
4. **中等**：给 `PrehashedString` 换成真正的哈希（`boost::hash_combine` 或
   FNV-1a），重新验证编译期折叠；
5. **困难**：实现一个 `to_string` 变参函数（任意类型拼成字符串），用
   变参包 + `if constexpr` + ostringstream，对比手写重载的简洁度。

## 17. 本章总结

- 模板元编程 = 编译期生成代码；复杂元代码应藏在库接口后；
- type traits / enable_if / is_detected 提供编译期类型内省与条件启用；
- `constexpr` + `if constexpr` 把计算与分支选择移到编译期；
- `std::integral_constant` 与汇编可验证真发生了编译期计算；
- 异构容器：`tuple`（静态）、`variant`（固定集+栈）、`any`（任意+运行期检查）；
- 实际应用：反射消除样板代码、safe_cast 防转换错误、编译期哈希省运行期成本；
- 一切以实测为准（本环境汇编见 §13）。
