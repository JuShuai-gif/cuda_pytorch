# 13 编译器优化与汇编分析

> 综合全书（Chapter 1/3/8/10 等）汇编与优化相关实验的方法论笔记，非单章翻译。
> 本项目汇编验证示例：`src/chapter08_metaprogramming/compile_time_hash`。

---

## 1. 为什么要看汇编

- 高级语言到机器码之间存在多级变换：编译器优化 + 硬件重排；
- 想验证"零成本抽象""编译期计算""内联是否发生"，汇编是最终证据；
- 本书多处用汇编证明结论：反射零开销、编译期哈希折叠为常量、if constexpr
  消除死分支。

## 2. 基础命令

```bash
# 生成汇编（-S），配合 -O2/-O3 观察优化后代码
g++ -std=c++17 -O2 -S src.cpp

# 只看关键函数
g++ -std=c++17 -O2 -S src.cpp && grep -A30 "<func>:" src.s

# 编译器在做什么（优化 pass 日志）
g++ -std=c++17 -O2 -fdump-tree-optimized src.cpp

# 反汇编已编译产物
objdump -d a.out | grep -A20 "<func>:"
```

> 现代补充：Clang 可用 `-S -emit-llvm` 看 LLVM IR；`-fopt-info` 系列输出优化
> 决策（GCC 也支持 `-fopt-info-all`）。

## 3. 关键优化与如何从汇编识别

| 优化 | 汇编特征 | 相关实验 |
|---|---|---|
| **常量折叠** | 直接 `mov $294` 而非调用函数 | chapter08 compile_time_hash |
| **内联** | 无 `call` 指令，函数体直接展开 | 各章 example |
| **死代码消除** | 相关指令完全不存在 | benchmark 需 barrier 防此 |
| **循环展开/向量化** | 重复块 / SIMD 指令（`movups` 等） | chapter06 |
| **if constexpr 消除** | 假分支无对应指令 | chapter08 generic_mod |
| **尾调用优化** | `jmp` 而非 `call+ret` | — |
| **寄存器分配** | 变量不在栈上（无 `[rsp+x]` 访问） | — |

## 4. 本项目实测的汇编证据

### 4.1 编译期哈希折叠（chapter08）

```cpp
constexpr auto hash = hash_function("abc");  // 编译期求值
```

反汇编结果（`-O2`）：

```asm
mov $294, %eax      ; hash 已在编译期算好，直接加载常量
```

> 说明：`hash_function("abc")` 没有运行期调用，`mov $294` 是唯一的证据。

### 4.2 if constexpr 消除死分支（chapter08）

`generic_mod` 对 int 走 `%`、对 float 走 `fmod`：int 版本的汇编中不存在
`fmod` 的 `call`，反之亦然——假分支的代码**根本没生成**。

### 4.3 反射零开销（chapter08）

书中断言 `reflect()` 生成的泛型运算符与手写版汇编一致；本项目以 tests 验证
语义等价（零开销抽象的核心主张）。

## 5. 常见陷阱

- **Debug 下看汇编没意义**：`-O0` 把所有东西压栈，看不出真实行为；
- **只看一段汇编**：需对照 `-fdump-tree-optimized` 理解整体变换；
- **忽略 ABI 开销**：函数调用约定、异常展开表（`.gcc_except_table`）也占空间；
- **误读内联**：`inline` 关键字不保证内联，`-O2` 下普通函数也可能内联；
- **perf 采样与汇编对不上**：`-fno-omit-frame-pointer`（本项目默认开启）保证
  栈回溯可用（顶层 CMakeLists 已加）。

## 6. 从汇编反推优化是否生效

1. **验证零成本抽象**：手写版 vs 抽象版汇编逐指令对比（diff）；
2. **验证编译期计算**：找常量 `mov`，确认无函数调用；
3. **验证分支消除**：搜索 `call fmod` / `call sqrt` 是否存在于不该在的路径；
4. **验证数据布局**：看结构体偏移量（`sizeof`、成员 offset），确认无多余 padding
   （Chapter 4）。

## 7. 汇编与性能的关系边界

- 更少指令 ≠ 更快：指令数、依赖链、cache、分支预测共同决定；
- 向量化（par_unseq）会**增加**指令但提速；
- 内联增加代码体积（I-cache 压力），不一定总是好事；
- 结论以 benchmark 为准，汇编用于**解释**而非**预测**。
