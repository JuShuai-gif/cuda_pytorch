# 15 高性能 C++ 常见误区

> 综合全书各章"常见错误"与性能结论的批判性笔记。每条误区都尽量给出
> 本项目的实测证据或书中观点页码，避免"我以为"。

---

## 1. 误区清单

### 1.1 "优化就是选更快的语法"

- **真相**：性能由数据布局、算法复杂度、cache 行为主导；语法差异常被
  编译器抹平（Chapter 1 零成本抽象 + Chapter 4 数据结构）。
- **反例**：`++counter` 循环里手写 vs `std::count`（chapter01 loop_vs_count），
  编译器把两者优化到几乎一致——真正的瓶颈常不在语法。

### 1.2 "越简洁的代码越快" / "抽象有性能税"

- **真相**：现代 C++ 抽象（STL 算法、智能指针、迭代器）在 `-O2` 下通常是
  零成本的（Chapter 1 整章主张）。
- **验证**：chapter08 反射生成运算符与手写版语义等价（零开销）。
- **例外**：滥用 `std::function` 类型擦除（Chapter 2）有间接调用成本；
  `std::any` 有运行期类型检查与潜在堆分配（Chapter 4）。

### 1.3 "更多线程一定更快"

- **真相**：CPU 密集任务线程数 ≈ 核数；线程过多，上下文切换开销反噬
  （Chapter 10 性能指南）。
- **验证**：chapter11 手写并行用 `hardware_concurrency()` 分块，系统负载/块
  不均时受最慢块限制（书中 naive 版缺陷）；GPU 则受数据搬运瓶颈。

### 1.4 "并行算法 = 串行算法改个参数就免费"

- **真相**：并行算法在**单核上更慢**（调度/原子/缓存开销），只在多核 + 数据量
  足够时受益（Chapter 11 开篇）。
- **验证**：chapter11 par_copy_if 的 sync 版（原子写位置）因伪共享比串行
  慢 11 倍；轻谓词下 split 版收益也有限。

### 1.5 "`std::shared_ptr` 是线程安全的"

- **真相**：**控制块（引用计数）线程安全**，被指向的对象**不是**；同一
  `shared_ptr` 对象被多线程读写需 `atomic_load/atomic_store`（Chapter 10）。
- **后果**：误以为对象安全而跳过锁 → 数据竞争（未定义行为）。

### 1.6 "减少系统调用/分配就是优化"（常见但需先测）

- **真相**：避免分配/系统调用常常有用，但要先确认它们是热点
  （perf/gprof），否则属于臆测优化（Chapter 3 方法论）。

### 1.7 "`constexpr` 一定编译期求值"

- **真相**：`constexpr` 只在**需要常量**时才编译期求值；运行期输入时退回
  运行期执行（Chapter 8）。
- **验证**：compile_time_hash 只有在字面量输入时汇编才折叠为 `mov $294`。

### 1.8 "`std::reduce` 等价于 `std::accumulate`"

- **真相**：`reduce` 是**无序**归约，要求操作满足交换律 + 结合律；整数加法/乘法
  可，字符串拼接顺序不定（Chapter 11）。

### 1.9 "数据竞争只要不崩溃就没事"

- **真相**：数据竞争是**未定义行为**，编译器可按 UB 自由优化，"看起来能跑"
  只是巧合（Chapter 10）。
- **验证**：chapter10 data_race 的 plain 版结果不确定；TSan 可确定性检出。

### 1.10 "`par_unseq` 谓词里可以随便写"

- **真相**：`par_unseq` 允许向量化，谓词**不得抛异常、不得加锁**（同线程
  交错执行会死锁）（Chapter 11）。

### 1.11 "GPU 一定比 CPU 快"

- **真相**：GPU 收益受**数据往返拷贝**瓶颈影响巨大；数据量小/搬运频繁时
  GPU 反而更慢（Chapter 11，书中 30x 是"计算密度高"场景）。

### 1.12 "书上说的数字直接用"

- **真相**：性能数字依赖硬件、编译器、标准库、数据规模。本书多处实测与
  书中不同（如 concat_proxy 5.2x vs 书中 10.7x；distance_proxy 1.14x vs 2x）。
  结论必须**本机实测 + 标注环境**（note/12 工作流）。

## 2. 通用原则（贯穿全书）

1. **先测量，再优化**（Chapter 3）；
2. **先正确，再快速**——"快而错的程序"毫无价值（Chapter 10）；
3. **优先 STL 算法**而非手写循环：可读性 + 自动获得未来优化（Chapter 6）；
4. **数据结构先行**：cache locality 与复杂度 > 语法细节（Chapter 4）；
5. **优化要可回归**：tests + benchmark 固定下来，防止退化（本项目每个实验
   都是 tests + benchmark 结构）。
