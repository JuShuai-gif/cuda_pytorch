## 2. 构建与运行

```bash
# 一次性构建全部项目
cmake -S projects -B build-projects
cmake --build build-projects -j

# 全部测试
for t in build-projects/*/*_tests; do ./$t; done

# 全部 benchmark
for b in build-projects/*/*_benchmark; do ./$b; done
```

## 3. 各项目要点

### 3.1 object_pool（对象池）

- 构造时一次性分配 N 个固定大小块，空闲链表管理；
- **对齐**：块大小规范到 `max_align_t` 对齐且 ≥ 指针大小（free list 需要）；
- **RAII**：`Pooled<T>` 在池内 placement-new，析构返回块，耗尽抛 `bad_alloc`；
- **benchmark**：本机约 0.5 ns/op vs `new/delete` 约 12 ns/op（**25x**）；
- 易错点：free list 存指针要求块足够大（`block_size < sizeof(void*)` 会越界）；
  编译器可能把"取块-还块"折叠掉，benchmark 需 `asm volatile` barrier。

### 3.2 task_system（线程池）

- 固定线程 + `mutex`/`condition_variable` 任务队列；空闲线程休眠不占 CPU；
- `submit(fn, args...)` 用 `packaged_task` 自动搭 promise，返回 `future`；
- 析构置停止标志 → `notify_all` → join（RAII 收尾）；
- **benchmark**：并行求和 vs 串行约 1.6x（本机 24 线程，受内存带宽限制）；
- 易错点：线程数默认 `hardware_concurrency()`；任务过小队列锁争用吃收益；
  使用 `packaged_task` 避免手写 promise/future 配对。

### 3.3 parallel_pipeline（并行流水线）

- map（transform）→ filter（copy_if + 压实）→ reduce 三个并行阶段；
- 每阶段一个 `std::execution` 策略调用，代码短、可读；
- **benchmark**：本机约 1.7x（轻量映射受带宽限制，重映射加速更明显）；
- 易错点：`reduce` 需交换 + 结合律；并行谓词不得抛异常/加锁（GCC 13
  libstdc++ 实测抛异常直接 terminate，见 note/11）；阶段间 vector 拷贝需内存。

### 3.4 high_performance_container（哈希集合）

- **开放寻址 + 线性探测**：元素存扁平 `vector`，无链节点、无逐节点堆分配；
- 负载因子上限 0.7，超限翻倍重哈希；
- **benchmark**：查询与 `std::unordered_set` 相当（ratio ~1.0x）；
- 易错点：探测起点必须对容量取模（`hash % cap`），否则大哈希越界（本项目
  曾因此段错误）；`vector<bool>` 节省位但读写慢；开放寻址删除需 tombstone。

## 4. 各项目如何呼应全书

| 全书主题 | 在本项目中的落点 |
|---|---|
| 零成本抽象（Ch1） | 对象池/容器不用虚函数与类型擦除，全内联 |
| 测量优先（Ch3） | 每个项目配套 tests（先对）+ benchmark（后快） |
| 数据结构与 cache（Ch4） | 哈希集合开放寻址的扁平布局 |
| 迭代器（Ch5） | 容器收集遍历、LinearRange 复用 |
| 内存管理（Ch7） | 对象池分配器、块对齐 |
| 并发（Ch10） | 线程池同步原语、future 返回值 |
| 并行算法（Ch11） | 执行策略流水线 |

## 5. 设计约定

- 每个项目：`hpp` 实现 + `example` 演示 + `tests` 断言 + `benchmark` + `README`；
- 独立 CMake，不依赖 `src/`（可单独拉取复用于其他项目）；
- 与 `src/` 相同的警告等级（`-Wall -Wextra -Wpedantic -Wshadow -Wconversion`）。
