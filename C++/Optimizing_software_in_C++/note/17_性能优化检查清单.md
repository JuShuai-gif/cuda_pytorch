# 17 性能优化检查清单

> 本笔记为全书综合（无独立 PDF 章节），把 01-16 笔记的原则提炼成一张"优化前→优化中→优化后"的检查清单，每条标注来源笔记与 PDF 页码，便于实践时对照自查。

## 1. 本章解决什么问题

把全书的方法论浓缩成**可勾选的清单**，防止优化时"漏项"或"走弯路"。按流程分成四部分：

1. 动手前（原则与定位）；
2. 代码层（语言结构与数据布局）；
3. 编译与工具链；
4. 测量与验证。

## 2. 核心概念

清单 = 可执行的"先测量，再优化"落地版。核心判断维度（PDF 第 24 页章节 5 与全书）：

- 收益（这个优化能省多少时间）；
- 成本（可读性、维护、出错风险）；
- 验证（能否用汇编/perf/Benchmark 证明）。

## 3. 工作原理

每条检查项对应一个"易错点"或"高收益点"，都有出处。勾选顺序即优化流程；任何"优化"如果无法通过第 4 步验证，就不算完成。

## 4. 检查清单（全书综合）

### A. 动手之前：原则与定位

- [ ] 我是否先定位了热点？只有热点才值得优化（PDF 第 16 页，03 笔记）。
- [ ] 我是否估算了这段代码的量级？<100 µs 且无感，不值得优化（PDF 第 15～16 页，01 笔记）。
- [ ] 我是否先考虑了算法/数据结构？好算法 > 微优化；但别过度设计（PDF 第 24 页，01 笔记）。
- [ ] 瓶颈是 CPU、内存还是 I/O？先判断再动手（PDF 第 16、21 页，03 笔记）。
- [ ] 我是否用真实数据、真实规模测试？小数据全在缓存里（PDF 第 170 页，14 笔记）。

### B. 代码层：语言结构与数据布局

- [ ] 变量尽量在函数内（栈）、避免全局/静态、避免无谓 new/delete（PDF 第 26、28 页，04/06 笔记）。
- [ ] 一起用的变量/函数存在一起（栈内连续、AoS、同源文件相邻）（PDF 第 93 页，06 笔记）。
- [ ] 大数组顺序访问、行主序遍历；非顺序访问避免 2 的幂行距（PDF 第 106～107 页，06 笔记）。
- [ ] 容器选型：`vector + reserve` 优先，避免链表；FIFO 用环形缓冲（PDF 第 98、103 页，06 笔记）。
- [ ] 大对象/向量数据用 `alignas` 对齐（16/32/64）（PDF 第 95、124 页，06/10 笔记）。
- [ ] 循环：整数计数器、预知终值、避免循环控制依赖循环内计算（PDF 第 46 页，04 笔记）。
- [ ] 长依赖链是否打破？（括号分组、多累加器）（PDF 第 113～114 页，08 笔记）。
- [ ] 热点内避免无谓函数调用/嵌套调用/虚函数/异常（PDF 第 48、55、62 页，04 笔记）。
- [ ] 查表是否可用？（输入集合有限、表热、无向量化冲突）（PDF 第 144 页，12 笔记）。
- [ ] 除法/模运算：常数？无符号？2 的幂？（PDF 第 150 页，12 笔记）。
- [ ] 是否混用 float/double？是否有无谓 int↔float 转换？（PDF 第 32、153 页，04/12 笔记）。
- [ ] 热点内的布尔分支能否用位运算/查表消除？（PDF 第 34、146 页，04/12 笔记）。
- [ ] 编译期已知的常数能否用模板/`constexpr` 在编译期算？（PDF 第 163 页，13 笔记）。
- [ ] 需要向量化时：数据小类型、无别名（`__restrict__`）、对齐、循环次数为向量宽倍数？（PDF 第 119 页，09 笔记）。
- [ ] 多线程：数据分解 + 局部累加 + 最后合并？避免共享缓存行竞争？（PDF 第 111～112 页，07 笔记）。

### C. 编译与工具链

- [ ] 用了 Release（`-O3`）而非 Debug 测性能？（PDF 第 85 页，16 笔记）。
- [ ] 指令集选项与 CPU 匹配？（本机到 AVX2；AVX-512 需检测分发）（PDF 第 174 页，11/16 笔记）。
- [ ] 是否需要 `-fno-trapping-math -fno-math-errno` 以允许向量化？（PDF 第 119 页，16 笔记）。
- [ ] 是否考虑过 `-Os`（代码体积受限时）？（PDF 第 85 页，16 笔记）。
- [ ] 关键代码是否需要 CPU dispatch 多版本？（PDF 第 135 页，11 笔记）。
- [ ] 速度敏感时用静态链接？（PDF 第 159 页，02/12 笔记）。
- [ ] 编译前是否声明了 `static`/`__restrict__`/`noexcept` 等帮助编译器优化的信息？（PDF 第 87～88 页，05 笔记）。

### D. 测量与验证

- [ ] 预热 + 多轮 + 取中位数/最小值？（PDF 第 168 页，14 笔记）。
- [ ] 用 perf 看了 instructions/cache-misses/branch-misses？（PDF 第 169 页，03/14 笔记）。
- [ ] 用 `-S`/objdump 看了汇编，确认优化真的发生？（PDF 第 89 页，05 笔记）。
- [ ] baseline 与 optimized 的结果校验和一致？（14 笔记）。
- [ ] 考虑了冷/热缓存（首次 vs 后续调用）？（PDF 第 168 页，14 笔记）。
- [ ] 实时/交互应用测了最坏情况？（PDF 第 171 页，14 笔记）。
- [ ] 优化后的代码在最终程序上下文中验证过（而非只测单函数）？（PDF 第 170 页，14 笔记）。

## 6. 未优化代码

优化前常见状态（清单多项未勾选）：

```cpp
// Typical "unoptimized" hotspot: division per element, mixed precision,
// virtual dispatch, and no measurement.
double Process::compute(const std::vector<double> &v, double scale) {
    double s = 0.0;
    for (size_t i = 0; i < v.size(); ++i) {
        s += v[i] / scale;          // division in loop (slow)
        s *= 1.5;                   // double constant vs float? check
    }
    return s;
}
```

## 7. 优化后代码

```cpp
// After checklist pass: multiply by reciprocal, single precision choice,
// -O3 + possibly vectorized. Measured before/after.
double Process::compute(const std::vector<double> &v, double scale) {
    const double rscale = 1.0 / scale;      // hoisted reciprocal (PDF p152)
    double s = 0.0;
    for (size_t i = 0; i < v.size(); ++i) {
        s += v[i] * rscale;                 // multiply, not divide
    }
    return s;
}
```

## 8. 为什么会更快

- **除法**：每元素除法 20-45 周期 → 乘倒数 3-8 周期（PDF 第 152 页，12 笔记）。
- **循环不变量外提**：`1/scale` 只算一次（PDF 第 72 页，05 笔记）。
- **可向量化**：乘法链比除法更易被自动向量化（PDF 第 119 页，09 笔记）。
- **可验证**：多轮测量 + 汇编确认 + perf，避免"自以为更快"。

## 9. 如何验证

```bash
# 对优化前后版本
g++ -O3 -std=c++17 baseline.cpp -o base
g++ -O3 -std=c++17 optimized.cpp -o opt
./base && ./opt            # 校验和一致 + 输出耗时（多轮中位数）
sudo perf stat -e cycles,instructions ./opt
g++ -O3 -std=c++17 -S -masm=intel optimized.cpp -o /tmp/opt.s
```

## 10. 常见误区

- **误区一：清单是死的。** 是辅助，不是教条；一切以测量为准。
- **误区二：做完 A 就停了。** D（测量验证）才是闭环。
- **误区三：微优化非热点。** 清单 A 步就应拦截。

## 11. 实践任务

1. 对自己最近写的一段代码，用本清单逐项勾选，找出遗漏项。
2. 挑一个优化想法，完整走 A→D 四步，验证它是否真的更快。
3. 找一个"看似优化实则更慢"的案例（如查表被驱逐出缓存），用清单 B/D 步分析原因。

## 12. 本章总结

- 优化流程 = 定位热点 → 选对手段 → 配好编译 → 测量验证。
- 每项手段都有适用条件（数据规模、CPU、缓存、向量化冲突）。
- 没有验证的优化不成立。
