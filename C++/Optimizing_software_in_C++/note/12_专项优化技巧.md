# 12 专项优化技巧

> 本笔记对应 PDF 第 14 章 Specific optimization topics（第 144～162 页），覆盖 14.1～14.13。静态/动态库（14.11）与 PIC（14.12）同时补充到 `note/02_平台与编译器选择.md` 的映射范围，此处给出完整内容。

## 1. 本章解决什么问题

前面章节讲"原理"，本章是**具体的优化招法库**：查表、边界检查、位运算、乘除法、浮点转换、数学函数、库与链接。每一条都给出"为什么快、什么时候用、什么时候别用"。

核心结论：**除法慢、查表快、位运算快；优化要按数据规模和应用场景选择，没有银弹。**

## 3. 工作原理

### 3.1 除法为什么慢

整数除法 27-80 周期（PDF 第 150 页）、浮点除法 20-45 周期（PDF 第 152 页），而加法 1 周期、乘法 3-11 周期。编译器把"除常数"变换为"乘倒数再移位"，把昂贵的除法变成便宜的乘+移位（PDF 第 150 页）。

### 3.2 查表为什么快

从 L1 缓存读一个数组元素只要几个周期（PDF 第 144 页）。若函数的输入集合有限（如阶乘只有 0-12），查表比循环计算快得多；若分支预测差，查表替代分支也能提速（PDF 第 144～145 页）。

### 3.3 静态 vs 动态链接

静态链接把库函数拷贝进可执行文件：调用直接、代码连续；动态链接运行时加载共享库，调用经 PLT/GOT 查表，且按页对齐加载引发缓存行争抢（PDF 第 158 页）。

## 4. PDF 核心观点

### 14.1 用查表（第 144～146 页）

- 从 L1 缓存读表只要几个周期；输入集合有限时查表替代计算/函数调用（PDF 第 144 页）。
- 阶乘例子：计算要 n-1 次乘法，查表一步到位；表声明 `const`（PDF 第 144～145 页，Example 14.1a/b）。
- 不适合查表的情况：表会被驱逐出缓存、且计算比重载缓存行便宜时；**查表无法向量化**，若查表阻止更快的向量化就别用（PDF 第 145 页）。
- 表放静态内存有缓存问题；可在函数内、内层循环外声明局部表，编译器拷贝到栈上（与局部变量连续，缓存更好）（PDF 第 145 页，Example 14.1c）。
- 用查表替代二选一分支：`a = OneOrTwo5[b & 1]`（PDF 第 146 页，Example 14.2）。
- switch 可用查表替代（打印希腊字母表，PDF 第 146 页，Example 14.3）。

### 14.2 边界检查（第 147～148 页）

- `i < 0 || i >= size` 两个比较合成一个：`(unsigned)i >= (unsigned)size`（负值转成超大正数触发检查）（PDF 第 147 页，Example 14.4）。
- 区间检查：`i >= min && i <= max` 变成 `(unsigned)(i-min) <= (unsigned)(max-min)`（PDF 第 147 页，Example 14.5）。
- 区间是 2 的幂时用位与：`list[i & 15]` 保证索引在 [0,15]（PDF 第 147～148 页，Example 14.6）。

### 14.3 位运算一次检查多个值（第 148～149 页）

- 把枚举值定义为 2 的幂，一条 `&` 检查多个条件：`if (Day & (Tuesday | Wednesday | Friday))`（PDF 第 148 页，Example 14.7）。
- 位运算无分支、快；布尔运算符 `&&`/`||` 有短路但可能产生分支（PDF 第 148 页）。

### 14.4 整数乘法（第 149～150 页）

- 乘法 3-10 周期；编译器把乘常数变成移位+加法：`a*16 = a<<4`，`a*17 = (a<<4)+a`（PDF 第 149 页）。
- 非顺序访问时，结构大小/列数为 2 的幂使地址计算用移位（PDF 第 149 页，Example 14.8/14.9）。
- **但大结构避免 2 的幂**（缓存竞争，见 06 笔记）（PDF 第 150 页）。

### 14.5 整数除法（第 150～152 页）

- 除法 27-80 周期；除 2 的幂用移位（PDF 第 150 页）。
- 除常数比除变量快（编译器变换为乘倒数）；**无符号比有符号更快**（少修正指令）（PDF 第 150 页，Example 14.10）。
- 取模同规则（Example 14.11）。
- 循环内除以常数可展开循环避开除法（PDF 第 151 页，Example 14.12/14.13）。

### 14.6 浮点除法（第 152～153 页）

- 除法 20-45 周期；除常数改乘倒数 `b * (1./1.2345)`（PDF 第 152 页，Example 14.14）。
- 消除除法：`a > b/c` → `a*c > b`（注意 c<0 反转符号、整数不精确）（PDF 第 152 页，Example 14.15）。
- 多个除法合并通分：`a1/b1 + a2/b2` → `(a1*b2+a2*b1)/(b1*b2)`（PDF 第 152 页，Example 14.16）。
- 独立除法共享倒数：`y1 = a1*b2*rd; y2 = a2*b1*rd;`（PDF 第 153 页，Example 14.17）。

### 14.7 不要混用 float 和 double（第 153 页）

- 64 位或 SSE2 后，混用精度引入转换指令；`b * 1.2` 中 `1.2` 是 double，全写 `1.2f` 或全 double（PDF 第 153 页，Example 14.18）。详见 04 笔记 7.3。

### 14.8 浮点↔整数转换（第 153～154 页）

- 标准要求截断，无 SSE2 时转换要改舍入模式，**40 周期**；SSE2 后快（PDF 第 153 页）。
- 用舍入代替截断约快 3 倍：`lrint`/`lrintf`（PDF 第 153 页，Example 14.19-14.21）。
- int→float：signed 快；unsigned 在无 AVX-512 时慢，可先转 signed（无溢出风险时）（PDF 第 154 页）。

### 14.9 用整数操作操纵浮点变量（第 154～157 页）

- IEEE-754 格式：符号位 + 指数 + 尾数；可用 union 以整数位操作浮点（PDF 第 154 页）。
- 应用：翻转符号位 `u.i ^= 0x80000000`、绝对值 `u.i &= 0x7FFFFFFF`、判零、乘 2^n（改指数）、正数比较、产生 [1,2) 随机数（PDF 第 155～156 页，Example 14.22-14.28）。
- 用 union 而非指针 cast（避免严格别名违规）（PDF 第 157 页）。
- double 分两半修改会触发 store-forwarding 延迟；64 位用 64 位整数别名（PDF 第 157 页）。
- 位序问题：big-endian 平台（如 PowerPC）不兼容（PDF 第 157 页）。

### 14.10 数学函数（第 158 页）

- x86 硬件有数学函数指令，但**SSE2 后软件实现更快**（多数编译器用软件实现）（PDF 第 158 页）。
- 单精度软件实现收益更大；Intel 数学库/向量库提供更多函数（PDF 第 158 页）。

### 14.11 静态 vs 动态库（第 158～160 页）

- 静态链接优点：只拷入用到的部分、单文件分发、调用快（无 PLT 查表）、代码不碎片化、不受其他应用库版本影响（PDF 第 158 页）。
- 动态链接优点：多进程共享代码段、库可独立更新、跨语言调用、插件化（PDF 第 158～159 页）。
- **速度敏感时用静态链接**（PDF 第 159 页）。
- 惰性绑定（lazy binding）首次调用要加载动态链接器，延迟大；只用于超大库（PDF 第 159 页）。

### 14.12 位置无关代码（第 160～162 页）

- Linux/BSD 共享库默认 PIC：所有公共函数/数据访问经 PLT/GOT 查表，即使库内部访问也要查——**即使"符号插入（override）"特性几乎没人用，代价照付**（PDF 第 160 页）。
- 32 位 Linux 数据相对寻址要 4 步（call 取自身地址→找 GOT→查表→访问），很慢；编译共享库可去掉 `-fpic`（PDF 第 160～161 页）。
- 64 位 Linux 用 `-fpie` 替代 `-fpic`：相对寻址但内部引用不查 GOT/PLT，更快；公共变量需隐藏（`static` 或 visibility hidden）（PDF 第 161 页）。
- GCC 5.1+ 可用 `-fno-semantic-interposition` 避免同文件内的 PLT/GOT 查表（PDF 第 161 页）。
- 32 位 Mac 默认 PIC + 惰性绑定，编译用 `-fno-pic`（非共享库）（PDF 第 161 页）。

### 14.13 系统编程（第 162 页）

- 设备驱动/ISR/高优先级线程中，一个耗时函数可能阻塞一切（PDF 第 162 页）。
- 系统代码必须遵守寄存器使用规则；动态分配（含垃圾回收时机不可控）尤其危险；队列用定长环形缓冲而非链表；**不要用标准容器**（PDF 第 162 页）。

## 5. 简单示例

查表替代计算（PDF 第 144～145 页，Example 14.1）：

```cpp
// Lookup table beats a loop when inputs are few (0..12).
int factorial(int n) {                        // n!
    static const int table[13] = {1, 1, 2, 6, 24, 120, 720, 5040,
        40320, 362880, 3628800, 39916800, 479001600};
    if ((unsigned)n < 13) return table[n];    // bounds check + lookup
    return 0;
}
```

## 6. 未优化代码

```cpp
// (A) Division in a hot loop (PDF p150): a/b with a runtime divisor.
int sum_div(const int *a, int n, int b) {
    int s = 0;
    for (int i = 0; i < n; ++i) s += a[i] / b;   // 27-80 cycles each
    return s;
}

// (B) Two comparisons for bounds checking (PDF p147).
bool in_range(int i, int size) {
    return i >= 0 && i < size;                   // 2 branches
}
```

## 7. 优化后代码

```cpp
// (A) Division by a constant (or make the divisor compile-time constant):
int sum_div10(const int *a, int n) {
    int s = 0;
    for (int i = 0; i < n; ++i) s += a[i] / 10;  // compiler: mul + shift
    return s;
}

// (B) Single unsigned comparison (PDF p147):
bool in_range(unsigned i, unsigned size) {
    return i < size;                             // 1 comparison, no branches
}
```

## 8. 为什么会更快

- **指令数量**：查表把 n-1 次乘法换成一次 load；`unsigned` 单比较把两条分支合成一条。
- **分支预测**：查表与位运算**无分支**，避免 15-25 周期误预测惩罚（PDF 第 43、148 页）。
- **除法代价**：除法 27-80 周期（整数）/20-45 周期（浮点）；乘倒数后 3-11 周期乘法（PDF 第 150、152 页）。
- **缓存**：查表命中 L1 只要几个周期；前提是表小且热（PDF 第 144 页）。
- **可移植性/风险**：`a*c > b` 需注意 c 符号；union 位操作在 big-endian 不适用；这些是"为什么快但别乱用"的边界。

## 9. 如何验证

```bash
# 编译并运行查表/除法等示例
g++ -O3 -std=c++17 lookup.cpp -o lookup
g++ -O3 -std=c++17 div.cpp -o div
./lookup
./div

# 验证除常数被编译为乘法+移位
g++ -O3 -std=c++17 -S -masm=intel div.cpp -o /tmp/div.s
grep -iE "imul|mul" /tmp/div.s      # 应看到 imul 而非 idiv（除常数）

# perf 对比
sudo perf stat -e cycles,instructions ./div
```

- 编译命令：`g++ -O3 -std=c++17`（本机 g++ 13.3.0）
- 运行命令：`./lookup` / `./div`
- 验证汇编：搜 `imul`（乘法实现）而非 `idiv`/`div`（真除法）
- Benchmark 方法：预热 + 多轮取中位数（`note/14_性能测试与Benchmark.md`）
- perf 命令：`sudo perf stat`（本机需 root）

## 10. 常见误区

- **误区一：查表永远更快。** 表被驱逐出缓存时反而更慢（PDF 第 145 页）。
- **误区二：查表和向量化能兼得。** 查表阻止向量化（PDF 第 145 页）。
- **误区三：`b / c`（变量）也快。** 只有除常数编译器才能变换（PDF 第 150 页）。
- **误区四：`a > b/c` 改成 `a*c > b` 总安全。** c<0 要反号、整数有精度问题（PDF 第 152 页）。
- **误区五：共享库的 PIC 开销无所谓。** 即使不用 override 特性，访问也查表；用 `-fpie`/`-fno-semantic-interposition` 可降低（PDF 第 160～161 页）。
- **误区六：union 位操作可移植。** big-endian 平台不适用；double 分半修改有 store-forwarding 延迟（PDF 第 157 页）。

## 12. 本章总结

- 查表：输入集合有限时最快；注意缓存与向量化冲突。
- 边界检查：无符号单比较、位与截断，省分支。
- 位运算：一次检查/设置多个条件，无分支。
- 乘除法：乘 2 的幂用移位、除常数编译器自动优化、无符号除法更快、浮点除改乘倒数。
- 浮点转换：能免则免；SSE2 后成本大降。
- 链接：速度敏感时静态链接；共享库用 `-fpie`/`-fno-semantic-interposition` 减开销。
