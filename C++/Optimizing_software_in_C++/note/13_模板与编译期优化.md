# 13 模板与编译期优化

> 本笔记对应 PDF 第 15 章 Metaprogramming（第 163～166 页），覆盖 15.1～15.3，并衔接第 7.30 节 Templates（第 59～61 页）。

## 1. 本章解决什么问题

"元编程"= 写能生成代码的代码。在编译型语言里，它的价值是**把能在编译期算完的东西放到编译期算**，运行时零成本。本章回答：

1. 有哪些编译期计算手段？（模板元编程、`if constexpr`、`constexpr` 函数）
2. 各有什么代价？（复杂度、编译时间、可读性）
3. 什么时候值得用？

核心结论：**`if constexpr` 与 `constexpr` 函数是现代 C++ 里简单可用的编译期优化手段；老式模板元编程极其复杂，作者"认为不明智，除非最简单情况"。**

## 2. 核心概念

| 术语 | 含义 | 出处 |
|------|------|------|
| 元编程（metaprogramming） | 写能产生代码/计算的代码 | PDF 第 163 页 |
| 模板元编程（TMP） | 用模板递归 + 特化实现编译期算法 | PDF 第 164 页 |

| `constexpr` 函数 | C++14 起可在编译期执行含分支/循环的函数 | PDF 第 167 页 |

## 3. 工作原理

### 3.1 编译期计算的本质

模板参数在编译期替换为实际值（PDF 第 59 页）：`MultiplyBy<8>(x)` 中编译器看到常数 `8`，可以把 `x*8` 变成 `x<<3`。元编程就是把依赖"编译期常数"的循环/分支在编译期展开。

### 3.2 模板递归如何模拟循环

模板没有运行时的循环，用**递归实例化**模拟；没有运行时的 if，用**模板特化**模拟（PDF 第 165 页）。递归必须有终止的特化版本。

### 3.3 `if constexpr` 为什么更好

C++17 的 `if constexpr`：条件在编译期求值，**false 分支的代码不会生成**（也不会实例化其中的模板，避免无限递归）。老式模板元编程的 false 分支也会展开，可能无限递归或指数爆炸（PDF 第 166 页）。

### 3.4 `constexpr` 函数

C++14 起 `constexpr` 函数内可以有分支、循环；只要参数是编译期常数，整个函数就在编译期执行，结果可作数组大小、模板参数（PDF 第 167 页）。

## 4. PDF 核心观点

### 第 7.30 节 Templates（第 59～61 页）

- 模板参数编译期替换：`MultiplyBy<8>(x)` 使编译器把乘 8 变成移位（PDF 第 59 页，Example 7.46）。
- 模板效率来自编译期解析；**执行速度上模板没有成本**（PDF 第 59 页）。
- 模板每套参数生成一份代码；参数组合多则代码膨胀（PDF 第 59 页）。
- 模板可实现编译期多态（ATL/WTL 风格 CRTP），比虚函数快；但语法"极其笨拙（kludgy）"，编译器能自动去虚化时更省事（PDF 第 60～61 页，Example 7.47）。

### 15.1 模板元编程（第 163～166 页）

- 元编程手段清单：预处理指令（`#if`）、程序生成程序、编译器编译期求值、模板实例化、`if constexpr`、`constexpr` 函数（PDF 第 163 页）。
- `pow(x,10)`：一般 `pow` 用对数；整数指数可只用乘法；手工展开 `x2=x*x; x4=x2*x2; x8=x4*x4; x10=x8*x2` 只要 4 次乘法（PDF 第 164 页，Example 15.1c）。
- 模板版 `powN<IsPowerOf2,N>` 用类模板特化实现"循环 + 分支 + 终止"（PDF 第 164～165 页，Example 15.1d）。
- 类模板而非函数模板，因为**部分特化只允许类**（PDF 第 165 页）。
- 作者观点：**模板元编程如此复杂，除了最简单情况不明智使用**——验证/调试/维护成本很少能被性能收益抵消（PDF 第 166 页）。

### 15.2 用 constexpr 分支（第 166～167 页）

- C++17 `if constexpr` 大幅简化：递归模板仍需要，但分支与终止更直接；**false 分支的模板不展开**（PDF 第 166 页）。
- 例：`integerPower<n>(x)` 用 `if constexpr` 处理 n==0、n<0、一般情况（PDF 第 166 页，Example 15.2）。
- 好的编译器把 Example 15.2 化简为纯乘法指令（PDF 第 167 页）。
- 需要 `-std=c++17`（PDF 第 163 页）。

### 15.3 用 constexpr 函数（第 167 页）

- `constexpr` 函数在参数为编译期常数时于编译期执行；C++14 起支持内部分支/循环（PDF 第 167 页）。
- 例：编译期实现 `bit_scan_reverse`（找最高位 1），结果可用作数组大小（PDF 第 167 页，Example 15.3）。
- 多数编译器只做简单编译期计算；`constexpr` 保证复杂的也能在编译期做（PDF 第 167 页）。
- 局限：无法生成 10 个 `func1..func10` 这样的命名实体（PDF 第 167 页）。

## 5. 简单示例

`if constexpr` 版本的高效整数幂（PDF 第 166 页，Example 15.2 的结构）：

```cpp
// Compile-time integer power with if constexpr (C++17).
// false branches are never instantiated (PDF p166-167).
#include <type_traits>

template <int n>
inline double ipow_step(double x, double y) {
    if constexpr ((n & 1) == 1) y *= x;        // multiply if bit set
    constexpr int n1 = n >> 1;
    if constexpr (n1 == 0) {
        return y;                              // recursion ends
    } else {
        return ipow_step<n1>(x * x, y);        // square and continue
    }
}

template <int n>
double integerPower(double x) {
    if constexpr (n == 0) return 1.0;
    else if constexpr (n < 0) return 1.0 / integerPower<-n>(x);
    else return ipow_step<n>(x, 1.0);
}
```

## 6. 未优化代码

```cpp
// Runtime power: pow() uses log/exp even for integer exponents,
// and the loop's branch/counter run every call.
#include <cmath>
double xpow10(double x) {
    return std::pow(x, 10);     // heavy general-purpose path
}
```

## 7. 优化后代码

```cpp
// Compile-time exponent: compiler generates just 4 multiplications.
// PDF p164 (Example 15.1c) shows the hand-unrolled equivalent.
double xpow10_fast(double x) {
    return integerPower<10>(x);   // fully computed/expanded at compile time
}
```

## 8. 为什么会更快

- **指令数量**：`integerPower<10>` 编译期为 4 次乘法（`x2,x4,x8,x10`）；`std::pow(x,10)` 含对数/指数函数与循环，指令多一个量级（PDF 第 163～164 页）。
- **分支消除**：编译期展开后循环/分支全部消失（PDF 第 167 页）。
- **运行时零成本**：所有"取决于常数"的工作在编译期完成，运行期只剩必须的运算（PDF 第 163 页）。
- **编译器优化能力**：模板实例化后编译器还能继续做 CSE、常量传播（PDF 第 165 页）。

## 9. 如何验证

```bash
# 编译（必须 C++17）
g++ -O3 -std=c++17 metaprogram.cpp -o metaprogram

# 运行：两个版本结果一致，且 fast 版更快
./metaprogram

# 确认 fast 版展开为乘法、无 pow 调用
g++ -O3 -std=c++17 -S -masm=intel metaprogram.cpp -o /tmp/meta.s
grep -cE "call.*pow" /tmp/meta.s     # fast 版应为 0 次 pow 调用
grep -E "mulsd" /tmp/meta.s          # 应看到若干标量乘法
```

- 编译命令：`g++ -O3 -std=c++17`（本机 g++ 13.3.0；`if constexpr` 需要 C++17）
- 运行命令：`./metaprogram`
- 验证汇编：fast 版无 `call pow`、只有 `mulsd` 等乘法指令
- Benchmark 方法：预热 + 多轮取中位数（`note/14_性能测试与Benchmark.md`）

## 10. 常见误区

- **误区一：模板元编程是性能优化的常规手段。** 作者明确不建议，除非最简单情况（PDF 第 166 页）。
- **误区二：`pow(x,10)` 很快。** 整数指数走通用对数路径；编译期已知指数时应手写/用模板（PDF 第 163 页）。
- **误区三：`if constexpr` 的 false 分支也会实例化。** 不会——这正是它优于老式模板的原因（PDF 第 166 页）。
- **误区四：`constexpr` 一定在编译期执行。** 只有参数是编译期常数时才会；运行时参数则按普通函数执行（PDF 第 167 页）。
- **误区五：模板越多越好。** 每套参数一份代码，膨胀代码占用缓存（PDF 第 59 页）。

3. 用 `if constexpr` 写一个 `constexpr` 的 `bit_scan_reverse`（最高位 1 的位置），验证编译期结果正确。
4. 写一个 `template<int N> constexpr int factorial() { ... }` 编译期阶乘，并用作数组大小。
5. 对比老式模板元编程（Example 15.1d）与现代 `if constexpr`（Example 15.2）的可读性，体会作者的观点。

## 12. 本章总结

- 编译期计算把"取决于常数"的工作移到编译期，运行时零成本。
- 手段演进：老式 TMP（递归+特化，复杂）→ `if constexpr`（C++17，简单）→ `constexpr` 函数（C++14+）。
- 收益：更少指令、无分支、可继续被编译器优化。
- 代价：可读性/维护性；作者不建议过度使用模板元编程。
