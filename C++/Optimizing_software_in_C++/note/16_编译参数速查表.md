# 16 编译参数速查表

> 本笔记对应 PDF 第 18 章 Overview of compiler options（第 174～177 页），内容为表 18.1（命令行选项）、表 18.2（指令与关键字）、表 18.3（预定义宏），并补充各选项说明（PDF 第 175 页）。

## 1. 本章解决什么问题

前面章节讲"用什么手段优化"，本章是**查表**：所有与优化相关的编译选项、指令、关键字、预定义宏，按编译器对照列出。读者写 CMake/命令行时可以快速定位。

适用范围：

- 本表以 GCC/Clang（本机 g++ 13.3.0）为主要目标；MSVC/Intel 列保留原书对照。
- 表中"本机已实测"的选项已验证可编译运行；未实测的标注"未验证"。

## 2. 核心概念

| 术语 | 含义 | 出处 |
|------|------|------|
| 优化级别 | `-O0/-O1/-O2/-O3/-Os`，速度与体积的权衡 | PDF 第 174 页 |
| 指令集选项 | `-msse2`/`-mavx2`/`-mavx512f` 等，决定可用指令 | PDF 第 174 页 |
| 浮点模型 | 精度与速度的权衡（`-ffast-math` 系列） | PDF 第 175 页 |
| 函数级链接 | 移除未引用函数，减小代码 | PDF 第 174 页 |
| 预定义宏 | 编译器/平台识别宏 | PDF 第 177 页 |

## 3. 工作原理

编译选项本质是告诉编译器"你可以做什么、不可以做什么"：

- **优化级别**：开启的优化趟数与激进程度；
- **指令集选项**：允许生成哪类指令（`-mavx2` 才敢用 YMM 寄存器）；
- **浮点选项**：允许哪些会改变精度/语义的变换（重排操作数、`a*0=0`、融合乘加、忽略 NaN/INF）。

## 4. PDF 核心观点

### 表 18.1 命令行选项（PDF 第 174～175 页，精选并核对）

| 用途 | MSVC (Windows) | GCC / Clang (Linux) | 说明 |
|------|----------------|---------------------|------|
| 优化速度 | `/O2` 或 `/Ox` | `-O3` 或 `-Ofast` | 本机 g++ `-O3` 实测 ✓ |
| 全程序优化 | `/GL` | `--combine`/`-fwhole-program` | 跨 .cpp 优化 |
| 无异常处理 | `/EHs-` | `-fno-exceptions` | 代码更小更快 |
| 无浮点陷阱 | `/fp:except-` | `-fno-trapping-math` | 向量化含分支循环必需 |

| 无 RTTI | `/GR-` | `-fno-rtti` | 关闭运行时类型识别 |
| 假设无别名 | `/Oa` | `-fno-alias`(Intel) | 需确认代码无别名 |
| 快速浮点 | `/fp:fast` | `-ffast-math` | 见下文选项说明 |

| 忽略零的符号 | - | `-fno-signed-zeros` | `x*0.0=0.0` |
| 函数级链接 | `/Gy` | `-ffunction-sections` | 移除未引用函数 |
| SSE 指令集 | `/arch:SSE` | `-msse` | 128 位 float |
| SSE2 | `/arch:SSE2` | `-msse2` | 128 位整数/double；x86-64 默认 |
| AVX | `/arch:AVX` | `-mavx` | 256 位浮点 |
| AVX2 | `/arch:AVX2` | `-mavx2` | 256 位整数 |
| AVX-512F | `/arch:AVX512` | `-mavx512f` | 512 位向量；本机 CPU 不支持 |
| 自动向量化 | `/fp:fast` | `-O2 -fno-trapping-math -fno-math-errno` | 另加 `-fveclib=libmvec`（GCC） |
| OpenMP | `/openmp` | `-fopenmp` | 并行指令 |
| 生成汇编 | `/FA` | `-S -masm=intel` | 查看编译器输出 |
| 生成 map 文件 | `/Fm` | `-Wl,-Map,out.map` | 看函数/数据布局 |

### 浮点选项详解（PDF 第 175 页）

- `-ffp-contract=fast`：`a*b+c` 融合为 FMA 指令，中间积无限精度。
- `-freciprocal-math`：除常数改乘倒数，对精度影响小、提速。
- `-fassociative-math`：允许 `(a+b)+c = a+(b+c)`；**精度后果严重**（例：`float a=1E10; b=(1+a)-a` 结果从 0 变 1）。建议用括号而不是开这个选项。
- `-ffinite-math-only`：允许 `x-x=0`，但若 x=INF 则错（INF-INF=NaN）；**可能检测不到 NaN/INF**。
- `-fno-trapping-math`：`0.0/0.0` 直接折叠为 NaN 不触发陷阱；向量化必需。
- `-fno-math-errno`：`sqrt` 等不再设 errno；向量化含数学函数的循环必需。
- `-fno-signed-zeros`：允许 `x*0.=0`、`x+0.=x`。

## 5. 简单示例

本项目的推荐编译参数（对应 `src/CMakeLists.txt`，阶段三实现）：

```bash
# Release 推荐组合（本机 g++ 13.3.0 实测可编译）
g++ -O3 -g -std=c++17 -Wall -Wextra -Wpedantic -fno-omit-frame-pointer main.cpp -o app

# 自动向量化分析
g++ -O3 -mavx2 -fopt-info-vec -fopt-info-vec-missed main.cpp -o app
# Clang 对应：-Rpass=loop-vectorize -Rpass-missed=loop-vectorize -Rpass-analysis=loop-vectorize

# 快速浮点（允许重排/FMA；注意精度语义变化）
g++ -O3 -ffast-math main.cpp -o app_fast
```

## 6. 未优化代码（参数层面）

```bash
# 默认编译 = 几乎无优化，且带调试信息
g++ main.cpp -o app           # 等价 -O0，性能极差（PDF p85）
```

## 7. 优化后代码（参数层面）

```bash
# Release 优化 + 保留调试符号 + 帧指针（便于 perf 定位）
g++ -O3 -g -fno-omit-frame-pointer -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o app

# 有损但更快的浮点（按应用取舍）
g++ -O3 -Ofast main.cpp -o app_ofast    # = -O3 -ffast-math
```

## 8. 为什么会更快

- **`-O3`**：开启函数内联、循环优化、向量化等全部常规优化（PDF 第 174 页）。
- **`-mavx2`**：允许用 256 位向量寄存器，吞吐翻倍于 SSE（PDF 第 73 页）。
- **`-ffast-math` 系列**：放行编译器不敢做的浮点变换（重排、FMA、`x-x=0`）（PDF 第 175 页）。
- **`-fno-omit-frame-pointer`**：保留帧指针供 perf 符号化热点（这是本项目故意保留的"逆向优化"，便于分析）。
- **`-g`**：保留调试符号，`perf report` 能显示函数名（PDF 第 89 页精神）。

## 9. 如何验证

```bash
# 同一源码，不同参数，看运行时间与汇编
g++ -O0 -std=c++17 main.cpp -o app_O0
g++ -O2 -std=c++17 main.cpp -o app_O2
g++ -O3 -std=c++17 main.cpp -o app_O3
g++ -O3 -mavx2 -std=c++17 main.cpp -o app_avx2
for a in app_O0 app_O2 app_O3 app_avx2; do echo "-- $a"; time ./$a; done

# 看 -mavx2 是否真的用了 ymm
g++ -O3 -mavx2 -std=c++17 -S -masm=intel main.cpp -o /tmp/app_avx2.s
grep -c "ymm" /tmp/app_avx2.s

# 对比 -Os vs -O3 的代码体积
g++ -Os -std=c++17 main.cpp -o app_Os && g++ -O3 -std=c++17 main.cpp -o app_O3
ls -l app_Os app_O3
```

- 编译命令：见上（本机 g++ 13.3.0）
- 运行命令：`time ./app_*`
- 查看汇编：`-S -masm=intel`；搜 `ymm`/`vaddps` 等确认向量化
- 代码体积：`ls -l`；函数级链接后 `-ffunction-sections` 效果

## 10. 常见误区

- **误区一：`-O3` 一定比 `-O2` 快。** 代码缓存/微操作缓存成为瓶颈时 `-Os` 可能更快（PDF 第 85 页）。
- **误区二：`-ffast-math` 只是"快一点"。** 它可能改变 NaN/INF 语义、重排操作数（PDF 第 175 页）。
- **误区三：`-mavx512f` 编出来就能跑。** 当前 CPU 无 AVX-512，会非法指令崩溃（PDF 第 124 页）。
- **误区四：默认编译就够。** 默认 `-O0`，性能与 `-O3` 差距巨大（PDF 第 85 页）。
- **误区五：`-fomit-frame-pointer` 无副作用。** 会牺牲栈回溯；本项目保留它用于 perf（PDF 第 86 页）。

## 11. 实践任务

1. 同一程序以 `-O0/-O1/-O2/-O3/-Os` 编译，记录运行时间与可执行文件大小，画一张权衡表。
2. 打开/关闭 `-ffast-math` 运行一个含 `x-x`、`0*x` 的浮点程序，观察结果变化（对应 PDF 第 175 页的例子）。
3. 用 `-mavx2` 与默认编译同一向量循环，用汇编确认寄存器宽度。
4. 添加 `-fopt-info-vec` 编译，阅读 GCC 的向量化日志。
5. 在 `-ffunction-sections` + `--gc-sections` 下对比链接后体积。

## 12. 本章总结

- 优化选项 = 告诉编译器"可以做什么"；级别、指令集、浮点模型是三大旋钮。
- 浮点选项有精度代价，按应用取舍，别盲目 `-ffast-math`。
- 指令集选项需与 CPU 能力匹配（本机上限 AVX2）。
- 查表：PDF 第 174～177 页表 18.1/18.2/18.3。
