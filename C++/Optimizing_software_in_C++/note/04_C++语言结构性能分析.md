# 04 C++语言结构性能分析

> 本笔记对应 PDF 第 7 章 The efficiency of different C++ constructs（第 25～68 页），覆盖 7.1～7.36 全部小节。

## 1. 本章解决什么问题

大多数程序员并不清楚一段 C++ 代码如何被翻译成机器码、CPU 又是如何处理这些机器码的。结果是一些普遍直觉是错的：

- 很多人以为单精度比双精度快——其实在非向量代码里两者一样快；
- 很多人以为模板类"复杂所以慢"——其实它比多态类（虚函数）更快。

本章逐一解释 C++ 各种语言元素的**相对效率**，帮助读者在所有选项中选择最高效的写法（来源：PDF 第 25 页，章节 7 引言）。它是后续"编译器优化""内存与缓存""乱序执行"等章节的语言基础。

## 2. 核心概念

| 术语 | 含义 | 出处 |

## 3. 工作原理

### 3.1 变量存在哪里？

C++ 变量的存储位置决定缓存效率（PDF 第 25 页）：

- **栈**：函数内声明的变量。同一地址反复复用，几乎必然命中 L1；栈是最高效的存储。
- **静态/全局**：整个程序生命周期占用，不能被其他用途复用，缓存效率差。但便于启动前初始化。
- **寄存器**：最快的存储，但数量有限（64 位 x86 约 14 个整数寄存器、16 个浮点寄存器）。
- **堆（new/delete）**：分配/释放耗时，容易碎片化，对象在内存中分散，缓存效率差（PDF 第 28 页）。

### 3.2 分支和预测

现代 CPU 用流水线取指/译码，遇到分支时必须在执行前决定走哪条路。猜错时之前取指、译码甚至推测执行的工作全部作废，恢复代价约 15-25 个周期（PDF 第 43 页）。CPU 依据分支的历史模式预测，周期性模式预测得好，50-50 随机的最差。

### 3.3 浮点有两种寄存器

x87 寄存器栈（80 位长双精度）与 SSE 向量寄存器（XMM/YMM/ZMM，单/双精度）。现代编译器在 64 位或启用 SSE 后都优先用向量寄存器（PDF 第 31-32 页）。这决定了 float/double 的转换成本等结论。

## 4. PDF 核心观点

按 7.1～7.36 组织，每条标注页码。

### 7.1 变量存储方式（第 25～29 页）

- 变量/对象应尽量在**使用它们的函数内部声明**（栈存储）；全局/静态变量应避免（PDF 第 26 页）。
- 查表数据应声明为 `static const`：`static` 让表只初始化一次，`const` 让编译器知道表永不改变，免去"首次调用检查"开销（PDF 第 26 页，Example 7.1）。
- 编译器自动把最常用的变量放入寄存器；**被取地址（有指针/引用指向）的变量不能进寄存器**（PDF 第 27 页）。
- `volatile` 防止优化、强制存内存，但**不保证原子性**，多线程写入仍需同步（PDF 第 27 页，Example 7.3）。
- `thread_local` 经线程环境块指针访问，低效；尽量改为线程函数内的普通局部变量（栈）（PDF 第 28 页）。
- 动态内存分配（new/delete）开销大、碎片化、破坏缓存；只有在大小编译期未知且上限无法预估时才值得用（PDF 第 28 页）。

### 7.2 整数变量与运算符（第 29～31 页）

- 用 `stdint.h`/`inttypes.h` 声明指定大小的整数（跨平台）（PDF 第 29 页，表 7.1）。
- 默认 `int`（寄存器宽度）最有效；char/short 转换约 0-1 周期；大数组用最小够用的类型省缓存（PDF 第 29 页）。
- signed vs unsigned：**除法/取模常数时 unsigned 更快**；**转浮点时 signed 更快**；unsigned 溢出有明确定义（回绕），signed 溢出是 UB（PDF 第 30 页，Example 7.4）。
- 加减/比较/位运算/移位约 1 周期；**乘法 3-11 周期**；**除法 40-80 周期**（PDF 第 31 页）。
- `x = array[i++]` 比 `x = array[++i]` 高效（后者要等 i 更新后才能算地址）（PDF 第 31 页）。

### 7.3 浮点变量与运算符（第 31～33 页）

- 非向量化时 **float 和 double 一样快**；但除法/开方/数学函数 float 更快（PDF 第 32 页）。
- 可用 float 存大数组省缓存；可用 double 而不用担心普通运算成本（PDF 第 32 页）。
- **不要混用 float 和 double**（转换 2-15 周期，XMM 下）；避免整数↔浮点转换（PDF 第 32 页）。
- 浮点加法 2-6 周期、乘法 3-8 周期、除法 14-45 周期（PDF 第 32 页）。
- 建议开启 flush-to-zero 模式避免次正规数（subnormal）惩罚：`_MM_SET_FLUSH_ZERO_MODE(_MM_FLUSH_ZERO_ON)`（PDF 第 33 页，Example 7.5）。

### 7.4 枚举（第 33 页）

- enum 就是整数，和整数一样快。

### 7.5 布尔（第 33～35 页）

- `&&`/`||` 短路求值：把**最可能 false** 的操作数放 `&&` 最后，**最可能 true** 的放 `||` 最前，减少求值次数（PDF 第 33 页）。
- 布尔变量是"过度决定"的（0/1），`a && b` 会生成分支；用位运算 `a & b`、`a | b` 替代可免分支（PDF 第 34 页，Example 7.9）。
- `b = !a` 可写为 `b = a ^ 1`（要求 a 确定是 0/1）（PDF 第 35 页）。
- 但 `a && b` 不能替换为 `a & b`，如果 b 有副作用或 a 为 false 时 b 不应求值（PDF 第 35 页）。
- 整数可作为"布尔向量"：`y = a & b` 一次做 32 个 AND（PDF 第 35 页）。

### 7.6 指针和引用（第 35～37 页）

- 指针和引用效率相同，生成代码相同，只是风格差异（PDF 第 35 页，Example 7.12）。
- 指针算术隐含乘以对象大小：结构大小为 2 的幂时用移位，更快（PDF 第 37 页，Example 7.13）。
- 计算两指针之差要做除法（除非对象大小为 2 的幂）（PDF 第 37 页）。
- `x = *(p++)` 比 `x = *(++p)` 高效（PDF 第 37 页）。

### 7.7 函数指针（第 37 页）

- 目标地址可预测（上次调用同一个函数）时只多几个周期；地址变化会误预测，惩罚大。

### 7.8 成员指针（第 37～38 页）

- 简单情况只是偏移量/地址；**多重继承等复杂情况会让实现变复杂**，应避免。

### 7.9 智能指针（第 38 页）

- 访问对象本身无额外开销；创建/删除/复制/转移有开销，`shared_ptr` 高于 `unique_ptr`（PDF 第 38 页）。
- GCC/Clang 能剥掉 `unique_ptr` 的大部分开销，只留 new/delete（PDF 第 38 页）。
- 大量小动态对象 + 各自智能指针可能太贵，宜合并进单个容器（PDF 第 38 页）。

### 7.10 数组（第 38～40 页）

- 数组连续存储，无维度信息；边界检查需要容器类封装（PDF 第 38 页）。
- 多维数组**最后一个下标变化最快**（行主序），否则缓存失效（PDF 第 39 页，Example 7.17）。
- 非顺序访问时，列数/对象大小取 2 的幂可让地址计算用移位（PDF 第 39 页，Example 7.18）。
- 但大数组非顺序访问时**避免 2 的幂**，否则缓存竞争（PDF 第 40 页，详见 06 笔记）。

### 7.11 类型转换（第 40～43 页）

- signed↔unsigned 转换免费（只是重新解释位）（PDF 第 40 页）。
- 整数加宽约 1 周期；缩窄免费（丢弃高位）（PDF 第 40～41 页）。
- float↔double 精度转换在 XMM 下 2-15 周期（PDF 第 41 页）。
- int→float 4-16 周期；**unsigned→float 更长**，可先转 signed 再转（无溢出风险时）（PDF 第 41 页）。
- float→int 无 SSE2 时 50-100 周期（标准要求截断，需临时改舍入模式）；SSE2 后快得多（PDF 第 41 页）。
- `const_cast`/`reinterpret_cast`/C 风格转换不产生额外代码；`dynamic_cast` 做运行时检查，更慢（PDF 第 42～43 页）。

### 7.12 分支与 switch（第 43～45 页）

- 分支误预测惩罚约 15-25 周期（PDF 第 43 页）。
- 分支预测基于历史：总走同一边预测好；周期性模式可预测；50-50 随机最差，误预测 50%（PDF 第 44 页）。
- switch 的 case 标签连续（+1 递增）时用跳转表最高效；标签稀疏时变分支树/查找表（PDF 第 44 页）。
- 关键路径上分支越少越好；用查表替代不可预测的小分支：`a = lookup[b]`（PDF 第 44 页，Example 7.29）。
- BTB（分支目标缓冲）容量有限，分支/调用过多会发生竞争导致误预测（PDF 第 44 页）。

### 7.13 循环（第 45～48 页）

- 小常数循环次数可被完美预测（上限因 CPU 而异，约 9-100+）（PDF 第 45 页）。
- 循环展开优点：减少循环控制分支、消除 if 分支；缺点：占代码缓存/微操作缓存、可能溢出回环缓冲、奇数次需额外处理（PDF 第 45～46 页，Example 7.30）。
- 展开仅当有具体收益时做；含浮点/向量且计数为整数的循环，收益通常由浮点代码决定而非循环控制（PDF 第 46 页）。
- 最有效的循环控制：**预知终值的整数计数器**；避免循环控制依赖循环内计算（PDF 第 46 页）。
- `while (*p != 0)` 改为已知长度后的 `for (i = len; i > 0; i--)`（PDF 第 46 页，Example 7.31）。
- 数学迭代（泰勒/牛顿）用固定最坏次数代替残差判断，让 CPU 提前预测分支（PDF 第 46～47 页）。
- 循环计数器尽量用整数；需要浮点计数时加一个整数计数器（PDF 第 47 页，Example 7.32）。
- 倒计数到 0 略高效，但数组正序访问缓存更好，按需选择（PDF 第 47 页）。
- 复制/清零数组用 `memset`/`memcpy`，编译器常自动转换（PDF 第 47～48 页，Example 7.33）。

### 7.14 函数（第 48～50 页）

- 函数调用开销来源：跳转（可达 4 周期）、代码缓存碎片、32 位模式栈传参、栈帧/寄存器保存/异常信息、BTB 占用（PDF 第 48 页）。
- **不要为"变短"而拆分函数**；关键内层循环尽量完整留在单个函数内（PDF 第 48 页）。
- 内联小函数、避免内层循环里的嵌套函数调用（帧函数）（PDF 第 48 页）。
- 宏 `#define MAX` 参数会被重复求值；用 inline/template 替代（PDF 第 49 页，Example 7.34）。
- `__fastcall`/`__vectorcall`：32 位传参优化；64 位默认寄存器传参（PDF 第 49 页）。
- 只在本模块用的函数加 `static`、匿名命名空间或 hidden 可见性（PDF 第 49 页）。
- 全程序优化（WPO）可跨模块优化；64 位传参比 32 位高效（PDF 第 50 页）。

### 7.15 函数参数（第 50～51 页）

- 简单类型按值传递高效；复合类型满足（小、无拷贝构造/析构、无虚、无 RTTI）时也可寄存器传递（PDF 第 50 页）。
- 复合对象用 **const 引用**最稳妥；内联时编译器可优化掉引用（PDF 第 50 页）。
- 64 位 Linux 最多 14 个寄存器参数（6 整 + 8 浮），64 位 Windows 只有 4 个（PDF 第 50 页）。

### 7.16 函数返回类型（第 51 页）

- 尽量返回简单类型/指针/引用/void；复合对象返回经隐藏指针拷贝，可能调用拷贝构造（PDF 第 51 页）。
- 替代方案：返回 static 对象指针（有风险）、用 new 返回指针（低效）、让函数作为对象成员修改现有对象（PDF 第 51 页）。

### 7.17 尾调用（第 51～52 页）

- 函数最后一条语句是调用另一函数时，编译器把 call 替换为 jump，省一次返回（PDF 第 51 页，Example 7.35）。

### 7.18 递归（第 52 页）

- 递归每层占栈空间、参数/局部变量各一份；深递归使返回地址预测低效（PDF 第 52 页）。
- 非分支递归总可以用循环替代（更快）；处理树形数据时递归仍可能最合适（PDF 第 52 页）。
- 阶乘递归 vs 循环示例（Example 7.37/7.38）；尾递归比普通递归好但不如循环（PDF 第 52 页）。

### 7.19 结构与类（第 52～53 页）

- OOP 正面：一起用的变量存在一起（缓存好）、成员函数免传参（PDF 第 52 页）。
- OOP 负面：拆太多小类低效、`this` 指针占一个寄存器（32 位稀缺）、虚函数更慢（PDF 第 53 页）。
- 用类和成员函数不贵；普通结构（无成员函数）零负面影响（PDF 第 53 页）。

### 7.20 类数据成员（第 53～54 页）

- 数据成员按声明顺序连续存储，有对齐空洞；**重排成员可减少空洞**（PDF 第 53 页，Example 7.39）。
- 有虚函数的类含虚表指针（32 位 4 字节、64 位 8 字节）（PDF 第 54 页）。
- **成员偏移小于 128 字节时用 8 位偏移，代码更紧凑**；大数组放最后、最常用成员放最前（PDF 第 54 页，Example 7.40）。

### 7.21 类成员函数（第 54～55 页）

- 成员函数和"带指针/引用参数的普通函数"一样快（PDF 第 54 页，Example 7.41）。
- **static 成员函数不需要 this 指针，更快**；不需要访问非静态成员时就声明为 static（PDF 第 55 页）。

### 7.22 虚成员函数（第 55～56 页）

- 多态类每个实例有虚表指针，运行时查表派发（PDF 第 55 页）。
- 调用总是同一版本时，虚调用只比非虚多几个周期；**版本变化时可能误预测，惩罚 10-20 周期**（PDF 第 55 页）。
- 运行时多态只在"编译期无法确定版本"时才需要；可用模板实现编译期多态（PDF 第 55 页）。
- 作者坦言模板多态语法非常笨拙（kludgy），编译器若能自动去虚化则更省事（PDF 第 61 页）。

### 7.23 RTTI（第 56 页）

- RTTI 给所有类对象加额外信息，不高效；**编译器选项应关闭 RTTI**，用替代实现。

### 7.24 继承（第 56 页）

- 一般几乎没有性能代价；子类含父类所有成员、成员偏移变大、父/子函数可能分布在不同模块影响缓存（PDF 第 56 页）。
- **多重继承**会使成员指针/虚函数复杂化；可改用"对象内嵌"替代（PDF 第 56 页，Example 7.42）。

### 7.25 构造函数与析构函数（第 56～57 页）

- 构造函数内部实现为返回对象引用的成员函数，和普通成员函数一样快；不需要时就不写（PDF 第 56 页）。
- 拷贝构造在赋值/传参/返回时触发，含内存分配时是时间消耗点；用引用、move、所有权转移避免（PDF 第 57 页）。
- 不需要析构函数就不写；虚析构和虚函数一样（PDF 第 57 页）。

### 7.26 联合体（第 57 页）

- 共享内存省空间；也可用 `union` 重新解释数据位（如用整数操作浮点位）（PDF 第 57 页，Example 7.43）。
- 比指针类型转换更安全（不违反严格别名规则）（PDF 第 57 页）。

### 7.27 位域（第 57～58 页）

- 位域比结构成员访问慢；但大数组时省缓存/文件空间可能划算（PDF 第 57 页）。
- 组合写入 `x.abc = A | (B << 4) | (C << 6)` 比逐成员赋值快（PDF 第 58 页，Example 7.44）。

### 7.28 重载函数（第 58 页）

- 不同版本只是不同的函数，无性能惩罚。

### 7.29 重载运算符（第 58～59 页）

- 重载运算符等价于函数；表达式 `a = b + c + d` 产生中间临时对象，可手动合并减少临时（PDF 第 58 页，Example 7.45）。
- 大多数编译器在简单情况下会自动优化掉中间临时。

### 7.30 模板（第 59～61 页）

- 模板参数在编译期替换：`MultiplyBy<8>(x)` 中编译器看到常量 8，可用移位替代乘法（PDF 第 59 页，Example 7.46）。
- 模板效率来自编译期解析，源代码复杂但目标代码不复杂；**执行速度上模板没有成本**（PDF 第 59 页）。
- 模板实例按参数集区分，参数不同各生成一份代码（PDF 第 59 页）。
- 模板可实现编译期多态（ATL/WTL 风格 CRTP），比虚函数快；但语法笨拙、维护成本高（PDF 第 60～61 页，Example 7.47）。

### 7.31 线程（第 61～62 页）

- 上下文切换昂贵（所有缓存需适应新上下文）；时间片 10-30 ms（PDF 第 61 页）。
- 线程用于：不同优先级任务分离、避免 UI 阻塞、利用多核（PDF 第 61 页）。
- 多线程四类成本：启动/停止线程、任务切换、**同步通信（互斥量/信号量开销大）**、线程独立存储（PDF 第 62 页）。
- 线程安全函数不应使用静态变量（PDF 第 62 页）。

### 7.32 异常与错误处理（第 62～66 页）

- 异常处理无论异常是否发生都有簿记开销；代价因编译器而异（表驱动方法低、代码驱动方法高）（PDF 第 62 页）。
- 不需要异常处理时应**关闭该选项**；单函数用 `noexcept`（且要求其调用链也 noexcept）（PDF 第 63 页）。
- 帧函数（调用其他函数）需保存栈展开信息，叶子函数可省；热循环内避免帧函数调用（PDF 第 64 页）。
- 异常与向量代码不兼容（单个元素异常、未走分支也可能触发陷阱）；向量代码应依赖 NaN/INF 传播而非陷阱（PDF 第 65 页）。
- 不可恢复错误不要用 try/catch/throw：自定义错误函数打印信息后 `exit` 更高效（PDF 第 65 页）。
- 异常安全：用带析构的包装类清理资源（内存、句柄、锁、文件、连接）（PDF 第 66 页）。

### 7.33 其他栈展开场景（第 66～67 页）

- 线程终止与 `longjmp` 也会触发栈展开；避免 `longjmp`，关键代码不要依赖它（PDF 第 67 页）。

### 7.34 NaN 和 INF 的传播（第 67 页）

- 浮点错误大多会传播到最终结果（INF/NaN），这是**零额外成本**的错误检测方式（PDF 第 67 页）。
- 注意特例：正常数/INF=0；INF-INF、INF/INF、INF*0、0/0、sqrt(-1) 产生 NaN（PDF 第 67 页）。
- 用 `finite()` 判断结果是否为 INF/NaN（PDF 第 67 页）。

### 7.35 预处理指令（第 67～68 页）

- `#` 开头的指令在编译前解决，运行时零成本；`#if` 比 `if` 高效（编译期 vs 运行时）（PDF 第 67 页）。
- `#define` 常量与 `const int` 一般等价；浮点常量总占内存（PDF 第 68 页）。

### 7.36 命名空间（第 68 页）

- 命名空间无执行速度成本。

## 5. 简单示例

以"变量存储影响缓存"为例：查表数据用 `static const`（PDF 第 26 页，Example 7.1）：

```cpp
// Source: PDF p26 (Example 7.1)
// static const on a lookup table: the table is initialized only once and
// the compiler knows it never changes -> no first-call guard is needed.
float SomeFunction(int x) {
    static const float list[] = {1.1f, 0.3f, -2.0f, 4.4f, 2.5f};
    return list[x];
}
```

要点：不加 `static` 每次调用都重新构造；不加 `const` 编译器要为"首次调用初始化"加检查。两者都加，所有编译器都能最大化优化（PDF 第 26 页）。

## 6. 未优化代码

两个典型的低性能写法（来自本章多个小节）：

```cpp
// (A) Mixing float and double in one expression (PDF p32, p41).
//     Every operand mixes precision -> conversion instructions (2-15 cycles).
float a, b;
a = b * 1.2;          // 1.2 is a double constant -> convert b to double,
                      // multiply, convert result back to float.

// (B) Boolean ops that generate unpredictable branches (PDF p34).
bool c, a, b;
c = a && b;           // becomes nested if/else with branch misprediction risk
```

## 7. 优化后代码

```cpp
// (A) Keep one precision everywhere (PDF p32, section 14.7 later).
float a, b;
a = b * 1.2f;         // all float, no conversions

// (B) Use bitwise ops on values guaranteed to be 0/1 (PDF p34, Example 7.9b).
char a = 0, b = 0, c;
c = a & b;            // single instruction, no branches
```

## 8. 为什么会更快

- **指令数量**：混精度会插入转换指令（cvt 类），全部 float 后每表达式省掉 1-2 条指令；位运算 `&`/`|` 是单指令。
- **分支预测**：`a && b` 展开为嵌套分支，随机数据下频繁误预测（15-25 周期惩罚，PDF 第 43 页）；`a & b` 无分支。
- **指令依赖**：转换指令在依赖链上插入延迟（2-15 周期），降低吞吐。
- **编译器优化能力**：`-O3 -ffast-math` 下编译器会自己把 `b * 1.2` 视为全 float（因为结果要存 float）或自动混合；但显式写 `1.2f` 在所有编译器和选项下都稳定。
- **缓存**：这是语言结构层面，缓存收益主要体现在 7.1 的存储位置选择（栈 vs 静态 vs 堆）和 7.10 的数组遍历顺序。

> 适用范围说明：具体周期数（乘法 3-11、除法 40-80 等）来自 PDF 第 31 页，是 2004-2026 年间多种 x86 处理器的区间范围。在当前 i9-14900HX 上量级一致，但精确值请以 `uops.info` 或 Agner Fog 指令表（本书配套手册 4）为准。

## 10. 常见误区

- **误区一：float 比 double 快。** 非向量时一样快（PDF 第 32 页）。
- **误区二：模板类比普通类慢。** 模板无执行开销（PDF 第 59 页）；多态（虚函数）才有运行时派发（PDF 第 55 页）。
- **误区三：函数拆得越细越好。** 与作者观点相反（PDF 第 48 页）。
- **误区四：指针比引用快。** 两者生成相同代码（PDF 第 35 页）。
- **误区五：`volatile` 等于原子。** 不是；多线程仍需同步（PDF 第 27 页）。
- **误区六：混用 float/double 没关系。** 会引入昂贵转换（PDF 第 32、41 页）。
- **误区七：虚函数永远慢。** 调用同一版本时只多几个周期；且编译器可能自动去虚化（PDF 第 55、76 页）。
- **误区八：异常只在抛出时才慢。** 不抛出也要做簿记，成本取决于编译器（PDF 第 62 页）。

## 12. 本章总结

- C++ 各种结构开销差异巨大，且很多结论与直觉相反（float vs double、模板 vs 多态）。
- 变量存储：优先栈，避免全局/静态与动态分配；查表用 `static const`。
- 数据布局：成员重排、2 的幂、行主序遍历，直接决定缓存效率。
- 控制流：分支越可预测越好；循环用整数计数；数学迭代用固定次数。
- 函数：避免无谓拆分与嵌套调用；`static`/`inline` 帮助编译器优化。
- 多态与异常：虚函数/异常/RTTI 都有隐藏成本，能避免就避免。
- 规则不是永远正确：所有数字都依赖具体 CPU/编译器，最终以测量为准（PDF 第 25 页引言的精神）。
