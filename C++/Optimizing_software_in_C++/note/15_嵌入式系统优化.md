# 15 嵌入式系统优化

> 本笔记对应 PDF 第 17 章 Optimization in embedded systems（第 172～173 页），并衔接第 14.13 节 System programming（第 162 页）。

## 1. 本章解决什么问题

微控制器的资源比 PC 少得多：主频可能低一两千倍、RAM 可能少上百万倍。本章回答**在极端资源约束下怎么优化**：

1. 语言与框架怎么选？（交叉编译的 C/C++，避免在设备上编译/解释）
2. 哪些"PC 上合理"的做法在嵌入式上是灾难？（动态分配、浮点、容器、字符串类、虚函数）
3. 关键差异在哪？（嵌入式 CPU 可能没有分支预测、缓存、乱序执行）

核心结论：**越小的系统越要省资源：免动态分配、免浮点、免容器、免字符串类、免虚函数；中断服务程序只做最小工作。**

## 3. 工作原理

嵌入式 CPU 与 PC CPU 的关键差异（PDF 第 173 页）：

- 小型微控制器**没有分支预测**、**没有缓存**、**没有乱序执行**；
- 因此 PC 上相关的优化（分支可预测性、缓存布局、打破依赖链）在嵌入式上**不需要考虑**；
- 相反，资源总量（RAM、flash、主频）成为一切取舍的核心。

## 4. PDF 核心观点

### 第 17 章（第 172～173 页）

- 资源更少，更要在软件上省资源；避免大图形框架、解释器、JIT、系统数据库等软件层（PDF 第 172 页）。
- 最好性能：选可交叉编译的语言（C/C++），设备本身不编译/解释；关键设备驱动可能需汇编（PDF 第 172 页）。
- 按指南使用 C++ 时，它只比 C 多一点点资源（PDF 第 172 页）。
- **RAM 要精打细算**：大数组声明在使用它的函数内（返回即释放）；或复用同一数组做多种用途（PDF 第 172 页）。
- **完全避免 new/delete、malloc/free**：堆管理开销大、垃圾回收时机不可控，会干扰实时应用（PDF 第 172 页）。
- **不用标准容器**：它们大量用 new/delete；FIFO 用定长环形缓冲，不用链表（PDF 第 172 页）。
- **不用 string 类**：所有常见实现都用动态分配；用 C 风格字符数组（注意溢出检查责任）（PDF 第 172 页）。
- **避免虚函数**：比非虚函数耗资源（PDF 第 172 页）。
- **避免浮点**：小微控制器没有浮点执行单元，任何浮点运算要加载庞大的浮点库，非常慢（PDF 第 172 页）。
  - `a = b * 2.5` → `a = b * 5 / 2`（注意中间 `b*5` 溢出）；
  - 出现**一个**带小数点的常量就会加载整个浮点库；
  - 要保留两位小数时把数乘 100 存成整数。
- 整数 8/16/32 位；必要时装不下用最小尺寸省 RAM；整数尺寸跨平台不统一（PDF 第 173 页）。
- **ISR 只做最小工作**：保存一个数据单元到缓冲/从缓冲发数据；**绝不在中断里响应命令或做其他 I/O**；命令应放到低优先级主循环处理（PDF 第 173 页）。

### 衔接 14.13 系统编程（第 162 页）

- 设备驱动/ISR/高优先级线程里，耗时函数可能阻塞一切（PDF 第 162 页）。
- 系统代码遵守寄存器使用规则，只能用为系统代码设计的编译器和函数库（PDF 第 162 页）。
- 动态分配尤其危险；队列用定长环形缓冲；不用标准容器（PDF 第 162 页）。

## 5. 简单示例

定长环形缓冲 FIFO（无动态分配，PDF 第 103 页 Example 9.6 + 第 172 页"FIFO 用环形缓冲"）：

```cpp
// Fixed-size circular buffer FIFO: no heap, no allocation (PDF p103, p172).
template <typename T, int maxsize>
class FIFOQueue {
    T list[maxsize];      // fixed buffer on the stack/static
    int head = 0, tail = 0, n = 0;
public:
    bool put(T x) {
        if (n >= maxsize) return false;
        list[head] = x;
        head = (head + 1) % maxsize;
        ++n;
        return true;
    }
    bool get(T &out) {
        if (n <= 0) return false;
        out = list[tail];
        tail = (tail + 1) % maxsize;
        --n;
        return true;
    }
};
```

## 6. 未优化代码

嵌入式环境下的"PC 思维"反模式（PDF 第 172 页）：

```cpp
// (A) std::string / std::vector allocate on the heap repeatedly.
//     On a small MCU this fragments RAM and may hit the garbage collector.
#include <string>
std::string build_message(int id) {
    return std::string("id=") + std::to_string(id);   // heap allocations
}

// (B) Any float constant pulls in the floating point library (PDF p172).
double area = 3.14 * r * r;    // "3.14" -> whole FP library linked
```

## 7. 优化后代码

```cpp
// (A) Fixed char buffer + manual formatting (watch overflow, PDF p105, p172).
char message[32];
void build_message(char *buf, int id) {
    snprintf(buf, 32, "id=%d", id);   // bounded, no heap
}

// (B) Fixed-point arithmetic: multiply before scaling (PDF p172).
// value in hundredths; e.g. 3.14 -> 314
int area_hundredths(int r) {
    // 3.14 * r * r  (in hundredths) : 314 * r * r, watch overflow
    return 314 * r * r / 100;
}
```

## 8. 为什么会更快

- **动态内存分配**：避免堆管理与垃圾回收，杜绝不可控的停顿（实时应用的关键）（PDF 第 172 页）。
- **浮点库**：整数定点运算省掉整个浮点库的加载与执行时间（PDF 第 172 页）。
- **缓存/分支/乱序**：小微控制器没有这些机制，相关优化无需考虑；**省资源才是核心**（PDF 第 173 页）。

## 10. 常见误区

- **误区一：嵌入式也可以用 PC 的容器/字符串。** 标准容器/string 大量动态分配，在微控制器上是灾难（PDF 第 172 页）。
- **误区二：浮点只是"慢一点"。** 没有 FPU 时整个浮点库都会被链接进来（PDF 第 172 页）。
- **误区三：嵌入式也要考虑缓存/分支预测优化。** 小微控制器没有这些机制（PDF 第 173 页）。
- **误区四：ISR 里可以做完整处理。** ISR 应只保存数据/发数据，其余放主循环（PDF 第 173 页）。
- **误区五：`-O3` 一定最好。** 代码空间受限时 `-Os` 更合适（PDF 第 85 页）。

## 12. 本章总结

- 嵌入式优化的核心是**省资源**：RAM、flash、主频、功耗。
- 免动态分配、免浮点、免容器/字符串类、免虚函数。
- 定长环形缓冲、C 风格字符串、定点数是嵌入式标准做法。
- ISR 只做最小工作；命令放主循环。
- 小微控制器无缓存/分支预测/乱序，PC 相关优化不需考虑。
