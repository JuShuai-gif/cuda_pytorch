# 07 多线程优化

> 本笔记对应 PDF 第 10 章 Multithreading（第 111～112 页），并衔接第 7.31 节 Threads（第 61～62 页）。

## 1. 本章解决什么问题

单核频率受物理限制，提升吞吐的出路是**同时做多件事**。本章回答：

1. 程序怎么利用多核？（功能分解 vs 数据分解）
2. 什么任务适合并行？（粗粒度 vs 细粒度）
3. 并行有哪些隐藏成本？（线程创建/切换/同步/缓存共享）
4. 共享缓存带来什么陷阱？（多线程写同一缓存行 = 相互驱逐）

核心结论：**粗粒度并行收益大、细粒度并行靠乱序/向量而不是线程；线程数不要超过逻辑处理器数；修改的数据各线程独立、只读数据可共享。**

## 2. 核心概念

| 术语 | 含义 | 出处 |
|------|------|------|
| 功能分解 | 不同线程做不同类型的任务（UI、网络、计算） | PDF 第 111 页 |
| 数据分解 | 同一任务的数据切成块，每线程一块 | PDF 第 111 页 |
| 粗粒度并行 | 大段操作相互独立，很少需要协调 | PDF 第 111 页 |
| 细粒度并行 | 大量小子任务，频繁协调 | PDF 第 111 页 |
| 同步（synchronization） | 线程间通信/协调（互斥量、信号量） | PDF 第 112 页 |
| 超线程（SMT） | 一个物理核跑两个逻辑线程，共享执行单元 | PDF 第 112 页 |
| 上下文切换 | 时间片到期时任务切换，缓存需适应新上下文 | PDF 第 61 页 |
| 缓存行（cache line） | 多线程写同一缓存行会互相驱逐（伪共享） | PDF 第 112 页 |

## 3. 工作原理

### 3.1 三种并行手段（PDF 第 111 页）

1. **多 CPU / 多核**：把工作分成线程，每线程一个核（本章）；
2. **乱序执行**：单线程内并行（第 11 章，见 08 笔记）；
3. **向量操作**：单指令处理多数据（第 12 章，见 09/10 笔记）。

### 3.2 线程怎么分（PDF 第 111 页）

- **功能分解**：一个线程管 UI、一个管数据库通信、一个算数学。保证 UI 不被重计算阻塞。
- **数据分解**：单一大任务，把数据切成 N 块，每线程处理一块，N 通常等于逻辑处理器数。

### 3.3 多线程的四种成本（PDF 第 62 页）

1. 启动/停止线程：任务太短就不值得开线程；
2. 任务切换：时间片到期切换昂贵；
3. 同步与通信：互斥量/信号量开销"相当大"；
4. 独立存储：线程各有栈，共享缓存时可能竞争。

### 3.4 共享缓存的两面性（PDF 第 112 页）

多核共享至少末级缓存。好处：线程间通信快、共享代码/只读数据。坏处：各线程用不同内存区域会挤满缓存；**多线程写同一缓存行会互相使缓存失效**。

## 4. PDF 核心观点

### 第 7.31 节 Threads（第 61～62 页）

- 现代 CPU 多核，可真正同时运行多线程；每线程分到约 30 ms（前台）/10 ms（后台）时间片，切换时所有缓存要适应新上下文，代价高昂（PDF 第 61 页）。
- 线程用于优先级分离：键盘/鼠标响应高优先级，拼写检查/重排版低优先级（PDF 第 61 页）。
- 长任务放独立低优先级线程，避免 UI 卡顿（PDF 第 61 页）。
- 多线程四类成本（PDF 第 62 页，见上文 3.3）。
- 线程安全函数不应使用静态/全局变量（PDF 第 62 页）。

### 第 10 章 Multithreading（第 111～112 页）

- 并行三手段：多核、乱序、向量（PDF 第 111 页）。
- 功能分解适合"不同类型任务"，数据分解适合"单一重任务"（PDF 第 111 页）。
- **粗粒度并行才适合多线程**；细粒度并行下通信/同步开销吃掉收益，应改用乱序/向量（PDF 第 111 页）。
- 同优先级线程数不要超过逻辑处理器数（PDF 第 111 页）。
- 划分工作的方法：手工多线程、编译器自动并行化、OpenMP、`std::thread`、多线程函数库（如 Intel MKL）（PDF 第 111 页）。
- 只读数据可共享；**被修改的数据各线程独立**，最好放线程函数局部变量（各自栈）（PDF 第 112 页）。
- 线程特定数据结构应**按缓存行大小对齐（当前通常 64 字节）**，避免多线程写同一缓存行（PDF 第 112 页）。
- 同步机制（信号量/互斥量/消息）都耗时；组织数据使线程间通信最少；"各自结构、最后合并"优于"共享同一队列"（PDF 第 112 页）。
- 单逻辑处理器上多线程争资源无益；但文件/网络访问放独立线程可让计算与等待并行（PDF 第 112 页）。

### 10.1 同时多线程（超线程）（第 112 页）

- 一个物理核跑两个线程（如 4 核 8 线程）。两线程共享缓存与执行单元（PDF 第 112 页）。
- 若共享资源是瓶颈，超线程反而让每线程跑不到单线程一半速度（缓存驱逐）；若时间花在 cache miss/误预测/长依赖链上，超线程有利，但**不可能翻倍**（PDF 第 112 页）。
- 是否需要超线程要靠实验；不利时只用偶数号逻辑处理器（0,2,4...）（PDF 第 112 页）。
- OS 无法阻止高/低优先级线程同核互抢资源（PDF 第 112 页）。

## 5. 简单示例

数据分解 + reduction（归约）的经典骨架：每个线程算局部和，最后合并（PDF 第 111 页"每线程处理自己的数据块" + 第 112 页"最后合并"）：

```cpp
#include <thread>
#include <vector>
#include <numeric>
#include <iostream>

// Data decomposition + per-thread partial sums (PDF p111-112):
// each thread owns its block, results are merged at the end.
double parallel_sum(const std::vector<double> &v, int nthreads) {
    std::vector<double> partial(nthreads, 0.0);
    size_t chunk = v.size() / nthreads;

    std::vector<std::thread> threads;
    for (int t = 0; t < nthreads; ++t) {
        size_t begin = t * chunk;
        size_t end   = (t == nthreads - 1) ? v.size() : (t + 1) * chunk;
        threads.emplace_back([&, t, begin, end] {
            double s = 0.0;
            for (size_t i = begin; i < end; ++i) s += v[i];
            partial[t] = s;          // each thread writes its OWN slot
        });
    }
    for (auto &th : threads) th.join();

    return std::accumulate(partial.begin(), partial.end(), 0.0);
}

int main() {
    std::vector<double> v(8'000'000, 1.0);
    double s = parallel_sum(v, 8);
    std::cout << "sum = " << s << "\n";   // 8000000
}
```

> 注意：每线程写独立的 `partial[t]`（不同缓存行/不同下标），避免共享缓存行竞争（PDF 第 112 页）。

## 6. 未优化代码

两个反模式：

```cpp
// (A) Two threads hammering the SAME variable -> data race + cache line ping-pong.
//     PDF p112: threads writing to the same cache line invalidate each other.
std::atomic<double> g_sum{0.0};   // atomic: correct but serialized & slow

void bad_accum(const std::vector<double> &v, int nthreads) {
    std::vector<std::thread> ts;
    for (int t = 0; t < nthreads; ++t) {
        ts.emplace_back([&, t] {
            for (size_t i = t; i < v.size(); i += nthreads) {
                g_sum.fetch_add(v[i], std::memory_order_relaxed);
            }
        });
    }
    for (auto &x : ts) x.join();
}

// (B) Too many threads for a tiny job -> thread startup overhead dominates
//     (PDF p62: don't put a short task in its own thread).
```

## 7. 优化后代码

```cpp
// Each thread keeps a LOCAL accumulator (its own stack, its own cache line),
// merged only once at the end. No atomics, no locks in the loop.
double good_accum(const std::vector<double> &v, int nthreads) {
    std::vector<double> local(nthreads, 0.0);
    size_t chunk = v.size() / nthreads;
    std::vector<std::thread> ts;
    for (int t = 0; t < nthreads; ++t) {
        size_t b = t * chunk, e = (t == nthreads - 1) ? v.size() : (t + 1) * chunk;
        ts.emplace_back([&, t, b, e] {
            double s = 0.0;
            for (size_t i = b; i < e; ++i) s += v[i];
            local[t] = s;
        });
    }
    for (auto &x : ts) x.join();
    double sum = 0.0;
    for (double s : local) sum += s;      // merge once
    return sum;
}
```

## 8. 为什么会更快

- **多核利用**：N 个核并行算各自数据块，理想情况下近线性加速（受合并段与启动开销限制）（PDF 第 111 页）。
- **同步成本**：`fetch_add` 是原子操作，内部可能加锁/总线竞争，把全部线程串行化；局部累加后一次性合并，把同步从 N 万次降到 N 次（PDF 第 112 页"使通信最少"）。
- **缓存行竞争**：写同一变量（同一缓存行）导致各核缓存相互失效（cache line ping-pong）；每线程独立槽位彻底消除。
- **线程数量**：线程数 ≈ 逻辑核数，避免无谓的切换开销（PDF 第 111 页）。

## 9. 如何验证

```bash
# 编译（需要 pthread 或 C++17 后 std::thread 已内置，无需 -pthread 于多数 libstdc++）
g++ -O3 -std=c++17 -pthread multithread.cpp -o multithread

# 运行：程序输出不同线程数下的耗时与加速比
./multithread

# 用 perf 看是否有缓存行竞争/上下文切换
sudo perf stat -e context-switches,cache-misses ./multithread
```

- 编译命令：`g++ -O3 -std=c++17 -pthread`（本机 g++ 13.3.0）
- 运行命令：`./multithread`
- Benchmark 方法：每个线程数测多轮取中位数（`note/14_性能测试与Benchmark.md`）
- perf 命令：`sudo perf stat -e context-switches,cache-misses`（本机需 root）
- 查线程数：`nproc`（本机 32）；注意超线程（每核 2 线程，P/E 核混合）

> 补充说明：本机 i9-14900HX 是 P+E 混合架构（性能核 + 能效核），`nproc` 显示 32 个逻辑线程。多线程扩展性测试会受混合架构影响，加速比曲线不会完美线性，这是当前硬件的正常现象。

## 10. 常见误区

- **误区一：线程越多越快。** 超过逻辑核数只会增加切换开销（PDF 第 111 页）。
- **误区二：细粒度任务也值得开线程。** 同步开销会吃掉收益；细粒度应靠乱序/向量（PDF 第 111 页）。
- **误区三：共享原子变量就行。** 原子只是正确性；缓存行竞争与原子序列化会让性能崩盘（PDF 第 112 页）。
- **误区四：多线程一定比单线程快。** 单核争资源时反而更慢（PDF 第 112 页）。
- **误区五：超线程能翻倍。** 不可能；是否有利要实测（PDF 第 112 页）。
- **误区六：短任务也开线程。** 启动/停止开销大于任务本身（PDF 第 62 页）。

## 12. 本章总结

- 并行三手段：多核（线程）、乱序（单线程内）、向量（SIMD）。
- 数据分解 + 每线程独立局部结果 + 最后合并，是最高效的多线程形态。
- 同步与缓存行竞争是两大隐藏成本；能减少通信就减少通信。
- 线程数 ≈ 逻辑核数；超线程是否有利要实测。
