## 零、总览：算子全景分类图

Liger `ops/` 下共有约 40 个算子文件。按数学结构分 6 大族，学习优先级从高到低：

| 家族 | 算子 | 文件 | 学习级别 |
| ---- | ---- | ---- | -------- |
| **归一化** | RMSNorm, LayerNorm, GroupNorm, PolyNorm, ModulatedRMSNorm, FusedAddRMSNorm | `rms_norm, layer_norm, group_norm, poly_norm, modulated_rms_norm, fused_add_rms_norm` | 必学 |
| **门控/激活** | SwiGLU, GEGLU, ReLUSquared | `swiglu, geglu, relu_squared` | 必学 |
| **位置编码** | RoPE, Llama4RoPE, Qwen2VL M-RoPE | `rope, llama4_rope, qwen2vl_mrope` | 必学 |
| **损失函数** | CrossEntropy, FusedLinearCE, KLDiv, JSD, TVD, FusedLinearJSD, VocabParallelCE | `cross_entropy, fused_linear_cross_entropy, kl_div, jsd, tvd, fused_linear_jsd, vocab_parallel_cross_entropy` | 必学 |
| **分布变换** | Softmax, Sparsemax | `softmax, sparsemax` | 必学 |
| **扩展** | TiledMLP, FusedMoE, MultiTokenAttention, DYT, MHC, GRPO loss, neighborhood attention | 大文件 | 可选/了解 |

总原则不变：**每完成一个算子，就独立推导 forward/backward → 独立实现 → 验证正确 → benchmark → Nsight 分析 → 写文档。不要同时铺开多个算子。**

推荐顺序（由易到难，每一步覆盖新的 Triton 技术点）：

```text
RMSNorm(reduction) → LayerNorm(双归约) → SwiGLU(pointwise) → GEGLU(近似函数)
→ ReLUSquared(最简单) → Softmax(两遍扫描) → RoPE(索引) → Sparsemax(排序+支撑集)
→ CrossEntropy(online softmax) → FusedLinearCE(分块GEMM)
→ KLDiv → JSD → TVD (log 空间损失)
→ GroupNorm(2D grid) → FusedAddRMSNorm(多输出) → PolyNorm(多幂次) → ModulatedRMSNorm(广播+atomic)
→ Llama4RoPE(复数) → Qwen2VL M-RoPE(分段) → VocabParallelCE(AllReduce) → TiledMLP(重计算)
```

## 一、前置知识（动手前必须掌握的）

### 1. GPU 硬件架构

| 概念 | 说明 |
| ---- | ---- |
| SM (Streaming Multiprocessor) | GPU 的基本计算单元，一个 GPU 有几十到上百个 SM |
| Warp | 32 个线程一组，GPU 的执行/调度基本单位 |
| Block/Grid | CUDA 的线程组织：grid = 若干 block，block = 若干 warp |
| 寄存器 (Register) | 每线程最快存储，容量最小，决定 occupancy |
| Shared Memory | 每个 block 内的共享存储，比全局快一个量级 |
| L1/L2 Cache | 缓存层次，L2 是所有 SM 共享的 |
| HBM/DRAM | 全局显存，带宽大但延迟高（几百 ns） |
| Tensor Core | 专门做矩阵乘的硬件单元，fp16/bf16 吞吐是 fp32 数倍 |
| Occupancy | 一个 SM 上同时驻留的 warp 数，受寄存器/共享内存限制 |
| HBM 带宽 | H100 ~3.3TB/s，A100 ~2TB/s，这是 memory-bound kernel 的天花板 |

**核心直觉：GPU 算得快，但"把数据搬进 GPU"慢。99% 的 kernel 优化是在权衡"多算一遍"还是"多读一次内存"。**

### 3. PyTorch autograd 机制

```python
class MyFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, w, eps):
        # 1. 调用 Triton kernel
        out, rstd = triton_forward(x, w, eps)
        # 2. ctx 保存 backward 需要的东西
        ctx.save_for_backward(x, w, rstd)   # 必须张量
        ctx.eps = eps                       # 任意 Python 对象
        return out

    @staticmethod
    def backward(ctx, grad_output):
        x, w, rstd = ctx.saved_tensors
        dx, dw = triton_backward(grad_output, x, w, rstd)
        return dx, dw, None   # 每个 forward 参数对应一个梯度，None 表示不需要梯度
```

要点：
- **返回的梯度数量必须和 forward 的输入参数数量一致**（包括非张量参数返回 None）
- **forward 返回多个张量时，backward 接收多个 grad_output**（如 FusedAddRMSNorm 返回 `Y, S`，backward 接收 `dY, dS_out`）
- `ctx` 里保存的东西决定了显存占用：**能重算的就不保存**（CrossEntropy 只在 forward 算梯度，backward 基本是空壳）
- `@amp_custom_fwd` / `@amp_custom_bwd`：混合精度下让自定义算子正确参与 autocast

### 4. 数值稳定性基础

```math
softmax(x_i) = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}, \quad m = \max_j x_j
```

- 直接算 `e^{x_i}` 在 x 很大时溢出 → 必须减去最大值 m
- 除法 `1/sqrt(v)` 用 `rsqrt` 代替（更准更快）
- 训练 kernel 的中间计算一律升 **fp32**，只在读写内存时用 fp16/bf16
- `e^x = e^{x·log2(e)} = 2^{x·1.4426950408889634}` → 硬件有 `ex2.approx` 指令，比 `exp` 快
- **log 空间运算**：损失函数（KL/JSD/TVD）的输入输出都是 log 概率，避免 `exp` 再 `log` 的精度损失
- **符号函数与不可导点**：TVD 的 `|x|` 在 0 处不可导，实现时取子梯度 `sign`

### 5. 分布与损失基础

```math
KL(P\|Q) = \sum_i P_i \log\frac{P_i}{Q_i}, \quad
JSD_\beta(P\|Q) = \beta\,KL(P\|M) + (1-\beta)\,KL(Q\|M), \quad M = \beta P + (1-\beta)Q
```

- KL 只在一个方向有梯度（对 Q 的梯度与 P 无关）
- 广义 JSD 把 forward KL（β=0）和 reverse KL（β=1）统一
- TVD 是全变差距离，实现最简单，常用作 stable 的蒸馏目标

## 四、阶段 1：RMSNorm（第一个算子，完整走一遍）

### 4.1 数学定义

```math
y_i = \frac{x_i}{\sqrt{\frac{1}{N}\sum_{j=1}^{N} x_j^2 + \varepsilon}} \cdot w_i
```

定义 `rstd = 1/sqrt(mean(x²) + eps)`（逐行一个标量），则：

```math
y_i = rstd \cdot w_i \cdot x_i
```

### 4.2 梯度推导（必须自己推一遍）

设损失 `L = Σ_i dy_i · y_i`，一行内 rstd 依赖所有 `x_j`。

```math
\frac{\partial L}{\partial w_i} = dy_i \cdot rstd \cdot x_i

\frac{\partial rstd}{\partial x_i}
= \frac{\partial}{\partial x_i} (\overline{x^2}+\varepsilon)^{-1/2}
= -\frac{rstd^3}{N} \cdot x_i

\frac{\partial L}{\partial x_i}
= dy_i w_i rstd + \left(\sum_j dy_j w_j x_j\right)\frac{\partial rstd}{\partial x_i}
= rstd \cdot (dy_i w_i) - \frac{rstd^3}{N}\left(\sum_j dy_j w_j x_j\right) x_i
```

用 Liger 源码注释里的写法（`ops/rms_norm.py:159`）：

```math
dx = \frac{1}{RMS}\left[dy \cdot w - \frac{1}{N}\frac{1}{RMS^2}\left((dy\cdot w)\cdot x\right)\cdot x\right], \qquad dw = \sum_{rows} dy \cdot \frac{x}{RMS}
```

### 4.3 源码阅读顺序（`ops/rms_norm.py`，669 行）

| 阅读段 | 行号 | 学什么 |
| ------ | ---- | ------ |
| `_rms_norm_forward_kernel` | 57-132 | 一行一个 program；`mask = col_offsets < n_cols`；fp32 升精度策略 |
| `_rms_norm_backward_kernel` | 135-225 | 梯度公式的 kernel 化；**按 SM 分 grid**（见下）；dW 用累加 |
| `rms_norm_forward/backward` | 422-595 | Python 启动层：grid 计算、stride 传参、dtype 处理、kernel 二选一逻辑 |
| `LigerRMSNormFunction` | 598-669 | autograd 壳：`save_for_backward(X, W, RSTD)` |

### 4.4 Liger 的三个关键设计（抄的重点）

**① RSTD 缓存（forward 保存 rstd 供 backward 用）**
- forward 里 `tl.store(rstd_base, rstd)`，backward 直接 `tl.load(rstd_base)`
- 省掉 backward 里 4 个操作（乘方、求和、除、开方），只多存 `n_rows` 个标量
- **这就是"中间结果存什么、重算什么"的权衡实例**

**② backward 按 SM 数分 grid（`ops/rms_norm.py:523`）**
```python
sm_count = torch.cuda.get_device_properties(X.device).multi_processor_count
rows_per_program = math.ceil(n_rows / sm_count)
grid = (sm_count,)
```
- 每个 program 处理 `rows_per_program` 行（用 for 循环遍历），一个 program 内累加 dW
- **好处：dW 没有跨 program 竞争，不需要 atomic，每个 program 只写自己那段 dW 列**
- 对比 naive 版本"一行一个 program"：grid 太大、dW 需要 atomic 归约

**③ casting_mode 三态（`ops/rms_norm.py:415-419`）**
| 模式 | 行为 | 对应模型 |
| ---- | ---- | -------- |
| `llama` | 只把 rstd 计算升 fp32，乘法在原 dtype | Llama |
| `gemma` | 全部升 fp32 算完，再 cast 回原 dtype | Gemma（还要 `offset=1.0` 即 `y = x·(w+1)`） |
| `none` | 全程原 dtype，最快但误差大 | 教学用 |

这是**复现 HuggingFace 数值行为**的关键，也是 benchmark 里要和 eager 版对得上的原因。

### 4.6 正确性测试模板（照抄这个结构）

```python
import torch
import torch.nn as nn

class LlamaRMSNorm(nn.Module):   # PyTorch Reference
    def __init__(self, hidden_size, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))
        self.variance_epsilon = eps
    def forward(self, hidden_states):
        input_dtype = hidden_states.dtype
        hidden_states = hidden_states.to(torch.float32)
        variance = hidden_states.pow(2).mean(-1, keepdim=True)
        hidden_states = hidden_states * torch.rsqrt(variance + self.variance_epsilon)
        return self.weight * hidden_states.to(input_dtype)

# 测试：
# 1. forward 对比：torch.testing.assert_close(ref_out, triton_out, rtol=..., atol=...)
# 2. backward 对比：分别 backward 后比 input.grad 和 weight.grad
# 3. shape 覆盖：(1,128) (7,768) (32,1024) (127,4096) (1024,4096) (4096,8192) —— 故意带非 2 次幂
# 4. dtype 覆盖：float32 / float16 / bfloat16
```

## 五、阶段 2：LayerNorm

### 5.1 数学定义（RMSNorm + 减均值）

```math
\mu = \frac{1}{N}\sum_j x_j, \qquad \sigma^2 = \frac{1}{N}\sum_j (x_j - \mu)^2, \qquad n_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \varepsilon}}
y_i = n_i \cdot w_i
```

### 5.2 梯度推导

```math
dx_i = \frac{w_i}{\sqrt{\sigma^2+\varepsilon}}\left[dy_i - \frac{1}{N}\sum_j dy_j - \frac{1}{N}\, n_i \sum_j dy_j n_j\right]
\qquad dw_i = \sum_{rows} dy_i \cdot n_i
```

推导（设 `n_i=(x_i-μ)/σ`，`L=Σ dy_i·w_i·n_i`）：
1. 链式法则：`dx_i = (∂n_j/∂x_i)` 的转置作用。先看 `dy` 对归一化的梯度 `v_j = dy_j·w_j`。
2. `n_j` 对 `x_i` 求导有三条路径：直接（`(1/σ)δ_ij`）、通过 μ（`∂n_j/∂μ·∂μ/∂x_i`）、通过 σ（`∂n_j/∂σ·∂σ/∂x_i`）。
3. 化简后得到上式。两条额外项分别对应 `mean(dy)` 和 `mean(dy·n)` 两个归约。

对比 RMSNorm 的梯度（`dx = rstd·(dy·w) - (rstd³/N)·(Σ dy·w·x)·x`），LayerNorm 多了**两个 reduction**：`Σ_j dy_j` 和 `Σ_j dy_j n_j`。

### 5.3 与 RMSNorm 源码对照（`ops/layer_norm.py`，320 行）

阅读重点：
- 同样有 `_layer_norm_forward_kernel` / `_layer_norm_backward_kernel`
- **多一个 mean 的 reduction**，backward 里要算两个 dot：`tl.sum(m, axis=0)` 和 `tl.sum(m * n, axis=0)`（对应上面梯度里的两个 Σ）
- 注意 `elementwise_affine` 分支：没有 weight 时跳过

### 5.4 知识点：多 reduction 的 kernel 怎么写

- forward 需要一次 pass 算 mean 和 var（`tl.sum` 两次，或 E[x²] - E[x]² 但数值不稳，推荐先算 mean 再算 var）
- backward 需要额外一遍 load x（不保存中间结果的话）
- 可以对比"保存 mean/var vs 重算"的显存-计算权衡（RMSNorm 学的是 rstd 缓存，这里学 mean+var 缓存）

## 六、阶段 3：SwiGLU / GEGLU / ReLUSquared

### 6.1 SwiGLU 数学定义

```math
\text{SiLU}(a) = a \cdot \sigma(a) = a \cdot \frac{1}{1+e^{-a}}, \qquad y = \text{SiLU}(a) \cdot b
```

（a 是 gate，b 是 up projection；PyTorch 里 `torch.nn.functional.silu(a) * b`）

### 6.2 SwiGLU 梯度推导

```math
\frac{d\,\text{SiLU}(a)}{da} = \sigma(a) + a\,\sigma(a)(1-\sigma(a)) = \text{SiLU}(a)\,(1-\sigma(a)) + \sigma(a)
\frac{\partial y}{\partial b} = \text{SiLU}(a), \qquad \frac{\partial y}{\partial a} = b \cdot \frac{d\,\text{SiLU}(a)}{da}
```

所以：

```math
db = dy \cdot \text{SiLU}(a), \qquad da = dy \cdot b \cdot \left(\text{SiLU}(a)(1-\sigma(a)) + \sigma(a)\right)
```

这正是 Liger `ops/swiglu.py:84` 的代码：`da_row = dc_row * (silu_a * (1 - sig_a) + sig_a) * b_row * gate_multiplier`。

### 6.3 GEGLU 数学定义（tanh 近似）

```math
\text{GELU}(a) = a \cdot \Phi(a) \approx \frac{1}{2}a\left(1 + \tanh\left(\sqrt{\frac{2}{\pi}}\left(a + 0.044715 a^3\right)\right)\right), \qquad y = \text{GELU}(a)\cdot b
```

### 6.4 GEGLU 梯度推导

设 `z = √(2/π)·(a + 0.044715·a³)`，`t = tanh(z)`。由 `GELU(a) = 0.5a(1+t)`：

```math
\frac{d\,\text{GELU}(a)}{da}
= \underbrace{0.5(1+t)}_{\text{term1}}
+ \underbrace{0.5 a (1-t^2)\,\sqrt{\tfrac{2}{\pi}}\,(1 + 3\cdot 0.044715\,a^2)}_{\text{term2}}
```

其中 term2 用了 `dt/da = (1-t²)·dz/da`，`dz/da = √(2/π)(1 + 3·0.044715·a²)`。于是：

```math
db = dc \cdot \text{GELU}(a), \qquad da = dc \cdot b \cdot (\text{term1} + \text{term2})
```

### 6.5 GEGLU 源码阅读重点（`ops/geglu.py`，146 行）

| 要点 | 说明 |
| ---- | ---- |
| `a_cubed = a*a*a` | 先算 a³ 复用 |
| `tanh_arg` | `sqrt_2_over_pi * (a + 0.044715 * a_cubed)`，常量 `sqrt_2_over_pi = 0.7978845608028654` |
| 重算不保存 | backward 重算 tanh 的所有中间量，只保存 a、b（`ctx.save_for_backward(a, b)`） |
| `geglu_a.to(dc_row.dtype).to(tl.float32)` | 注意 71 行先降精度再升精度，匹配 PyTorch 的数值行为 |
| `db_row.to(dc_row.dtype)` | 写回前 cast 到原始 dtype |

### 6.6 ReLUSquared（最简单的点算子）

```math
y = \text{relu}(x)^2 = \max(x, 0)^2
\frac{dy}{dx} = 2\,\text{relu}(x) = 2x \cdot \mathbb{1}(x>0)
```

源码（`ops/relu_squared.py`，120 行）：
- forward：`relu_x = tl.maximum(x_row, 0); y = relu_x * relu_x`
- backward：`dx = dy * 2 * relu_x`（重算 relu，不保存）
- **整个算子只有 forward/backward 两个 kernel，无归约、无 grid 技巧**，是理解"重算 vs 保存"的最小样例

### 6.7 知识点：pointwise fusion 是什么

- 普通实现：`silu(a)` 一次读+写，`*b` 又一次读+写 → **同一块数据读了 2 遍、写了 2 遍**
- fused 实现：一个 kernel 里完成 `silu(a)*b`，只读 a、b 各一次，写 y 一次 → **带宽减半**
- 这是 memory-bound kernel 优化最直接的收益来源

## 七、阶段 4：RoPE

### 7.1 数学定义（Llama/Mistral 的旋转位置编码）

对位置 m、维度对 `(2k, 2k+1)`，旋转：

```math
\begin{bmatrix} x'_{2k} \\ x'_{2k+1} \end{bmatrix}
=
\begin{bmatrix} \cos(m\theta_k) & -\sin(m\theta_k) \\ \sin(m\theta_k) & \cos(m\theta_k) \end{bmatrix}
\begin{bmatrix} x_{2k} \\ x_{2k+1} \end{bmatrix}

\theta_k = \frac{1}{10000^{2k/d}}
```

注意：**Liger 的旋转发生在"前半维 x_{i} 与后半维 x_{i+d/2}"之间**，不是相邻对（`ops/rope.py:91` 注释：`y = [x1,x2]*[cos,cos] + [-x2,x1]*[sin,sin]`），这是 HF Llama 的实现约定，和论文原版不同。

```math
x'_1 = x_1\cos - x_2\sin, \qquad x'_2 = x_2\cos + x_1\sin
```

### 7.2 梯度推导（旋转矩阵是正交矩阵）

旋转矩阵 `R` 满足 `R^T = R^{-1}`，所以 backward 就是把 grad 乘以 `R^T`：

```math
dx_1 = d\cdot\cos + \tilde d \cdot\sin, \qquad dx_2 = -d\cdot\sin + \tilde d \cdot\cos
```

（其中 d、\tilde d 分别是对应两个梯度的位置）这正是 `ops/rope.py:104-107`：
`new_q_tile_1 = q_tile_1*cos + q_tile_2*sin; new_q_tile_2 = q_tile_2*cos - q_tile_1*sin`。

### 7.3 Liger 源码阅读重点（`ops/rope.py`，239 行）

| 要点 | 说明 |
| ---- | ---- |
| 1D grid，一个 program 一个 token | `pid = program_id(0)`；`batch_idx = pid // sl`，`cos_row_idx = pid % sl` 反解出 (batch, seq) |
| 前/后半维分开 load | `first_half_q_offsets = arange(pad_n_qh)[:,None]*hd + arange(pad_hd//2)[None,:]`，二维 tile |
| **pad 到 2 次幂** | `pad_hd = next_power_of_2(head_dim)`，mask 掉越界元素 |
| cos/sin 只读左半 | cos 矩阵右半是左半的复制，只 load `hd//2` 个 |
| **in-place 写回** | forward 把 q、k 直接旋转后写回原地址（forward 与 backward 用同一个 kernel，`BACKWARD_PASS` 控制符号） |
| transpose trick | `q.transpose(1,2)` 让头维变成连续，再 `contiguous()` |

### 7.4 知识点

- **多维索引转成一维 tile**：`[:,None]` + `[None,:]` 广播生成二维 offset，这是 Triton 处理高维数据的基本功
- **in-place 与 `torch.autograd` 的配合**：`LigerRopeFunction.forward` 里 `ctx.save_for_backward(cos, sin)`，backward 对同一个 buffer 再旋转一次
- **分 head 的 mask**：`n_qh`（query head 数）和 `n_kv_h`（kv head 数）不同，mask 要分开写

## 八、阶段 5：CrossEntropy（最关键的算子）

### 8.1 数学定义

输入 logits `X[BT, V]`，target `y[BT]`。

```math
p_i = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}, \quad m = \max_j x_j, \quad \text{lse} = m + \log\sum_j e^{x_j-m}
\text{loss} = -\log p_y = \text{lse} - x_y
```

mean reduction（N = 非 ignore 的 token 数）：

```math
dx_y = \frac{p_y - 1}{N}, \qquad dx_i = \frac{p_i}{N}\ (i \neq y)
```

### 8.2 为什么需要 fused（显存关键）

普通 PyTorch 流程会显式生成 logits 张量 `[BT, V]`。BT=16384、V=128256 时 fp16 就是 **4GB**。Liger 的做法是**在 forward 里同时算 loss 和梯度，梯度写回 logits 本身**，整个流程只需要一个 kernel：

```text
X（logits）
  ↓ 一个 kernel：第一遍算 max+sum（online softmax），第二遍写回梯度到 X
loss（标量） + X 变成 grad_logits
```

这样 **backward 变成空壳**：不需要保存 X 和 target（`ctx.save_for_backward(_input.detach())`），显存省掉整个 logits 的备份。

### 8.3 Online Softmax（两遍扫描，`ops/cross_entropy.py:133-178`）

第一遍（在线更新 max 和 sum，参考 FlashAttention 论文 Algorithm 3）：

```math
m_{new} = \max(m, m_{block}), \qquad d_{new} = d \cdot e^{m - m_{new}} + \sum_{block} e^{x_i - m_{new}}, \qquad m = m_{new}
```

关键点：
- **分块扫描**（V 可以大于 BLOCK_SIZE，循环处理），每块都要更新全局 m、d
- 一旦 max 变化，前面块的求和要**按新的 m 重新缩放**（`d * exp2((m-m_new)*LOG2_E)`）
- **`tl.exp2(x*LOG2_E)` 替代 `tl.exp(x)`**：硬件指令，快 2-3 倍

第二遍（写梯度，`ops/cross_entropy.py:200-262`）：

```math
dx_i = \frac{e^{x_i - m}}{d} = \text{softmax}(x_i) \qquad\text{然后归一化}
```

### 8.4 label smoothing 的梯度（`ops/cross_entropy.py:279-292`）

```math
\varepsilon = \frac{\text{label\_smoothing}}{V}, \qquad
H(q',p) = (1-\alpha)H(q,p) + \varepsilon\sum_i \log\text{softmax}(x_i)
```

```math
dx_i = \frac{p_i - \varepsilon}{N}\ (i\neq y), \qquad dx_y = \frac{p_y - \varepsilon - (1-\alpha)}{N}
```

实现技巧：`scaled_x_sum` 在**第一遍**顺手累加 `Σ -ε·x_i`（因为 loss 里 `ε·Σ logsoftmax(x_i) = ε·Σ(x_i - lse)`），第二遍只处理 softmax 部分。

### 8.5 z-loss（`ops/cross_entropy.py:294-305`）

```math
\mathcal{L}_{z} = \beta \cdot \text{lse}^2, \qquad \frac{\partial}{\partial x_i} = \frac{2\beta\,\text{lse}\cdot p_i}{N}
```

用于训练稳定性（PaLM 论文），防止 logits 无限增长。

### 8.6 Liger 源码阅读重点（`ops/cross_entropy.py`，585 行）

| 行号 | 内容 | 学什么 |
| ---- | ---- | ------ |
| 97-116 | 先 load y，若 `y == ignore_index` 直接把该行 X 置 0 返回 | 分支短路，减少无谓计算 |
| 126-178 | 第一遍 online softmax，顺便算 `scaled_x_sum` | 多任务复用同一遍扫描 |
| 199-262 | 第二遍写梯度，`tl.debug_barrier()` 保证原地写对 | **原地写回时的同步问题** |
| 262 | `tl.store(X_ptr + y, tl.load(X_ptr+y) + dxy)` | 对 target 位置做最后修正 |
| 405-439 | host 层：`HAS_GRADIENTS = _input.requires_grad` | 用 constexpr 把分支编译掉 |
| 483-585 | `LigerCrossEntropyFunction` | backward 只做 grad_output 的缩放 |

### 8.7 知识点：为什么这里必须 `tl.debug_barrier()`

第二遍把 `dx_i` 写回 X，然后 `dx_y` 需要**先读回刚写好的 `X[y]` 再加修正项**。同一个 block 内，store 后立即 load 同一地址可能读到旧值 → 必须 `tl.debug_barrier()` 强制写可见。

**坑提醒**：第一遍循环里 `X_row` 是 `other=float("-inf")`，第二遍重新 load；grad 是原地写 X，所以 backward 的 `save_for_backward(_input.detach())` 保存的是**已经是梯度的张量**。

## 九、阶段 6：Fused Linear CrossEntropy（压轴）

### 9.1 要解决的问题

最后一层线性层 `logits = X @ W^T`（X 是 `[BT, H]`，W 是 `[V, H]`），logits `[BT, V]` 是**全模型最大的中间张量**。Fused 思路：**把 token 分成 chunk，每块只物化 `chunk_size × V` 的 logits**。

### 9.2 分块大小的公式（`ops/fused_linear_cross_entropy.py:64-70`）

```python
inc_factor = cdiv(V, H)                  # V 是 H 的几倍
chunk_size = next_power_of_2(cdiv(BT, inc_factor))
num_chunks = cdiv(BT, chunk_size)
```

**让 chunk 数 = inc_factor**，则 logits 内存从 `BT×V` 降到 `(BT/inc_factor)×V = BT×H`，和输入 X 同量级。例：BT=16384, V=32000, H=4096 → inc_factor=8, chunk_size=2048。

### 9.3 整体流程（`fused_linear_cross_entropy_forward`）

```text
对每个 chunk:
  logits_chunk = X_chunk @ W^T            # chunk_size × V，物化一块
  liger_cross_entropy_kernel(logits_chunk) # 算 loss + 把梯度写回 logits_chunk（原地）
  grad_input[start:end] += grad_logits_chunk @ W          # dL/dX
  grad_weight += grad_logits_chunk.T @ X_chunk            # dL/dW
  grad_bias += grad_logits_chunk.sum(dim=0)               # dL/db
```

### 9.4 梯度（与普通 CE 相同，只是按 chunk 累加）

```math
\frac{\partial L}{\partial X} = G @ W, \qquad \frac{\partial L}{\partial W} = G^T @ X, \qquad \frac{\partial L}{\partial b} = \sum_{tokens} G, \qquad G = \frac{p - y_{onehot}}{N}
```

所有梯度**在 forward 就算完**（`grad_weight` 用 `torch.zeros_like` 初始化为累加器），backward 只做一件事：

```python
def fused_linear_cross_entropy_backward(grad_output, grad_input, grad_weight, grad_bias):
    # grad_output == 1.0 时直接跳过（CE 是最后一层）
    element_mul_kernel[(n_rows,)](grad_input, ..., grad_output, ...)   # 统一乘以 grad_output
```

这就是 **`@amp_custom_fwd` / `@amp_custom_bwd`** 存在的意义：forward 里完成所有数学，backward 只是缩放。

### 9.5 源码阅读重点（`ops/fused_linear_cross_entropy.py`，487 行）

| 行号 | 内容 |
| ---- | ---- |
| 108-197 | chunk 循环主体：matmul → CE kernel → 累加三个梯度 |
| 225-228 | `reduction="none"` 的 per-token grad_output 要先乘到 grad_logits 再投影（否则无法还原逐 token 权重） |
| 233-257 | grad_weight 的 addmm 路径（`out_dtype=fp32` 精确累加，注意 2.8 版本分支） |
| 292-336 | backward 的 `element_mul_kernel` 缩放 |
| 339-487 | `LigerFusedLinearCrossEntropyFunction`：`ctx.defer_grads` 处理 reduction="none" 的重算路径 |

### 9.6 知识点

- **梯度即时算（gradient checkpointing 的思想）**：forward 把 X、W、target 三个梯度都算好，backward 零重算
- **累加器精度**：`grad_weight += torch.mm(...).float()` 用 fp32 累加，避免 bf16 累加误差
- **`element_mul_kernel` 复用**：`ops/utils.py:108` 的通用小 kernel，被 CE 和 FusedLinearCE 共用 → **公共工具抽出来**

## 十、阶段 7：Softmax / Sparsemax（分布变换）

### 10.1 Softmax 数学定义

```math
y_i = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}, \quad m = \max_j x_j
```

### 10.2 Softmax 梯度推导

雅可比矩阵：`∂y_j/∂x_i = y_j(δ_{ij} - y_i)`。由 `dx_i = Σ_j dy_j ∂y_j/∂x_i`：

```math
dx_i = dy_i\, y_i - y_i\sum_j dy_j y_j = y_i\left(dy_i - \sum_j dy_j y_j\right)
```

记 `dot = Σ_j dy_j·y_j`，则 `dx = y ⊙ (dy - dot)`。这是 `ops/softmax.py:81` 的 `dx = y * (dy - dot)`。

### 10.3 Softmax 源码阅读重点（`ops/softmax.py`，201 行）

| 要点 | 说明 |
| ---- | ---- |
| 单块 vs 多块 | `n_cols <= BLOCK_SIZE` 用单块（`_softmax_single_block_forward_kernel`），否则用两遍扫描的多块版本 |
| 多块 forward | `m = -inf` 初始化，循环里 `d = d*exp(m-new_m) + sum(exp(x-new_m))`（online 更新） |
| 多块 backward | 第一遍循环累加 `acc = Σ dy·y`，第二遍循环 `dx = y*(dy-acc)` |
| cache modifier | load 用 `.ca`，store 用 `.cs`/`.wb`，控制 L1/L2 缓存策略 |
| 保存 y 而非 x | `ctx.save_for_backward(y)`，backward 只需要 y 和 dy（不需要 x） |

### 10.4 Sparsemax 数学定义

Sparsemax 是 softmax 的稀疏版本，在 simplex 上投影：

```math
\text{sparsemax}(x) = \arg\min_{p \in \Delta^{V-1}} \|p - x\|^2
```

解为：设 `x` 降序排序为 `x_{(1)} ≥ x_{(2)} ≥ ...`，求最大的 `k` 使 `1 + k·x_{(k)} > Σ_{j≤k} x_{(j)}`，则阈值：

```math
\tau = \frac{\sum_{j=1}^{k} x_{(j)} - 1}{k}, \qquad y_i = \max(x_i - \tau, 0)
```

### 10.5 Sparsemax 梯度推导

输出 `y = max(x - τ, 0)` 在**支撑集**（`y_i > 0`）上是仿射的：

```math
dx_i = \begin{cases} dy_i - \frac{1}{k}\sum_{j: y_j>0} dy_j, & y_i > 0 \\ 0, & y_i = 0 \end{cases}
```

推导：支撑集内 `τ` 依赖所有支撑集元素，`∂τ/∂x_j = 1/k`（因为 `τ = (Σ x_j - 1)/k`），所以 `dx_i = dy_i - Σ_j dy_j·(1/k)`。支撑集外梯度为 0。

### 10.6 Sparsemax 源码阅读重点（`ops/sparsemax.py`，177 行）

| 要点 | 说明 |
| ---- | ---- |
| host 层排序 | `x_sorted = torch.sort(x, dim=-1, descending=True)` 在 Python 里先排好序传入 |
| `tl.cumsum` | `cssv = tl.cumsum(z_valid, 0)` 一次算出所有前缀和 |
| `t_vec = (cssv - 1)/r` | 向量化求所有候选阈值，`r = offs+1` 是位置下标 |
| `support = z_sorted > t_vec` | 判断支撑集，`k = sum(support)` |
| `tau = (s-1)/k` | 最终阈值，`s = sum(z_sorted where support)` |
| 梯度 kernel | 两遍循环：第一遍算 `go_sum` 和 `supp_cnt`，第二遍 `gi = go - go_sum/supp_cnt` |

## 十一、阶段 8：归一化家族（GroupNorm / PolyNorm / ModulatedRMSNorm / FusedAddRMSNorm）

### 11.1 GroupNorm 数学定义

把 channel 分成 G 组，每组内归一化：

```math
\mu_g = \frac{1}{N_g}\sum_{i\in g} x_i, \quad \sigma_g^2 = \frac{1}{N_g}\sum_{i\in g}(x_i-\mu_g)^2, \quad N_g = \frac{C}{G}\cdot H
y_i = \frac{x_i - \mu_g}{\sqrt{\sigma_g^2+\varepsilon}}\cdot w_{c(i)} + b_{c(i)}
```

其中 `c(i)` 是元素 i 的 channel 下标。

### 11.2 GroupNorm 梯度推导（与 LayerNorm 相同，group 内归约）

```math
dx_i = \frac{w_{c(i)}}{\sigma_g}\left[dy_i - \frac{1}{N_g}\sum_{j\in g} dy_j w_{c(j)} - \frac{n_i}{N_g}\sum_{j\in g} dy_j w_{c(j)} n_j\right]
dw_c = \sum_{i: c(i)=c} dy_i\, n_i, \qquad db_c = \sum_{i: c(i)=c} dy_i
```

**与 LayerNorm 的唯一区别是归约范围**：从"整个 hidden"变成"组内 C/G×H 个元素"。数学形式完全相同。

### 11.3 GroupNorm 源码阅读重点（`ops/group_norm.py`，311 行）

| 要点 | 说明 |
| ---- | ---- |
| **2D grid** | `grid = (batch_size, num_groups)`，一个 program 处理一个 batch 的一个组 |
| mean/var 的 online 算法 | 循环累加 `s += sum(X)`、`squared_sum += sum(X*X)`，最后 `variance = E[X²] - E[X]²` |
| 按 channel 取 w/b | `global_channel = group_idx*channels_per_group + offsets // hidden_size_per_channel`，用索引整除 |
| **backward 用 atomic** | 不同 group 可能写同一个 channel 的 dW → `tl.atomic_add(DW_ptr + channel_idx, dW)`（`ops/group_norm.py:176`） |
| c1/c2 累计 | `c1 += Σ n·w·dy`、`c2 += Σ w·dy`，跨组累加后 `dx = (wdy - (n·c1+c2))·rstd` |

**知识点：什么时候该用 atomic？** RMSNorm 按 SM 分 grid 规避了竞争（每 program 写不同列），但 GroupNorm 多个 program 会写同一 channel，只能 atomic。对比学习两种方案。

### 11.4 FusedAddRMSNorm 数学定义

decoder 层常见三步融合成一个 kernel：

```math
S = X + R \quad(\text{残差相加}), \qquad \text{residual 更新为 } S, \qquad Y = \text{RMSNorm}(S)
```

返回 `(Y, S)` 两个输出。

### 11.5 FusedAddRMSNorm 梯度推导

因为加法 `S = X + R` 把梯度劈成两份：`dX = dR = dS`。而 `S` 同时流入 RMSNorm，所以：

```math
dX = dR = dS\_out + dS\_rms, \qquad dS\_rms = \text{RMSNormBackward}(dY, S, W)
```

即 `ops/fused_add_rms_norm.py:349` 的 `return dX, dX, dW  # dR is equal to dX`。

### 11.6 FusedAddRMSNorm 源码阅读重点（`ops/fused_add_rms_norm.py`，419 行）

| 要点 | 说明 |
| ---- | ---- |
| forward 输出两个张量 | `return Y, S`，backward 签名是 `backward(ctx, dY, dS_out)`（`ops/fused_add_rms_norm.py:400`） |
| **多输出 autograd** | 学习 `torch.autograd.Function` 的多输出写法 |
| `has_dS_out` | constexpr 控制是否加 dS_out（没有残差梯度时省一次 load） |
| dW 先算 | 注释说明"先算 dW 复用 dY 的寄存器，降低寄存器压力" |
| **没有 block 版本** | `# TODO: add _block_fused_add_rms_norm_forward_kernel` —— 只实现了一行一 program 的版本 |

### 11.7 PolyNorm 数学定义（PolyCom 论文）

```math
y = w_0\,\text{norm}(x^3) + w_1\,\text{norm}(x^2) + w_2\,\text{norm}(x) + b, \qquad \text{norm}(u) = \frac{u}{\sqrt{\text{mean}(u^2)+\varepsilon}}
```

`W` 形状 `(3,)`，`B` 是标量。

### 11.8 PolyNorm 梯度推导

记 `r_p = 1/\sqrt{\text{mean}(x^{2p})+\varepsilon}`（forward 缓存三个），`norm_p = x^p·r_p`，`D_p = 1/r_p = RMS(x^p)`，`S_p = Σ_i dy_i·x_i^p`：

```math
dx_i = \sum_{p=1,2,3} w_p \left[ p\, x_i^{p-1}\, r_p\, dy_i - \frac{p}{N}\, x_i^{2p-1}\, r_p^3\, S_p \right]
dw_p = r_p\, S_p, \qquad db = \sum_i dy_i
```

推导与 RMSNorm 完全同构：对每个幂次 p，把 `x^p` 看作 RMSNorm 的输入，`p·x^{p-1}` 是幂的链式因子，`∂r_p/∂x_i = -(p/N)·r_p³·x_i^{2p-1}`。

### 11.9 PolyNorm 源码阅读重点（`ops/poly_norm.py`，384 行）

| 要点 | 说明 |
| ---- | ---- |
| RSTD 形状 `(n_rows, 3)` | forward 缓存三个 rstd，`RSTD_row_stride = 3` |
| `w0/w1/w2` 标量 load | `tl.load(W_ptr + 0/1/2)`，`b = tl.load(B_ptr)` |
| backward 三个 S 标量 | `S_3 = sum(dY*X_pow3)` 等，标量归约 |
| 梯度拆三项 | `grad_x_3 + grad_x_2 + grad_x_1`（对应上式三个幂） |
| dW/dB 按 SM 累加 | `dW_ptr[pid][0/1/2]`、`dB_ptr[pid]`，host 端 `sum(dim=0)` |

### 11.10 ModulatedRMSNorm 数学定义

```math
y = \text{RMSNorm}(x)\cdot(1 + \text{scale}) + \text{shift}
```

`scale`/`shift` 形状 `(scale_rows, H)`，按 `rows_per_modulation = n_rows / scale_rows` 广播（多个 token 行共享一个 scale/shift 行）。

### 11.11 ModulatedRMSNorm 梯度推导

记 `rms_out = RMSNorm(x) = x·rstd·(w+offset)`，`Mod = 1+scale`：

```math
dscale = dy \cdot rms\_out, \qquad dshift = dy
dx = \text{RMSNormBackward}(dy \cdot Mod) \quad \text{（对 rstd 的路径不变）}
dw = \sum_{rows} dy\cdot Mod \cdot (x\cdot rstd)
```

推导：`y = rms·Mod + shift`，对 scale/shift 是逐元素的，`dy = ∂L/∂y` 先乘回 `Mod` 再走 RMSNorm 的 backward。

### 11.12 ModulatedRMSNorm 源码阅读重点（`ops/modulated_rms_norm.py`，508 行）

| 要点 | 说明 |
| ---- | ---- |
| `mod_row_idx = row_idx // rows_per_modulation` | 广播索引计算 |
| `dScale = dY * rms_output` | `rms_output` 是 RMSNorm 在**乘 Mod 之前**的输出（`ops/modulated_rms_norm.py:210`） |
| **`tl.atomic_add` vs `tl.store`** | `rows_per_modulation == 1` 直接 store，否则多个 token 行累加到同一 scale 行 → atomic（`:211-214`） |
| `has_shift` constexpr | 无 shift 时把 shift 当 scale 的别名省参数 |

**知识点：这是"广播 + atomic 累加"的典型案例**，和 GroupNorm 的 atomic 是同类问题。

## 十二、阶段 9：损失函数家族（KLDiv / JSD / TVD / FusedLinearJSD）

### 12.1 KLDiv 数学定义

```math
KL(P\|Q) = \sum_i P_i(\log P_i - \log Q_i)
```

PyTorch 约定：`input` 是 `log Q`（logspace），`target` 是 `P`（概率）。`log_target=True` 时 target 也是 log 空间。

```math
\text{loss}_i = \begin{cases} P_i(\log P_i - \text{input}_i), & \text{log\_target=False} \\ e^{Y_i}(Y_i - \text{input}_i), & \text{log\_target=True}\ (Y=\log P) \end{cases}
```

### 12.2 KLDiv 梯度推导

只对 `input`（即 `log Q`）有梯度（`P` 是常数目标）：

```math
\frac{\partial \text{loss}_i}{\partial \text{input}_i} = \begin{cases} -P_i, & \text{log\_target=False} \\ -e^{Y_i}, & \text{log\_target=True} \end{cases}
```

所以 backward 只是 `res = target * -1`（或 `-exp(target)`），见 `ops/kl_div.py:114-117`。这是**最轻量的 backward**——不需要 X，只依赖 target。

### 12.3 KLDiv 源码阅读重点（`ops/kl_div.py`，259 行）

| 要点 | 说明 |
| ---- | ---- |
| 4 种 reduction | `none/sum/mean/batchmean` 用 `tl.constexpr` 整数枚举 |
| `tl.log(tl.maximum(y_true, eps))` | 用 eps 防 log(0) |
| `log_target` constexpr | 两个分支编译期展开 |
| host 端做 reduction | `batchmean → sum()/BT`，`mean → sum()/(BT*V)`（注意 PyTorch 的坑：KLDiv 的 mean 是除全部元素数） |
| `ctx.save_for_backward(y_true)` | backward 只需要 target，不需要 input |

### 12.4 JSD 数学定义（generalized Jensen-Shannon）

```math
JSD_\beta(P\|Q) = \beta\,KL(P\|M) + (1-\beta)\,KL(Q\|M), \qquad M = \beta P + (1-\beta)Q
```

- `β=0.5`：标准 JSD（对称）
- `β=0`：forward KL `KL(P||Q)`
- `β=1`：reverse KL `KL(Q||P)`

输入全部在 log 空间：`X = log Q`（student），`Y = log P`（teacher）。

### 12.5 JSD 梯度推导（元素级）

逐元素 loss（log 空间，`P=e^Y`，`Q=e^X`，`M=βP+(1-β)Q`）：

```math
\text{loss}_i = \beta P_i Y_i + (1-\beta)Q_i X_i - M_i \log M_i
```

对 `X_i` 求导（注意 `Q_i=e^{X_i}`、`M_i` 依赖 `X_i`）：

```math
\frac{\partial \text{loss}_i}{\partial X_i}
= (1-\beta)Q_i + (1-\beta)Q_i X_i - (1-\beta)Q_i(\log M_i + 1)
= (1-\beta)Q_i\,(X_i - \log M_i)
```

这就是 `ops/jsd.py:85` 的 `dX = one_minus_beta_Q * (X - log_M)`。特例：β=0 时 `dX = -P`（`jsd.py:59`），β=1 时 `dX = Q(X-Y) + Q`（`jsd.py:65`，来自 reverse KL 的 `Q(X-Y)` 加 `Q` 的 log-sum 项）。

### 12.6 JSD 数值稳定性（log 空间防溢出）

```math
Q = e^{X - m}\cdot e^{m}, \quad P = e^{Y - m}\cdot e^{m}, \quad m = \max(\max X, \max Y)
```

先减全局最大值再 exp，然后乘回 `exp(m)` 补偿（`ops/jsd.py:67-76`）。这比直接 `e^X` 稳定。

### 12.7 JSD 源码阅读重点（`ops/jsd.py`，201 行）

| 要点 | 说明 |
| ---- | ---- |
| 一个 kernel 同时算 loss 和 dX | forward 里 `dX` 就写好了，backward 只乘 grad_output（`jsd.py:134-139`） |
| `HAS_LABEL` | 有 `shift_labels` 时对 ignore_index 的行梯度置 0 直接 return |
| β 三态 | `β==0` / `β==1` / 其他，三个分支都在 kernel 里用常量展开 |
| `scale = 1/n_non_ignore` | 提前乘进 loss 和 dX，避免 Python 端除法 |

### 12.8 TVD 数学定义

```math
TVD(P\|Q) = \frac{1}{2}\sum_i |P_i - Q_i|
```

### 12.9 TVD 梯度推导

```math
\frac{\partial}{\partial P_i}\left(\frac{1}{2}|P_i-Q_i|\right) = \begin{cases} +\frac{1}{2}, & P_i > Q_i \\ -\frac{1}{2}, & P_i < Q_i \end{cases}
```

（在 `P_i = Q_i` 处取子梯度 0。）代码：`grad_res = tl.where(p > q, 0.5*scale, -0.5*scale)`（`ops/tvd.py:89`）。

### 12.10 TVD 源码阅读重点（`ops/tvd.py`，218 行）

| 要点 | 说明 |
| ---- | ---- |
| **最简单损失** | 无 exp/log，无归约，逐元素 `abs` + `where` |
| reduction 缩放融进 kernel | `scale` 提前算好传入，loss 和 grad 都在 kernel 内乘好 |
| 和 JSD 结构一致 | host 端 `n_non_ignore`、`HAS_LABEL`、reduction 枚举全部复用 JSD 的模式 |

### 12.11 FusedLinearJSD 数学定义

蒸馏场景：student 和 teacher 各有最后一层 linear，融合 loss 不进内存。chunk 逻辑与 FusedLinearCE 相同。

```math
z_s = X_s W_s^T,\ \ z_t = X_t W_t^T \quad(\text{除以 } \tau \text{ 温度}),\quad \hat p_s = \text{log-softmax}(z_s/\tau),\ \ \hat p_t = \text{log-softmax}(z_t/\tau)
\text{loss} = JSD_\beta(\hat p_t \| \hat p_s)
```

### 12.12 FusedLinearJSD 梯度链

JSD kernel 输出的是 `∂L/∂(log Q)`（即 `∂L/∂\hat p_s`）。要回传 linear 层需经过 log-softmax 的雅可比：

```math
\frac{\partial L}{\partial z_s} = \frac{1}{\tau}\left(g - p_s\,\text{sum}(g)\right), \qquad g = \frac{\partial L}{\partial \hat p_s}, \quad p_s = \text{softmax}(z_s/\tau)
```

这正是 `ops/fused_linear_jsd.py:118-122` 的 `student_logits_chunk = student_prob_chunk - softmax(...)*sum(...)` 再除以 temperature。

### 12.13 FusedLinearJSD 源码阅读重点（`ops/fused_linear_jsd.py`，265 行）

| 要点 | 说明 |
| ---- | ---- |
| 复用 `_jsd_kernel` | 从 `ops.jsd` import，不改 kernel，只改调用（`fused_linear_jsd.py:96`） |
| log-softmax 在 Python 层 | `torch.log_softmax`（不是 Triton），因为 block 内 exp/sum 的精度足够 |
| 温度缩放 | `student_logits_chunk / temperature` 在 matmul 之后 |
| chunk + 原地梯度 | 和 FusedLinearCE 完全同构的分块循环 |

## 十三、阶段 10：RoPE 变体（Llama4 / Qwen2VL M-RoPE）

### 13.1 Llama4 RoPE：复数表示

Llama4 用复数形式：把 pair `(x_real, x_imag)` 看作复数 `z = x_real + i·x_imag`，旋转是复乘：

```math
z' = z \cdot e^{i\theta} = (x_r + i x_i)(\cos\theta + i\sin\theta)
x'_r = x_r\cos\theta - x_i\sin\theta, \qquad x'_i = x_r\sin\theta + x_i\cos\theta
```

与 RoPE 的旋转矩阵完全相同，只是用 `freqs_cis`（复数张量 `e^{iθ}`）表示。

### 13.2 Llama4 RoPE 梯度推导

因为乘的是单位复数，backward 用共轭：

```math
\frac{\partial z'}{\partial z} = e^{i\theta}, \qquad \frac{\partial L}{\partial z} = \frac{\partial L}{\partial z'} \cdot e^{-i\theta} = \frac{\partial L}{\partial z'}\cdot\overline{e^{i\theta}}
```

即把 `imag_sign` 翻号（`ops/llama4_rope.py:179`：`imag_sign=-1.0`），forward/backward 用同一个 kernel。**比标准 RoPE 更优雅：不需要分别写 forward 和 backward 的旋转公式。**

### 13.3 Llama4 RoPE 源码阅读重点（`ops/llama4_rope.py`，180 行）

| 要点 | 说明 |
| ---- | ---- |
| **2D grid** | `grid = (batch*seq, n_heads)`，一个 program 负责一个 token 的一个 head（`llama4_rope.py:134`） |
| 复数 split | `freqs_real, freqs_imag = tl.split(freqs_complex)`，`freqs_complex` 来自 `torch.view_as_real` |
| FMA | `tl.math.fma(q_real, freqs_real, -(q_imag*freqs_imag))` 一次乘加 |
| 维分块 | `for d_start in tl.static_range(0, head_dim_half, BLOCK_SIZE)` 处理大 head |
| 动态 BLOCK_SIZE | `_select_kernel_meta(head_dim_half)` 按维度启发式选 block/num_warps |

### 13.4 Qwen2VL M-RoPE：分段多模态 RoPE

Qwen2VL 把 head_dim 分成三段：temporal、height、width，每段用**不同的位置编码**：

```math
\theta_i = \frac{m_{sec}}{10000^{2i/d}}, \quad m_{sec} = \begin{cases} m_t, & i < t\_end \\ m_h, & t\_end \le i < h\_end \\ m_w, & h\_end \le i < hd/2 \end{cases}
```

cos/sin 有三个副本（`cos` 形状 `(3, bs, sl, hd)`），kernel 里用 mask 分别取段再相加：

```python
cos_row = t_cos_row + h_cos_row + w_cos_row   # ops/qwen2vl_mrope.py:62
```

### 13.5 Qwen2VL M-RoPE 梯度推导

与标准 RoPE 相同（每段内的旋转矩阵都正交），backward 同样用转置，代码里 `BACKWARD_PASS` 分支和 `ops/rope.py` 完全一致（`ops/qwen2vl_mrope.py:96-107`）。

### 13.6 知识点：三个 RoPE 的对比

| 版本 | 旋转单位 | grid | backward 写法 | 复杂度 |
| ---- | ------- | ---- | ------------- | ------ |
| `rope.py` | 前半维×后半维 | 1D 每 token | 手写转置公式 | 基础 |
| `llama4_rope.py` | 复数对 | 2D 每 (token, head) | 共轭（imag_sign） | 进阶 |
| `qwen2vl_mrope.py` | 前半维×后半维（3 段） | 1D 每 token | 手写转置（同基础版） | 进阶 |

先学 `rope.py`，再理解 `llama4_rope.py` 如何用复共轭统一 forward/backward，最后看 `qwen2vl_mrope.py` 如何用 mask 分段。

## 十四、阶段 11：分布式与重计算（VocabParallelCE / TiledMLP）

### 14.1 VocabParallelCE：Megatron 风格张量并行

**问题**：TP 下 vocab 被切成 `V_local = V/world` 份，普通 CE kernel 无法跨 rank 做 softmax。Liger 拆成**两个 kernel + 两次 AllReduce**。

**核心数学**（和标准 CE 相同，只是 sum/max 是全局的）：

```math
\text{loss} = \log\left(\sum_{ranks}\text{sum\_exp\_local}\right) - \text{predicted\_global}, \quad m = \text{AllReduce}(MAX),\ \ \sum e^{x-m}
```

### 14.2 VocabParallelCE 流程

```text
Python: logits_max = amax(dim=-1) → AllReduce(MAX)   # 全局 max
Kernel1: exp(shifted) 写 fp32 buffer + sum_exp_local + predicted_local（V_local 一遍）
Python: AllReduce(SUM) × 2                            # sum_exp_global, predicted_global
Python: loss = log(sum_exp_global) - predicted_global（+ label smoothing）
Kernel2: exp(shifted)/sum_exp_global → softmax，target 位置减 1，写梯度 in-place
```

### 14.3 VocabParallelCE 源码阅读重点（`ops/vocab_parallel_cross_entropy.py`，363 行）

| 要点 | 说明 |
| ---- | ---- |
| **为什么两个 kernel** | 标准 CE kernel 无法 straddle Python 层的 AllReduce（文件头 docstring 解释） |
| TP=1 单代码路径 | `tp_group` 为 None/size=1 时 AllReduce 是 no-op，一套代码跑所有 TP 规模 |
| `vocab_start = rank * V_local` | 判断 target 是否在本 rank：`off_rank = (y < start) | (y >= start+n_cols)` |
| off-rank 处理 | pred_local 存 0，AllReduce(SUM) 后只剩 owner 的贡献 |
| exp buffer 复用 | `exp_buf` fp32 保存给 backward，kernel2 原地写梯度 |
| label smoothing 两公式 | `pytorch`（`alpha_eff = LS`）和 `megatron`（`alpha_eff = LS·V/(V-1)`），K 取 global 或 partition |

### 14.4 TiledMLP：重计算式省显存

**不是 Triton kernel**，而是纯 Python 的 `torch.autograd.Function`（`ops/tiled_mlp.py`，136 行）。核心思想：**长序列时把 token 分片，backward 里重新 forward**，从而把 MLP 的激活显存从 `O(seq)` 降到 `O(seq/shards)`。

```python
# forward: no_grad 下分片算一次
with torch.no_grad():
    output_shards = [fn(mlp_module, x_shard) for x_shard in x_shards]

# backward: enable_grad 下重算 forward 再 backward
with torch.enable_grad():
    output = fn(mlp_module, x_shard)
torch.autograd.backward(output, incoming_grad_shard)
```

### 14.5 知识点：三种省显存策略对比

| 策略 | 原理 | 代价 | 例子 |
| ---- | ---- | ---- | ---- |
| 梯度即时算 | forward 里算梯度，backward 只缩放 | 无（backward 变空壳） | CrossEntropy、FusedLinearCE、JSD |
| 保存中间量 | 存小量的 rstd/mean | 一点显存 | RMSNorm、LayerNorm |
| 重计算 | backward 重算 forward | 前向算两遍 | TiledMLP |

## 十六、阶段 13：接入真实模型

### 16.1 目标

用自己的算子替换一个小型 Llama/Qwen 模型的对应模块，验证**训练 loss 收敛一致 + 显存/吞吐提升**。

### 16.2 做法（Liger 的 monkey patch 机制）

Liger 的做法是 `transformers/monkey_patch.py` + `transformers/model/*.py`：运行时把 HF 模型里的 `RMSNorm` 换成 `LigerRMSNorm`。

你自己的做法（更简单）：
1. 用 HF 加载一个小模型（如 `HuggingFaceTB/SmolLM2-135M`）
2. `model.model.norm = LigerRMSNorm(...)`，`model.model.layers[i].mlp.gate_up_proj` 换成 SwiGLU 版本，`loss_fct` 换成 Liger CE
3. 对比替换前后：同 seed 下 loss 曲线是否一致、显存峰值、每步吞吐

### 16.3 验证清单

```text
原始 HF 模型            → 一条 loss 曲线
替换 RMSNorm            → 对比（应逐位接近或极小误差）
替换 RoPE / SwiGLU      → 继续对比
替换 CrossEntropy       → 继续对比
测显存峰值（nvidia-smi）
测吞吐（tokens/s）
```

> 学习指南里说得对：**这一步才真正对应 Liger Kernel 的实际用途**——训练算子最终要能插进真实训练循环。

## 十八、公式速查表

| 算子 | Forward | Backward |
| ---- | ------- | -------- |
| **RMSNorm** | `y_i = x_i·rstd·w_i`, `rstd = 1/sqrt(mean(x²)+ε)` | `dx = rstd·(dy·w) - (rstd³/N)·(Σ dy·w·x)·x`, `dw = Σ dy·x·rstd` |
| **LayerNorm** | `y_i = (x_i-μ)/sqrt(σ²+ε)·w_i` | `dx = (w/σ)[dy - mean(dy) - n·mean(dy·n)]`, `dw = Σ dy·n` |
| **GroupNorm** | `y = (x-μ_g)/σ_g·w+b`（组内归约） | 同 LayerNorm 公式，归约范围为组内 `C/G×H` |
| **SwiGLU** | `y = SiLU(a)·b`, `SiLU(a)=a·σ(a)` | `db = dy·SiLU(a)`, `da = dy·b·(SiLU(a)(1-σ(a))+σ(a))` |
| **GEGLU** | `y = GELU(a)·b`（tanh 近似） | `db = dy·GELU(a)`, `da = dy·b·(0.5(1+t) + 0.5a(1-t²)√(2/π)(1+3·0.0447a²))` |
| **ReLUSquared** | `y = max(x,0)²` | `dx = dy·2·max(x,0)` |
| **RoPE** | `x'1 = x1cos - x2sin`, `x'2 = x2cos + x1sin` | `dx1 = dy1cos + dy2sin`, `dx2 = dy2cos - dy1sin` |
| **Llama4 RoPE** | `z' = z·e^{iθ}`（复数乘） | `dz = dz'·e^{-iθ}`（共轭，imag_sign=-1） |
| **CrossEntropy** | `loss = lse - x_y`, `lse = m + log Σ e^{x-m}` | `dx_i = (p_i - 1_{i=y})/N`（LS/z-loss 见 8.4/8.5） |
| **FusedLinearCE** | 分 chunk: `G = (p - onehot)/N` 直接在 forward 算 | 只需 `grad × grad_output` 缩放 |
| **Softmax** | `p_i = e^{x_i-m}/d` | `dx = p ⊙ (dy - Σ dy·p)` |
| **Sparsemax** | `y_i = max(x_i - τ, 0)`, `τ=(Σ_support x - 1)/k` | `dx_i = dy_i - mean_{support}(dy)`（支撑集内） |
| **KLDiv** | `loss_i = P(logP - logQ)` | `dx = -P`（log_target: `-e^Y`） |
| **JSD(β)** | `loss_i = βP·Y+(1-β)Q·X - M·logM` | `dx = (1-β)Q·(X - logM)` |
| **TVD** | `loss_i = ½|P-Q|` | `dx = ±½`（sign） |
| **FusedLinearJSD** | `z/τ → log_softmax → JSD` | `dz = (1/τ)(g - p·Σg)`（过 log-softmax 雅可比） |
| **FusedAddRMSNorm** | `S=X+R; Y=RMSNorm(S)` | `dX = dR = dS_out + dS_rms` |
| **PolyNorm** | `y = Σ_p w_p·norm(x^p) + b` | `dx = Σ_p w_p[p·x^{p-1}·r_p·dy - (p/N)x^{2p-1}r_p³S_p]` |
| **ModulatedRMSNorm** | `y = RMSNorm(x)·(1+scale)+shift` | `dscale = dy·rms_out`, `dshift = dy`, `dx = RMSNormBwd(dy·(1+scale))` |
| **VocabParallelCE** | `loss = log(Σ sum_exp) - pred_global`（AllReduce） | `exp/sum_exp_global → softmax - onehot`（kernel2） |
| **Effective Bandwidth** | `(BytesRead + BytesWritten) / time` | fp16 pointwise ≈ `6N/t` |
| **TFLOPS (GEMM)** | `2MNK / (t × 10¹²)` | 只适合 compute-bound 算子 |
| **Arithmetic Intensity** | `FLOPs / BytesTransferred` | 判断 memory-bound vs compute-bound |
| **Online Softmax 更新** | `m' = max(m, m_b)`, `d' = d·e^{m-m'} + Σe^{x-m'}` | FlashAttention Alg. 3 |
| **数值稳定 softmax** | `p_i = e^{x_i-m}/Σe^{x_j-m}` | m = 行内 max |
