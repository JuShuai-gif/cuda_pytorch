# TinyEngine 学习计划：每天 45 分钟，从入门到理解核心

**一句话定位**：TinyEngine 是 MIT HAN Lab 开源的 MCU 端深度学习推理/训练引擎。Python 编译前端（TFLite/JSON → C 代码）+ C 运行时后端（ARM SIMD 内核），端到端部署到 STM32 MCU。

**总时长**：约 4 周（20 个学习日），每天 45 分钟。

**重要性说明**：
- ⭐⭐⭐⭐⭐ = 必须掌握（不然后续无法理解）
- ⭐⭐⭐⭐   = 核心理解（面试/开发中常见）
- ⭐⭐⭐     = 重要但可先走读（用到再细看）
- ⭐⭐       = 了解即可（高级/特定场景）

## 附录：常见误区

| 误区 | 正解 |
|------|------|
| tflite/ 下文件要手写 | 全是 flatc 自动生成的，不要手动改 |
| TfliteConvertor 解析所有 TFLite 算子 | 只支持常用算子，不支持的会抛 `NotImplementedError` |
| 内存调度是通用分配器 | 专门针对 CNN 特征图的 tensor 生命周期优化 |
| 代码生成是模板替换 | 每个 unique conv 配置生成专属 C 文件，不是模板 |
| 推理和训练用同一套解析 | 推理用 TfliteConvertor，训练用 TTEParser，IR 统一 |

## 附录 B：工业落地实践

### 1. 模型导出流水线（实际生产中的坑）

```
训练框架(PyTorch/TF) → TFLite 导出 → TinyEngine 编译 → 部署
     ↑                  ↑              ↑              ↑
   坑1: BN融合      坑2: 量化校准    坑3: 不支持的   坑4: 内存溢出
   必须在导出前     需要代表性       算子需要实现    实测验证
   fuse BN到Conv    校准数据集       或替换          buffer分配
```

| 常见坑 | 现象 | 原因 | 解决方案 |
|--------|------|------|---------|
| 量化精度下降 | 部署后精度比训练低 >3% | 量化校准数据集不具代表性 | 从训练集均匀采样 100-200 张做校准 |
| 不支持的算子 | `NotImplementedError: Unsupported HARD_SWISH` | TFLite 有但 TinyEngine 的 TfliteConvertor 没实现 | (1) 模型替换为支持的算子；(2) 在 `_handleOperator` 中添加支持 |
| OOM at compile time | 生成的 C 代码报告 buffer 超 SRAM | 模型太大或调度不够 aggressive | (1) 启用 patch 推理；(2) 检查模型通道数 |
| 权重加载乱码 | 输出全零或随机值 | FlatBuffer 的权重字节序/platform 不匹配 | 检查 model 导出时的 `--optimizations` 和量化参数 |
| 实时性不达标 | MCU 推理太慢 | 模型太大或未用高性能内核 | (1) 减少通道数；(2) 确认用了 INT8 而非 FP32 |

### 2. 典型部署架构

```
┌─────────────────────────────────────────────────┐
│  PC/Server 侧（离线做一次）                       │
│  PyTorch 训练 → TensorFlow 转换 → TFLite INT8   │
│  → TinyEngine Python 编译 → C 代码产出            │
└────────────────────────┬────────────────────────┘
                         │ C 代码 + 权重数组
                         ▼
┌─────────────────────────────────────────────────┐
│  MCU 侧（固件的一部分）                          │
│  genModel.c + genModel.h + TinyEngine 运行时     │
│  → STM32CubeIDE 编译 → .elf → 烧录 → 运行        │
└─────────────────────────────────────────────────┘
```

### 3. 生产环境 checklist

| 阶段 | Checklist | 对照文件/工具 |
|------|-----------|-------------|
| 模型准备 | ✅ BN fused ✅ INT8 量化 ✅ 算子兼容性检查 | TfliteConvertor 的 SKIP_OPs 列表 |
| 编译生成 | ✅ `vww.py` 跑通 ✅ 生成的 C 代码可编译 ✅ buffer 分配不超限 | `codegen/` 输出目录 |
| 设备验证 | ✅ 推理结果与 PC 端一致 ✅ FPS 达标 ✅ 内存不泄漏 ✅ 功耗可接受 | `TinyEngine/tutorial/` |
| CI/CD | ✅ 模型更新自动触发重新编译 ✅ 输出 .elf 自动签名 ✅ 有回滚机制 | 自建 |

### 4. 常见硬件平台与优化策略

| 平台 | SRAM | Flash | 适用技术 | 限制 |
|------|------|-------|---------|------|
| STM32F746 | 320KB | 1MB | INT8 推理 + first-fit | 不支持 INT4 |
| STM32H743 | 1MB | 2MB | 大模型推理 + FP 重量化 | 成本较高 |
| STM32L4 | 128KB | 512KB | Patch 推理必须开 | 模型必须很小 |
| nRF52840 | 256KB | 1MB | INT8 推理 + BLE 传输 | ARM Cortex-M4, 无 M7 SIMD |
