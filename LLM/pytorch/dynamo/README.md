## Torch Dynamo

Dynamo 是一个追踪器（tracer）：给定一个函数和它的输入，它会执行该函数并记录一系列线性指令（不含控制流）到计算图中。

从 `01.py` 可以看到，`foo()` 从函数中捕获计算图，Dynamo 将捕获的计算图保存为 FX 图。

### Python 字节码

Dynamo 在 Python 字节码翻译过程中捕获计算图。Python 函数在执行前会被 Python 虚拟机编译为字节码。每个函数实例对应一个称为帧（frame）的东西，它存储了全局变量、局部变量、字节码和运行函数所需的其他信息。

Python 虚拟机是一个基于栈的虚拟机，维护三个栈：

**调用栈** - 追踪当前正在调用的函数。当 `foo()` 调用 `bar()` 再调用 `baz()` 时，调用栈持有三个帧：`baz`（顶部）、`bar`、`foo`（底部）。每个帧存储该函数的局部变量、字节码和执行状态。当函数返回时，其帧从栈中弹出。

**求值栈（或数据栈）** - 每个帧有自己的求值栈，字节码指令在此进行压栈/弹栈操作以处理中间值。例如 `a + b` 的编译结果是：`LOAD_FAST a`（压入 a）、`LOAD_FAST b`（压入 b）、`BINARY_OP +`（弹出两个值，压入结果）。

**块栈** - 每个帧有一个块栈，追踪嵌套的控制结构如循环、`try`/`except`、`with` 块等。当你进入一个 `for` 循环时，块标记被压入；退出时弹出。这告诉虚拟机在遇到 `break` 或 `continue` 时如何操作——这些操作针对的是栈上最内层的循环块。块栈纯粹关乎控制流（循环、异常处理），不涉及数据。

Torch Dynamo 的编译过程发生在执行之前，即它是一个 JIT 编译器。当 Python 即将执行一个函数时，TorchDynamo 开始翻译字节码并捕获计算图。它通过使用一个 Python 虚拟机模拟器来实现，在模拟 Python 字节码执行的同时构建相应的计算图。

### Guard（守卫）

Guard 是一个非常重要的概念。

捕获计算图之后，你需要验证后续执行是否仍可使用同一个计算图。TorchDynamo 从编译后的函数中创建一个 Python 可执行函数，称为 guard。它负责检查编译函数的输入属性是否发生了变化。如果没有变化，之前编译的函数可以复用；否则，当前输入对之前编译的函数无效，需要重新编译函数。

Dynamo 编译的所有函数都存储在每个函数的缓存中，以避免重复输入的重复编译。默认 `cache_size_limit = 8`，意味着最多缓存 8 个独特的 guard/输入组合。超出此限制后，Dynamo 记录警告并回退到 eager 模式（我认为）。

另外，并非每次输入变化都会触发重新编译。Dynamo 可以将形状维度标记为动态，如果 Dynamo 判定某个维度可变，两个不同的形状可以共享一个编译后的计算图。

但关于 dtype、device 或其他张量属性的 guard 总是会导致重新编译，因为这些无法动态化。

### Graph Break（图断裂）

Dynamo 无法将所有函数捕获到单个计算图中。当 TorchDynamo 遇到不支持的运算符时，它会创建一个图断裂，将计算图拆分为若干个它支持的子图，并将结果返回给 Python 解释器执行无法处理的运算符。

这通常是性能下降的地方，你需要非常小心地处理这种情况。

### 静态 vs 动态形状

默认情况下，TorchDynamo 使用静态形状模式，在捕获计算图时记录张量的形状和步长（stride）。计算图捕获结束时，生成的 guard 会检查计算图中的输入信息是否发生变化。如果没有变化，就复用已编译的计算图；否则，重新捕获并重新编译计算图（图重新编译）。从第二次起，现在以动态形状模式捕获静态形状。

如果你知道某个维度的大小会变化，可以在调用 `torch.compile` 之前通过 `torch._dynamo.mark_dynamic` 将其标记为动态。这将避免第一次以静态形状的编译。
