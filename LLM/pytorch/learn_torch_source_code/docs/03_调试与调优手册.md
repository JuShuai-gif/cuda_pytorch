# 第一部分 · 调试技巧

## 调试决策树(先定位问题类型)

```
报错/异常?
├─ Python 报错、逻辑错     → §1 Python 调试
├─ 形状/类型/设备不匹配    → §2 shape/dtype/device
├─ CUDA 报错(错位/不清晰) → §3 CUDA 异步错误
├─ 结果 NaN/Inf            → §4 数值调试
├─ 反向报错(inplace/图)   → §5 Autograd 调试
├─ 想进 C++/CUDA 内核      → §6 gdb/cuda-gdb
├─ OOM / 显存泄漏          → §7 显存调试
├─ torch.compile 慢/报错   → §8 编译调试
└─ 多卡挂起/不一致         → §9 分布式调试
```

## §1 Python 层调试
- **作用**:定位逻辑错、看变量、单步。
- **怎么用**:
  ```python
  breakpoint()                      # Python 3.7+ 内置,等价 import pdb; pdb.set_trace()
  ```
  或 VSCode "Python: Debug Current File"(`justMyCode:false` 可步入 torch 源码)🧪`01_python_debug.py`。
- **何时用**:任何 Python 逻辑问题的第一手段;想看 torch Python 源码怎么走时。

## §2 形状 / 类型 / 设备不匹配
- **作用**:最常见的报错来源。
- **怎么用**:
  ```python
  print(x.shape, x.dtype, x.device, x.stride())   # 四要素一起打
  torch._assert(x.shape == y.shape, f"{x.shape} vs {y.shape}")
  ```
  形状难追时用 `torchtyping`/`jaxtyping` 注解,或临时插 `assert`。
- **何时用**:`size mismatch`、`expected same device`、`expected scalar type` 类报错。

## §3 CUDA 异步错误(报错行不对)
- **作用**:CUDA 默认异步,报错栈常指向错误的行。
- **怎么用**:
  ```bash
  CUDA_LAUNCH_BLOCKING=1 python train.py        # 同步执行,报错定位到真实 kernel
  TORCH_USE_CUDA_DSA=1 ...                       # 开 device-side assert(需重编)
  compute-sanitizer python train.py             # 非法访存/竞态/未初始化
  ```
- **何时用**:`CUDA error: device-side assert`、`illegal memory access`、报错行明显不对时。
  → 可跑:`debug_demo.py` 的 `demo_cuda_async_note`(含安全的 CPU 类比)
## §4 数值调试(NaN / Inf)
- **作用**:定位第一处产生 NaN/Inf 的算子。
- **怎么用**:
  ```python
  torch.autograd.set_detect_anomaly(True)        # 反向 NaN 定位到前向算子(慢,仅调试)
  # 或手动埋点:
  assert torch.isfinite(x).all(), "NaN/Inf detected"
  # 注册 hook 扫描每个模块输出:
  for n, m in model.named_modules():
      m.register_forward_hook(lambda mod, i, o, n=n:
          print(n, "NaN") if not torch.isfinite(o).all() else None)
  ```
- **何时用**:loss 变 NaN、梯度爆炸、fp16 溢出(→ 上 GradScaler §性能AMP)。
  → 可跑:`debug_demo.py` 的 `demo_nan_inf`

## §5 Autograd 调试
- **作用**:反向图相关错误。
- **怎么用**:
  ```python
  # inplace 破坏反向: "a leaf Variable ... modified by an inplace operation"
  #   → 找到 x += / x.relu_() 改成非 inplace
  # 图已释放: "backward through the graph a second time"
  loss.backward(retain_graph=True)               # 需要多次反向时
  # 看某张量的反向节点:
  print(y.grad_fn, y.grad_fn.next_functions)
  torch.autograd.set_detect_anomaly(True)        # 定位 inplace 冲突的具体操作
  ```
- **何时用**:inplace 报错、retain_graph 报错、梯度为 None、自定义 Function 求导错。参考 🧪`trace_backward`。
  → 可跑:`debug_demo.py` 的 `demo_autograd_inplace` / `demo_retain_graph`

## §6 C++ / CUDA 内核调试(gdb / cuda-gdb)
- **作用**:进入 PyTorch C++/CUDA 源码断点。
- **怎么用**:
  ```bash
  # host 端 C++:
  cd ../B_core_mechanism
  gdb -q -batch -x stage1_trace_add.gdb --args python stage1_trace_add.py
  # 关键断点: b at::TensorIteratorBase::build / b <算子>::apply
  # device 端 kernel:
  cuda-gdb -p <PID>                              # 附加后 b at::native::...
  # 让 Python 报错带 C++ 栈:
  TORCH_SHOW_CPP_STACKTRACES=1 python x.py
  ```
- **何时用**:研究内部实现、C++ 崩溃(segfault)、自定义 C++ 算子调试。详见 `../A_setup_debug/README.md`。

## §7 显存调试(OOM / 泄漏)
- **作用**:定位显存去哪了。
- **怎么用**:
  ```python
  print(torch.cuda.memory_summary())             # 分类显存占用
  torch.cuda.memory._record_memory_history()     # 开始记录
  # ... 跑一段 ...
  torch.cuda.memory._dump_snapshot("mem.pickle")  # 传到 pytorch.org/memory_viz 可视化
  ```
  ```bash
  PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True python x.py   # 缓解碎片
  ```
- **何时用**:`CUDA out of memory`、显存随迭代增长(泄漏,常因保留了带图的张量:`total_loss += loss` 应 `+= loss.item()`)。参考 📓`s4_03_memory_allocator`。
  → 可跑:`debug_demo.py` 的 `demo_memory_leak`(实测 bad 3498MB vs good 277MB)

## §8 编译调试(torch.compile)
- **作用**:诊断 graph break / 重编译 / 精度差异。
- **怎么用**:
  ```bash
  TORCH_LOGS="graph_breaks,recompiles" python x.py   # 看断点与重编原因
  TORCH_LOGS="+dynamo,inductor,output_code" python x.py  # 全过程 🧪 stage5
  TORCH_COMPILE_DEBUG=1 python x.py                   # dump 中间产物
  ```
  ```python
  torch._dynamo.explain(fn)(*args)                    # graph 数/break 数/原因
  torch._dynamo.config.suppress_errors = True         # 出错退回 eager 而非崩
  ```
- **何时用**:compile 后没加速(可能全是 graph break)、频繁重编(guard 失效)、compile 后结果不一致。参考 📓`s5_08_compile_debug`。

## §9 分布式调试
- **作用**:多卡挂起、结果不一致。
- **怎么用**:
  ```bash
  TORCH_DISTRIBUTED_DEBUG=DETAIL python -m torch.distributed.run ...
  NCCL_DEBUG=INFO ...                            # NCCL 通信日志
  ```
  挂起常因:各 rank 执行的集合通信不对称(有的 rank 少调一次 all_reduce)、unused parameters(DDP 需 `find_unused_parameters=True`)。
- **何时用**:训练卡住无输出、各卡 loss 不一致、DDP 报 unused parameter。参考 📓`s5_13_ddp_reducer`。

# 第二部分 · 性能调优

## 铁律:先测量,再优化

```python
import torch.utils.benchmark as bench
t = bench.Timer(stmt="model(x)", globals={"model": model, "x": x})
print(t.blocked_autorange())        # 自动 warmup + synchronize + 统计
```
> 别凭感觉改。永远先 profile 找瓶颈,再判断 compute-bound 还是 memory-bound(roofline 📓`s4_08`),然后优化对的地方。
>
> → 可跑:`perf_demo.py` 演示 §P1/§P2/§P3 叠加加速(基线→TF32→bf16→compile,实测 3.45x)。

## §P0 profiling(优化第一步)
- **怎么用**:
  ```python
  from torch.profiler import profile, ProfilerActivity, schedule
  with profile(activities=[ProfilerActivity.CPU, ProfilerActivity.CUDA],
               record_shapes=True, profile_memory=True) as prof:
      for _ in range(10):
          model(x); prof.step()
  print(prof.key_averages().table(sort_by="cuda_time_total", row_limit=20))
  prof.export_chrome_trace("trace.json")     # chrome://tracing 或 perfetto 打开
  ```
  更深:**Nsight Systems**(时间线,看 gap/同步)、**Nsight Compute**(单 kernel)。
- **何时用**:任何性能优化开始前;找出耗时 top kernel 与 GPU 空闲区间。📓`s4_04_profiler`

## §P1 混合精度 AMP
- **作用**:fp16/bf16 加速 + 省显存(Tensor Core)。
- **怎么用**:
  ```python
  scaler = torch.amp.GradScaler("cuda")
  with torch.autocast("cuda", dtype=torch.bfloat16):   # bf16 无需 scaler;fp16 需要
      out = model(x); loss = loss_fn(out, y)
  scaler.scale(loss).backward(); scaler.step(opt); scaler.update()
  ```
- **何时用**:几乎所有训练默认开;Ampere+ 用 bf16(稳),老卡用 fp16+GradScaler。📓`s2_06_amp`

## §P2 torch.compile
- **作用**:抓图 + 融合 + codegen,通常 1.3-2x。
- **怎么用**:
  ```python
  model = torch.compile(model)                        # 默认
  model = torch.compile(model, mode="max-autotune")   # 搜最优 kernel(编译久,收益大)
  model = torch.compile(model, mode="reduce-overhead")# 用 CUDA Graph 省 launch 开销
  ```
- **何时用**:模型稳定后加一行;小算子多/launch 密集时收益大;先用 §8 确认没有大量 graph break。📓`s5_04` 🧪`stage5_compile`

## §P3 matmul 精度(免费加速)
- **怎么用**:
  ```python
  torch.set_float32_matmul_precision("high")   # 允许 TF32,fp32 matmul 提速数倍
  torch.backends.cudnn.benchmark = True        # 固定输入尺寸时自动选最快卷积算法
  ```
- **何时用**:Ampere+ 上跑 fp32 且能接受微小精度损失;输入 shape 固定的卷积网络。📓`s4_06_cudnn_backend`

## §P4 内存格式 channels_last
- **怎么用**:
  ```python
  model = model.to(memory_format=torch.channels_last)
  x = x.to(memory_format=torch.channels_last)
  ```
- **何时用**:CNN(尤其卷积)在 Tensor Core 上更快。📓`s1_01_tensor`

## §P5 消除同步点(常被忽视的大坑)
- **作用**:`.item()`/`.cpu()`/`print(tensor)`/`.numpy()` 会强制 GPU 同步,打断流水。
- **怎么用**:
  ```python
  # 坏: 训练循环里 total += loss.item()  每步同步
  # 好: 累积在 GPU 上,循环外再 .item()
  losses.append(loss.detach())            # 不同步
  # 用 nvidia-smi/profiler 看是否有大量 cudaStreamSynchronize
  ```
- **何时用**:GPU 利用率低、profiler 里出现频繁同步时。

## §P6 DataLoader 调优(避免数据饥饿)
- **怎么用**:
  ```python
  DataLoader(ds, batch_size=B, num_workers=8,        # 一般设为 CPU 核数
             pin_memory=True,                         # 配合 non_blocking 异步拷贝
             persistent_workers=True, prefetch_factor=4)
  x = x.to("cuda", non_blocking=True)
  ```
- **何时用**:GPU 利用率忽高忽低(等数据)时;profiler 显示 GPU 有空档。📓`s1_06_dataloader`

## §P7 显存优化(换更大 batch / 跑更大模型)
- **怎么用**:
  ```python
  from torch.utils.checkpoint import checkpoint        # 激活重算,省显存换算力
  out = checkpoint(block, x, use_reentrant=False)
  # 梯度累积: 小 batch 累积 N 步再 step,等效大 batch
  ```
  加上 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 缓解碎片。
- **何时用**:OOM、想加大 batch、模型太大放不下。📓`s2_02_checkpoint`、`s4_03`

## §P8 注意力优化
- **怎么用**:
  ```python
  import torch.nn.functional as F
  out = F.scaled_dot_product_attention(q, k, v, is_causal=True)  # 自动选 FlashAttention
  ```
- **何时用**:任何 Transformer;长序列时显存/速度收益巨大。📓`s4_05_sdpa_attention`

## §P9 优化器 / 其它
- **怎么用**:
  ```python
  opt = torch.optim.AdamW(model.parameters(), fused=True)   # 融合优化器,减少 kernel
  opt.zero_grad(set_to_none=True)                            # 比清零更快更省显存
  ```
- **何时用**:优化器 step 占比高时用 fused;`set_to_none` 建议默认。📓`s2_04_optimizer`

## §P10 分布式性能
- **怎么用**:DDP 的 bucket 大小、通信-计算重叠、梯度压缩 comm hook;大模型上 FSDP/TP。
- **何时用**:多卡扩展效率低(通信瓶颈)时。📓`s5_13_ddp_reducer`、`s5_14`

# 第三部分 · 完整调优工作流(照着做)

```
1. 建立基线:固定输入,用 benchmark.Timer 测当前吞吐/延迟
2. profile:torch.profiler 找 top kernel + GPU 空闲区
3. 判定瓶颈:
   - GPU 利用率低 → 数据饥饿(§P6)或同步点(§P5)或 launch 开销(§P2 reduce-overhead)
   - 某 kernel 耗时高 → 是 compute 还是 memory bound(roofline)?
       compute-bound → 混合精度(§P1)/TF32(§P3)/更好算法
       memory-bound  → 融合(§P2)/channels_last(§P4)/减少中间张量
4. 逐项施加,每次只改一个,重测对比(记录加速比)
5. 显存不够 → §P7;注意力 → §P8;多卡 → §P10
6. 出报告:GPU 型号/torch 版本 + 每步优化的加速比 + 最终 vs 基线
```

## 何时用什么(速查)
| 症状 | 先查 | 手段 |
|------|------|------|
| GPU 利用率低 | profiler 时间线 | §P5 同步点 / §P6 数据 / §P2 reduce-overhead |
| 单 kernel 慢 | Nsight Compute | §P1 AMP / §P3 TF32 / §P8 SDPA |
| OOM | memory snapshot §7 | §P7 checkpoint/累积 / §P1 省显存 |
| compile 没加速 | §8 graph_breaks | 消除 break / max-autotune |
| 多卡扩展差 | NCCL/DDP 日志 | §P10 重叠 / bucket / FSDP |
| 结果 NaN | §4 anomaly | §P1 GradScaler / 数值稳定化 |
