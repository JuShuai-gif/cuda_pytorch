# 附录 H — 常见坑(Pitfalls,踩过才算懂)

## Autograd
- inplace 操作破坏反向所需张量 → `a version mismatch` 报错(版本计数 📓`s2_03`)
- 多次 backward 未 `retain_graph=True` → 图已释放
- `.detach()` vs `.data`、`no_grad` vs `inference_mode` 的区别 🧪`s2_01`
- 累积梯度未清零(`optimizer.zero_grad`)

## CUDA / 性能
- 异步执行 → 计时不 `torch.cuda.synchronize()` 得到错误耗时
- 隐式 device 同步点(`.item()`/`.cpu()`/`print`)拖慢训练
- 小 kernel launch 过多 → launch 开销主导(用 CUDA Graph/融合)
- pin_memory + non_blocking 才能真正异步拷贝 📓`s4_01`

## 数值
- fp16 溢出 → 需 GradScaler 📓`s2_06`;bf16 精度低但范围大
- 累加顺序不同 → 非确定性(atomic);softmax 未稳定化 → NaN

## 编译
- graph break(Python 副作用/数据依赖控制流)→ 退化 📓`s5_08`
- 频繁 recompile(输入 shape/类型变化触发 guard 失效)
- 动态 shape 未标记 → 特化过度

# 附录 J — Benchmark 方法论(避免自欺)

```python
import torch.utils.benchmark as bench
t = bench.Timer(stmt="f(x)", globals={"f": f, "x": x})
print(t.blocked_autorange())   # 自动 warmup + 多次 + 统计
```
铁律:
1. **Warmup**:首次含编译/cudnn 选算法/显存分配,必须丢弃前几次
2. **同步**:GPU 计时前后 `torch.cuda.synchronize()`,或用上面的 Timer
3. **隔离**:关掉其它进程;固定时钟(`nvidia-smi -lgc`)减少抖动
4. **对照**:eager vs compile vs 手写,同输入同 dtype
5. **看瓶颈**:先 roofline 判定 compute/memory bound 📓`s4_08`,再优化对的地方
6. **报告**:中位数 + 分位数,不是单次;带 GPU 型号/驱动/torch 版本
