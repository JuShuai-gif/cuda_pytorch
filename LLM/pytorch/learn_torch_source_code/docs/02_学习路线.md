### 各阶段一句话结论
1. Python 调用经**两次 dispatch**(Autograd 记图 → redispatch → CPU 执行)→ structured kernel。
2. `backward()` = **就绪队列驱动的图拓扑执行**(`Engine::execute`→`thread_main`→`evaluate_function`→`XxxBackward0::apply`)。
3. 内置 `aten` 与自定义 `myops` 走**同一套 dispatcher**;`TORCH_LIBRARY` 就是手写版的 `native_functions.yaml`。
4. `Tensor` → `TensorImpl`(元数据)→ `Storage`(内存)→ `Allocator`;view/slice 共享 Storage 不拷贝。
5. `torch.compile` = Dynamo 抓图 → AOTAutograd 降解 → Inductor **算子融合+代码生成** → CPU 向量化 C++ / GPU Triton。

## 阶段 3:Dispatcher + 算子(约 2 周,理解扩展机制)

```
aten/src/ATen/native/native_functions.yaml # 算子注册总表(起点)
aten/src/ATen/core/dispatch/Dispatcher.h   # 运行时分发
c10/core/DispatchKey.h                      # Autograd / CPU / CUDA 键
torchgen/                                   # 代码生成器
```

**动手**:
1. 挑 `add` 端到端追一遍(Python → dispatcher → ATen kernel → `ufunc/add.h`)。
2. 用 `TORCH_LIBRARY` 注册一个自定义算子,理解注册与分发。

`add` 端到端链路参考:

```
torch.add(a, b)
  -> Python C 绑定 (torchgen 生成)
  -> at::add  (dispatcher, DispatchKey 查表)
  -> Autograd 层 (记录 AddBackward0) -> redispatch
  -> add.out structured kernel (meta + impl, TensorIterator)
  -> CPU: add_stub -> BinaryOpsKernel.cpp
  -> 标量内核 aten/src/ATen/native/ufunc/add.h:16   (self + alpha * other)
```

## torch/ 目录速查

| 需求         | 目录                                    |
| ------------ | --------------------------------------- |
| 搭模型       | `torch/nn/`                               |

| 算子注册表   | `aten/src/ATen/native/native_functions.yaml` |
| 编译加速     | `torch/_dynamo/`、`torch/_inductor/`、`torch/fx/` |
| 分布式       | `torch/distributed/`                      |
| 设备管理     | `torch/cuda/`、`torch/backends/`            |
