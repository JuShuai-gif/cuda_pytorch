## 混合专家模型（MoE）

MoE 是一种稀疏模型，与 Transformer 使用 FFN（前馈层）不同，它将 FFN 替换为专家网络。这些专家实际上就是 FFN 层，但被拆分成了较小的片段。

核心思想是：给定一个问题，将问题路由到多个专家，然后组合每个专家的响应来给出最终结果。

那我们需要什么来实现这一点？

1. **路由器** - 接收问题并决定使用哪个专家的智能层。
2. **实际的专家**，即 FFN 层。

训练这部分是比较棘手的。
- 假设我们有 10 个专家，当权重被初始化为零时，每个专家被选中的概率相等。我们需要能够只选择合适的专家。
- 另外，如果某些专家比其他专家更受偏好，它们将总是被选中。

**解决方案：**
1. 使用 top-k 方法选择专家——不是让所有 10 个专家一直活跃，而是只选择 top-k 专家活跃。这确保我们不会使用所有专家。路由器负责此事。
2. 另一种技术是添加一些噪声，这样有时会混入不同的选择，训练会随时间变得更稳定。

好的，现在我们有了 MoE 的基本概念。是时候巩固理解，并在有输入到来时对这个架构进行推理了。

我以 qwen3-30B 为例，因为我一直在使用它。它有 128 个专家层，但只有 8 个是活跃的。

假设我们有一个 100 个词的输入句子。路由器将 10 个词路由到 expert 1，50 个词路由到 expert 2，依此类推。

1. **负载均衡** - 大多数 token 被路由到某个特定专家，这导致该专家负载高而其他专家闲置未训练。我们需要找到一个良好的机制来均衡负载。
2. 当你跨多个 GPU 扩展这些专家时，我们使用专家并行（expert parallelism）技术，每个层分布在 N 个 GPU 节点上。在这种情况下，如果只有一个专家被加载，其他 GPU 只是利用不足，MFU 就很低。

GShard 论文提出：
1. **专家容量** - 如果我们强制限制某个专家可以处理的 token 数量呢？这样负载就均衡了。溢出的 token 激活值不变，只是作为连接传递到下一层。
2. 类似的辅助损失，如噪声来平衡训练等。

这种方法的难题在于找到正确的容量值。如果容量太高，最终会丢失大量 token，影响训练。
