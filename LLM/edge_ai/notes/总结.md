## 二、知识点总索引

### 2.1 端到端系统流水线 (01)

- **核心概念**：端到端延迟、吞吐量(FPS)、P50/P99/P999 尾延迟、抖动(Jitter)
- **三级流水线**：感知→规划→控制，每阶段时延预算(L4：感知25-50ms / 规划10-25ms / 控制1-5ms)
- **流水线并行**：时间并行(不同帧同时在不同阶段)、空间并行(一帧数据拆分处理)
- **性能指标**：延迟、吞吐量、抖动(标准差)、丢帧率、CPU/GPU利用率、内存带宽利用率
- **缓冲队列**：背压机制、丢帧策略、队列大小对延迟的影响
- **时钟同步**：多传感器时间戳对齐(硬件同步 / 软件插值)
- **传感器融合**：前融合(Early)、中融合(BEV/Middle)、后融合(Late)
- **卡尔曼滤波(Kalman)**：predict-测量-update 三步循环、卡尔曼增益 K、协方差矩阵 P
- **PID 控制器**：P(比例)/I(积分)/D(微分) 三个参数、横向PID+纵向PID
- **三次样条轨迹**：保证 C1/C2 连续性、Thomas算法求解三对角方程组
- **顺序模式 vs 流水线模式**：延迟不变，吞吐量提升 max(stage)
- **std::queue vs Ring Buffer**：锁粒度、内存分配、背压控制、缓存友好
- **工业方案**：boost::lockfree::spsc_queue / moodycamel::ConcurrentQueue / ROS2自带无锁队列
- **性能诊断路线**：pipeline_metrics → perf record → perf lock → perf sched → 针对性优化
- **Amdahl 定律**：加速比上限 = 1/(1-P)，优先优化占比最大的部分

### 2.2 CPU/GPU 混合计算优化 (02)

- **CPU vs GPU 选择矩阵**：小矩阵(<128×128)选CPU、大矩阵(>1024×1024)选GPU；分支密集选CPU、数据并行选GPU
- **PCIe 带宽**：3.0 x16 ~16GB/s、4.0 x16 ~32GB/s、5.0 x16 ~64GB/s
- **可分页内存 vs 页锁定内存(Pinned)**：pinned支持DMA直接访问，带宽接近理论值；但过多消耗物理内存
- **统一内存(Managed Memory)**：按需page fault迁移，适合不规则访问
- **CUDA Stream 并发**：不同stream并行执行kernel + 数据传输
- **计算与传输重叠**：双stream流水线，H2D→kernel→D2H 交替隐藏传输延迟
- **异步回调**：cudaLaunchHostFunc / cudaEventQuery 轮询
- **Pinned Memory 池**：避免重复分配/释放 pinned memory 的开销
- **零拷贝(Mapped Memory)**：cudaHostAlloc mapped，GPU直读主机内存但有PCIe延迟
- **设备端内存池**：cub::CachingDeviceAllocator / cudaMemPool_t
- **合并访问(Coalesced Access)**：同一warp访问连续全局内存
- **Bank Conflict**：共享内存32个bank不要有地址冲突
- **调试工具**：nvidia-smi / nsys(Nsight Systems) / ncu(Nsight Compute) / nvprof

### 2.3 系统瓶颈识别与优化 (03)

- **优先级反转(Priority Inversion)**：高优先级等低优先级锁→被中优先级抢占→无限等待
- **优先级继承(Priority Inheritance)**：持锁者临时继承等待者的高优先级
- **优先级天花板(Priority Ceiling)**：锁被赋予所有使用者的最高优先级
- **护航效应(Convoy Effect)**：长时间持锁导致等待队列堆积，锯齿状CPU利用率
- **锁类型选择矩阵**：临界区<100ns用无锁/原子、100ns~1μs用spinlock、1μs~100μs用mutex/rwlock
- **自旋锁(spinlock)**：忙等待不睡眠，适合极短临界区
- **互斥锁(mutex/futex)**：睡眠等待，适合较长临界区
- **读写锁(shared_mutex/rwlock)**：多读单写，读多写少场景
- **RCU(Read-Copy-Update)**：读操作完全无锁
- **假唤醒与条件变量**：必须while(!ready) cv.wait()，不能用if
- **伪共享(False Sharing)**：两线程改同一cache line不同变量→MESI一致性风暴，慢20-100x
- **缓存行对齐**：alignas(64) 或 padding 解决伪共享
- **缓存抖动(Cache Thrashing)**：步长访问 > 关联度 → 不断evict，行优先遍历解决
- **内存拷贝开销**：<128B函数调用占优、128B~4KB用SIMD、>4KB带宽饱和
- **零拷贝技术**：mmap共享内存、DMA、io_uring、XDP、sendfile/splice
- **常见反模式**：循环中malloc、全局锁热点、虚函数热循环、shared_ptr滥用、日志在热路径
- **IPC指标**：>2为佳，<0.5说明大量停顿

### 2.4 高性能运行时与流水线设计 (04)

- **Future/Promise**：生产者写入Promise、消费者读取Future，适合单次异步
- **协程(C++20 Coroutines)**：co_await/co_return，内存<100B，适合复杂异步编排
- **回调(Callback)**：零抽象开销、事件驱动，但有回调地狱问题
- **事件循环(Event Loop)**：单线程epoll/kqueue轮询，无锁但阻塞一个会拖累全体
- **流水线并行加速比**：上限 = sum(stage_i) / max(stage_i)
- **阶段划分原则**：负载均衡、遵守数据依赖、I/O边界、硬件亲和
- **双缓冲(Ping-Pong Buffer)**：生产者写A/消费者读B→交换→生产者写B/消费者读A
- **Ring Buffer**：原子head/tail指针、无锁、零分配、缓存友好
- **ROS2 Executor**：SingleThreaded/MultiThreaded/EventsExecutor
- **ROS2 Loan Message**：节点间零拷贝共享内存
- **CUDA Graph**：预录制命令序列重放，消除kernel launch开销

### 2.5 性能剖析监控工具 (05+10)

- **perf stat**：cycles、instructions、IPC、cache-misses、branch-misses、context-switches
- **perf record + report**：调用栈采样(默认4000Hz)，生成热点函数报告
- **perf lock**：锁竞争分析，哪个锁wait time最长
- **perf sched**：调度延迟分析，线程被踢出CPU的频率和时长
- **火焰图(FlameGraph)**：on-CPU(函数时间占比)、off-CPU(阻塞时间占比)、差分火焰图
- **NVIDIA Nsight Systems**：CPU/GPU时间线、CUDA API+kernel行、NVTX区间标记
- **NVIDIA Nsight Compute**：单个kernel的SM利用率、内存带宽、occupancy分析
- **eBPF / bpftrace**：内核追踪(kprobe/tracepoint)、调度延迟histogram、syscall统计
- **BCC 工具集**：execsnoop、biolatency、tcptop、funclatency、cachestat
- **Valgrind/Cachegrind**：L1/L2缓存模拟分析，精确到行
- **Heaptrack**：堆内存分配火焰图，谁分配最多/是否内存泄漏
- **Massif**：堆内存快照随时间变化
- **cyclictest**：Linux实时延迟标准测试，PREEMPT_RT下应<20μs
- **oslat**：OS整体延迟基准测试
- **性能工程核心循环**：假设→测量→修复→验证→回归保护(CI/CD)

### 2.6 C++ 多线程 (07)

- **线程创建与管理**：std::thread、线程池(常驻不销毁)
- **互斥量**：std::mutex、std::lock_guard、std::unique_lock、std::scoped_lock
- **条件变量**：std::condition_variable、notify_one/notify_all、while(!ready)模式
- **原子操作**：std::atomic<T>、memory_order_relaxed/acquire/release/seq_cst
- **无锁数据结构**：lock-free queue、CAS(compare_exchange_strong/weak)
- **spinlock实现**：std::atomic_flag、PAUSE指令
- **线程局部存储**：thread_local、本地计数器减少全局竞争
- **线程亲和性**：pthread_setaffinity_np、CPU_SET、绑核
- **实时调度**：SCHED_FIFO、SCHED_RR、SCHED_DEADLINE、chrt命令
- **内存锁定**：mlockall(MCL_CURRENT | MCL_FUTURE) 防止page fault

### 2.7 计算机体系结构 (08)

- **缓存层次**：L1(4-5 cycle/32KB) → L2(12-14 cycle/256KB-1MB) → L3(40-50 cycle/8-64MB) → DRAM(100-200 cycle)
- **缓存行(Cache Line)**：x86 64B，一次加载整个行
- **缓存关联度(Associativity)**：L1 8-way、L3 12-16 way
- **缓存抖动**：步长为路数倍数→持续evict
- **MESI 协议**：
  - M(Modified)：独占已修改，只有本核有最新数据
  - E(Exclusive)：独占未修改，与内存一致
  - S(Shared)：多个核心共享，不可直接写
  - I(Invalid)：副本已作废
  - 状态转换：本地读(BusRd)→E/S、本地写(BusRdX)→M、远程读→S、远程写→I
  - Invalidation风暴：多核竞争同一cache line→ping-pong→慢20-100x
- **MOESI 协议(AMD)**：增加 Owned 状态，共享修改过的数据不回写内存
- **NUMA 架构**：本地内存~100ns vs 远程内存~150-300ns
  - numactl --hardware、lstopo 查看拓扑
  - libnuma API：numa_alloc_onnode、numa_bind、numa_set_preferred
  - 实际策略：传感器靠近PCIe NUMA节点、interleave避免单节点瓶颈
- **CPU 流水线**：IF→ID→EX→MEM→WB，现代CPU 10-20级
  - 流水线停顿(Stall)：数据依赖、cache miss、分支预测失败
  - 数据转发(Bypass)：EX结果直接给下一个EX
- **分支预测**：
  - 1-bit预测器、2-bit饱和计数器
  - GShare(全局历史xor地址)、锦标赛(Tournament)预测器
  - 预测失败代价：x86 15-20 cycles，ARM 2-3 cycles
  - 优化：分离数据流替代循环内分支
- **推测执行(Speculative Execution)**：Spectre/Meltdown的根源
- **SIMD 指令集**：
  - x86：SSE(128b) → AVX(256b) → AVX-512(512b)
  - ARM：NEON(128b) → SVE(变长128-2048b)
  - 适用场景：连续内存、无分支循环、统一数据类型
  - __builtin_ia32_pause()：自旋提示，降低功耗/避免投机错误
- **CFS 完全公平调度器**：
  - vruntime = actual_runtime × (1024/weight)
  - 红黑树按vruntime排序，nice=-20优先级最高
  - 关键参数：sched_latency_ns(6ms)、sched_min_granularity_ns(0.75ms)
- **实时调度策略**：SCHED_FIFO(运行到主动让出)、SCHED_RR(同优先级轮转100ms)、SCHED_DEADLINE(EDF)
- **CPU 隔离(Isolcpus)**：isolcpus + nohz_full + rcu_nocbs 三者配合
- **SoA vs AoS**：结构数组(连续访问)优于数组结构(跨步访问)
- **循环分块(Tiling)**：复用缓存数据
- **软件预取**：不规则访问模式用 prefetch 提示

### 2.8 GPU 优化 (09)

- **Kernel 启动开销**：~5-20μs，合并小kernel或使用CUDA Graph
- **Occupancy**：SM上活跃warp数/最大warp数，受寄存器/shared memory限制
- **Warp Divergence**：同一warp内线程执行不同分支→串行化
- **Global Memory 合并访问**：连续地址→一次transaction完成
- **Shared Memory**：on-chip SRAM，寻址灵活但要注意bank conflict
- **Roofline 模型**：区分 compute-bound vs memory-bound kernel
- **FP16/INT8 推理**：Tensor Core加速，FP16吞吐量是FP32的2-8x
- **Kernel Fusion**：合并多个kernel减少launch开销和global memory访问
- **CUDA Graph**：预录制命令图，消除重复launch开销
- **Async Copy**：cuda::memcpy_async 用SM copy engine做数据搬移

### 2.9 实时系统基础 (12)

- **三类实时系统**：
  - 硬实时(Hard RT)：错过期限=系统失败(飞行控制/紧急制动)
  - 固实时(Firm RT)：偶尔可容忍但结果作废
  - 软实时(Soft RT)：偶尔超时只是降级(游戏渲染)
- **确定性(Determinism)**：最差延迟可预测 > 平均延迟低
- **抖动(Jitter)来源**：调度抢占(1μs~10ms)、中断(10-100μs)、DVFS(10μs~1ms)、SMI(~100μs)
- **WCET(最坏执行时间)**：控制循环要保守估计WCET，用WCET做调度分析
- **RMS(速率单调调度)**：周期越短优先级越高(静态)，可调度利用率≤69%(n→∞)
- **EDF(最早截止时间优先)**：deadline越近优先级越高(动态)，可调度利用率100%
- **优先级反转经典案例**：1997火星探路者系统反复重启
- **Linux实时支持**：
  - PREEMPT_RT 补丁 → 完全可抢占内核，中断线程化
  - SCHED_DEADLINE(Linux 3.14+)：EDF+CBS，最先进方案
  - mlockall 锁内存 → 设置调度策略 → 错误顺序会缺页异常高优先级
- **实时编程陷阱**：
  - 实时路径禁止 malloc/new（可能触发sbrk/mmapp/syscall）
  - 实时路径禁止 printf/日志（缓冲区刷新不可预测）
  - 实时路径禁止 open/close/read/write 磁盘（可能阻塞）
  - 实时路径禁止创建/销毁线程（线程池替代）
- **系统配置清单**：PREEMPT_RT + isolcpus + IRQ affinity + performance governor + 关C-States + huge pages + 关SMI + RCU隔离
- **验证工具**：cyclictest（理想<20μs）、oslat、自定义CLOCK_MONOTONIC打点

### 2.10 边缘端性能优化实战 (13)

- **RK3588 DMA Buffer 问题**：uncached内存CPU读取~15ms vs cached+SYNC~0.3ms，差距50x
- **DMA_BUF_IOCTL_SYNC**：
  - START|READ: CPU读前invalidate cache
  - END|READ: 读完后释放
  - START|WRITE: CPU写后writeback cache
  - END|WRITE: 写完DMA可读
- **Fail-closed 策略**：sync失败则拒绝处理该帧，绝不使用不确定状态的数据
- **NEON SIMD 局限性**：计算快但带宽瓶颈时收益有限(<10%)
- **带宽瓶颈 vs 计算瓶颈**：
  - 带宽瓶颈：增数据量延迟线性增长、降精度延迟几乎不变、NEON提升<10%
  - 计算瓶颈：增数据量延迟不变、降精度延迟下降、NEON提升2-4x
- **嵌入式特有考量**：DDR带宽被多模块共享(NPU/RGA/CPU/Display)，局部优化可能被全局争抢抵消
- **优化路径**：uncached→cached+SYNC(80%收益) → NEON转换(8%) → buffer预分配(5%) → 其他(7%)

### 2.11 NPU 推理优化 (14)

- **"外围比核心慢"陷阱**：输入/输出管线开销(82ms) >> 模型推理(11ms)
- **IO 持久化**：rknn_set_io_mem() 一次注册持续复用，消除每帧DMA分配(27ms→0.1ms)
- **双 Letterbox 问题**：硬编码尺寸与模型输入不匹配，SDK自动CPU resize(额外22ms)
- **NEON LUT 查表法**：uint8→FP16 转换，预计算256项查找表，vld1q_u8 + tbl + vst1q_f16
- **NPU 利用率诊断**：利用率 = 推理时间/总帧时间，低利用率=有东西在阻塞NPU
- **逐层下钻分析**：全pipeline打点 → perf top热点 → perf record追踪点 → NPU利用率 → 日志插桩
- **配置匹配性价比最高**：一行CLI参数纠正带来2x吞吐

### 2.12 机械臂控制 (15)

- **正运动学(FK)**：DH参数→齐次变换矩阵 T_i → 连乘得末端位姿 T_0_N
- **DH 参数四元组**：a(连杆长度)、α(扭转角)、d(关节偏移)、θ(关节角)
- **逆运动学(IK)分类**：
  - 解析IK：O(1)，仅适用于满足Pieper准则的6-DOF臂
  - 数值IK：O(n²~n³)，适用于任意构型，需迭代收敛
- **Newton-Raphson IK**：Δθ = J⁺·e，奇异点附近J伪逆不稳定
- **DLS (Damped Least Squares)**：Δθ = Jᵀ(JJᵀ+λ²I)⁻¹e，λ自适应抑制奇异
- **SVD 零空间优化**：Δθ = J⁺e + (I-J⁺J)·z，在完成主任务同时优化次任务(避奇异/避障)
- **全身控制(WBC)**：多任务优先级——高优先级任务先解，低优先级在零空间求解
- **MPC(模型预测控制)**：滚动时域优化，利用未来预测做决策
- **导纳/阻抗控制**：质量-弹簧-阻尼虚拟模型，力位混合交互

### 2.13 人形机器人平衡 (16)

- **ZMP(零力矩点)**：支撑多边形内→稳定，边界外→倾倒
- **DCM(发散运动分量)**：将CoM动力学解耦为稳定/不稳定分量，控制DCM在支撑域内
- **全身动量控制**：角动量+线动量联合控制
- **步态规划**：摆线/TEB步态、足底倾角自适应

### 2.14 ROS2 实时应用 (17)

- **ROS2 vs ROS1**：DDS替代自定义协议、节点内零拷贝
- **Callback Group**：互斥组串行、可重入组并行
- **Loan Message API**：节点间零拷贝共享内存
- **确定性执行器(EventsExecutor)**：基于事件依赖图调度
- **QoS 配置**：Reliability(BestEffort/Reliable)、Durability(Volatile/TransientLocal)、Deadline/Lifespan
- **ROS2实时实践**：PREEMPT_RT + 绑核 + 禁用DDS内部malloc + 使用intra-process通信

### 2.15 团队协作 (06)

- **性能profiling应成为code review的一部分**
- **CI/CD集成性能回归测试**：自动对比pipeline_metrics的P50/P99变化
- **可重复的基准测试环境**：固定CPU频率、关闭无关进程、隔离核心
- **性能数据可视化**：延迟时间序列图、P50/P99趋势图、吞吐量变化
- **优化决策需要量化数据支撑**：不做凭直觉的"优化"

### 2.16 抖动诊断指南 (jitter_diagnosis)

- **6 类抖动来源**：OS调度抢占、缓存/TLB miss、内存带宽竞争、中断(IRQ)、CPU频率调节(DVFS)、动态内存分配(malloc)
- **验证工具链**：perf stat → perf sched → cyclictest → /proc/interrupts → cpufreq-info
- **判断标准**：p99/mean>3x→调度抢占严重；spike>10us频率>100/百万次→IRQ风暴；cycle variation>5%→DVFS活跃
- **解决映射**：调度→SCHED_FIFO+绑核、缓存→prefetch+大页、带宽→NUMA绑定、中断→IRQ affinity、变频→performance governor、分配→预分配池
