# 05｜灰度发布：模型 V1 → V2 的逐步放量与自动回滚

## 本模块解决的问题

新模型版本上线，直接 100% 切换是拿全部用户做实验。灰度发布让新版本从小流量逐步放量，监控异常自动回滚。本章回答：

```text
灰度发布的流程是什么？（1% → 10% → 50% → 100%）
监控什么指标？出现回归怎么自动回滚？
灰度和 A/B test 有什么区别？
```

配套代码：`src/serving/canary_release/`（`canary.py` 灰度控制器 + 监控 + 回滚）。

---

## 1. 灰度发布流程

```text
Model V1（稳定）  ──100% 流量──►  基线
Model V2（新）    ── 1% 流量──►  观察 error/latency
                    │ 无回归
                    ▼
                 ──10% 流量──►  继续观察
                    │ 无回归
                    ▼
                 ──50% 流量──►
                    │ 无回归
                    ▼
                 ──100% 流量──► 全量切换
```

每一步都在监控新版本，一旦回归立即回滚到 V1。

---

## 2. 监控指标（不只是 accuracy）

master prompt 强调：灰度监控 **error rate、latency、accuracy、GPU utilization**，而不是只看 accuracy。因为回归有多种形态：

| 回归类型 | 监控指标 | 本模块模拟 |
|---|---|---|
| 精度回归 | error rate / accuracy | V2 错误率 8x 基线 |
| 性能回归 | latency | V2 延迟 5x 基线 |
| 资源回归 | GPU utilization | （理论，需真实 GPU） |

### 本机实测（模拟器，eval 10000 请求/阶段）

**精度回归（V2 错误率 8% vs V1 1%）**：

```text
share=1%  err 1.1% -> 9.0%  -> rollback
```

**延迟回归（V2 延迟 50ms vs V1 10ms）**：

```text
share=1%  lat 10ms -> 50ms  -> rollback
```

**健康版本**：

```text
share=1% -> 10% -> 50% -> 100%  （每个阶段 err/lat 都正常，逐步 advance）
```

**核心价值**：回归在 **1% 流量**就被捕获，只影响 1% 的用户；如果没有灰度，直接 100% 上 V2，8% 的错误率会砸到所有用户。

---

## 3. 自动回滚的判据

本模块的回滚逻辑（`_is_regression`）：

```text
error regression:  candidate_err / stable_err > 2.0（误差容差）
latency regression: candidate_lat / stable_lat > 1.5（延迟容差）
```

关键点：

1. **用比值，不用绝对值**：新版本比基线差多少（相对），而不是超过某个固定阈值。这样能适配不同流量下的基线波动。

2. **统计显著性**：低流量阶段样本少，误差率高可能是噪声。本模块用 10000 请求/阶段（1% 流量 = 100 样本），让统计可靠。真实系统里，低流量阶段要观察更久（累积更多样本）或做统计检验。

---

## 4. 灰度 vs A/B test（Stage 21 预告）

| | 灰度发布 | A/B test |
|---|---|---|
| 目的 | 安全地切换新版本 | 对比两个版本的业务效果 |
| 流量 | 新版本逐步放量到 100% | 两个版本长期共存（各 50%） |
| 关注指标 | error/latency（技术） | 业务指标（转化率、robot success rate） |
| 回滚 | 有回归就回滚 | 选胜者，淘汰败者 |

灰度是"安全上线"，A/B 是"效果实验"。两者常组合：先灰度（保技术稳定），再 A/B（看业务效果）。

---

## 5. 本模块闭环小结

```text
问题：新模型上线怎么避免"上线即事故"
      ↓
流程：1% → 10% → 50% → 100%，每步监控
      ↓
监控：error rate + latency + accuracy + GPU util（相对比值判据）
      ↓
实测：精度/延迟回归都在 1% 流量被捕获并回滚
      ↓
下一步：Stage 21 A/B Test（业务指标 vs 技术指标）
```

要继续就说「继续」。
