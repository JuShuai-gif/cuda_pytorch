# 04｜实时性：Latency / Jitter / Deadline 与控制稳定性

## 本模块解决的问题

Stage 14 讲了 jitter 的现象（p99 涨 40%）。本章用**控制理论**量化 jitter 的危害，回答 master prompt 的核心问题：

```text
为什么平均 latency = 15ms 但 p99 = 200ms 会导致机器人不可用？
恒定延迟和抖动延迟对控制系统的区别是什么？
为什么恒定延迟可以补偿，抖动延迟不能？
```

配套代码：`src/robotics/realtime/`（二阶系统 + PID 控制 + 可变延迟模拟）。

---

## 1. 实时性指标

| 指标 | 含义 | 机器人为什么关心 |
|---|---|---|
| Latency | 采样到动作的延迟 | 动作过时的程度 |
| Jitter | latency 的波动 | 系统能否稳定 |
| Deadline | 控制周期上限 | 是否掉帧 |
| Control Frequency | 1 / 控制周期 | 能跟踪多快的运动 |
| Priority | 调度优先级 | 关键任务不被抢占 |

---

## 2. 控制系统的视角：为什么 jitter 致命

一个受控系统（如机器人关节）用 PID 控制跟踪目标。控制延迟的作用：**延迟越大，系统越难稳定**（延迟相当于相位滞后，高增益 + 大延迟 = 振荡/发散）。

关键在于**恒定 vs 抖动**：

```text
恒定延迟：可以补偿——设计控制器时把延迟算进去（降增益换取稳定）
抖动延迟：无法补偿——延迟时大时小，控制器的有效增益每个周期都在变
```

抖动延迟的破坏性在于：**大部分时间延迟低（可以用高增益，响应快），但偶发的大延迟让这个高增益在那一瞬间失去稳定**。你无法为"时大时小"的延迟调参。

---

## 3. 实测：三种延迟分布的跟踪误差

二阶系统跟踪目标 1.0，PID 控制（dt=10ms），系统先稳定后注入不同延迟：

```text
latency                  rms_error   max_error   settled
constant 10ms            0.019       0.069       是
constant 200ms           1.512       4.764       否
jittery（mean ~15ms）    0.159       0.485       否
```

### 读法（本模块的灵魂）

1. **constant 10ms**：稳定跟踪，误差小（rms 0.019）。

2. **constant 200ms**：大振荡（max 4.76，rms 1.51）——高增益在 200ms 延迟下不稳定。**但这是"可解决的"**：把增益调低，200ms 也能稳定（只是响应慢）。

3. **jittery（平均 15ms，偶发 50ms 卡顿）**：
   - rms 只有 0.159（**平均看起来还行**，因为大部分时间延迟低）
   - 但 **max_error = 0.485，是 constant 10ms 的 7 倍**，且不 settled

**这就是"平均 15ms 但 p99=200ms 导致不可用"的量化答案**：偶发的大延迟让末端执行器瞬时偏离目标 48%（0.485 / 1.0），而且反复发生（不 settled）。对机器人，这意味着**偶发地偏离目标位置近一半，可能撞到物体或人**。

### 关键洞察：rms 掩盖了 jitter 的危害

```text
jittery 的 rms = 0.159（比 constant 200ms 的 1.51 好很多，看起来"还行"）
jittery 的 max = 0.485（比 constant 10ms 的 0.069 差 7 倍，实际上"危险"）
```

**rms/mean 是"平均感受"，max/p99 是"最坏情况"**。机器人安全由最坏情况决定，不是平均。

## 4. 工程含义

```text
1. 监控机器人推理，必须看 p99 和 deadline miss，不是 mean（Stage 14 结论的强化）
2. 恒定慢可以接受（降增益补偿），抖动慢不可接受（无法补偿）
3. 消除 jitter 的手段：CUDA Graph（稳定 kernel 序列）、去同步、预分配（Stage 14 的 batch=1 优化）
4. 实时系统的优化目标：不是"更快"，是"更稳"——把 p99 压到 deadline 内
```
