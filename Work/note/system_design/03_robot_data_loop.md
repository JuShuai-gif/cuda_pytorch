# System Design 3：Robot Data Loop

## 需求

机器人数据闭环：异常数据上传 → 分析 → 训练 → 评估 → 模型发布。目标是让机器人车队"越用越好"（数据飞轮，Stage 27）。

---

## 2. 核心组件

### 异常检测（机器人端 + Edge）

```text
为什么：1000 台机器人的全量数据太大，只上传有价值的

策略：
  1. 失败案例（task result = failed）→ 必传
  2. 低置信度（模型输出不确定）→ 必传
  3. 分布外（novel object / 罕见场景）→ 必传
  4. 正常案例 → 采样（比如 1%）
```

### 失败挖掘（Failure Mining，Stage 27）

```text
职责：从运行数据中筛选失败案例，分析失败原因

输出：
  失败案例数据集（负面样本，最珍贵）
  失败原因分类（low_light / occlusion / novel_object ...）
  失败统计（哪种失败最频繁 → 训练优先级）
```

### 训练 / 评估

```text
训练：失败案例 + 原有数据混合训练（失败案例加权）
评估：离线评估（accuracy）+ 上线评估（task success rate，Stage 21）

评估门槛：
  离线 accuracy 不退化
  灰度 task success rate 不退化（Stage 20）
```

### 模型发布

```text
评估通过 → Model Registry → 灰度发布（System Design 1）
```

## 3. 关键流程（飞轮）

```text
Round 1：
  机器人运行 → 1000 个任务 → 51.7% 失败
  → 异常检测上传失败案例 → 失败挖掘（按原因分类）
  → 训练（失败案例加权）→ 新模型 → 灰度发布

Round 2：
  机器人跑新模型 → 失败率 37%
  → 继续挖掘 + 训练 → 失败率 17% → 5% ...

数据飞轮：部署越多 → 数据越多 → 模型越好 → 失败越少
```

---

## 4. 规模化的关键权衡

| 问题 | 权衡 | 决策 |
|---|---|---|
| 全量 vs 采样上传 | 数据完整 vs 带宽/存储 | 失败必传 + 正常采样 |
| 失败案例 vs 成功案例 | 训练效率 | 失败案例加权（更值钱） |
| 自动 vs 人工标注 | 速度 vs 质量 | 失败原因自动分类 + 人工抽查 |
| 闭环速度 | 快（风险）vs 慢（安全） | 灰度发布保证安全的前提下尽量快 |
| 隐私（相机数据） | 数据价值 vs 合规 | 脱敏 + 权限控制 |

---

## 5. 数据质量与治理

```text
数据质量：噪声、异常、重复都要过滤（否则训练出更差的模型）
数据治理：版本、来源、权限（相机数据隐私）
数据血缘：哪个模型产生的数据 → 训练出哪个模型（可追溯）
```

## 7. 设计要点总结

```text
1. 只上传有价值的案例（失败/低置信/分布外），全量上传会压垮带宽和存储
2. 失败案例是"负面样本"，比成功案例更值钱（暴露盲区）
3. 数据飞轮是规模化护城河（越用越好，对手追不上）
4. 闭环要安全（灰度）和可追溯（数据血缘）
5. 数据治理（隐私/权限/版本）是规模化后必须面对的问题
```
