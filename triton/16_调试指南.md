# 16 调试指南（深度版）

> 本文目标：掌握 Triton 的调试工具链——dump IR、triton-opt、triton-reduce、解释执行、MLIR reproducer。

## 1. 工具总览

| 工具 | 入口 | 用途 |
| --- | --- | --- |
| Dump IR | `TRITON_DUMP_IR=1` + `TRITON_DUMP_DIR` | 各阶段 IR |
| triton-opt | `bin/triton-opt` | 单跑 MLIR pass |
| triton-reduce | `bin/triton-reduce` | 崩溃 IR 最小化 |
| 解释执行 | `TRITON_INTERPRET=1` | Python 解释 kernel |
| reproducer | `triton-opt --run-reproducer` | 崩溃复现 |
| proton | `third_party/proton` | 性能插桩 |

## 2. Dump IR（深度）

```bash
TRITON_DUMP_IR=1 TRITON_DUMP_DIR=/tmp/dump python my_kernel.py
ls /tmp/dump
# *.ttir *.ttgir *.llir *.ptx *.cubin
```
- 开关在 `knobs.py`（`TRITON_KERNEL_DUMP`）。

## 3. triton-opt（深度）

```bash
bin/triton-opt /tmp/x.ttgir --ttgpu-coalesce --ttgpu-accelerate-matmul
```
- 在 IR 文件上手动执行 pass。
- lit 测试的底层工具。
- **注意**：`--run-reproducer` 可跑 MLIR 崩溃复现文件。

## 4. 崩溃复现（深度，AGENTS.md 准则）

1. 编译器崩溃时保存 `mlir_reproducer`（含 `{-# ... #-}` metadata）到 `/tmp/x.mlir`。
2. `triton-opt /tmp/x.mlir --run-reproducer` 本地复现。
3. `triton-reduce` 最小化。
4. 修 bug / 报 issue。

## 5. triton-reduce（深度）

```bash
bin/triton-reduce /tmp/crash.ttgir --triton-reduce-pass=...
```
- 自动最小化触发 bug 的 IR。
- 产出最小复现文件。

## 6. 解释执行（深度）

```bash
TRITON_INTERPRET=1 python my_kernel.py
```
- `runtime/interpreter.py` 用 Python 逐语句解释。
- 慢，但便于调试语义/结果错误。

## 7. 从缓存读产物

```bash
ls ~/.triton/cache/<hash>/
# kernel.ttir/.ttgir/.llir/.ptx/.cubin + .json
```
- 用 `kernel.asm["ptx"]` 或直接读文件。

## 8. 常见错误定位（深度）

| 症状 | 手段 |
| --- | --- |
| 编译错误 | 看 traceback 定位 pass + dump IR |
| 结果错误 | `TRITON_INTERPRET=1` + 对照 ref |
| 崩溃 | reproducer + triton-opt |
| 性能差 | 看 ttgir 的布局/mma（`17`） |
| 缓存不更新 | `TRITON_ALWAYS_COMPILE=1` |
