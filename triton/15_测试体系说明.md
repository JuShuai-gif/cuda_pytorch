## 2. lit 测试机制（深度）

`test/TritonGPU/accelerate-matmul.mlir`：
```mlir
// RUN: triton-opt %s --ttgpu-accelerate-matmul | FileCheck %s
// CHECK: tt.dot ... tensor<128x64xf16, #ttg.dot_op<...>>
```
- `RUN:`：声明执行命令（triton-opt + FileCheck）。
- `CHECK:`：断言输出包含。
- 验证：`make test-lit` 或 `ninja -C $BUILD_DIR check-triton-lit-tests`。

**为什么是行为真相**：pass 的输出以 `.mlir` 断言形式"可执行地"固定，比注释可靠。

## 3. pytest 测试（深度）

```bash
make test-unit
python -m pytest python/test/unit -s --tb=short
python -m pytest python/test/unit/test_xxx.py::test_name
```

AGENTS.md 准则：
- 编译器改动加 lit 或 pytest。
- GPU 测试放 `python/test/unit/`，命名 `test_<feature>_<condition>`。
- 用 `pytest file.py::test_name` 跑单个。

## 4. C++ 单测

```bash
make test-cpp   # ninja check-triton-unit-tests
```
- 需 `TRITON_BUILD_UT=ON`。

## 5. 如何加测试（深度）

对 pass 改动：
1. `test/TritonGPU/` 加 `.mlir`：RUN 行 + FileCheck。
2. 用 triton-opt 跑新 pass。
3. CHECK 断言关键输出。

对 Python/算子：
1. `python/test/unit/` 加 `test_<feature>.py`。
2. 参考实现对比 + do_bench。
