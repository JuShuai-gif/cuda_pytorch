# 34 工程落地·生命周期与状态机（深度版）

> 本类问题的共性：编译器里的对象有明确的**创建→使用→销毁**生命周期。难点在于"**谁拥有、何时释放、引用是否悬垂**"。

## 机制 1：CompiledKernel 的显式卸载

### 约束
- `cuModuleLoadData` 加载的 CUfunction 句柄不随 Python GC 自动释放。
- 必须显式 `cuModuleUnload`。

### 实现（`compiler.py:445` + `driver.c:354`）
```python
def __del__(self):
    self._delete_handles()   # → unloadModule → cuModuleUnload(mod)
```
```c
void unloadModule(KernelHandle_t handle) { cuModuleUnload(handle); }
```

> **不变量 L1**：CUfunction 的释放必须显式进行，且不能悬垂（先于其依赖的 module 卸载）。

### 工程判断
- **C 资源的显式析构**：Python GC 管内存，但 CUDA 句柄必须显式 `__del__`——**语言 GC 管不了的资源要手动归还**。
- 对比 TileLang：Python 引用计数让 module 随 GC 管理，但 CUfunction 一样要显式。

## 机制 2：driver.active 懒加载生命周期

### 约束
- `import triton` 不能触发 CUDA 初始化（要快）。
- driver 生命周期 = 进程生命周期（全局单例）。

### 实现（`runtime/driver.py:36-40`）
```python
class DriverConfig:
    @property
    def active(self):
        return self.default()   # 懒加载：首次访问才创建
```

> **不变量 L2**：driver 的初始化严格推迟到首次使用点，且进程内唯一。

### 工程判断
- **懒加载推迟启动成本**：把 CUDA 初始化（`cuInit` 探测）推迟到真正需要时。
- **全局单例**：driver 是进程级资源，不可多实例（多实例会竞争 CUDA context）。

## 机制 3：流水线 buffer 版本窗口

### 约束
- `LowerLoops.cpp` 多缓冲：producer 写版本 i，consumer 读版本 i-k。

### 状态机
```cpp
num_versions = getDefUseStageDiff(...);   // = useStage - defStage
// alloc 第一维 = num_versions
// 循环携带 insertIdx/extractIdx 取模递增
```

> **不变量 L3**：任一 buffer 版本，从 producer 写入到 consumer 读取完成之间，不允许被覆写。

### 工程判断（与 lease 同构）
- 版本窗口 = "对象存活期"；stage 差 = "TTL"；循环外 `AsyncWaitOp({},0)` = "最后持有者离场"。
- **生命周期管理在编译器里的通用形态**。

## 机制 4：时钟（时间）与缓存失效

### 约束
- 缓存失效必须不依赖易变时钟。

### 工程判断
- **正确性靠内容哈希**：`triton_key()`（cache.py:283）对编译器源码 + libtriton 二进制做哈希，`src.hash()` 含 AST hash + 起始行号——**全部是内容指纹，不依赖 mtime**。
- **行号进 key 是极端保守**：挪一行就失效，但绝不跑旧结果（呼应面试题"正确性不依赖时钟"）。
- 时钟只用于非关键路径（如清理残留）。

## 机制 5：TMA 描述符生命周期

### 约束
- `cuTensorMapEncodeTiled` 创建的 TMA 描述符有对齐要求（128/64 字节）。
- 必须在 kernel 使用期间存活。

### 实现（`driver.c:512-525`）
```c
// posix_memalign(128) 对齐分配
```

> **不变量 L4**：TMA 描述符在其关联 kernel 执行期间必须存活且保持对齐。

### 工程判断
- **对齐是生命周期的一部分**：分配时保证对齐，避免使用期 UB。
- 这是"生命周期 + 资源属性"耦合的典型。

## 本类工程判断总结

1. **语言 GC 管不了的资源要显式析构**（CUfunction）。
2. **懒加载推迟启动成本，全局单例管进程资源**。
3. **生命周期窗口 = 版本窗口**（写读之间不许动）。
4. **正确性不依赖时钟**：失效靠内容哈希。
5. **对齐是资源生命周期的一部分**。
