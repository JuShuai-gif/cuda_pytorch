# 15 测试体系（深度版）

> 本文目标：理解测试作为"源码行为真相来源"的价值——尤其是 transform 测试如何精确定格 pass 的行为，这比读注释更可靠。

## 1. 测试目录结构

```
testing/
├── conftest.py
├── python/           # 算子级 pytest
│   ├── kernel/       # kernel 正确性
│   └── transform/    # pass 行为测试（重点！）
├── cpp/              # C++ 单测（gtest）
examples/<op>/test_*.py  # 示例自带测试
```

## 2. transform 测试的价值（深度）

`testing/python/transform/test_tilelang_transform_pipeline_planning.py` 这类文件，用 `assert` 精确记录了 pass 的输出。例如（已确认）：

```python
# pipeline planning 输出
assert anno["software_pipeline_stage"] == [0, 0, 2]   # 拷贝→stage0, 消费→2
assert anno["software_pipeline_order"] == [0, 1, 2]
assert anno["tl_pipelined_num_stages"] == 3
```

**为什么这是最佳学习资料**：pass 的行为以断言形式"可执行地"固定下来，比读 C++ 注释更精确、更不会过时。

## 4. 测试模式

```python
# 典型 kernel 正确性测试
def test_matmul(...):
    a = torch.randn(M, K, dtype=torch.float16, device="cuda")
    b = torch.randn(N, K, dtype=torch.float16, device="cuda")
    ref = (a.float() @ b.float().T).half()
    c = matmul(M, N, K, ...)
    torch.testing.assert_close(c, ref, ...)
```

## 5. C++ 测试

- `testing/cpp/`：gtest。
- 需构建时开测试（`TRITON_BUILD_UT` 类似选项）。
- 运行：`./build/testing/cpp/test_xxx`（以实际构建为准）。

## 6. CI 流程

`.github/workflows/`：

- 测试：`pytest testing` + examples。
- CI 脚本是"干净环境安装"的最佳文档（见 `12`）。

## 7. 如何加测试（深度）

对 pass 改动：
1. 在 `testing/python/transform/` 加 `test_<pass>.py`。
2. 用 `tilelang.transform.PassContext` + 直接构造 PrimFunc。
3. assert pass 前后 IR 的关键属性。

```python
from tilelang import transform

def test_layout_inference_...():
    mod = ...  # 构造含 T.gemm 的 IRModule
    mod2 = transform.LayoutInference()(mod)
    # assert 布局结果
```
