## 2. 解剖 example_gemm.py（深度）

核心 kernel（`examples/gemm/example_gemm.py`）：

```python
@tilelang.jit(out_idx=[2])
def matmul(M, N, K, block_M, block_N, block_K, threads, stages):
    dtype = "float16"; accumulate_dtype = "float32"
    A = T.Tensor((M, K), dtype)
    B = T.Tensor((N, K), dtype)
    C = T.Tensor((M, N), accumulate_dtype)
    with T.Kernel(T.ceildiv(N, block_N), T.ceildiv(M, block_M), threads=threads) as (bx, by):
        A_shared = T.alloc_shared((block_M, block_K), dtype)
        B_shared = T.alloc_shared((block_N, block_K), dtype)
        C_local = T.alloc_fragment((block_M, block_N), accumulate_dtype)
        T.clear(C_local)
        for ko in T.Pipelined(T.ceildiv(K, block_K), num_stages=stages):
            T.copy(A[by * block_M, ko * block_K], A_shared)
            T.copy(B[bx * block_N, ko * block_K], B_shared)
            T.gemm(A_shared, B_shared, C_local)
        T.copy(C_local, C[by * block_M, bx * block_N])
    return C
```

### 逐行语义 → 编译行为

| 行 | 语义 | 编译行为 |
| --- | --- | --- |
| `out_idx=[2]` | C 是输出 | JITKernel 运行时用 `torch.empty` 分配（`tvm_ffi.py:270`） |
| `T.Kernel(ceildiv(N,BN), ceildiv(M,BM), threads)` | block 网格 | launch frame → `thread_extent` |
| `T.alloc_shared((BM,BK), fp16)` | A 的 shared 缓冲 | `__shared__ half A_shared[...]`（swizzle 布局） |
| `T.alloc_fragment((BM,BN), fp32)` | C 累加器 | 寄存器（mma fragment 布局，每线程 BN*BM/32 元素） |
| `T.clear(C_local)` | 清零 | `tl.tileop.fill` → 置零 |
| `T.Pipelined(..., stages)` | K 循环流水线 | PipelinePlanning + InjectSoftwarePipeline |
| `T.copy(A[...], A_shared)` | global→shared | cp.async（`tl.enable_async_copy`） |
| `T.gemm(A_shared, B_shared, C_local)` | tile 乘加 | LowerTileOp → ldmatrix + mma.sync |

## 3. 关键变体对比

### gemm_ss vs gemm_rs（存储作用域）
- `gemm_ss`：A、B 都在 shared → 两者都 `make_swizzled_layout`（`gemm_mma.py:44-49`）。
- `gemm_rs`：A 在 fragment、B 在 shared → **A 不加载**，直接作为 mma 操作数（`gemm_mma.py:173-199` `_gemm_rsr`）。
- 什么时候用 rs：A 来自前一算子直接产出的 fragment（如转置/cast），避免 shared 中转。

### splitk / streamk
- splitk：K 维切分到多个 block，各自部分和，再归约。
- streamk：动态负载均衡（对不均匀 shape）。

## 4. FlashAttention 结构解剖（`examples/flash_attention/`）

核心模式：
```python
with T.Kernel(ceildiv(seqlen, block_N), ...) as bx:
    acc_s = T.alloc_fragment((block_M, block_N), accumulate_dtype)  # 行 softmax 状态
    acc_o = T.alloc_fragment((block_M, block_N), accumulate_dtype)  # 输出累加
    m_i = T.alloc_fragment((block_M,), accumulate_dtype)            # running max
    for k in T.Pipelined(seqlen // block_N, num_stages=stages):
        Q_shared = ...; K_shared = ...
        S = T.alloc_fragment((block_M, block_N), accumulate_dtype)
        T.gemm(Q_shared, K_shared, S)      # QK^T
        # online softmax: 更新 m_i、exp、acc_o
        T.reduce_max(S, m_i, dim=1)        # 或手动在线更新
        ...
    T.copy(acc_o, O[...])
```

**关键：fragment 间的 gemm + online softmax 的跨迭代状态更新**。这展示了 fragment 布局如何支持"累加器跨循环存活"。
