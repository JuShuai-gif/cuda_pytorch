# 16 调试与错误处理（深度版）

> 本文目标：掌握"编译期"与"运行期"两类错误的完整调试链路，重点深入 dump IR、pass_diff、错误渲染机制。

## 1. 错误类型 → 调试工具矩阵

| 症状 | 工具 | 定位 |
| --- | --- | --- |
| 编译失败（TVMError） | dump IR + lower_trace | 定位出错 pass |
| 结果错误 | get_kernel_source + 对照 ref | 定位逻辑/布局问题 |
| 越界/非法访问 | safe memory + 小 shape | 定位索引问题 |
| 布局冲突 | 错误消息的 Layout(...) 文本 | 定位冲突 buffer |
| 性能差 | dump_ir + Nsight | 定位生成代码问题 |

## 2. dump IR（深度）

```python
k = matmul.compile(..., pass_configs={
    PassConfigKey.TL_ENABLE_DUMP_IR: True,
    PassConfigKey.TL_DUMP_IR_DIR: "/tmp/dump_ir",
})
```
- 产物：`/tmp/dump_ir/` 下每两个 pass 之间一个 IR 文件。
- **用法**：用 `diff` 相邻文件，看"哪个 pass 改变了什么"。

## 3. pass_diff / lower_trace（深度）

- `TILELANG_PASS_DIFF=terminal`（`tilelang/utils/pass_diff_hook.py`）：终端输出 pass 前后 diff。
- `TL_LOWER_TRACE=1`：逐 pass 追踪，生成脚本。

## 4. 错误渲染机制（深度）

`tilelang/errors.py` + `span_utils.h`：
- pass 失败时输出 `--> file:line:col`（`SpanHintSuffix`）。
- `enrich_error` 把它渲染成带源码行和脱字符的片段：
```
tvm.error.InternalError: The layout for fragment C_local ...
  --> /path/to/kernel.py:21:1
   |
21 |     C_local = T.alloc_fragment((block_M, block_N), accum_dtype)
   |     ^
```

## 5. 布局错误（深度）

`layout_inference.cc:246-264` 布局冲突错误：
```cpp
LOG(FATAL) << "Get different layout for " << buffer
           << "\n current layout: " << layout->DebugOutput()
           << "\n previous layout: " << layout_map[buffer]->DebugOutput();
```
- `LayoutNode::DebugOutput()`（layout.cc:1128）打印：
  ```
  Layout([M,K] -> [out], transform: [i0,i1] -> [...])
  Fragment([M,K] -> [out], replicate: N, thread: T, forward_thread: ..., forward_index: ...)
  ```
- 典型：两个 gemm 对同一 acc 推断出不同 thread_range → `"Get different layout for acc"`（测试 `test_tilelang_transform_producer_consumer_ws.py:560`）。

## 6. 语义检查（semantic check）

`tilelang/engine/semantic_check.py`：
- lower 前 Python 侧检查参数类型/dtype 合法性。
- `TL_DISABLE_PRELOWER_SEMANTIC_CHECK` 可关闭（默认开）。

## 7. 越界安全

`LegalizeSafeMemoryAccess` pass（`legalize_safe_memory_access.cc`）：
- 默认开，为越界访问生成边界保护。
- `TL_DISABLE_SAFE_MEMORY_LEGALIZE` 关闭（性能权衡）。
- `TL_DISABLE_OUT_OF_BOUND_WARNING` 关警告。

## 8. 数据竞争检查

- 默认关闭（`TL_DISABLE_DATA_RACE_CHECK` 默认 True），因误报。
- 开启：`TILELANG_ENABLE_DATA_RACE_CHECK=1`（pass_config.py:52-60）。

## 9. 运行期调试

- `kernel.get_kernel_source()`：看最终 CUDA。
- `compile(debug_root_path=...)`：保存 `tilelang_jit_program_*.py`（PrimFunc script）。
- Nsight Compute：`ncu` 看 kernel 内部分析。
