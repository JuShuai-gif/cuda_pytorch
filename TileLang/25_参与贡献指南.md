# 25 参与贡献指南（深度版）

> 本文目标：在流程基础上，给出"什么样的改动会被合并"的技术标准，以及本地复现 CI 的方法。

## 1. 仓库信息

- 上游：https://github.com/tile-ai/tilelang
- 版本 0.1.13（本仓库 commit 9d5f81b7），MIT。
- 语言：Python + C++。

## 2. 技术验收标准（深度）

| 改动类型 | 必须包含 | 质量标准 |
| --- | --- | --- |
| 新 pass | lit/transform 测试 | 断言精确行为 |
| 新算子 | 正确性测试 + 性能数据 | 与 cuBLAS 对比 |
| 修 bug | 复现用例 | 根因修复非症状 |
| 新 API | docstring + 使用示例 | 与其他 API 风格一致 |

## 3. 本地复现 CI

```bash
# 构建（C++ 改动）
pip install -e . --no-build-isolation

# 测试
pytest testing/python/transform -q
pytest examples/gemm/test_example_gemm.py -q

# lint（若配置）
ruff check tilelang/
```

## 4. 提交规范

- Conventional Commits：`[Pass] Fix ...`、`[BugFix] ...`。
- 每个 PR 聚焦一个主题。
- 测试与代码同 PR。

## 5. 面试视角：什么是有价值的贡献

- **性能优化**：某算子在 RTX 4090 上的 TFLOPS 提升（有数据）。
- **新算子**：覆盖常见场景。
- **pass 改进**：布局/流水线相关。
- **基础设施**：缓存、错误信息、文档。

## 6. PR 自检清单（升级）

- [ ] `pytest` 相关通过
- [ ] 新功能有测试
- [ ] lint 通过
- [ ] C++ 改动跑过 `make`/重编
- [ ] 性能有数据（若涉及）
- [ ] 分支干净
