# 39 工程落地·类型系统与精度（深度版）

> 本类问题的共性：GPU 编程的类型/精度决策影响正确性（溢出、精度丢失）与性能（mma 支持的 dtype）。难点在于"**推导规则要正确、精度提升要显式、不支持的组合要拒绝**"。

## 机制 1：dtype 推导规则

### 约束
- `T.Tensor((M,K), "float16")` 的类型来自用户注解。
- gemm 的 M/N/K 从 shape 推导，dtype 从 buffer 取。

### 实现（`language/gemm_op.py:77-89`）
```python
M, N = C_shape[-2], C_shape[-1]
M_A = A_shape[-1] if transpose_A else A_shape[-2]
K = A_shape[-2] if transpose_A else A_shape[-1]
assert prim_expr_equal(M_A, M)   # M 一致性
assert prim_expr_equal(K, K_B)   # K 一致性
```

> **不变量 T1**：gemm 的 M/N/K 必须由 A/B/C 形状唯一确定且一致，否则编译报错。

### 工程判断
- **推导规则是显式断言**，不是静默猜：shape 不一致直接 assert（对应 fail-fast 原则）。
- 这是"类型系统即编译器正确性防线"的体现。

## 机制 2：累加精度（accumulate_dtype）

### 约束
- fp16 输入 + fp32 累加（避免精度损失）。
- mma 指令对累加精度有硬性要求。

### 实现（`mma_macro_generator.py`）
- `accumulate_dtype` 决定 C fragment 的类型。
- fp16×fp16→fp32 走 `mma.sync.m16n8k16.f32.f16.f16.f32`。

> **不变量 T2**：累加器精度必须 ≥ 输入精度（除非显式要求）。

### 工程判断
- **精度提升默认且显式**：用户写 `accumulate_dtype="float32"`，编译器据此选 mma 变体。
- 这避免了 fp16 累加的精度灾难（大 K 时误差累积）。

## 机制 3：dtype 支持矩阵与拒绝

### 约束
- 不是所有 dtype 组合都支持 mma（如 fp8 只有部分架构支持）。
- 不支持的组合必须拒绝而非静默降级。

### 实现（`cuda/op/gemm.cc` 的 Allow* 判断 + `gemm_base.py` 的 validate）
```cpp
// AllowWgmma 对 dtype 细分
if (dtype == fp16/bf16) require k%16==0;
if (dtype == fp8/tf32/int8) require !transA && transB && k%32==0;
```

> **不变量 T3**：不支持的 dtype×指令组合，必须在编译期拒绝并给出原因。

### 工程判断
- **能力矩阵显式化**：`AllowWgmma`/`AllowTcgen5Mma` 等谓词是"能力清单"，违反即拒绝。
- 与 Triton 的 `supportMMA`（Utility.cpp:1105）同构。
- 拒绝比静默降级好：静默用 FMA 算 fp8 是错误结果。

## 机制 4：精度相关的 pass 开关

### 约束
- 快速数学、TF32 模拟等影响精度。

### 实现（pass_configs）
- `tl.enable_fast_math`：nvcc `--use_fast_math`（牺牲精度）。
- `tl.disable_wgmma`：禁用 wgmma（架构降级）。
- Triton 侧：`emuTF32 = capability//10 >= 8`（`F32DotTC`），`TRITON_F32_DEFAULT`。

> **不变量 T4**：影响精度的选项必须是显式开关，且默认安全（fast_math 默认 False）。

### 工程判断
- **精度/性能权衡由用户显式控制**，编译器默认走正确路径。
- 这符合"默认安全、显式加速"的工程原则。

## 机制 5：低位宽打包（int4/fp4）

### 约束
- int4/fp4 元素 2 个/字节，不能直接数组下标访问。

### 实现（`codegen_cuda.cc:5297-5335`）
```cpp
// int4: tl_int4_packed_store((signed char*)vid, idx, value)
// fp4:  tl_fp4_packed_store(...)  // 避免覆盖相邻 nibble
```

> **不变量 T5**：亚字节 dtype 的读写必须经过打包/解包，不得直接标量访问。

### 工程判断
- **特殊 dtype 在 codegen 层显式处理**：不是"默认能跑"，而是特判路径。
- 注释明确说明"普通赋值会覆盖相邻 nibble"——**这是被真实 bug 逼出来的特判**。

## 本类工程判断总结

1. **类型推导即正确性防线**：shape/dtype 一致性靠显式断言。
2. **精度提升默认且显式**：accumulate_dtype 由用户指定，编译器选指令。
3. **能力矩阵 + 拒绝**：不支持的组合当场拒绝，绝不静默降级。
4. **精度开关默认安全**：fast_math 默认关，显式开。
5. **亚字节 dtype 特判**：codegen 层打包/解包，被真实 bug 逼出。
