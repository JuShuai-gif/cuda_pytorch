## 已确认结论

（基于源码、构建文件、README、CI 配置，状态：已确认）

1. TileLang 构建系统是 CMake + scikit-build-core，Python >= 3.10，C++17（Windows 下 tilelang_objs 用 C++20）。
2. TileLang 使用**定制 TVM**（`3rdparty/tvm`，TileLang/tvm）作为编译器基础设施，运行时 FFI 使用 `apache-tvm-ffi`（PyPI 依赖 `apache-tvm-ffi>=0.1.11,<0.1.13`）。
3. 默认执行后端是 `tvm_ffi`（`ExecutionBackendSpec("tvm_ffi", ...)`，见 `tilelang/cuda/execution_backend.py:34-43`）。
4. 编译主入口是 `tilelang.jit.JITImpl.compile` → `tilelang.jit.compile` → `KernelCache.cached` → `JITKernel` → `tilelang.lower`。
5. Pass Pipeline 按 target 注册（`PassPipeline` 注册表，见 `tilelang/backend/pass_pipeline/pipeline.py`），CUDA 流水线见 `tilelang/cuda/pipeline.py`。
6. C++ Pass 通过 `TVM_FFI_STATIC_INIT_BLOCK` + `refl::GlobalDef().def("tl.transform.XXX", fn)` 注册；Python 侧 `tvm_ffi.init_ffi_api("tl.transform", __name__)` 绑定（见 `tilelang/transform/_ffi_api.py`）。
7. Kernel 缓存：单例 `KernelCache`，默认目录 `~/.tilelang/cache`，键由 `func.script(show_meta=True)` 的 sha256、out_idx、args repr、target、backend、pass_configs、`__version__`、tilelang 库内容 hash 组成（`tilelang/cache/kernel_cache.py:241-282`）。
8. CUDA 设备编译由全局回调 `tilelang_callback_cuda_compile` 完成，调用 `nvcc.compile_cuda`，产物为 cubin 或 fatbin，并有一级 `CUDABinaryCache`（`tilelang/engine/lower.py:101-175`）。
9. 设备代码生成入口是 C++ 全局函数 `target.build.tilelang_cuda`（`src/cuda/codegen/rt_mod_cuda.cc:175-180`），实现类是 `CodeGenTileLangCUDA`（`src/cuda/codegen/codegen_cuda.cc`）。
10. DSL 采用 eager builder：`@tilelang.jit` 将 Python 函数转成 `JITFunc`，调用时用 `PrimFunc` builder（`tilelang/language/eager/builder.py`）把 Python 源码翻译成 TIR（TIRX）。
11. 仓库自带后端：CUDA/ROCm/Metal/LLVM(CPU)/WebGPU/CuTeDSL；另有生态仓库负责 Ascend/MACA/MUSA。
12. 仓库规模：约 299 个 Python 测试，`tilelang/` 下 Python 代码约数万行，`src/` 下 C++ 代码（transform 约 40 个 pass 文件）。

## 根据源码推断的结论

（调用链不完全显式，但可由代码关系推断，状态：根据源码推断）

1. `T.Kernel` 宏返回 `_ffi_api.KernelLaunch(...)`，对应 C++ 侧的 `tl.KernelLaunch` FFI（`tilelang/language/kernel.py:277-340`），它构建一个带 `kThreadBinding` 循环的 launch frame；真正把 launch nest 变成 `thread_extent` AttrStmt 或串行 For 的是 `MaterializeKernelLaunch` pass（`tilelang/transform/__init__.py:201-220`）。
2. `@tilelang.jit` 的 lazy/eager 两种模式由 `JITFunc._is_lazy_style` 推断：函数体显式 `return` 一个 `PrimFunc` 为 lazy，使用注解式 tensor 为 eager（`tilelang/jit/__init__.py:380-401`）。
3. 默认执行后端 "auto" 时按 target kind 选择：CUDA → `tvm_ffi`（若不可用则可能回落 nvrtc/cython）（`tilelang/backend/execution_backend.py:89-111`）。
4. JIT 首调开销 = Python DSL 构建 IR + Pass Pipeline + nvcc 子进程编译 + 缓存写盘；缓存命中后仅剩 adapter 加载与 kernel launch（`tilelang/cache/kernel_cache.py:284-419`）。
