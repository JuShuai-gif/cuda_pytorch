## 7. 步骤三：源码安装/编译

> 本学习项目以**阅读/追踪源码**为主，使用"可编辑安装"（editable），这样改 Python 源码立即生效，改 C++ 后重跑同一条命令即可增量编译。

```bash
cd /home/hpc/ghr_code/tilelang

# 可编辑安装：改源码立即生效，改 C++ 后重跑本命令增量编译
# CMAKE_BUILD_PARALLEL_LEVEL=4 限制编译只使用 4 核，避免占满整机
CMAKE_BUILD_PARALLEL_LEVEL=4 pip install -e . --no-build-isolation   # 需要先装好 build 依赖
```

> 说明：`-e .` 会触发 CMake 配置 + 编译 `libtilelang.so`。首次编译较慢（10-30 分钟），之后增量编译快很多。若失败，查看 `cmake` 缓存与日志（`pip` 会输出完整日志，或用 `--verbose`）。

### C++ 在哪一步被编译

TileLang 的核心（IR 构造、Pass、codegen、runtime）是 **C++ 源码**（`src/**` + `3rdparty/tvm`），必须编译成一个 `libtilelang.so` 供 Python 调用。

编译**不是**单独的 `make` 命令，而是 `pip install` 自动触发：

1. `pip install -e .` → 调用 `scikit-build-core`（`pyproject.toml` 的 `build-backend`）
2. → 跑 `cmake` configure（读顶层 `CMakeLists.txt`）
3. → 编译所有 C++ 源码 → 产出 `libtilelang.so`
4. → 把 `.so` 作为 package data 装入 Python 包目录

因此：
- **首次编译慢（10-30 分钟）= 在编 C++**，属正常。
- **只改 Python**（`tilelang/*.py`）→ 无需重编，改完直接生效。
- **改 C++**（`src/**`）→ 需重新 `pip install -e . --no-build-isolation` 触发 CMake 增量编译（详见 `24_源码修改入门.md`）。
- 编译失败时看 `pip` 完整日志（`--verbose`）或 `build/` 下的 CMake 缓存。

## 9. 常见问题

- **Q：`libtilelang.so` 加载失败（`undefined symbol`/`libstdc++` 错误）？** A：确认 venv 与编译时环境一致；`LD_LIBRARY_PATH` 指向同一 CUDA；必要时 `conda` 环境卸载 `libstdc++` 冲突（用 `LD_PRELOAD` 排查）。
- **Q：CMake 找不到 CUDA？** A：设 `CUDA_HOME` / `CMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc` 重试。
- **Q：编译报 `ninja` not found？** A：`pip install ninja` 或改用 `cmake -G "Unix Makefiles"`（`pyproject.toml` 的 `cmake.args` 默认 `-G Ninja`，`CMAKE_GENERATOR` 环境变量可覆盖）。
- **Q：内存不足？** A：本机编译命令已默认限 4 核（`CMAKE_BUILD_PARALLEL_LEVEL=4`）；若仍不足，可降到 `=2`。
- **Q：`torch-c-dlpack-ext` 缺失？** A：`pip install torch-c-dlpack-ext`；或接受 JIT 首次导入慢。
- **Q：想用 NVRTC 后端而不是 nvcc？** A：`execution_backend="nvrtc"`（运行时指定，无需重新编译）。
