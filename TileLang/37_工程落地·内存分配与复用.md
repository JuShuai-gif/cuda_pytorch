# 37 工程落地·内存分配与复用（深度版）

> 本类问题的共性：GPU 内存（shared/寄存器）是稀缺资源，且生命周期差异巨大。难点在于"**在保证正确性的前提下最大化复用**"，这是性能与正确性的交界。

## 机制 1：MergeSharedMemoryAllocations——生命周期复用

### 约束
- 多个 shared buffer 在不同阶段存活。
- 若各自独占，显存爆掉；若错误复用，数据竞争。

### 实现（`src/transform/merge_shared_memory_allocations.cc`）
- 分析每个 buffer 的 def/use 区间。
- 存活期不重叠的 buffer 合并到同一块地址。

> **不变量 M1**：被合并的 buffer，其存活区间互不重叠。
> **不变量 M2**：合并后每个 buffer 的最终偏移保持在其合法范围内。

### 工程判断
- **复用是"生存期分析"的应用**：不是靠运气，是靠可证明的不重叠。
- 这与寄存器分配、编译器的 live range analysis 同构。
- 聚合配置：`tl.disable_shared_memory_reuse`（关复用但保留合并）、`tl.enable_aggressive_shared_memory_merge`（激进合并）。

### 边界
- **不变量 M2 的失败形态**：复用导致数据错位（静默错误）——所以必须有正确的偏移计算。
- 与 Triton 的 `Allocation.cpp`（共享内存分配）+ `MemDescType` 同理。

## 机制 2：寄存器分配——fragment 布局即分配

### 约束
- fragment（`T.alloc_fragment`）映射到寄存器。
- 寄存器数是硬上限（如 255/线程），溢出 → spills → 性能崩。

### 实现（`layout_inference.cc:1012-1167` 的 kFree 模式）
```cpp
// Union-Find 连通分量 + 最小寄存器搜索
int64_t reg_num = 0;
for (auto &[buffer, layout] : tmp_layout_map) {
  if (auto frag = layout.as<Fragment>())
    for (auto i : frag.value()->OutputShape()) reg_num *= *pci;  // 估算寄存器数
}
// 选所有根中寄存器最少的方案
```

> **不变量 M3**：推断出的 fragment 布局必须使寄存器占用最小（在 kFree 模式下）。

### 工程判断
- **布局推断把"寄存器分配"编码进布局选择**：kFree 模式尝试每个 op 作根，算总寄存器数，选最小——这是"布局即分配"的优雅设计。
- 与 Triton 的 `mmaVersionToInstrShape` 每线程元素数同理。

## 机制 3：StorageRewrite——临时存储的重写与别名

### 约束
- 中间结果可能分配为独立 buffer。
- 在可证明安全时复用存储（减少 local 内存）。

### 实现（`src/transform/storage_rewrite.cc`）
- `tl.storage_rewrite_detect_inplace` 控制是否允许 inplace 复用（如 `dst[i]=f(src[i])` → 复用 src）。
- 默认 False（保守），开启后 `read_buf[0]=read_buf[0]*2` 复用。

> **不变量 M4**：存储复用必须不引入别名歧义（别名时结果语义必须保持）。

### 工程判断
- **默认保守**：alias 是危险的，宁可多占内存也不引入隐性别名。
- **显式 opt-in**：把风险交给用户选择。
- 这正是"该保守时保守、该激进时给开关"的工程平衡。

## 机制 4：共享内存 bank conflict 规避（swizzle）

### 约束
- 32 个 bank，若 warp 内线程访问同一 bank → 串行化。

### 实现（`gemm_layouts.cc:442-528`，128B swizzle）
```cpp
c_swizzle = xor8x8(c, s);   // 行号 XOR 列组号
index = vec + (c_swizzle + s*8) * vector_size;
```

> **不变量 M5**：swizzle 后，同一 warp 内对同一列的访问分散到不同 bank。

### 工程判断
- **内存布局本身即优化**：不是"访问时绕开冲突"，而是"把地址重排让冲突不可能发生"。
- 验证：8 行同列访问 → 8 个不同 bank（见 `19` 表格）。

## 本类工程判断总结

1. **复用必须有可证明依据**：存活期不重叠（M1）、别名安全（M4），绝不靠运气。
2. **布局即分配**：寄存器分配编码进布局选择，kFree 最小化。
3. **默认保守 + 显式开关**：alias/复用默认关，风险交给用户。
4. **布局本身即性能**：swizzle 在地址层消除冲突。
5. **错误复用 = 静默数据错位**：所以正确性分析优先于内存节省。
